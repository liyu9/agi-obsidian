# 第一节 AI产品经理的类型划分

## AI行业产业链结构

对于产品经理来说，如果你已经认清楚了这一点，那我们再往下看，究竟AI产品经理相比于传统产品经理有哪些变化跟不变的地方。

在说这个之前，我们先来看一下整个行业的上下游：

```
基础设施层 → 模型层 → 应用层
```

### 产业链层级

| 层级 | 内容 | 说明 |
|------|------|------|
| 基础设施层 | 数据、算力、算法 | 最上游部分 |
| 模型层 | 底层通用大模型、垂类大模型、开源社区 | 偏中游部分 |
| 应用层 | 跨模态产品、多模态组合、策略型设计 | 最下游，基于模型做应用封装 |

## AI产品经理类型划分

从基础设施层、模型层再到应用层这几个维度，我们可以看一下对于AI产品经理来说究竟有对应的哪些类型。

### 基础设施层的AI产品经理

在基础设施层，其实产品经理主要是以**AI平台产品经理**或者是**偏服务层的产品经理**为主。

这些产品经理更多的考验是在于：

- 如何能够去通过一般这种产品经理以前也是比较偏做云服务产品的
- 怎么去更好的理解整个算法原理、数据策略的部分
- 然后可以将这些AI的能力建设出来，最好是封装成一整个平台型的能力

### 模型层的AI产品经理

中游尤其是模型层的AI产品经理，更偏向于是做一些**模型性能优化**的部分。可能这里面也会有一些**策略型的产品经理**，重点是去思考怎么让模型在预训练、在微调的过程中可以有更好的性能提升和效果的提升。

### 应用层的AI产品经理

最后针对下游的AI产品经理，一般我们会区分这几种类型：

| 类型 | 说明 |
|------|------|
| C端产品经理 | 直接面向消费者，面向C端应用场景 |
| B端产品经理 | 偏服务于企业服务的，偏企业的一些运用 |
| 策略产品经理 | 偏设计对话效果，把整个对话的效果设计的更好，涉及模型能力、数据、提示词的优化 |

## AI应用产品经理四象限

在AI应用的产品经理里，究竟如果要再细分的话，其实还是可以再列出一个四象限的：

```
            C端
    AI原生应用     产品内嵌AI
            B端
```

### C端AI产品经理

对于C端的产品经理来说，我们一般有这几种产品类型：

#### AI原生应用

- 通用的ChatBot
- 垂类应用：AI换脸、虚拟恋人、角色扮演、垂直定制写真等

#### 产品内嵌AI

- 短视频 + AI：做创作者的分身
- 旅游 + AI：做旅游规划
- 电商 + AI：更智能化的探索
- 搜索 + AI：更智能化的探索

#### C端AI产品经理人才类型

| 类型 | 说明 |
|------|------|
| 端侧产品经理 | 专门做这种比较偏终端型的产品经理 |
| 多模态产品经理 | 懂图文、懂音乐、懂语音等 |
| 策略产品经理 | 偏把终端的能力跟你背后服务层的能力怎么去嫁接 |
| AI开放平台产品经理 | 把一些AI能力封装成一些服务接口，对外暴露给其他的产品应用 |
| 基于业务的AI产品经理 | 偏业务内嵌AI的产品经理 |

### B端AI产品经理

B端的产品经理里面，其实AI原生应用相对还比较少，但也有，比如一些医疗诊疗的应用、金融投资的应用。

那他们可能需要的是一些比较偏**智能体开发平台的产品经理**。

然后关于产品内嵌AI，这个其实在B端产品经理中还是比较盛行的，因为很多B端的场景里，他很需要通过AI来去做提效和增收。

#### B端AI应用场景

- 企业办公
- 金融
- 物流供应链

这些行业其实目前都有陆陆续续的在内嵌AI去做一些更智能化的探索，比如说数字员工、像一些金融+AI等。

#### B端AI产品经理人才类型

| 类型 | 说明 |
|------|------|
| 智能体开发平台产品经理 | 需要比较偏智能体开发平台的产品经理 |
| AI开放平台产品经理 | 把一些AI能力封装成服务接口 |
| 基于业务的AI产品经理 | 有足够的业务经验，结合AI能力 |

## 招聘视角下的AI产品经理

分析完了这些角色之后，我们也来看看市面上的一些招聘视角，对于AI产品经理的职责和能力上面的要求。

### 通用要求

不论你招的是一些AI原生的产品经理，还是招募一些比较偏业务内嵌AI的这种产品经理，他本质上对于产品经理的要求都还有一些相似之处：

- 你要去理解AI这些相关的技术原理
- 也要知道如何确保产品满足市场需求跟业务的目标
- 希望你有比较多的大模型技术的理解能力
- 对AI应用有比较多的理解跟热情

### 核心能力提炼

#### 产品经理底层能力（通用）

不论你现在是应聘传统的产品经理还是AI产品经理，本质上底层能力的要求还是比较普适的，只是说你要去补齐AI专用领域的认知跟技能。

#### AI专用领域能力

- 关于整个数据的体系
- 关于算法的原理
- 同时也要关于整个工程的链路

#### 通用素质

- 需求的分析
- 原型的设计
- 用户的洞察
- 数据分析
- 市场调研

这些都是属于通用的素质。

### 能力迁移策略

对于我们来说更适合去做AI产品经理转型，就是要学会迁移你原有的经验跟能力：

| 你的背景 | 转型方向 | 说明 |
|---------|---------|------|
| C端产品经验 | AI原生应用端侧产品策划 | 非常懂怎么去做好用户的体验，怎么去让产品跟用户之间的互动可以有更强的粘性 |
| B端产品经验 | 业务内嵌AI创新 | 基于自己本身的业务经验，比如说你现在做的是一款金融的产品，可以基于自己本身的业务经验来结合大模型的能力去增强平台的能力 |

## 案例：抖音AI创作者分身项目

这里给一个案例，关于抖音AI创作者分身的项目。

### 项目背景

这个项目其实是关于抖音内有很多各种专业的作者，还有一些行业的商家，包括一些行业的专家等等。这些大V创作者们，他们日常都有一些比较大的痛点，就是不知道能不能让自己有更多的时间和精力来去维系跟自己粉丝之间的互动粘性。

因为很多大V他其实根本没有这个时间，但是他又需要跟自己的粉丝有比较强的互动。

### 解决方案

那现在作者怎么做呢？他可能会在评论区里面去回复Top 3的铁粉。但是有一些类型的作者其实远远不够，比如说虚拟恋人、或者是一些美妆博主、知识科普博主。

那他为了去维系粉丝之间的互动，可能也需要去建立一些像粉丝群，然后包括有更强的这种评论区的互动，甚至是直播间互动的场景。

这种情况下平台可以做什么呢？那抖音就推出了一个AI创作者分身项目。

这个项目本身他是可以支持让一些作者给自己结合自己的一些情绪、内容风格来去创作另外一个自己，就是创作一个作者的分身。这个分身可以帮作者去分摊他日常跟粉丝之间在评论区、在私信、在直播间面板，然后在包括其他的场域里面都可以跟粉丝有一个双向的互动。

同时通过跟粉丝互动的这些数据也可以反哺给作者，让他可以更清楚的知道自己接下来更适合去对外释放什么样的内容。

### 项目所需产品经理类型

整个项目其实是会区分几个大的能力板块，你会发现他招募的产品经理一般会区分大概四类角色：

| 产品经理类型 | 职责 |
|------------|------|
| C端用户产品经理 | 负责AI分身在用户端的一些体验上面的优化，负责私信、评论区等不同场景里面的一些对话效果的提升 |
| B端平台产品经理 | AI分身管理平台的搭建，底层的一些算法工程能力，怎么去支持一些上层的应用，甚至未来如何去开放整个平台的能力给到更多的第三方开发者 |
| 策略型产品经理 | 负责大模型的对话策略设计，包括一些产品数据体系、模型评估反馈等 |
| 多模态产品经理 | 负责AI对话过程中的语音、表情、图片等多模态效果的呈现 |

这个是作为一个属于业务内嵌AI的项目里面，他需要招募的几类角色。其实同理在我们其他看得到看不到的一些C端B端的产品里面，如果有涉及到一些产品经理的诉求，基本上也是围绕这几个方向去展开的。
