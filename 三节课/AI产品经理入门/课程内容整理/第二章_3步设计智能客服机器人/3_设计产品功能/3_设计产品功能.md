# 第3步：设计产品功能

## 一、AI产品功能设计三大要点

### 1. 核心认知

**AI产品经理的特点**：
- 对算法和逻辑的理解要求更高
- 策划稿/需求稿绝大部分内容是算法需求描述或策略逻辑描述

**产品形态类比**：

```
┌─────────────────────────────────────┐
│  AI产品冰山模型                      │
├─────────────────────────────────────┤
│  ★ 冰山以上（用户可见）              │
│    前端交互设计                      │
│    用户体验                          │
├─────────────────────────────────────┤
│  冰山以下（用户不可见）              │
│  ├── 算法工程师的工作               │
│  └── 工程化迭代逻辑策略             │
└─────────────────────────────────────┘
```

### 2. 三大设计要点

| 要点 | 说明 |
|------|------|
| **重视前端交互设计** | 虽然交互内容不多，但用户体验核心在此 |
| **保证算法功能闭环** | 从设计到验证上线迭代优化满足全场景业务流程闭环 |
| **技术不够产品来补** | 算法效果有限时，利用工程力量（规则、辅助）提升效果 |

## 二、智能客服机器人交互触点分析

### 1. 用户与机器人交互全流程

```
┌──────────────────────────────────────────────────────┐
│  用户与机器人交互全流程                                │
├──────────────────────────────────────────────────────┤
│                                                      │
│  ┌─────────────┐                                    │
│  │ 1.访客端聊天页面 │ ←─────── 快捷入口               │
│  └──────┬──────┘         │                          │
│         │                │                          │
│         ↓                │                          │
│  ┌─────────────┐         │                          │
│  │ 2.智能问答   │ ←─── 用户输入问题                 │
│  └──────┬──────┘                                    │
│         │                                            │
│         ↓                                            │
│  ┌─────────────┐                                    │
│  │ 3.管理后台   │ ←─── 知识库维护/数据报表          │
│  └─────────────┘                                    │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 2. 三大核心触点

#### （1）访客端聊天页面

**包含内容**：

**用户希望看到的内容**：
- 能快捷解决问题的内容
- 符合当前场景的个性化推荐

**企业希望用户看到的内容**：
- 近期活动推广
- 关联商品推荐

**内容分类**：

| 内容类型 | 特点 | 示例 |
|---------|------|------|
| **个性化内容（千人千面）** | 针对每个用户定制 | 订单推荐、商品推荐 |
| **固定内容** | 所有用户相同 | 活动公告、操作引导 |

**快捷入口设计**：
- 转人工快捷入口
- 评价快捷入口
- 操作快捷入口

**问题推荐逻辑**：

| 用户来源 | 推荐策略 |
|---------|---------|
| 从订单详情页进来 | 推荐该订单相关问题 |
| 从商品详情页进来 | 推荐该商品相关问题 |
| 从官网/店铺首页进来 | 推荐近期活动内容 |
| 刚下完订单 | 推荐物流查询、快递公司询问 |

#### （2）智能问答交互

**机器人与用户进行智能问答**

**当用户没有点击推荐内容，而是自己输入问题时** → 进入机器人问答环节

**会话结束后**：
- 梳理机器人无法应答的问题
- 或人工会话可应答但机器人无法应答的问题
- 推荐给AI训练师/运营管理人员进行标注维护

**管理后台需要具备的功能**：
- 知识库维护
- 机器人训练学习
- 数据报表查看

#### （3）管理端后台

**核心功能**：

| 功能模块 | 说明 |
|---------|------|
| **知识库维护** | 添加/修改/删除问答知识 |
| **机器人训练** | 让机器人学习新知识 |
| **数据报表** | 查看机器人应答效果、接线情况 |

## 三、对话管理设计

### 1. 对话流程设计原则

**核心依据**：根据当前业务场景需要设计对话管理步骤

### 2. 不同场景的对话设计

#### （1）强引导场景

**典型场景**：
- 售前场景
- 机器人引导场景
- 语音呼入/外呼场景

**设计特点**：
- 机器人强引导
- 多轮对话强制引导用户进行对答

#### （2）VUI设计师

**岗位定义**：Voice UI Designer（语音交互设计师）

**职责**：
- 设计用户与机器人的对话话术
- 设计对话流程
- 设计交互方式

**特殊背景**：
> 在语音机器人的场景下，连访客端的页面都没有，用户所有的体感都来自于用户与机器人的每一轮对答。

### 3. 话术设计技巧

#### （1）变量称呼

**原则**：在答案里尽可能多贴合业务系统，给到用户可选择性内容

**对比示例**：

**普通做法**：
> "您在APP我的订单管理找到你的订单去查"

**优化做法**：
> "您要查哪一个订单？我目前看见您有A、B、C三个订单"

**价值**：用户在当前页面就能处理完问题，体验更好

#### （2）避免指示性内容

**指示性内容**：告诉用户去某个地方操作

**推荐方式**：直接提供选项，让用户选择

## 四、前端交互设计重要性

### 1. 容易被忽视的问题

> 作为AI产品经理，平时工作中绝大部分时间都在研究算法、研究业务场景、研究需求、研究逻辑，所以很容易忽视掉前端的功能设计。

### 2. 实际案例对比

**对比对象**：
- 左侧：阿里小蜜
- 右侧：某电商平台智能客服机器人

**关键洞察**：

> 即便是右边的电商平台智能客服机器人，你的语义理解准确率高得吓人，智能推荐精准到可以怀疑人生。但是对比这两个用户界面，给到用户的体感是一目了然的。

### 3. 设计原则

**核心观点**：

> 虽然说比较核心的工作或者大量的时间都投入在研究逻辑、研究算法、研究效果，但是作为一个产品经理，我们是为用户提供价值的，用户的体感才是第一位的。还是要通过一些相对不错的前端页面，能够把你产品的价值传达出来。

## 五、算法功能闭环设计

### 1. 闭环的重要性

**核心要求**：从功能设计到效果验证、上线迭代优化，需要能够满足全场景的业务流程闭环

**两种实现方式**：

| 方式 | 适用场景 | 说明 |
|------|---------|------|
| **线下实现** | 企业内部AI系统 | 功能界面不完善时可以进行线下训练 |
| **线上产品化** | SaaS系统 | 必须考虑在管理后台可以完成整个路径的操作 |

### 2. SaaS系统闭环设计要点

**必须具备的功能**：

```
┌─────────────────────────────────────────┐
│  SaaS管理后台算法闭环                    │
├─────────────────────────────────────────┤
│  1.智能推荐待标注语料                   │
│     ↓                                  │
│  2.AI训练师标注                         │
│     ↓                                  │
│  3.模型训练、迭代、上线                 │
│     ↓                                  │
│  4.查看核心指标数据                     │
└─────────────────────────────────────────┘
```

### 3. 大公司 vs SaaS产品的深度差异

**大公司自研AI应用**：

**特点**：在效果方面做得比较深入

**案例**：以智能客服机器人为例

**深度优化流程**：
- FAQ匹配、情感识别、问题聚类等四个环节
- 每个环节可以做多个深度学习模型
- 在业务场景里做线上AB测试

**AB测试案例**：
- FAQ识别：做10个深度学习模型
- 每个模型分配10%流量
- 一段时间后对比10个渠道的识别效果
- 选择效果最好的模型，将所有流量切换过去

**SaaS产品的局限**：
- 不太会提供这种深度优化能力
- 通常提供通用解决方案

## 六、算法深度优化流程

### 1. 参与角色

```
┌─────────────────────────────────────────┐
│  算法深度优化五大角色                    │
├─────────────────────────────────────────┤
│  ① AI产品经理                          │
│  ② 数据分析师                           │
│  ③ 语料标注人员（AI训练师）             │
│  ④ AI知识研究员                        │
│  ⑤ 算法工程师                          │
└─────────────────────────────────────────┘
```

### 2. 优化流程

```
1. AI产品经理明确优化点
   ↓
2. 提交给数据分析师
   ↓
3. 共同制定核心数据指标
   ├── 当前指标值
   └── 目标指标值
   ↓
4. AI产品经理判断是否需要标注数据
   ↓
5. 如需标注 → 提供给语料标注人员
   ↓
6. 标注完成后进行模型训练
   ↓
7. 测试是否达到指标预期
   ↓
   ├── 达标 → 优化完成
   └── 未达标 → AI知识研究员参与
       ↓
       优化知识库体系
       ↓
       提交给算法工程师进行模型训练
       ↓
       返回数据分析师验证效果
```

### 3. 效果天花板认知

**现实情况**：

> 作为一位AI产品经理，你需要能够理解，有时候算法的效果可能是受制于当前标注语料，也有可能是因为当前这个场景本身就有技术壁垒，需要寻求更深的技术突破。

**案例**：
- 算法从70分提升到80分：可能需要算法工程师和标注团队付出非常多的努力
- 如果加上产品设计的辅助：从70分提升到85分还是很有希望的

## 七、技术不够产品来补

### 1. 核心思路

> 有时候付出了80%的努力，可能对算法的准确率或者召回率提升只有一个点两个点。那这种情况下产品经理要能利用工程的力量——比如规则或者对算法的一些辅助、对语料的一些清洗等等其他的一些方式——能够提升一下算法的效果。

**核心原则**：技术不够，产品来补

### 2. 两大方向

```
┌─────────────────────────────────────────┐
│  技术不够产品来补                        │
├─────────────────────────────────────────┤
│  方向一：辅助算法识别                   │
│  方向二：清洗数据降低算法噪声            │
└─────────────────────────────────────────┘
```

### 3. 方向一：辅助算法识别

#### （1）冷启动阶段扩写相似问题

**场景**：智能客服机器人冷启动

**问题**：有100个FAQ问答对，每个FAQ的标准问题没有匹配相似问题

**现状**：直接上线算法匹配准确率相对会比较低

**解决方案**：给这100个标准问题扩写或生成相似问题

**案例**：

**标准问题**："能不能退货"

**人类表达方式**：
- 能不能退货
- 怎么样退货
- 我已经收货七天了还能不能退货
- 退货的入口在哪里
- 可以申请退款吗
- 退货怎么操作
- 退货流程是什么

**价值**：
- 人类表达方式有很多种
- 但都对应同一个答案
- 前期扩写相似问题很有必要

#### （2）添加正则表达式和关键词强制召回

**场景**：冷启动阶段减少扩写工作量

**案例**：

**标准问题**："退货方式"

**解决方案**：
- 只要用户问题里包含"退货"这个词
- 冷启动阶段就可以强制召回"退货方式"这个标准问题

**价值**：
- 减少冷启动阶段扩写语料的工作量
- 辅助算法进行精准识别

#### （3）引导用户点击选择

**功能类型**：
- 输入推荐
- 问题推荐
- 快捷入口

**原理**：
- 用户点击 = 最精准的匹配
- 点击后直接出答案
- 不需要算法再去匹配用户输入的问题

**案例**：

**输入推荐**：
- 用户输入过程中输入了几个字
- 系统直接匹配问题库中包含这几个字的问题
- 推荐给用户点击
- 点击后直接返回答案

**快捷入口**：
- 会话开始前展示用户最可能问的问题
- 输入框上方展示快捷入口icon
- 用户问了一个问题后，预测下一个最可能的问题
- 以缩写或快捷短语形式展示，引导点击

**核心价值**：

> 不论是输入推荐还是快捷入口，展示的内容都是引导用户点击。用户点击的话就最精准的一个匹配，点击以后就直接出答案了。

### 4. 方向二：清洗数据降低噪声

#### （1）维护ASR转译词库

**场景**：语音转文本（ASR）

**问题**：方言或口语化表达无法正确识别

**案例**：
- 四川话里"要得"意思是"可以"或"好的"
- 普通话里"要得"机器人无法识别

**解决方案**：
- 维护一个转译词库
- 将"要得"维护成"好的"的正向映射
- 辅助ASR转译结果更精准

#### （2）维护专有词库和同义词库

**同义词库案例**：

**问题**：品牌名不同但指代相同

**案例**：
- "YSL" = "圣罗兰"
- 用户问"YSL有什么色号" = 用户问"圣罗兰有什么色号"

**解决方案**：
- 将"YSL"和"圣罗兰"维护成同义词
- 召回到同一个标准问

**专有词库案例**：

**问题**：算法分词会把专有名词切开

**案例**：
- "神州租车" → 算法分成"神州"和"租车"
- "网易七鱼" → 算法分成"网易"和"七鱼"

**解决方案**：
- 将"神州租车"、"网易七鱼"维护成专有词
- 算法分词时不会把这些词切开
- 辅助算法识别

#### （3）维护屏蔽词库

**问题**：用户说话中有无意义的内容

**影响**：
- 直接灌给算法不太有意义
- 甚至会干扰算法识别

**解决方案**：
- 将无意义的词句过滤出来
- 维护在屏蔽词库中
- 降低算法识别过程中的噪声

## 八、实战案例：问题匹配准确率提升

### 1. 功能描述

**问题匹配**：
- 用户问了一个问题
- 机器人从已有问题库中匹配最精准的问题
- 把该问题的答案回复给用户

**问题库规模**：几千个甚至几十万个FAQ问题

**核心挑战**：用户一句问句，在几十万个FAQ问题中匹配到最精准的答案

**衡量指标**：匹配率

### 2. 匹配结果类型

| 结果类型 | 场景 | 回复方式 |
|---------|------|---------|
| **精确答案** | 匹配到一个精准答案 | 直接回复该答案 |
| **反问答案** | 匹配到3-5个相关问题 | "请问您是否想咨询以下问题？"推荐给用户选择 |
| **不知道** | 完全匹配不到 | "很抱歉我没有识别到您的问题"或直接转人工 |

### 3. 产品设计提升准确率

**两大成熟功能**：

#### （1）输入推荐

**触发时机**：用户输入问题过程中

**功能逻辑**：
- 用户输入几个字
- 系统拿这几个字在问题库中匹配
- 包含这几个字的问题展示给用户

**用户行为**：点击推荐问题

**结果**：直接返回对应答案

#### （2）快捷入口

**类型1：会话开始前**
- 展示用户最可能问的问题
- 用户直接点击

**类型2：输入框上方**
- 展示快捷入口icon

**类型3：预测下一个问题**
- 用户问了一个A问题
- 预测用户下一个可能问B问题
- 以缩写或快捷短语形式展示在输入框上方
- 引导用户点击

**核心价值**：用户点击 = 最精准匹配 = 直接出答案

### 4. 产品设计辅助算法的本质

> 为什么说这两个功能是通过产品设计来提升识别准确率，或者说属于"技术不够产品来补"呢？

**原因**：
- 智能客服机器人是NLP领域、对话机器人领域发展比较成熟的业务方向
- 这些功能的设计意图可以看出是为了辅助算法识别
- 作为AI产品经理，做相对不成熟的业务场景时，思考的思路也是一样的

**核心思路**：
- 持续辅助算法的识别
- 持续降低算法匹配过程中的噪声数据

```

├── 1.重视前端交互设计
```
