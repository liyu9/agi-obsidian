# 第五周：项目管理

## 从业务到项目管理

同学们好，我是不眠。这一章我们来讲项目管理的部分。

### 业务与项目的关系

项目管理的核心目的是**把业务目标落地**。当你有了业务驱动模型和中长期规划后，需要通过一个一个的项目去实现：

```
业务目标 → 项目拆解 → 项目启动 → 协作执行 → 复盘迭代
```

---

## [一] 准备一场高质量的项目启动会

### 项目启动会的重要性

项目启动会是项目成功的关键起点。一场好的启动会能解决：

1. **统一目标**：让所有参与者对项目目标达成共识
2. **明确分工**：每个人的职责和交付物清晰
3. **建立信任**：团队成员之间有基本的了解和信任
4. **设定节奏**：明确项目的时间节点和里程碑

### 项目启动会的准备工作

| 准备项 | 内容 |
|--------|------|
| **明确会议目标** | 这次启动会要达成什么结果 |
| **准备核心材料** | PRD、项目计划、里程碑、资源清单 |
| **提前沟通关键人** | 提前与核心成员对齐，避免会议争议 |
| **确定会议议程** | 会议流程和时间分配 |

### 启动会核心议程

1. **项目背景和目标**（由产品经理主讲）
   - 为什么要做这个项目
   - 项目的核心目标是什么
   - 成功标准是什么
2. **项目范围和分工**
   - 做哪些事情（范围）
   - 不做哪些事情（排除）
   - 谁负责什么
3. **项目计划和里程碑**
   - 关键时间节点
   - 阶段性成果
4. **资源需求和风险**
   - 需要什么资源
   - 可能的风险及应对方案

### 启动会的产出

- 达成共识的项目目标
- 明确的项目分工
- 确定的时间节点
- 项目协作工具和沟通机制

## [二] 在团队中形成一致的协作机制

### 为什么协作机制重要

> 没有协作机制，团队就是一盘散沙。每个人按自己的方式工作，最终会导致项目混乱。

### 协作机制的关键要素

| 要素 | 说明 |
|------|------|
| **沟通机制** | 什么情况下用哪种沟通方式（日报/周会/即时消息） |
| **决策机制** | 谁做什么决策，什么情况下升级决策 |
| **信息同步机制** | 关键信息如何传递到所有人 |
| **问题反馈机制** | 遇到问题如何反馈、多长时间内响应 |

### 常见协作机制

```
日常沟通
├── 即时消息（日常工作沟通）
├── 日报（个人工作同步）
├── 周会（团队进度同步）
└── 站立会（每日同步，15分钟以内）

决策机制
├── 产品决策 → 产品经理
├── 技术决策 → 技术负责人
├── 业务决策 → 项目经理/产品总监
└── 重大决策 → 升级到高层

问题处理
├── 小问题 → 即时处理
├── 中等问题 → 当天解决
└── 重大问题 → 立即上报
```

### 协作机制的建立步骤

1. **项目启动时明确**：在项目启动会上明确协作规则
2. **执行中持续优化**：根据团队反馈调整机制
3. **出现问题时复盘**：协作问题及时拿出来讨论
4. **形成团队习惯**：好的机制需要时间沉淀

## [三] 做好阶段性总结与复盘

### 复盘的目的

| 目的 | 说明 |
|------|------|
| **沉淀经验** | 好的做法固化下来，下次继续用 |
| **发现问题** | 识别过程中的问题，避免重复犯 |
| **优化流程** | 基于实际执行改进协作流程 |
| **团队成长** | 通过复盘提升团队整体能力 |

### 复盘的方法

#### 四步复盘法

```
第一步：回顾目标
├── 我们当初的目标是什么？
├── 目标是否清晰？
└── 有没有偏离目标？

第二步：评估结果
├── 哪些目标达成了？
├── 哪些没有达成？
└── 与目标的差距有多大？

第三步：分析原因
├── 成功的原因是什么？
├── 失败的原因是什么？
├── 哪些是可控因素？
└── 哪些是不可控因素？

第四步：总结改进
├── 哪些做法要保留？
├── 哪些做法要改进？
├── 下一步行动计划是什么？
└── 谁来跟进改进措施？
```

### 复盘的频率

| 频率 | 适用场景 |
|------|----------|
| **每个迭代结束后** | 敏捷开发的Sprint复盘 |
| **每个里程碑后** | 阶段性成果评估 |
| **项目结束后** | 项目整体复盘 |
| **出现重大问题后** | 问题复盘和追责 |

### 复盘的关键原则

> 复盘不是追责会，而是**学习会**。目的是找出问题根因、沉淀经验，而不是找谁背锅。

### 有效复盘的核心心态

1. **对事不对人**：聚焦问题本身，不针对个人
2. **开放坦诚**：每个人都能真实表达
3. **重在改进**：不是找责任，而是找方案
4. **持续迭代**：复盘是持续的过程，不是一次性的

## 学习要点

1. **项目启动会**是统一团队认知的关键节点，准备工作决定启动会质量
2. **协作机制**需要提前明确，在执行中持续优化
3. **复盘**的核心是学习改进，不是追责
4. 项目管理的最终目标是**把业务目标落地**

## 总结

第五周的项目管理章节，核心是围绕如何把一个项目从启动到执行再到复盘的全流程管理。高质量的项目启动会、一致的协作机制、有效的复盘总结，这三者构成了推动项目成功的关键保障。对于P3产品经理来说，不仅要懂业务、懂产品，还要懂如何通过项目管理把业务目标落到实处。
