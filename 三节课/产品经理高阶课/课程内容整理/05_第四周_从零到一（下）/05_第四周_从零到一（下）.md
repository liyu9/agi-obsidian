## 验证产品：用户调研与用户访谈

同学们好，我是不眠。今天我们来讲一讲验证产品的过程，用户调研与用户访谈。

### 用户验证在P3阶段的特殊性

在从零到一的过程中，用户验证与P1/P2阶段有本质区别：

| 维度 | P1/P2 | P3（从零到一） |
|------|-------|---------------|
| **目的性** | 收集需求、了解反馈 | 验证假设、判断方向 |
| **效率** | 可相对宽松 | 必须高效聚焦 |
| **决策** | 功能层面 | 产品存亡层面 |

## [四] 种子用户调研方法（上）

### MVP过程中的用户调研

MVP的本质是低成本快速验证，用户调研在其中扮演关键角色。

### MVP设计流程回顾

```
明确用户需求 → 流程设计 → 原型设计 → 小范围推广测试 → 循环迭代
```

### 用户故事再分解

当我们从Idea画布拿到初步的用户故事后，需要进一步分解：

| 要素 | 内容 |
|------|------|
| **用户** | 一群什么样的人 |
| **场景** | 在什么场景下 |
| **想解决的问题** | 想解决什么问题 |
| **具体问题** | 在解决问题过程中碰到什么具体问题 |
| **当前解决方案** | 用户现在怎么解决的 |

### 用户需求拆解示例

以"看电影决策"为例：

```
步骤一：呼朋唤友（不知道看什么/决定和谁看）
    ↓
步骤二：找片子（好多电影，不想看烂片，受微博/朋友圈影响）
    ↓
步骤三：决定（买票问题/让闺蜜信任你的选择）
    ↓
步骤四：反馈（让自己和同伴都觉得选择是靠谱的）
```

**早期切入点**：帮助呼朋唤友的女生找片子的过程。

### MVP阶段的用户需求原则

> 在MVP阶段，不要考虑用户故事找得准不准、好不好。要**更快地假设**，假设完了进行分析，搞到一类人就不妨碍往下做。

## [四] 种子用户调研方法（中）

### 如何找到种子用户

| 方式 | 说明 | 优先级 |
|------|------|--------|
| **着陆页收集** | 通过海报、宣传页吸引用户留信息 | ★★★★★ |
| **预售/付费** | 让用户花钱投票，验证真需求 | ★★★★★ |
| **加群/加个人微信** | 建立种子用户群，深度互动 | ★★★★ |
| **转介绍** | 种子用户推荐新用户 | ★★★ |
| **精准投放** | 最小词投放吸引目标用户 | ★★★ |

### 种子用户调研的核心目的

1. 验证产品价值假设
2. 发现用户真实行为模式
3. 收集产品改进方向
4. 寻找产品增长引擎的线索

### 用户访谈要点

| 要点 | 说明 |
|------|------|
| **找对用户** | 找典型目标用户，不是好友或粉丝 |
| **场景还原** | 让用户回忆真实使用场景，而不是假设场景 |
| **关注行为而非观点** | 用户做了什么比说了什么更重要 |
| **寻找痛点强度** | 用户在解决当前问题时的痛苦程度 |

## [四] 种子用户调研方法（下）

### PMF验证中的用户信号

寻找PMF过程中，来自用户的信号至关重要：

### 正面信号

- 用户愿意付费
- 用户会用不同方式绕开限制持续使用
- 用户在产品很难用时还愿意用
- 用户主动推荐给他人
- 用户为停用产品感到不满

### 负面信号

- 用户来了就走（留存率低）
- 用户需要大量引导才能理解产品价值
- 用户使用后无任何反馈
- 用户离开后无任何回归意愿

### ClassPass案例的启发

ClassPass团队发现用户换邮箱反复领取免费体验包时，没有选择堵漏洞，而是意识到：
> **用户愿意为这个价值付出更大努力，意味着产品真的有价值。**

他们把免费体验转化为**付费订阅模式**（80美元/月任选4-6个课程），找到了真正PMF。

## [五] 产品早期运营规划

### 从1万到10万用户增长的设计逻辑

当产品从MVP验证阶段走向早期增长阶段，需要系统的运营规划。

### 早期运营的核心命题

| 命题 | 说明 |
|------|------|
| **留存＞增长** | 早期用户留存比拉新重要，先确保产品价值被认可 |
| **种子用户质量＞数量** | 高质量种子用户带来真实反馈和口碑传播 |
| **运营动作可衡量** | 每个运营动作都需要有数据支撑 |
| **找到增长引擎** | 是口碑传播、投放、还是渠道合作？ |

### 早期运营规划框架

```
第一阶段：种子期（0 - 1万用户）
├── 找到核心种子用户（着陆页/预售/加群）
├── 深度服务种子用户（一对一沟通、快速迭代）
├── 建立用户反馈闭环
└── 验证留存率达标

第二阶段：增长期（1万 - 10万用户）
├── 明确增长引擎（口碑/投放/渠道/转介绍）
├── 建立运营数据体系
├── 开始小规模投放测试
└── 找到可规模化的增长路径
```

### 不同产品类型的早期运营重点

| 产品类型 | 早期运营重点 |
|----------|-------------|
| **C端内容型** | 内容质量 + 用户留存 > 用户量 |
| **C端工具型** | 核心功能体验 + 口碑传播 |
| **B端SaaS** | 标杆客户打样 + 案例沉淀 |
| **平台型（双边）** | 稀缺资源方优先（供给或消费） |
| **交易型** | 信任体系 + 交易闭环 |

### 从PMF到规模增长的路径

```
        ┌───────┐
        │ IDEA  │
        └───┬───┘
            ↓
        ┌───────┐
        │ MVP   │ ← 循环验证
        └───┬───┘
            ↓
        ┌───────┐
        │ PMF   │ ← 找到临界点
        └───┬───┘
            ↓
    ┌───────────────┐
    │   快速增长期   │ ← 投放/转介绍/补贴
    └───────────────┘
```

### 关键观点

> PMF没到的情况下疯狂砸钱，最后会把自己砸死。

### 案例：叮咚小区

在产品刚上线时花大量资金在北上广深地铁砸广告，但次日留存只有个位数，大部分用户装完卸载。**产品本身没有给用户带来价值**，砸再多钱也没用。

## [章节总结]

### 从零到一的完整流程

```
┌──────────────────────────────────────────────────┐
│                从零到一完整流程                      │
├──────────────────────────────────────────────────┤
│  第一步：假设（Idea分析画布）                       │
│  ├─ 用户与场景假设                                 │
│  ├─ 可行性分析（关键因素）                          │
│  ├─ 可能性分析（商业价值）                          │
│  └─ 市场分析（行业与竞品）                          │
│                                                   │
│  第二步：MVP设计                                   │
│  ├─ 0→0.5：验证价值（Demo/视频/文档/预售/着陆页）   │
│  ├─ 0.5→1：让用户能用（流程设计+原型设计）          │
│  └─ 小范围测试与迭代                               │
│                                                   │
│  第三步：用户验证                                  │
│  ├─ 种子用户调研（深度访谈）                        │
│  ├─ 验证产品价值假设                               │
│  └─ 寻找PMF信号                                   │
│                                                   │
│  第四步：早期运营（找到PMF后）                      │
│  ├─ 留存＞增长                                    │
│  ├─ 找增长引擎                                    │
│  └─ 从1万到10万用户                               │
└──────────────────────────────────────────────────┘
```

### PMF与MVP的关系

- MVP和PMF是不断在循环、相互佐证的过程
- 我们通过一系列的MVP去找到PMF
- PMF不是找出来的，是**试出来的**
- 找到PMF后再投入资源做规模化增长

### 成功产品的共同特征

> 每一个成功的产品背后都有个很艰难的开始。这个开始就是MVP。

独角兽公司一开始的版本都非常难看。很少有一开始布局非常大、高举高打最后打出来的产品。

---

## 学习要点

1. **种子用户调研**在P3阶段要更聚焦于验证假设，而非收集需求
2. **用户真实行为**比口头反馈更有价值
3. 早期运营要坚持**留存大于增长**，先确保产品价值
4. PMF没到之前砸钱推广是最大的浪费
5. MVP到PMF是循环迭代的过程，不是一次性完成

## 总结

第四周是"从零到一"的下半部分，完成了从假设→MVP→用户验证→早期运营的完整闭环。核心方法论是Idea分析画布和MVP设计，目标是在资源有限的情况下找到PMF。这个体系帮助P3产品经理在接手新业务时，能够系统化地降低失败概率，增加成功的确定性。
