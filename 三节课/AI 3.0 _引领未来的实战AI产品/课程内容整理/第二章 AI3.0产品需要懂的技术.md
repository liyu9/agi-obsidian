# 第二章 AI3.0产品需要懂的技术

## 一、AI产品经理要不要懂技术

### 1. 核心结论

**不懂技术很难入行，只懂技术很难高薪**

### 2. 两句话总结

| 场景 | 结论 |
|------|------|
| 入行时不懂技术 | 很难入行 |
| 只懂技术不懂其他 | 难以拿到高薪 |

### 3. 学习建议

| 阶段 | 推荐学习 |
|------|---------|
| 入门阶段 | 《产品经理进化论》《数据增长模型》 |
| 提升高薪阶段 | 《AI赋能》 |

### 4. AI产品经理技术分层（六个级别）

| 级别 | 技术内容 |
|------|---------|
| L0级别 | 看过科幻书、机器人三定律、图灵测试、《西部世界》电影 |
| L1级别 | 机器学习、神经网络、深度学习、数据挖掘、知识图谱、分类/聚类/预测 |
| L2级别 | 正则表达式、图搜索、启发式搜索、模拟退火、增量学习、对话系统 |
| L3级别 | 神经网络、线性回归、生成模型、CNN、文本分析、语义分析 |
| L4级别 | 马尔科夫链、集成学习、迁移学习、卡尔曼滤波、CNN、RNN |
| L5级别 | VC理论、博弈论、微分动力系统、流形学习、变分推断 |
| L6级别 | 旋理论、量子计算、泛函分析、认知科学 |

## 三、AI算法解析-文生文（上）

### 1. AI本质三要素

```
┌─────────────────────────────────────┐
│             庞大数据                 │
├─────────────────────────────────────┤

### 2. ChatGPT技术原理

**官方回答：**
- Transformer架构
- 大规模训练数据集
- 无监督学习
- 超大规模参数
- 有监督微调

### 3. Claude技术架构

```
┌────────────────────────────────────────────┐
│               Claude技术架构                 │
├────────────────────────────────────────────┤
│  数据层                                     │
│  ↓                                         │
│  语言编码器（文本→向量/矩阵）               │
│  ↓                                         │
│  自监督学习 + 强化学习                      │
│  ↓                                         │
│  对话管理模块（决定回答策略）                │
│  ↓                                         │
│  监督模块（检测错误并修正）                  │
└────────────────────────────────────────────┘
```

### 4. Bard技术架构（谷歌）

| 组件 | 功能 |
|------|------|
| 数据集 | 书籍、文章、代码库、网站等文本和代码 |
| 技术框架 | Transformer深度学习技术 |
| 编码器 | Encoder将提示转换为向量 |
| 解码器 | Decoder使用向量生成输出文本 |

### 5. 文生文算法三步流程

```
┌────────────────────────────────────────────────────────┐
│                    文生文算法流程                        │
├────────────────────────────────────────────────────────┤
│  第一步：收集数据                                        │
│  → 原始数据（Raw Data）                                 │
│  → 分成训练级、验证级、测试级                            │
│  ↓                                                      │
│  第二步：选择模型                                        │
│  → Transformer框架                                       │
│  → Encoder编码 + Decoder解码                             │
│  ↓                                                      │
│  第三步：优化精调                                        │
│  → 训练→精调→输出                                      │
└────────────────────────────────────────────────────────┘
```

### 6. 关键数据对比

| 模型级别 | 训练数据量级 |
|---------|------------|
| 普通模型 | 按MB计算 |
| 基础大模型 | 按TB计算起步 |
| GPT-3/3.5/4 | 仅是起点 |

### 7. Transformer框架优势

- 能够跨语言
- 能够跨模态
- 具有涌现性
- 不纠结单一模态

### 8. 大模型训练三大并行

| 并行方式 | 说明 |
|---------|------|
| 数据并行 | 多个GPU并行处理不同数据 |
| 算法并行 | 多个Transformer框架并行 |
| 流水并行 | 流水线式计算 |

## 四、AI算法解析-文生图、图生图、文生视频（下）

### 1. MidJourney实战

#### 基本操作流程

```
1. 在Discord中创建服务器
2. 添加MidJourney机器人到服务器
3. 使用/imagine命令生成图片
```

#### 命令详解

| 命令 | 功能 | 示例 |
|------|------|------|
| /imagine | 文生图 | /imagine 一个帅哥正在写AI驱动的书籍 |
| /describe | 图生文 | 上传图片自动生成描述 |
| /blend | 图片融合 | 两张图片融合 |

#### MidJourney底层原理

```
Text输入 → Tokenize（文本数字化）→ Embedding（向量化）→ 
Transformer处理 → Diffusion扩散 → Decoder解码 → Image输出
```

### 2. InsideFace实战

#### 命令系统

| 命令 | 功能 |
|------|------|
| /save | 保存目标人脸 |
| /sw | 替换人脸 |
| /list | 查看已保存人脸 |
| /list all | 显示所有ID |
| /delete | 删除指定人脸 |
| /delete all | 删除全部人脸 |

#### 使用示例

```
/save 古天乐001（保存目标人脸）
上传自己的照片
/sw 古天乐001（将古天乐的脸替换到自己脸上）
```

### 3. Runway文生视频

**功能：**
- Text-to-Image（文生图）
- Text-to-Video（文生视频）
- Image-to-Video（图生视频）
- 图生视频

**特点：** 跨多模态，比MidJourney和InsideFace更复杂

### 4. 底层算法对比

| 产品 | 底层模型 | 能力 |
|------|---------|------|
| MidJourney | Diffusion扩散模型 | 文生图、图生文、图片融合 |
| InsideFace | Diffusion扩散模型 | 图生图、人脸替换 |
| Runway | Diffusion + 多模态 | 文生图、图生图、文生视频、图生视频 |

### 5. AI算法解析总结

```

│                     ↓                                │
│              Transformer框架处理                      │
│                     ↓                                │
│              Decode解码                              │
│                     ↓                                │

## 五、如何深度学习AI技术

### 1. 核心技术：Transformer

**核心观点：学会Transformer，等于学会AI**

Transformer统一架构可以处理六大任务：
- 计算机视觉（CV）
- 自然语言处理（NLP）
- 强化学习
- 语音处理（STT/TTS）
- 翻译
- 图数据处理

### 2. Transformer架构详解

```
┌─────────────────────────────────────────────────────────┐
│                    Transformer架构                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  输入部分                                                │
│  ├── 原文本嵌入层 + 位置编码器                           │
│  └── 目标文本嵌入层 + 位置编码器                         │
│                                                         │
│  编码器部分（左侧N层）                                   │
│  ├── 多头注意力层（Multi-Head Attention）                │
│  ├── 规范化层                                           │
│  ├── 残差连接层                                         │
│  └── 前馈全连接层                                       │
│                                                         │
│  解码器部分（右侧N层）                                   │
│  ├── Masked多头注意力层                                 │
│  ├── 编码器-解码器注意力层                               │
│  ├── 前馈全连接层                                       │
│  └── 规范化层 + 残差连接层                               │
│                                                         │
│  输出部分                                                │
│  ├── 线性层                                             │
│  └── Softmax层                                          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3. 各组件详解

#### 输入嵌入（Input Embedding）
- 将输入序列中的每个单词/符号映射到连续向量表示
- 使模型能够处理和理解文本

#### 注意力机制（Attention）

| 类型 | 说明 |
|------|------|
| 自注意力 | 捕捉序列内部依赖关系和语义信息 |
| 编码器-解码器注意力 | 解码器关注输入序列的相关部分 |

**核心公式：** Attention(Query, Key, Value)

- Query：查询
- Key：键
- Value：值

#### 多头注意力（Multi-Head Attention）
- 并行使用多个注意力机制
- 捕捉不同的语义信息
- 更好处理非线性和线性环境

#### 前馈神经网络
- 对每个位置的向量进行非线性变换
- 增加模型的表达能力和表示多样性

### 4. GPT vs BERT vs T5

| 模型 | 架构 | 特点 | 擅长任务 |
|------|------|------|---------|
| GPT | Transformer Decoder | 无监督预训练，预测下一个词 | 文本生成、问答 |
| BERT | Transformer Encoder | 遮蔽语言建模 | 文本分类、命名实体识别 |
| T5 | Encoder-Decoder全架构 | Text-to-Text框架 | 文本分类、生成、翻译 |

### 5. 模型压缩与优化

当大模型需要在边缘设备（智能家居、车联网）应用时，需要：

| 优化技术 | 说明 |
|---------|------|
| 网络剪枝 | 减少模型参数量和计算量 |
| 分层结构+局部注意力 | 将全局注意力转化为局部计算 |
| 参数共享+跨层连接 | 减少重复计算 |
| 低精度计算 | 混合精度计算（如16bit/32bit） |

### 6. 学习建议

**核心策略：** 先理解Transformer架构，再深入各组件原理
