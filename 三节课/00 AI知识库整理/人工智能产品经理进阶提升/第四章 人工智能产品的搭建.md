# 第四章 人工智能产品的搭建

## 学习要点

- 理解AI产品开发流程与互联网产品开发流程的差异
- 掌握AI产品流程的两大分支：产品研发与模型开发
- 理解AI产品经理的四大关键文档：BRD/PRD/SRD/DRD
- 掌握技术预研中"业务技术化"的核心方法
- 理解可用性原则：50%→90%（3天），90%→99%（1年）
- 掌握需求分析三大维度：数据、问题、商业
- 理解AI产品定价的"十分之一原则"
- 掌握自建vs外包的决策原则

---

## 1. 人工智能产品的开发流程

### 1.1 传统互联网产品开发流程

```
产品定位 → 需求分析 → 产品研发跟进 → 运营
```

| 阶段 | 说明 | 输出文档 |
|------|------|----------|
| **产品定位** | 商业模式、行业分析、产品规划、竞品分析 | BRD（商业需求文档） |
| **需求分析** | 用户画像、场景分析、交互规划、功能设计 | PRD（产品需求文档）、SRD（软件需求文档）、DRD（数据需求文档） |
| **产品研发跟进** | 与研发团队沟通，跟进开发进度 | 技术文档 |
| **运营** | 用户增长、活动管理、数据分析 | 运营报告 |

### 1.2 AI产品开发流程的独特之处

```
产品定位 → 需求分析 → 技术预研 → 模型开发 → 运营
                     ↓           ↓
                 产品研发    模型开发（双分支）
```

**与互联网产品的核心差异**：

| 差异点 | 互联网产品 | AI产品 |
|--------|------------|--------|
| 开发主线 | 单一产品研发线 | 产品研发 + 模型开发双线并行 |
| 技术预研 | 不需要 | 需要将业务需求转化为技术方案 |
| 数据处理 | 传统数据库 | 需要数据标注、数据清洗 |
| 验收标准 | 功能完整 | 模型精度达标 + 功能完整 |

### 1.3 产品定位阶段

**商业模式**（由高层决策）：
- 公司运转的基础逻辑
- 决定产品在市场的定位和盈利方式
- 输出：BRD（商业需求文档）

**行业分析**：
- AI产品多为B端属性，行业特征明显
- 需要深入了解行业规则
- 未来5-10年B端产业互联网将高速增长

**产品规划**：
- 制定产品发展路线图（Roadmap）
- 跟随商业进程和用户变化

**竞品分析**：
- 持续监控竞品是产品经理的基础素质
- 关键是形成**差异化**——找到竞品没有的独特价值点

### 1.4 需求分析阶段

**场景分析**（核心方法论）：
> **场景大于逻辑**——用户使用产品的环境和条件比产品本身的逻辑流程更重要

**案例：微信的返回逻辑**
- 从任意联系人进入聊天页面
- 点击返回 → 直接回到主聊天列表（而非逐层返回）
- 这就是基于"场景"（用户在单聊场景）而非"逻辑"（逐层返回）的设计

**需求分析输出文档**：

| 文档类型 | 全称 | 说明 |
|----------|------|------|
| **PRD** | 产品需求文档 | 产品功能需求的详细说明 |
| **SRD** | 软件需求文档 | 软件系统层面的需求 |
| **DRD** | 数据需求文档 | 数据相关的需求（数据产品经理常用） |

### 1.5 技术预研阶段——AI产品经理的核心能力

> **业务技术化**：将业务需求转化为技术方案

**AI技术预研与算法工程师技术预研的区别**：

| 角色 | 关注点 |
|------|--------|
| **算法工程师** | 纯技术方案——用什么算法，用什么框架 |
| **AI产品经理** | 业务技术化——用什么技术手段解决业务问题 |

**案例：专利语义检索的技术预研过程**

```
业务需求：判断一篇新专利是否侵权/与已有专利重复
                    ↓
技术问题转化：这是一个语义检索任务
                    ↓
业务分析：专利内容可能上百页，不适合全文检索
                    ↓
聚焦范围：标题 + 摘要 + 权利要求（Claim）
                    ↓
技术细分：中文分词 → 语义相似度计算 → PageRank评分
```

### 1.6 模型开发阶段

```
定义数据问题 → 数据处理 → 标注 → 模型训练 → 模型测试 → 模型调优
```

**可用性原则（核心忠告）**：
> 50%提升到90%——可能只需要3天
> 90%提升到99%——可能需要1年
> 99%提升到99.5%——可能一辈子也完不成

- AI项目不是科研项目，不需要追求极致精度
- 达到可用阈值即可发布上线
- 避免过度优化

### 1.7 数据处理的关键步骤

| 步骤 | 说明 | 关键点 |
|------|------|--------|
| **数据定义** | 明确输入数据是什么，预测目标是什么 | 确定数据量和问题类型（分类/排序等） |
| **数据切分** | 训练集/验证集/测试集的划分 | 通常比例：60%/20%/20% |
| **数据标注** | 人工标注训练数据 | 涉及大量成本 |
| **数据归一化** | 将数据统一到相同尺度 | 提高训练稳定性 |

### 1.8 从商业到产品的通用方案

```
商业模式 → 业务梳理 → 过程分析 → 资源评估 → 方案组织 → 产品实施
```

**资源评估的核心**：**时间 = 金钱**
- 项目进度可以用钱来衡量（挣值管理）
- 标注数据是最大的成本项——需要标注团队（DC团队）、高校学生或专业人士

## 2. 需求分析拆解的三大维度

### 2.1 三维度评估框架

```
项目是否适合做AI？
    ├── 数据维度
    ├── 问题维度
    └── 商业维度
```

### 2.2 数据维度

| 评估维度 | 关键问题 | 说明 |
|----------|----------|------|
| **数据可获取性** | 数据是否方便获得？ | 医疗等特殊行业数据获取难度大 |
| **数据质量** | 数据是否全面、有代表性？ | 需要覆盖所有特征维度 |
| **数据存量** | 当前有多少数据可用？ | 数据越多越好（保证质量的前提下） |
| **数据闭环** | 能否持续获取反馈数据？ | 让机器持续学习 |

**数据全面性案例**：
- 湘雅医院皮肤病PASI评分项目
- 需要近照、远照、侧照、皮肤镜下照片等多角度数据
- 数据不全导致项目困难，后续补了大量数据

**数据代表性案例**：
- 微博用户数据**不能**代表全民偏好（有数据偏差）
- 快手、抖音、B站用户画像各不同

**AI的核心法则**：
> **AI的上限由数据的上限决定**
> 有什么样的数据，就能做出什么样水平的模型

### 2.3 问题维度

| 评估维度 | 说明 | 案例 |
|----------|------|------|
| **可解释性** | 是否需要解释决策原因 | 诊断需要；推荐不需要 |
| **错误容忍度** | 能容忍多少错误 | 语音翻译容忍度高；人脸识别容忍度低 |
| **问题复杂度** | 特征数量和规则数量 | 特征多+确定性弱→适合AI |
| **鲁棒性** | 模型泛化能力 | 同一模型在不同场景是否可用 |
| **实时性** | 对响应速度的要求 | 刷脸需要秒级响应；诊断可等几分钟 |

**三原则**：
1. 越需要**因果关系**解释的 → 偏向传统机器学习，而非深度学习
2. 错误**容忍度低** → 谨慎使用深度学习，人机协同是方向
3. **商业价值与性价比** → 衡量投入产出比

**确定性强弱与特征多少的决策矩阵**：

| 特征数量 | 确定性强 | 确定性弱 |
|----------|----------|----------|
| **特征多** | 可用规则 | ✅ **最适合AI** |
| **特征少** | 可用规则 | 需要人工解决 |

**案例：游戏外挂检测**
- 简单游戏（俄罗斯方块）：特征少+确定性强 → 规则即可
- 复杂游戏（吃鸡）：特征多+确定性弱 → **适合AI检测**

### 2.4 商业维度

| 评估维度 | 说明 |
|----------|------|
| **业务价值** | AI对业务价值的贡献有多大 |
| **痛点** | 这个痛点是否真实、够痛 |
| **AI辅助人工** | 是否能有效辅助人工 |
| **商业化可行性** | 投入产出比是否合理 |

**AI产品定价原则——十分之一原则**：
> **AI产品定价 =（节省的人工成本 ÷ 10）**

**计算方式**：
1. 计算AI替代人工后节省的人天数量
2. 乘以人天单价（如1000元/天）
3. 除以10即为AI产品的定价

### 2.5 李开复5秒钟法则

> 如果人类能在**5秒钟**内对某个任务进行反馈/判断，那么这个任务适合用AI解决

**吴恩达的观点**更激进：**小于1秒钟**就可以做AI

### 2.6 自建 vs 外包的决策

| 类型 | 适合方式 |
|------|----------|
| **机器学习项目** | 可自建、可外包 |
| **深度学习项目** | 尽量自建（参数调节多，需大量迭代沟通） |
| **核心竞争壁垒项目** | 必须自建 |

## 总结

| 核心概念 | 关键要点 |
|----------|----------|
| AI开发流程 | 技术预研 + 模型开发双分支，区别于互联网单线流程 |
| 业务技术化 | AI产品经理的核心能力——将业务需求转化为技术方案 |
| 可用性原则 | 50%→90%需3天，90%→99%需1年，够用即可 |
| 场景大于逻辑 | 用户使用环境比产品逻辑更重要 |
| 需求三维度 | 数据（可获取/质量/存量/闭环）、问题（可解释/容错/复杂度）、商业（价值/痛点/Roi） |
| 十分之一原则 | AI定价 = 节省人工成本 ÷ 10 |
| 五秒钟法则 | 5秒内能反馈的任务适合AI |
| 自建vs外包 | 深度学习项目建议自建，壁垒项目必须自建 |
