# 第三章 实战从0到1打造AI产品

## 一、典型AI产品经理的工作方法

### 1. AI产品经理分类

| 类型 | 特点 | 主要工作 |
|------|------|---------|
| 加AI型（软件） | 挖掘需求、技术选型、驱动开发 | 懂行业痛点、懂业务Knowhow |
| 加AI型（软硬件） | 额外需要BOM规划、硬件设计 | 软件+硬件协同 |
| AI加型（行业） | 现有AI+行业探索 | 行业解决方案 |
| AI加型（消费） | 公司AI核心算法 | C端应用产品开发 |
| 纯AI型（基站） | 底层技术 | 算法、架构、编码 |

### 2. AIGC时代工作特征

```
┌─────────────────────────────────────────────────────────────┐
│                    AIGC产品工作流程                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  原始数据（Raw Data）                                        │
│  ↓                                                          │
│  Token化处理                                                 │
│  ↓                                                          │
│  基础模型（Base Model）                                      │
│  ├── 数千至上万张GPU训练                                     │
│  └── 如：GPT、LLAMA、PLAM模型                               │
│  ↓                                                          │
│  监督微调（SFT）                                             │
│  ├── Prompt/Response                                        │
│  └── 人力反馈强化学习                                        │
│  ↓                                                          │
│  奖励模型训练（RM）                                          │
│  └── 约1B参数，分类训练                                       │
│  ↓                                                          │
│  强化学习（RL）                                              │
│  ↓                                                          │
│  最终模型输出                                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3. AIGC工作核心要点

- **与数据深度打交道**
- **与MoE框架下的学习方法常打交道**
  - 监督微调
  - 奖励学习
  - 强化学习

### 4. 案例：微软AI双肩包

**产品特点：**
- 自动识别佩戴者周围环境
- 自动响应用户聊天请求
- 访问云端信息
- 与其他设备交互

**产品工作涉及：**
```
业务场景 → AI技术 → 供应链管理 → 数据采集/预处理 → 模型训练
```

### 5. 加AI产品完整工作方法（三阶段）

#### 第一阶段：项目启动
| 要素 | 考虑事项 |
|------|---------|
| 人 | 团队构建、算法/工程/数据人员 |
| 钱 | 预算规划、融资需求 |
| 物 | AI技术选择（自研/采购第三方API） |

**技术选择：**
- 自研大模型
- 采购第三方API
- 本地推理

**算力选择：**
- 自购GPU（A100/V100/H100）
- 采购第三方云计算

#### 第二阶段：项目研发
- 深度理解业务Knowhow
- 数据预处理
- 构建AI商业模型

#### 第三阶段：项目上线
- 算力测试
- 推理能力测试
- 网络带宽测试
- 模型产品测试
- 运营收集反馈

### 6. AI项目团队构建

| 角色 | 职责 |
|------|------|
| 算法人员 | 核心算法设计 |
| 算法工程人员 | 算法实现 |

**团队搭配建议：**
- 资深专家 + 新手组合

### 7. 项目实施关键点

| 阶段 | 参与人员 | AI产品经理职责 |
|------|---------|---------------|
| 样本测试 | 算法、算法工程、数据处理 | 把握业务Knowhow、算法边界 |

## 二、如何善用AI价值（行业业务+AI）

### 1. 核心观点：360行，行行可以加AI

### 2. 案例：国有银行贷款审核AI系统

**业务痛点：**
- 传统人工审核，只服务大中型企业
- 政策要求给中小企业放贷
- 审核难度大、数据质量差

**AI解决方案：**

```
┌────────────────────────────────────────────────────────────┐
│              银行贷款审核AI系统                              │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  票据处理流程数字化                                         │
│  ↓                                                        │
│  数据预处理 → 分成训练级/验证级/测试级                      │
│  ↓                                                        │
│  Transformer框架计算                                        │
│  ↓                                                        │
│  贷款审核AI模型                                            │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 3. 项目决策：自研 vs 开源 vs 外包

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 自研 | 定制化强、核心技术自主 | 成本高、周期长 | 核心技术壁垒高 |
| 开源 | 成本低、快速启动 | 需配备专业人员 | 边缘应用 |
| 外包 | 省心省力 | 质量难控 | 非核心功能 |

### 4. 选择服务商评估维度

| 评估维度 | 具体内容 |
|---------|---------|
| 算力提供能力 | GPU数量、稳定性 |
| 算力部署能力 | 能否支撑数据并行、算法并行、流水并行 |
| 工程能力 | 大规模GPU并行计算能力 |
| 精准画像能力 | 对垂直行业的理解 |

### 5. AI产品经理测试要点

| 测试优先级 | 内容 |
|-----------|------|
| 第一优先级 | 业务Knowhow是否满足需求 |
| 第二优先级 | 功能测试 |
| 第三优先级 | 性能测试 |

### 6. 常见坑点及解决方案

| 坑点 | 说明 | 解决方案 |
|------|------|---------|
| 算力预估不准 | 大模型时代算力普遍不够 | 提早规划、精确评估 |
| 算力冲突 | 多服务商共享GPU资源 | 按业务功能分配算力 |
| 数据资源坑 | 数据标注和处理是隐形大坑 | 重点关注数据质量和成本 |

### 7. 大模型训练 vs 推理的算力差异

| 类型 | GPU要求 | 特点 |
|------|--------|------|
| 训练大模型 | GPU卡质量更高、算力更大 | 一次性大投入 |
| 推理大模型 | 相对较低但仍需规划 | 持续性投入 |

**核心原则：** 推理也需要购买GPU或云计算，不能完全依赖开源

## 三、如何从0开始做软硬件协同AI产品

### 1. 软硬件协同产品流程

```
调研市场方向 → 定义市场需求 → 挖掘需求 → 软硬件产品设计 → 上市前准备 → 上市
```

### 2. 市场调研方向

| 产品类型 | 调研方向 | 示例 |
|---------|---------|------|
| 魔镜类 | 使用场景 | 体测魔镜、试衣魔镜、美容魔镜 |
| 户外产品 | 使用地点 | 山、海、露营地 |
| 户外产品 | 使用功能 | 安全、通信、社交 |

### 3. 需求挖掘方法

**案例：试衣魔镜**

| 需求点 | 具体内容 |
|-------|---------|
| 人体参数 | 肩部是否平整（破肩、高低肩） |
| 穿衣建议 | 基于参数的个性化推荐 |
| ERP打通 | 与品牌供应链系统对接 |

### 4. Feature List设计

| 考虑维度 | 内容 |
|---------|------|
| 目标用户 | 高端品牌（香奈儿、LV）vs 中低端（七匹狼） |
| 功能设计 | 软件与品牌ERP系统对接 |
| 硬件参数 | 摄像头、板卡性能、工作时长、逆光性 |

### 5. 软硬件产品设计要点

#### 软件部分
- Feature List定义
- 产品设计
- 开发测试
- 产品验证

#### 硬件部分
- BOM规划（材料清单）
- 外观ID设计
- 工厂洽谈（代工生产、开模）
- 软硬件联调
- 小批量生产
- 可靠性测试（防水、防雨、耐磨、防阳光）

### 6. 硬件PRD目录结构

```
├── 包装
├── 产品介绍
├── 操作简介
├── 安装图示
├── 产品尺寸
├── 规格参数
├── 电源连接情况
├── 电池情况
└── 注意事项
```

### 7. 硬件BOM规划要点

| 项目 | 考虑事项 |
|------|---------|
| 板卡选择 | 瑞芯微、MTK等 |
| 面板尺寸 | 根据产品定位 |
| 摄像头 | 集成vs单独、模组选择 |
| 传感器 | 蓝牙低功耗、LoRa等 |
| 外观结构 | 公模vs开私模 |

### 8. 硬件生产流程

```
洽谈工厂 → 开模试机 → 软硬件联调 → 小批量生产 → 可靠性测试 → 认证（3C/ISO/CE）
```

### 9. 上市前准备

| 类型 | 准备内容 |
|------|---------|
| 软件 | 模型验证、用户体验测试 |
| 硬件 | KOA/KOC测试、品质测试、质量测试、认证 |

## 四、电商、直播、短视频+数字人

### 1. 行业痛点与机遇

#### 主播培养的痛点
| 痛点 | 说明 |
|------|------|
| 培养成本高 | 培养周期长、投资大 |
| 工作难以监管 | 人为主播难以7×24小时工作 |
| 优质主播易单飞 | 有名气后容易离开 |
| 忠诚度问题 | 即使忠诚，主播也需要休息 |

#### 数字人解决方案优势
| 优势 | 说明 |
|------|------|
| 可7×24小时工作 | 无需休息 |
| 成本相对较低 | 比真人主播便宜 |
| 忠诚度高 | 不会单飞 |
| 稳定性强 | 不会情绪波动 |

### 2. 数字人需求方向

| 方向 | 应用场景 |
|------|---------|
| 品牌营销 | 官方平台AI虚拟主播引流 |
| 营销导流 | 电商平台导流 |
| 智能客服 | 客服数字人 |
| 直播带货 | 数字人主播 |
| 会员活动 | AI虚拟会员互动 |

### 3. 数字人技术方案对比

| 类型 | 技术方案 | 制作周期 | 数据流要求 | 适用客户 |
|------|---------|---------|-----------|---------|
| 超写实1:1 | 720度灯光球拍照+3D建模 | 数月 | 非常大（需4090/3090） | 大品牌、大电视台 |
| Avatar风格 | 抓取特征渲染 | 较短 | 中等 | 中小品牌 |
| AI渲染2D | 10张左右图片+AI渲染 | 极短 | 较小 | 中小卖家、批量销售 |

### 4. 数字人产品落地方案

```

│                    数字人产品落地方案                        │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  需求确认                                                  │
│  ↓                                                        │
│  技术方案选择（超写实/Avatar/AI渲染）                       │
│  ↓                                                        │
│  数据准备                                                  │
│  ├── 直播内容准备                                          │
│  ├── 优秀主播话术学习                                       │
│  ├── 出镜/口播/静默/绿幕视频                               │
│  └── 数字人服装/道具管理                                    │
│  ↓                                                        │
│  模型训练                                                  │
│  ├── 3D超写实模型                                          │
│  ├── Avatar模型                                            │
│  └── 2D AI渲染模型                                         │
│  ↓                                                        │
│  管理平台开发                                              │
│  ├── 换装/换道具                                           │
│  ├── 内容更新                                              │
```

### 5. 商业模式设计

| 模式 | 说明 |
|------|------|
| 直接售卖 | 卖数字人产品 |
| 直播带货分成 | 与商家合作分成 |
| 租赁 | 租给商家使用 |

### 6. 案例：AI客服替代真人

**应用场景：** 淘宝电商客服

**数据：**
- 淘宝电商客服从业者约80-100万
- 大部分问题回答模式固定
- ChatGPT-4以后的版本完全可以替代

## 五、AI3.0 AI产品规划

### 1. 行业背景

| 趋势 | 说明 |
|------|------|
| 网民增长放缓 | 存量博弈时代 |
| 就业竞争激烈 | 应届生面临转行需求 |
| 新机会诞生 | AI3.0产品岗位 |

**核心观点：** AI能够降本增效，任何老板都愿意做

### 2. AI赋能行业案例

| 行业 | 应用 | 具体案例 |
|------|------|---------|
| 教育 | AI教育 | 个性化学习 |
| 农业 | 病虫害预警 | 传感器+AI识别稻瘟病 |

### 3. 2B vs 2C产品方向

#### 2B产品

| 场景 | 产品示例 |
|------|---------|
| 汽车行业 | 新能源电池管理系统（BMS） |

| 场景 | 产品示例 |

### 4. AI Agent：下一个风口

**定义：** 基于环境感知做行动的AI载体

| 特点 | 说明 |
|------|------|
| 靠近AGI | 技术前沿 |

### 5. AI产品规划方法

| 步骤 | 内容 |
