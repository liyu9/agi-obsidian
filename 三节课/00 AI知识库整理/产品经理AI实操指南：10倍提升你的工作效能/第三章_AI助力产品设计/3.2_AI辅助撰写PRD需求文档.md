# 3.2 AI辅助撰写PRD需求文档

> 同学们好，这第三章的第二节我会带你学习如何借助AI完成产品需求文档的撰写。AI技术可以帮我们自动化的生成需求文档框架结构，确保文档的完整性和一致性。此外AI还可以帮我们整理和优化需求描述，让内容更加的清晰准确，易于理解。

## 一、课程目标

### 1.1 任务目标

**明确任务**：针对我们想要设计的产品"资讯助手"写一份PRD（产品需求文档）。

### 1.2 PRD质量要求

- **足够专业和标准**：能讲清楚产品的功能框架
- **满足的需求和实现逻辑**：要满足的需求和实现逻辑
- **无歧义**：目的是让所有看到文档的人对产品的理解没有歧义

## 二、AI辅助撰写PRD全流程

### 2.1 第一步：确定PRD文档框架

**核心方法**：直接用提示词让AI告诉你一份标准的PRD文档应该包含哪些内容框架。

**提示词模板**：
> 假设自己是一名资深的产品经理。这样的角色需要让他扮演产品经理帮我输出一份PRD也就是产品需求文档。这份文档我希望他先告诉我一份标准的PRD文档应该包含哪些内容。让他帮我列出框架。

**ChatGPT输出的PRD框架**（推荐使用）：

| 模块 | 具体内容 |
|------|---------|
| 1. 文档介绍 | 文档目的、范围、术语定义 |
| 2. 产品概述 | 产品愿景、目标用户、核心价值 |
| 3. 功能需求 | 用例、功能列表 |
| 4. 非功能需求 | 性能需求、安全性需求、兼容性需求 |
| 5. 用户界面和设计 | 界面原型、交互设计 |
| 6. 技术需求 | 技术栈、数据模型、第三方服务 |
| 7. 测试计划 | 测试用例、测试环境 |
| 8. 发布计划 | 里程碑、发布时间 |
| 9. 风险评估和互度 | 风险识别、应对策略 |

> **注意**：技术栈的选择和测试用例可以交给技术人员来帮你完善和补充，但发布计划需要产品经理自己心里有数，提前预估产品的风险和应对策略。

### 2.2 第二步：填充PRD内容

#### 方法一：使用对话式AI填充内容

**提示词要点**：
- 明确产品名称（资讯助手）
- 描述产品的具体功能
- 让AI基于框架填充内容

**ChatGPT填充内容**（完整度更高）：
- 包含测试用例
- 包含功能列表
- 包含非功能需求
- 包含用户界面设计

**智谱清言填充内容**：
- 内容相对简单
- 格式有些乱
- 但也包含性能需求、安全性需求、兼容性需求

#### 方法二：使用专业PRD工具（PMAI）

**工具介绍**：
PMAI是一款专门针对产品经理设计的AI辅助工具软件。

**公司背景**：
- 背后的公司叫做**质子引擎**
- 国内最早开展多模态AI大模型研究的团队
- 在多模态检索、多模态生成领域保持着领先地位
- CEO高一昭：人民大学高领人工智能学院博士
- 2023年连续拿到两轮数千万人民币的融资

**PMAI核心功能**：

| 功能 | 说明 |
|------|------|
| PRD生成 | 输入产品名、功能名，一键生成PRD文档 |
| 原型图转PRD | 通过原型图生成PRD |
| 流程图生成 | 自动生成流程图 |
| 时序图生成 | 自动生成时序图 |
| 页面结构图 | 自动生成页面结构图 |
| 测试用例生成 | 自动生成测试用例 |
| 数据库字段 | 基于PRD描述生成数据库字段 |
| PRD检查 | 检查PRD是否有问题 |
| 功能价值分析 | 功能价值分析 |
| 接口生成 | 生成API接口 |
| 周报生成 | 生成周报 |

**使用方法**：
1. 进入PMAI的PRD生成界面
2. 输入功能名称
3. 输入需求描述（越详细越好）
4. 选择是否包含相关子内容
5. 点击"生成文档"
6. 免费用户每天可生成5次，会员可生成500次

**功能描述示例**（内容摘要功能）：
- 功能名称：网页内容的自动提取摘要
- 实现步骤：
  1. 安装浏览器插件
  2. 访问网页
  3. 在网页上唤醒插件
  4. 点击总结摘要的功能按钮
  5. 展示网页内容摘要，给出关键信息列表

**PMAI生成的PRD内容结构**：
- 功能概述
- 用户的使用旅程
- 实现逻辑（访络页面→用识别→点击摘要插件→AI摘要提取算法→展示内容摘要）
- 相关页面列表
- 页面元素和按钮
- 功能的详细描述
- 异常处理

**PMAI额外生成内容**：
- 页面结构脑图
- 数据字段分析
- 流程图
- 时序图
- 类图
- 测试用例（正向测试、界面兼容性测试）

**PRD修改功能**：
- 点击"AI修改"按钮
- 输入修改提示词
- AI根据指令修改PRD内容

## 四、核心要点总结

### 4.1 关键工具对比

| 工具 | 优势 | 劣势 |
|------|------|------|
| ChatGPT/智谱清言 | 灵活、可定制、可生成完整PRD框架 | 需要较多提示词工程 |
| PMAI | 专注PRD、功能丰富、可生成图表 | 免费次数有限、定制化稍弱 |

### 4.2 PRD各部分责任人

| PRD部分 | 建议负责人 |
|---------|----------|
| 功能需求 | 产品经理 |
| 技术栈选择 | 技术/开发人员 |
| 测试用例 | 测试人员 |
| 发布计划 | 产品经理 |
| 风险评估 | 产品经理 |

### 4.3 成功关键点

1. **框架标准化**：先让AI生成标准PRD框架，确保完整性
2. **内容详细化**：输入越详细，生成内容越完善
3. **善用专业工具**：PMAI可以一站式生成PRD、流程图、测试用例
4. **人机协作**：AI生成初稿，产品经理审核修改

> "通过依赖技术，我们可以永远有效的沟通产品需求，确保团队对产品目标和需求有一个清晰的理解。"
