# 第十一章 模型能力选型和API调用指南

## 章节引入

好，接下来我们来讲模型能力选型和API调用的实战指南。

那上节课我们学到的Agent的框架呢，主要关注的是如何组织和执行任务。Agent呢作为一个智能体，它是能够接收输入执行任务，并且根据上下文去进行反馈的。

如果你现在要做一个AI产品呢，要靠谁来执行呢？哪个模型来提供能力，它在哪里，它是怎么听懂你的指令，怎么样去响应用户的请求的呢？

**模型选型其实就是选择给这个Agent它提供一个智能的核心工具——AI模型**。这些模型它其实就是Agent执行任务的大脑。

那这节课我们就来讲一下你要接通哪个大脑，怎么样把它更高效、更安全、更聪明地用起来。

**这一步它不是一个简单的选哪一个模型就好，而是说你要根据具体的产品需求、用户的使用场景、技术架构、成本限制来选择最适合的AI模型**。

那我们简化理解，就是Agent的框架呢它是负责将任务串联起来，确保任务有条不紊地去执行。那模型能力选型则是根据Agent的大脑去使用哪个AI模型来理解和处理任务。

如果你的Agent的框架它是需要文本理解和生成文本的功能，那么你选择的模型很可能就是GPT-4或者是Claude。如果任务是图像识别，那么你选择的模型很可能就是Midjourney或者是DALL-E。

## 模型选型是产品策略

**那第一部分呢，模型选型它不是一个技术问题，它是一个产品策略。为什么现在就要选模型？**

首先因为这个决定了你的产品能不能够最终上线。

第二个，不同的模型对应的能力、响应费用和安全、用户体验，它的影响是完全不一样的。它不是说等技术选好了再来的问题，它是需要产品经理一开始就要去拍板的一个决策。

### 模型选型的关键维度

那么在决策过程中间，你需要面对的几个维度：

| 维度 | GPT-4 | Claude | DeepSeek |
|------|-------|--------|----------|
| **智力强度** | 依然王者 | 表现稳定 | 能力优秀 |
| **语言适配** | 英文为主 | 中文友好 | 中文优秀 |
| **响应速度** | 稍微慢一点 | 温和 | 快 |
| **成本控制** | 偏贵 | 友好 | 有限流 |
| **接入便利** | 配置适配多 | 直接调用 | 开放API本地部署 |

## 非理想场景的处理

**第三部分就是理想情况下，但是很多时候其实是非理想场景的**。

我们要能够做长期稳定运行的产品呢，就需要为这个模型设计一套**防抖动、防熔断、防失控的策略**。

### 常见的非理想场景

| 场景 | 说明 |
|------|------|
| **延迟** | 响应时间过长 |
| **调用失败** | 接口调用异常 |
| **成本爆炸** | 费用超出预期 |
| **国内合规问题** | 政策监管要求 |

## 成本和效益评估

**那第四部分就是我们怎么样去评估API调用的成本和效益**。

那我们的调用控制点，成本控制的几个要素分别是说调用的次数是乘以单价的：

比如说我们的OpenAI它是按照token去计费的，那每1000个token他会收你多少钱。看似不是很多，但是如果用户刷一整天的聊天记录，这个成本就会很可怕了。

### 响应时间

就是请求响应时间。如果我们做的是对话的或者是搜索推进功能的，它对响应时间的要求就非常高。所以我们需要在交互设计上面也要考虑怎么样去做缓冲。

### 吞吐量限制

这就是一个吞吐量限制。比如有些API每秒钟只允许你发几十次请求，那用户一多就爆炸。还有一些在测试阶段是ok的，但是这是上线他可能会崩。

### 地域部署问题

还有一个就是地域部署问题，就是你在中国调用美国的API的时候。可能会出现有点卡的现象，那部署地选错了，体验会拉垮。

## 成本优化的策略

**还有一个就是跟大家说一下成本优化的一个小技巧**：

### 1. 批量请求

我们在调用的过程中间，可以用哪些小策略把我们的成本优化下来呢？比如说你可以**批量的去请求**，你不要一条一条的去请求，就合并起来一起发，能够便宜不少。

### 2. 缓存机制

第二个呢就是**缓存机制**。你缓存就是常见的这种热门问题，常见的提示语的话，你就没必要每次都重新算一遍。你缓存之后直接返回就可以了。

### 3. 调用监控

再有一个就是**调用监控**，那每天调用的次数超限的次数，异常的响应到底是什么样子的。

### 4. 分级调用策略

再有一个就是**分级的调用策略**，用户他的级别不同，你给他用不同的模型。你你比如说普通的用户会调GPT-4，然后VIP用户调GPT-o，这个时候用户的分层。所以这个成本就能够节省下来不少。

## API集成方式

**第五部分就是怎么样去跟API进行一个集成API调用的基础的流程**。

其实我觉得大家应该是都做过产品经理的，都应该知道的，不需要说太详细吧。你首先查阅一下API说明书嘛，了解了一些请求参数之后，你调试一下去测试一下。看模型有没有听懂你的说话，他会给到你一个返馈结果嘛。他回信了你，你还得把回信变成一万里的文字、图像、情绪条、标签这些可以交互的内容嘛。

### 集成AI模型的四种常见方式

| 方式 | 说明 |
|------|------|
| **直接调用API** | 最直观的，写个请求就能够跑的 |
| **封装接口** | 把调用包组成一个组件，统一的去管理参数和返回值，比较适合于中大型的项目 |
| **LangChain集成** | 适合多步任务，上下文记忆和链式调用的 |
| **流式输出** | 能够让用户像直播一样看到AI在一步一步地输出，比较适合于对话机器人实时的生成 |

**那不是所有的项目都需要用到LangChain，也不是所有的调用都需要自己写代码**。你只需要知道这个模型在哪儿，你怎么样去使用它就可以了。
