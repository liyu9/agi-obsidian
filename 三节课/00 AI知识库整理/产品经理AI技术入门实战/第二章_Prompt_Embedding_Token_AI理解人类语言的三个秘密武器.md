# 第二章 Prompt、Embedding、Token：AI理解人类语言的三个秘密武器

## 章节引入

接下来我们进入第二讲，prompt、embedding、token，他们三个是AI理解人类语言的几个秘密武器。

先让我们来看一下产品经理最早能够掌握能够理解的认知prompt。

很多人学AI一上来就说要知道大模型，要懂机器学习，要马上学神经网络。但是呢我们很多小白其实会一脸懵逼，因为最常见的真实问题其实是：**我写的问题，AI为什么会答非所问。我觉得我已经说得很清楚了，为什么它给我的答案我不满意**。

那这个背后其实就是你并不是很了解prompt、token、embedding它的底层运作机制。所以我们要直接地去切入AI是如何去理解你的这件事。

## 第一部分：Prompt

### Prompt的本质

**Prompt它不是问题，而是指令**。你以为你在问问题，其实你在写任务说明书。

Prompt它就是你给AI的工作交代。我们来举一个产品人很熟悉的比喻：

比如说，你不会直接跟开发说"你来给我做个按钮"，你会跟他说"给我一个蓝色的圆角，写着'提交申请'的按钮，放在表单的右下角，用点击后会调用POST的接口"。

这是一个比较完整的描述：加目标说明，加格式限制的内容，这才是一个有效的提示词。

**烂的提示词**：
> "我的agent，你来帮我写个评价呗"

**好的提示词**：
> "请你用三句话来评价某一个新的产品，分别从用户价值、技术可行性或者商业潜力的角度出发。要求每句不超过30个字"

所以你来看一下，这个prompt它不是问问题，它是发指令，是你给AI的角色扮演脚本。

### 产品经理写Prompt的天然优势

**产品经理它其实是有天然的写提示词的优势的**。这个其实我们类比一下就知道了，它是一个活脱脱的很微缩版的PRD。

所以提示词它跟写代码没有任何关系，它是写产品说明书。

那我们产品经理写PRD的时候，本来就是需要：
- 把模糊变成清楚
- 把隐性目标变成显性目标
- 把业务语言翻译成技术理解

然后我们会需要去限定AI的边界、输出的格式和输入的条件。

这个你听下来是不是感觉两边是一模一样的？

### 产品经理能力与Prompt技能的对应

我们可以来穿插比对一下：

| 产品经理能力 | Prompt需求 |
|------------|----------|
| 产品经理的强项是结构能力，能够把需求拆成步骤 | Prompt它就需要我们拆解成为"角色 + 任务 + 限制" |
| 产品经理它是能够写清楚业务逻辑，表达能力很强 | Prompt它就需要你写清楚上下文和目标输入 |
| 产品经理需要设定接口返回内容，达到预期的控制 | Prompt同样的是需要你去设定AI的输出格式 |
| 产品经理需要有兜底策略 | 你在写提示词的时候，同样可以加入"当你不确定的时候你怎么样"，这个也是一个兜底策略 |
| 产品经理最重要的是需要懂业务的场景和业务的闭环 | 那就需要精细的去设定用途和边界 |

## 第二部分：Embedding

### Embedding的本质

**Embedding你可以把它理解成为是一个AI的语言定位系统**。

因为AI它不理解文字，它理解的是数字向量。你说的每一个词AI它并不会看自然语言的字面意思，而是会把它转成一串数字，放到一个巨大的语义空间。

你可以把这个空间想象成为一个三维坐标。首先是相似的词会靠得很近：
- 比如猫猫狗狗、老鼠兔子这些小动物
- 那毫无相关的词它们会隔得非常远，就比如说"芹菜"和"WiFi"基本上没有什么关联关系，它们的距离就远

它就是通过这样的数字向量来做一个定位。

### Embedding在流程中的位置

Embedding它在整个大模型的流程里边，它是**进入模型前的翻译器**。它的功能就是把你的文本输入翻译成为AI能懂的语义坐标。

那你这么一想，觉不觉得他就是产品经理在做需求梳理的时候，把用户的语结构化成为字段呢？

### Embedding的运作流程

我举个例子，就是我们这里有个真实的小剧场：

你比如说你给GPT说"帮我写一段面试后的感谢邮件，去表达你的专业和诚意"。

这句话呢它并不会直接地传到大模型里边，而是会先经过embedding的处理：

1. **Token**：它会把整句话拆成token
2. **Embedding**：它会把每句转换成为语义向量
   - "感谢"它是一个方向的
   - "邮件"呢它把它列为一个对象类型
   - "专业"呢它会选择情绪和风格的标签
   - "诚意"呢一些情感的调性的点
3. 它会把它转换成为不同位置的语义向量
4. 再把这些向量送到transformer里边去进行一个推理和生成
5. 在输出的结果code再变成一句一句的话

### Embedding的具体应用场景

Embedding它还有一些什么具体的应用场景呢？主要有三种：

1. **语义搜索**：用户在比如说用户会搜"怎么提升团队效率"，他实际上他可以搜出一个OKR的管理工具，这个时候靠的是一个语义相似度

2. **RAG系统中的召回内容**：用户提问题到向量，到去知识库找到最相关的片段

3. **多模态的跨类型的匹配**：把图像音频也转化成为向量，和文本的向量合并，再把它进行一个内容的生成

**一句话总结**：Embedding它是AI理解语言世界的地图坐标系统，是所有的语义推理和搜索的起点。有了它AI才能够真正地理解你的意思，所以embedding是非常重要的。

## 第三部分：Token

### Token的定义

**Token它其实是一个AI世界的语言碎片加上预算**。

如果你是做产品经理的，你对token其实是非常熟的。但是这个token它跟互联网token是不一样的。

常常遇到的token其实分三种：

1. **互联网的token**：在账号系统或者是API的权限管理里边会有一些token，比如接口授权，这些都是我们互联网常见的token

2. **区块链的token**：出来很久了，它的含义是一个数字资产或者是凭证

3. **AI语言模型里的token**：代表着最小语言的处理单元，它既不是"一个字"，也不是"一个词"，而是能够被模型分割处理的原片段

### Token与产品经理熟悉的字符长度的对比

你可以这样去理解，token它是AI读文字的颗粒单位。它既不是一个字，也不是一个词，而是能够被模型分割处理的原片段。

我们就从产品的视角去进行一个完整的对比：

| 对比维度 | Token | 字符长度 |
|---------|-------|---------|
| 所属体系 | 大语言模型 | 产品经理常用的表单等 |
| 拆分方式 | 按照字词音节词块去切的 | 按照字节或者字符数去计算的 |
| 英语 | 通常会被拆分成为多个token，比如"understand"会切成"un"+"der"+... | 英语单词基本上是等于多个字符，每个字母是一个字符 |
| 中文 | 每个汉字基本上是一个token | 每个汉字基本上会算一个token，或者是一个字符、两个字节 |

真实的差距就是一个英文句子看起来很短，但是有可能是3到5倍的token数。而字符长度看起来很多，但是它不会影响语义的理解。

### Token的三大功能角色

Token它是相当于AI的一个阅读配额加上一个输出的限制器。它有三大功能角色：

1. **输入的配额计量**
2. **模型处理的切分器**
3. **输出内容的预算器**

Token它其实就是决定了模型一次能够看多长，能够思考多久，能够说多少话，它其实是一个限制器。

### Token的位置

在我们前面提到的大模型的五层路径中间，token的位置在哪呢？

它其实是在输入前和生成后，它是围绕着prompt、output两侧的一个硬性约束机制。

要注意的是呢，不管是prompt还是output，它都是在消耗token的。

### Token的度量公式

Token的度量呢其实我们先记一下一个公式：

**token的总用量 = 1个prompt输入token + 输出token + 上下文历史的token**

### Token对产品经理的实际意义

所以也就是了解了token的度量，你才能够想明白：
- 为什么DeepSeek是那么冷冰冰的一个设计
- GPT-4为什么又保留着大量的记忆
- 同时我们也可以推出来，为什么token对产品经理很关键

因为作为产品人，你会遇到这些实际的场景：

1. **Prompt超长，AI输出残缺**：是因为token超上限了，它会自动截断

2. **用户上传的知识库太大，系统会读取失败**：也是因为token爆掉照会异常

3. **输出的结果太短**：会默认token分配不够

4. **付费模型和免费模型**：就是因为token的预算完全不同，直接影响效果

### Token相关的坑和解决方案

Token相关的坑有哪些呢？

- **知识库太大或Prompt设计太随意**：会导致token的冗余
  - 解决方案：需要去模板化、结构化prompt

- **输出不够完整**：会导致生成token不够
  - 解决方案：需要增加max token的参数

- **成本不明确**：计费是基于token的
  - 解决方案：需要加入token的预算管理逻辑

## 本章总结

接下来我们来总结一下今天学的三个概念：

| 概念 | 理解方式 |
|------|---------|
| **Prompt** | 理解成工作指令，它就是告诉AI你要去做什么 |
| **Embedding** | 是一个语义的地图，把你的话定位到模型世界中间 |
| **Token** | 就是一个文字碎片加上一个阅读预算，限制模型能够看多长、说多少、花多少钱 |

好，我们的逻辑基本上就是这个样子：

1. **Tokenization**：就是切碎，token ser干的
2. **Embedding**：是打坐标，是embedding layer干的
3. **Transformer**：去处理它

再就用向量用于检索它的逻辑完整的基本上就是可以这么理解：

- 先是把一句完整的话切成AI能处理的小颗粒
- 接着就把每个token变成一个语义坐标，方便AI理解和存储
- 再带着这些向量去分析它的关系，做思考
- 在RAG或者agent的场景用embedding向量去查资料
