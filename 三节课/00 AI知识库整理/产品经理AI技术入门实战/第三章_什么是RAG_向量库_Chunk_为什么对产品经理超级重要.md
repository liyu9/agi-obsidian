# 第三章 什么是RAG、向量库、Chunk？为什么它对产品经理超级重要？

## 章节引入

现在我们进入第三讲，什么是RAG、向量库和Chunk，为什么他们几个对产品经理来说是超级重要的？

在这套课程中间呢，我们跟其他的课是不一样的，我们会选择场景驱动作为学习的一个起点。因为这些模块离产品经理他的日常工作是最接近的，很容易去唤起我们产品经理"我可以做这个"的实际想法。

所以我们不会先直接去讲大语言模型这些东西。我们来讲一下向量库、讲一下RAG、讲一下Chunk。通过这些模块大家可以去快速地构建对于AI项目的场景的联想能力。

那大语言模型呢，它作为一个核心智能体，它是抽象不可见、不可配置性又很弱的。它是需要我们在后面再去理解，所以这个我们会放到下一节课去讲。

## RAG是什么？

### RAG的定义

首先我们来讲一下RAG是什么东西。它的中文意思就是**检索增强生成**。

这个名字的意思就是我们让AI先去查一查再来说一说，说白了就是相当于给AI装了一个知识外挂加上一个记忆仓库。

如果这个时候你说你老是提LLM它是什么东西，如果你之前没有听说过的话，你就理解为它是一个整个AI的核心大脑就可以了。

### RAG的作用

RAG它不是一种工具，它是一种工作机制，它是帮我们的大语言模型去补足两个短板。

**大语言模型有什么短板呢？**

1. **模型是静态的训练**，与过去的数据没有办法去实时更新的（你们现在所用的所有的大模型都是你之前的数据）

2. **模型是很容易出现幻觉**的

**那RAG怎么补呢？**

- 首先他会查实时的外部资料
- 第二个他会查有依据的内容，能够降低幻觉的概率

所以你们经常如果是做那些法律的、做医疗的，甚至是那种政务的，他是需要那种非常专业的术语的资料的时候，基本上RAG这个东西是跑不掉的。

### RAG的核心结构

从产品经理的角度，RAG的结构可以拆分成三大模块：

1. **检索器**：如果我遇到用户问题，我就要用到检索器，这个检索器就需要从向量库里找出相关的文段

2. **生成器**：在基于资料生成回答

3. **输出**：最后输出给客户

这个是不是就很像我们工作时候的操作流程？**首先是老板问你一个问题，让你先去查，你就说好，我先去查一下项目资料。查到项目资料了，最后你就把这个回复发送邮件给到你的老板进行一个汇报**。

所以**RAG它本质上就是让AI更像人一样的去工作，先去看资料，再开口再回复你**。

## 向量库

### 向量库的定义

来我们来讲一下这个向量库，向量库它就相当于RAG的一个资料仓库。

RAG好不好用，关键看你的资料是否有准备好，能不能够高效地去检索。

这个时候就有了一个叫向量库的东西，它是一个能理解语义的数据库。但是它不是按照关键词搜的，它是按照语义、按照意思去找的。

### 向量检索的案例

举个很简单的例子，比如说中国人常说的"吃瓜群众"是什么意思：

- **普通的关键词检索**：他会搜"吃瓜群众"四个字，对不对。但是如果是找不到这个关键词，"吃瓜"或者"吃瓜群众"他就会回复你"对不起，我没有找到"

- **向量检索呢**：他就会找到"吃瓜群众约等于围观事件的人群"这个概念。他找到这个概念呢，他会把相似的这种片段抓出来交给大语言模型，然后输出回答

### 向量库是如何检索的？

那向量库它是怎么检索出来的呢？

聪明的你已经想到了这个背后的关键机制，就是先embedding。然后把每一段文本压缩成为一个多维的语义向量。

然后当用户输入问题的时候，也把问题embedding成一个向量。在向量空间里边用数学方式，也就是**余弦相似度**找到最靠近的这个内容。

### 向量检索的可视化理解

我们把这个可视化一下：

我们先立一个知识库：
- "吃瓜群众是指围观的人" → 向量可能是(0.12, 0.88, 0.54, 1.2)
- "项目经理需要掌握五大技能" → (0.5, 0.54, 0.76, 1.1)
- "写简历要突出成果导向" → (0.03, 0.09, 0.87, 0.33)

这个时候的话我们有了一个叫**语义宇宙图谱**的东西。这个图谱是在不同的内容，在坐标系里边的位置是不一样的。

如果用户提问"吃瓜群众是什么意思"这句话，AI他会先embedding一下。他会把"吃瓜群众"变成一个向量，比如(0.11, 0.9, 0.48, 1.19)。

这个时候你看他和第一句的那个(0.12, 0.8, 0.45, 1.2)是不是非常接近呢？这个越接近是不是就代表了它们语义也是类似的。

### 余弦相似度算法

那我们的检索器这个时候是怎么样找到这个向量的呢？

这个检索器它是用一些算法把用户提的问题的向量和资料库中的每一个内容的向量，它是逐个地对比的。会挑出最相似的top k个，找出相关的内容。

因为前期embedding已经帮他理解了每一段话的意思，并且变成了可以比对的语义向量。

**我们现在可以下一个小的结论**：
- **向量检索 = 语义相似匹配度**
- **Embedding是它背后的理解力的发动机**

### 为什么要通过余弦相似度去找？

当我们把每一段内容embedding成语义向量之后，我们就需要一个相似度算法来判断哪些内容和用户说的这句话意思最相近。

这个时候AI背后用的就是一个叫做**余弦相似度**的算法。

它的核心的思想是**不比词，不比字，而是比方向**。

你可以简单地理解成为：你说这句话的意思是不是跟资料库里的某一段话的方向切近。

比如说你问的"吃瓜群众是啥"，他就会找到那些语义方向接近的"围观群众"的段落。

**你不需要懂公式，你只需要记住这一句话：余弦相似度就是比语义方向像不像，不是看有没有一样的词**。

### 用图像化理解向量检索

我们用图像化去理解一下：embedding我们刚才已经强调了，它是把一个文本变成语义向量。其实就相对于把每一句话标上一个位置坐标，这些点都是在一个语义宇宙的多维空间里边漂浮着。

那检索到内容之后呢，他就会接下来交给我们的大语言模型，让他带着参考资料去生成答案。然后大语言模型就会根据参考内容组织一段话：

> "吃瓜群众通常是指发生在事件发生时，在旁边围观，不参与但是关注的普通人"

所以你可以把这个大语言模型想象成为一个写稿的人。向量库呢只是帮他找参考资料的助手，**他们配合的好不好决定了AI答的准不准**。

## Chunk机制

### 为什么需要分块？

那理解了向量库前面的流程，我们就可以进一步地了解向量库的建构步骤是：文档分块 → 文本去embedding → 然后存进向量数据库。

你看这个其实就是我们产品人非常熟悉的一个流程，对不对？就是知识切片、结构化到入库管理。

那为什么要向量库构建步骤呢？因为**产品经理是这部分数据准备的协作者**，你可能不会去亲自地写代码。但是你需要懂负责内容分块策略：

- 比如说要考虑一个段落多长合适
- 怎么切不会丢上下文
- 然后决定哪些资料要进库
- 哪些是低频的冷知识就可以不要的
- 设计一些入库的策略，到底是标签还是来源，还是可追溯性

### 什么是Chunk？

接下来来到我们的Chunk机制全集，就叫Chunk分块机制，产品经理是一定要懂这个东西的。

首先我们要来说一下**为什么要分块**，原因很简单，但是也很重要。

这是因为**大语言模型它一次性的是处理不了太长的内容的**。比如说你上传一份50页的这个PPT你想让AI帮你去提炼重点。如果你直接丢进去的话，他很可能会出错。

他要么是只读前面几千个token他就读不完，要么呢他就给你答非所问。

所以**我们必须把大段的内容去切成一段段的，让AI先去读小块，然后建立向量纯进向量库**。

那这个里边每一段其实就相当于一个chunk。这样在用户问问题的时候，我们就能够用向量检索在所有的碎片里边找出最相关的那几段，再去交给大语言模型。

### Chunk的分法策略

那接下来我们要谈一下这个chunk到底是怎么分的，有哪些策略呢？

这个其实就是产品经理非常能够参与的设计点：

| 分块策略 | 说明 |
|---------|------|
| **固定token数量切分** | 按固定长度切分 |
| **按自然段标题分段** | 按文档结构切分 |
| **窗滑动窗口切分** | 设置重叠区域保持上下文 |
| **语义类切分** | 把内容聚类成主题段落，更依赖于算法和训练 |

你可以这么去理解这些不同的切块的方式，它其实就是你给AI设置的这种**知识口袋的模式**是不一样的。

如果你分的太小了，它的碎片会很多，知识会被稀释。如果分的太大了，那模型是读不完的，命中率会很差。

### 产品经理在Chunk设计中的参与点

所以**我们产品经理能够在中间参与哪些设计呢？**

首先产品经理能够对于知识内容进行预处理：
- 你要考虑哪些PDF内容要进库，哪些要清晰
- 三个策略的选择：按照自然段、划窗还是聚类，谁来切
- chunk大小设置：一块有多大，需不需要重叠
  - 太碎了会降低效率
  - 太大了它命中率又差
- 原数据标签：需要给每块内容加上标签，比如说来源文件、时间列码

### Chunk命中调试

**向量命中的调试**：问出来之后，你能看到哪些chunk它是被命中的，患者多不多。

这里要提到一个点：就是很多团队他们的RAG项目答非所问，根本的原因并不在于大语言模型不行，而是在于他的chunk并没有切好。

所以**Chunk它是一种语义空间的记忆颗粒，你每一个chunk切的越小越巧的时候，它就会记得越清楚**。

## 本章总结

我们来总结一下：

| 概念 | 说明 |
|------|------|
| **RAG** | 检索增强生成，让AI先查资料再生成回答 |
| **向量库** | RAG的资料仓库，按语义检索而非关键词 |
| **Chunk** | 大段内容的切分单位，是RAG系统的知识最小单元 |

**Chunk它是整个的RAG系统中间的知识最小单元**：
- 它决定了向量库的检索命中率
- 决定了语言模型的回答是不是靠谱
- 更决定了产品体验是不是聪明
