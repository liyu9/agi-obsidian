# 第三节 要求对比：AI产品经理 vs 传统产品经理

## 工作要求对比

我们来稍微回顾一下，AI产品经理究竟跟传统产品经理在工作流上面有了三个部分的补充之外，在工作要求整体上来看二者有什么样的一个差异。

### 传统产品经理

- **交付目标**：相对比较明确，有明确目标的功能型产品
- **关注重点**：业务的指标带来的一些增长
- **交付目标**：比较明确
- **工作重心**：结合目标来去识别业务的机会点，然后通过需求分析、交互设计和产品运营来实现产品的价值
- **交互范式**：以GUI为主
- **迭代周期**：相对比较稳步推进，以功能开发的周期为主
- **资源协调**：主要是在协调前后段的研发资源

### AI产品经理

- **交付目标**：坦白说是没有那么明确的，它是一个概率型的产品
- **工作重心**：
  - 第一：模型表现、背后的数据策略、业务结合大模型能力的一些应用模式是否是OK的
  - 第二：概率型产品在用户侧的体验如何
- **交互范式**：目前还是一个混合的模式，LUI跟GUI互相结合
- **迭代周期**：
  - 更依赖模型训练跟测试的周期，而不是一个单纯的开发周期
  - 模型的训练周期、验证调优周期比较长，而且不太可控
  - 上线新功能的时候可能还需要进行多次的AB测试来验证模型的效果
  - 工作节奏有比较多的探索空间，需要在短时间内探索比较多的算法策略，分析效果后再选择最优解
- **资源协调**：比较多样，包括数据、算法、研发、策略等等多个团队的协作

## 工作要求对比总结

| 对比维度 | 传统产品经理 | AI产品经理 |
|---------|-------------|-----------|
| 交付目标 | 明确 | 不太明确，概率型产品 |
| 工作重心 | 识别业务机会点，实现产品价值 | 模型表现 + 用户体验 |
| 交互范式 | GUI为主 | LUI + GUI混合 |
| 迭代周期 | 功能开发周期为主，稳步推进 | 模型训练测试周期，不可控，频繁AB测试 |
| 资源协调 | 前后端研发资源 | 数据、算法、研发、策略等多团队 |

## 能力要求对比

**小结**：

- 传统产品经理：更偏重业务跟产品的设计
- AI产品经理：更看重你的AI技术理解、业务抽象和产品的实现能力

### 详细能力对比

#### 需求分析能力

| 类型 | 说明 |
|------|------|
| 传统产品经理 | 围绕用户群体和产品商业变现投入 |
| AI产品经理 | 一方面需要了解业务，一方面要了解AI能力，才能知道二者怎么结合起来，有不同情况下的场景化设计 |

#### 交互与UI设计

| 类型 | 说明 |
|------|------|
| 传统产品经理 | 更看重用户体验跟视觉的呈现（很多B端产品经理在交互跟UI设计上面落脚点比较轻） |
| AI产品经理 | 可能更多的注重整个引导化的设计，比如连续对话的引导、一些对话的推荐等，偏引导式的 |

#### 技术理解能力

| 类型 | 说明 |
|------|------|
| 传统产品经理 | 基本了解推动功能实现（很多复杂B端产品对技术理解能力要求也比较高，需要考验产品经理的系统规划能力） |
| AI产品经理 | 要求肯定会更高，因为需要理解AI算法的工作原理，而且可以结合具体的场景来定义模型的目标 |

**AI产品经理需要掌握的技术领域**：

- 优化推荐
- 生成内容
- 实现对话策略
- 通过提示工程来影响生成式模型的输出效果

#### 数据分析能力

| 类型 | 说明 |
|------|------|
| 传统产品经理 | 更多的关注用户的行为数据跟转化率，策略部分比较偏功能规则的设计 |
| AI产品经理 | 跟策略设计息息相关，需要数据驱动，需要设计策略并且获取高质量的数据来指导算法优化，对于数据和策略的理解要求比传统产品经理高很多 |

## 能力要求对比总结

| 能力维度 | 传统产品经理 | AI产品经理 |
|---------|-------------|-----------|
| 需求分析 | 围绕用户和商业变现 | 业务+AI能力结合，场景化设计 |
| 交互设计 | 用户体验和视觉呈现 | 引导化设计，对话引导 |
| 技术理解 | 基本了解功能实现 | 深入理解AI算法原理，能定义模型目标 |
| 数据分析 | 用户行为和转化率 | 数据驱动策略，指导算法优化 |
| 策略设计 | 功能规则设计 | 提示工程、知识库、微调等 |
| 团队协作 | 前后端研发 | 多团队协作（数据、算法、研发、策略） |

## 本节学习要点

1. **工作要求差异**：AI产品经理的交付目标不如传统产品经理明确，因为是概率型产品。

2. **迭代周期差异**：AI产品经理的迭代周期更依赖模型训练测试周期，不确定性高。

3. **核心能力差异**：
   - 传统产品经理偏重业务和产品设计
   - AI产品经理更看重AI技术理解、业务抽象和产品实现能力

4. **四大能力提升**：
   - 需求分析：要从业务和AI能力两个维度考虑
   - 交互设计：注重引导化设计
   - 技术理解：深入理解AI算法原理
   - 数据分析：数据驱动策略设计

5. **团队协作**：AI产品经理需要协调更多类型的团队，包括数据、算法、研发、策略等。
