# 第二章 3步设计智能客服机器人

## 第1步：拆分业务需求

> 产品经理日常工作中，分析需求、评估需求、将需求转化为产品功能是核心工作。对于AI产品经理来说，在评估需求的合理性、可行性，并最终转化为技术方案的过程中，有哪些不一样的地方？

## 一、AI产品经理工作流程概览

```
┌─────────────────────────────────────────┐
│  AI产品经理三步工作法                    │
├─────────────────────────────────────────┤
│  第1步：拆分业务需求                     │
│  ↓                                      │
│  识别AI需求的可行性                      │
│  将业务需求进行拆分细化                   │
│  ↓                                      │
│  第2步：跟进算法效果                     │
│  ↓                                      │
│  提出算法需求                           │
│  了解每个环节算法能实现的效果              │
│  ↓                                      │
│  第3步：设计产品功能                     │
│  ↓                                      │
│  基于算法最佳效果设计产品功能              │
│  （技术不够，产品来补）                   │
└─────────────────────────────────────────┘
```

## 二、业务需求分析案例

### 1. 常见的业务需求示例

| 需求方 | 需求描述 |
|--------|---------|
| 数据组 | 从用户历史反馈文本中挖掘有价值的信息 |
| 行政部 | AI会议记录生成工具 |
| 市场部 | AI智能推广策略，精准推送提升触达率 |
| 客服部 | 智能应答工具，拦截部分咨询量 |

### 2. 需求分析方法

#### （1）数据分析需求

**需求**：从用户历史反馈文本中挖掘有价值的信息

**分析方法**：
- 访问业务方：如果人工分析，会得出什么结论
- 期望分析出什么维度的信息

**判断标准**：
> 如果作为具有主观意识的人都无法定义出规则或预期，那么算法更无法做出类似功能。这就相当于是一个不明确的需求。

#### （2）技术依赖型需求

**需求**：智能会议记录工具

**核心技术点**：ASR（语音转文本）技术

**分析维度**：

**第一点**：细化业务需求
- 会议中每个人的话都要记录？
- 十个人开会，要分别记录下来？

**第二点**：了解当前技术能否满足业务预期

#### （3）策略类/决策类需求

**需求特征**：
- 左侧有一堆内容（如软文/问题）
- 右侧有一堆目标（如客户/答案）
- 需要进行智能匹配

**案例1：智能推广策略**
- 左侧：软文
- 右侧：客户
- 目标：精准匹配

**案例2：智能客服**
- 左侧：用户问题
- 右侧：答案库
- 目标：智能匹配答案

## 三、策略类需求分析方法

### 1. 第一步：判断是否为AI需求

**核心问题**：当前场景能否用规则描述？

**判断方法**：简单来说就是在不考虑数据量和规模的情况下，作为外行的人能否做出相关决策和判断。

**案例分析：智能推广策略**

> 如果说左侧有一堆软文，右侧有一堆用户。比如针对近期有购买过的用户推A类软文，针对女性用户推B类软文。这就相当于是一个可以被清晰描述出来的规则。

**判断结论**：
- 如果规则数量很多、无法穷举，或需要算法自动学习历史规则 → 需要用到深度学习或机器学习算法
- 如果能用清晰规则描述 → 可能不需要算法

### 2. 第二步：拆分算法需求

**核心要求**：颗粒度越细越好

**拆分原则**：
- 区分哪些是算法工程师需要完成的
- 区分哪些是工程侧研发需要完成的

### 3. 第三步：整理算法需求

**必备要素**：
- 明确输入输出
- 定义业务场景下的效果指标
- 提出明确的产品预期

## 四、实战案例：电商客服业务分流

### 1. 业务背景

**场景**：某电商平台客服团队分为售前和售后两个组

**问题**：
- 商品详情页客服入口由售前团队接待
- 但有30%情况下用户咨询的是售后问题
- 需要售前团队将会话转接给售后组

### 2. 需求描述

**目标**：智能预测用户咨询类型

**方案**：如果预测用户要咨询售后问题，直接分配给售后组，降低售前转接比例

### 3. 需求分析

**第一步：判断是否可用规则描述**

分析用户特征：
- 有未完成的订单
- 没有浏览过店铺首页
- 浏览商品不超过10秒就进入咨询入口

**99%咨询售后问题的用户都有上述三个特点**

**结论**：需求可以被规则清晰描述，不需要使用算法

**第二步：规则实现方案**

当用户从商品详情页进入咨询时，技术上使用三个规则判断用户特征：
1. 检查是否有未完成订单
2. 检查是否浏览过店铺首页
3. 检查浏览商品时长

全部符合 → 直接进入售后咨询会话

## 五、规则 vs 算法决策边界

### 1. 适合用纯规则解决的场景

**特征**：规则清晰且数量有限，或可被统计规则直接覆盖

**案例**：
- 有明确特征的用户给他推荐什么产品
- 今日APP首页推荐点击量最高的TOP 10商品

### 2. 适合用算法解决的场景

**特征**：
- 有一定不确定性
- 规则无法被穷举
- 需要算法学习一部分规则或特征

**案例**：
- 两个句子的相似度判断
- 从1000张图片中找出猫的头像

## 六、实战案例：AI客服机器人需求分析

### 1. 业务背景

**场景**：某K12在线教育平台暑假期间流量高峰

**数据**：日活数量预估翻倍

**现状**：客服团队已满负荷运作

**需求**：自研客服机器人为在线客服团队拦截一部分咨询

### 2. 业务场景梳理

**用户与机器人交互全流程**：

```
用户进入咨询页面
    ↓
提问前推荐
    ├── 推荐近期活动
    ├── 推荐用户最可能点击的问题
    └── 关联用户浏览过的商品/订单信息
    ↓
用户提问
    ├── 问题识别与回复
    ├── 负面情绪识别与安抚
    └── 转人工机制
    ↓
会话结束
    ├── 效果优化
    ├── 知识库补充
    └── 数据报表监控
```

### 3. 算法参与环节分析

#### （1）快捷入口推荐

**时机**：用户进入咨询页面时

**推荐内容**：
- 近期活动
- 用户订单
- 用户浏览过的商品

#### （2）问题推荐

**时机**：用户进入会话后

**目标**：根据用户特征推荐最可能点击的问题

**案例**：用户刚买了高二语文课程 → 推荐"高二语文课程开课时间"

#### （3）FAQ匹配

**时机**：用户提问后

**流程**：
1. 识别用户问题
2. 在知识库中匹配
3. 返回对应答案

#### （4）情感识别

**时机**：用户提问时

**触发条件**：用户语气或文本带有负面情绪词

**策略**：安抚或转人工

#### （5）转人工策略

**触发条件**：机器人无法解答问题时

**执行**：转接到人工客服

#### （6）问题聚类

**时机**：会话结束后

**输入**：
- 机器人无法应答的用户问题
- 用户转人工后问人工的问题（机器人无法回答）

**流程**：
1. 对问题进行聚类
2. 由AI训练师决定是否添加为新知识点
3. 更新机器人知识库

### 4. 四大核心算法需求

| 算法需求 | 输入 | 输出 | 业务指标 |
|---------|------|------|---------|
| **问题推荐** | 用户特征（进线渠道、时间等） | Top N个推荐问题 | 推荐问题的点击率 |
| **FAQ匹配** | 用户问题 | 具体答案 | 问题识别准确率/匹配率 |
| **情感识别** | 用户问题文本 | 情绪分类（正向/中性/负向） | 情感识别准确率（目标70%+） |
| **问题聚类** | 未识别问题/转人工问题 | 聚类结果 | 聚类采纳率 |

#### （1）问题推荐

**输入**：用户特征（进线渠道、进线时间等）

**输出**：Top N个推荐问题

**指标**：推荐问题点击率

**案例**：推荐5个问题，点击率30% → 30%情况下推荐被用户点击，预测正确

#### （2）FAQ匹配

**输入**：用户问题

**输出**：具体答案

**匹配场景**：

**场景1：精准匹配**
- 匹配到一个问题 → 返回对应答案

**场景2：多匹配（反问）**
- 匹配到3个可能问题 → 反问用户
- "请问您是否想咨询ABC三个问题？"

**场景3：未匹配**
- 完全无法匹配 → 回复："很抱歉我没有识别到您的问题，您可以换个说法再问一下" 或直接转人工

**指标**：问题识别准确率/匹配率

#### （3）情感识别

**输入**：用户问题

**输出**：情绪分类结果
- 正向
- 中性
- 负向（可细分：焦虑、生气等）

**指标**：情感识别准确率

**参考值**：标注数据不太差的情况下，准确率达到70%以上没有问题

#### （4）问题聚类

**输入**：
- 机器人无法应答的用户问题
- 转人工后用户问人工的问题（机器人无法回答）

**输出**：聚类结果

**案例**：输入1000或10000个用户问题 → 输出10个聚类知识点

**指标**：聚类采纳率

**案例**：聚类出10个问题给AI训练师 → 6个被采纳 → 添加到知识库

## 七、本节总结

### 核心要点

```
业务需求分析三步法
├── 第1步：判断是否为AI需求
│   └── 能否用规则描述
├── 第2步：拆分算法需求
│   └── 梳理全业务流程，定义算法参与环节
└── 第3步：整理算法需求
    └── 明确输入输出和业务指标
```

### 关键判断标准

| 判断维度 | 结论 | 行动 |
|---------|------|------|
| 规则清晰且有限 | 可用纯规则实现 | 不需要算法 |
| 规则无法穷举，需算法学习 | 需要算法 | 拆分算法需求 |
| 技术强依赖 | 细化技术点 | 了解技术边界 |

### 算法需求定义要素

1. **输入**：算法处理的数据
2. **输出**：算法的返回结果
3. **指标**：衡量算法效果的量化标准
4. **预期**：业务对指标的期望值

### 学习要点

- 理解策略类/决策类需求的分析方法
- 掌握规则与算法的适用场景
- 学会拆分和定义算法需求
- 理解算法指标与业务指标的关系
