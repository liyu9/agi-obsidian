## 核心方法框架总览

### 产品规划六步法

```
① 战略理解与业务拆解 → ② 技术展望 → ③ 产品架构蓝图设计
→ ④ 需求优先级管理与落地 → ⑤ 内外协同与交付运营 → ⑥ 复盘驱动迭代
```

### REACT模型（产品目标度量）

| 维度 | 含义 |
|------|------|
| R - Revenue | 业务营收 |
| E - Experience | 用户体验 |
| A - Enable | 赋能业务 |
| C - Cost Saving | 降本增效 |
| T - Time to Market | 响应加速 |

### B3C优先级原则

| 维度 | 含义 |
|------|------|
| B - Business | 业务价值（可度量） |
| C - Constraint | 约束条件（人/时间/依赖） |
| C - Confidence | 信心/成功率 |
| C - Cost | 成本 |

### 五看三定

```
看行业趋势 → 看客户市场 → 看竞争 → 看自己 → 看机会
                                                        ↓
                                    定策略 → 定目标 → 定架构
```

### JTBD + AI融合

```
角色拆解（人 vs AI）→ 能力成熟度评估 → 时间策略（短期→长期）
```

### AI流程设计三原则

1. 框架没变，AI提升上限
2. 把AI当成人来设计（会犯错的正常人）
3. 数据推动流程持续优化

### 交付运营迭代的3×3矩阵

|  | 交付 | 运营 | 迭代 |
|--|------|------|------|
| **关注点1** | 软件交付 | 反馈收集 | 场景驱动 |
| **关注点2** | 能力交付 | 数据指标 | 算法驱动 |
| **关注点3** | 流程机制交付 | 运营策略 | 体系驱动 |

## 关键认知升级

### 从"数字鸿沟"到"智能鸿沟"
数字化时代差距是接入信息的差距，未来差距是用AI和不用AI的能力差距。能熟练使用AI的人效能高2-5倍，收益差距会越来越大。

### 产品经理的核心转型
- 从工具赋能者 → 智能化伙伴的设计者
- 从流程设计师 → 人机协同的架构师
- 从需求分析者 → 角色解构与重组的推动者

### 三种产品经理类型
| 类型 | 定位 | 要求 |
|------|------|------|
| AI驱动的产品经理（AI-enabled） | 底线要求 | 会用AI工具提升个人效能 |
| AI产品经理（AI-integrated） | 课程目标 | 构建融合AI特性的数字化产品 |
| AI平台产品经理（AI-platform） | 高阶方向 | 创造AI特性和能力平台 |
