## 三、AI产品设计与落地能力

### 3.1 AI产品设计五步法

| 步骤 | 内容 | 输出 |
|------|------|------|
| 1. 任务拆解 | 将模糊需求翻译为可执行的AI任务 | 任务流程草图、AI职责矩阵 |
| 2. 模型选型 | 评估延迟/成本/安全性，选择合适模型 | 模型能力对比表+选型逻辑 |
| 3. 输入设计 | 设计Prompt任务指令系统 | Prompt模块化结构 |
| 4. RAG设计 | 知识库搭建与检索方案 | 知识结构图+数据接入方式 |
| 5. 流程编排 | Chain+Action+Memory+状态控制 | 流程链设计方案 |

### 3.2 Agent搭建六步法

```
1. 确定数据类型（文本/图像/语音）
2. 数据转换（Embedding/ASR/图像分类）
3. 选择模型能力（大模型/分类模型/RAG）
4. 控制输出（Prompt模板/微调）
5. 对接服务（API调用/推理服务）
6. 构建Agent（大模型+工作链路+意图管理+反馈）
```

### 3.3 AI产品开发流程

```
产品定位 → 需求分析 → 技术预研 → 模型开发 → 运营
                      ↓           ↓
                  产品研发     模型开发（双线并行）
```

### 3.4 交付四阶段

| 阶段 | 目标 | 核心工作 |
|------|------|---------|
| 原型期 | 概念验证 | 快速验证AI是否靠谱 |
| MVP期 | 从能用到能跑 | 明确输入输出、知识库、Prompt结构 |
| 小范围测试 | 暴露问题 | 异常处理、权限控制、监控 |
| 正式交付 | 产品上线 | 用户权限、数据加密、日志审计 |

### 3.5 AI产品迭代三重驱动力

```
场景扩展 → 模型能力提升 → 数据积累
```

## 五、行业认知与商业能力

### 5.1 需求评估三维度

```
                 ┌──── 数据维度 ────┐
                 │ 可获取性/质量     │
                 │ 存量/闭环        │
                 └──────────────────┘
                 ┌──── 问题维度 ────┐
项目是否适合AI？  │ 可解释性/容错度   │
                 │ 复杂度/实时性    │
                 └──────────────────┘
                 ┌──── 商业维度 ────┐
                 │ 业务价值/痛点    │
                 │ ROI/商业化可行性 │
                 └──────────────────┘
```

### 5.2 垂直行业场景

| 行业 | AI典型场景 | 产品经理需要掌握的行业知识 |
|------|-----------|------------------------|

| 零售 | 智能推荐、商品管理 | 供应链、用户行为分析 |

### 5.3 核心商业原则

| 原则 | 说明 |
|------|------|
| 可用性原则 | 50%→90%需3天，90%→99%需1年，够用即可上线 |
| 十分之一原则 | AI产品定价 = 节省人工成本 ÷ 10 |
| 五秒钟法则 | 人类5秒内能判断的任务适合AI解决 |
| 技术分层原则 | 不懂技术难入行，只懂技术难高薪 |

## 六、能力分层成长路径

## 七、AI产品经理与传统产品经理核心差异速览

| 维度 | 传统产品经理 | AI产品经理 |
|------|-------------|-----------|
| 产品性质 | 确定性产品，功能明确 | 概率型产品，结果不确定 |
| 核心驱动力 | 功能逻辑和用户体验 | 数据-模型-场景三角关系 |
| 交互范式 | GUI图形用户界面 | LUI+GUI混合模式 |
| 迭代节奏 | 功能开发周期，稳定可预期 | 模型训练周期，不可控 |
| 协作团队 | 前后端研发 | 数据+算法+研发+策略多团队 |
| 交付标准 | 功能完整 | 模型精度达标+功能完整 |
| 技术依赖 | 浅（API调用） | 深（技术边界判断） |

---

> **总结**：AI产品经理是"技术+产品+行业"的复合型人才，核心是将AI能力转化为可落地的产品解决方案。短期看AI产品经理是一个独立岗位，长期看所有产品经理都需具备AI能力。
