## 一、案例背景：银行客户经理周报统计分析

同学们好，欢迎收看本节课程能力升维，掌握COZE工作流。本节给大家介绍案例：银行客户经理周报统计分析，会涉及批量提取非结构化文本信息、缺失信息快速定位、生成数据分析报告工作流的设计以及创建方法。

### 1.1 需求痛点

| 痛点 | 描述 |
|------|------|
| 信息完整性审核困难 | 支行行长无法快速识别哪些周报存在关键信息缺失，缺乏自动化校验机制 |
| 数据汇总工作繁重 | 需要手动从15-30份周报中提取关键数据并整合，每周需花费数小时 |
| 缺乏整体视角 | 无法快速获得全支行客户经理的工作综合视图，难以实现横向比较 |
| 报告标准化程度低 | 客户经理填写方式各异，同类信息表述不一，难以直接比较 |

### 1.2 案例背景

某商业银行拥有数百家支行，每家支行平均管理15-30名客户经理。作为银行业务的一线人员，客户经理需按照要求每周提交标准化的周报。

**现有管理流程**：
1. 客户经理按照模板编写Word格式周报并提交
2. 支行管理人员逐一查阅周报，检查信息完整性
3. 手动汇总各客户经理周报数据，制作统计报表
4. 支行行长基于汇总数据进行业务分析和决策

**流程瓶颈**：
- 客户经理提交的周报质量参差不齐，信息缺失现象普遍
- 支行行长难以在有限时间内全面审核每份周报
- 手工汇总数据耗时费力且容易出错
- 无法及时获得全支行业务情况的整体视图

## 二、工作流设计

### 2.1 工作流程图

```
┌─────────┐    ┌──────────┐    ┌────────────┐    ┌──────────┐    ┌───────────┐    ┌────────┐
│  开始   │───→│ 读取报告  │───→│  提取信息  │───→│  保存信息 │───→│  查询数据 │───→│ 结束 │
└─────────┘    └──────────┘    └────────────┘    └──────────┘    └───────────┘    └────────┘
```

**完整流程**：
1. 读取报告（Word文档）
2. 提取信息（大模型处理）
3. 保存信息（数据库）
4. 查询数据（数据库查询）
5. 分析报告（大模型生成）
6. 生成文档（PDF/Word）

### 2.2 需要使用的组件

| 组件 | 用途 |
|------|------|
| 插件 | 读取Word文档、创建文档 |
| 大模型 | 提取字段信息、生成分析报告 |
| 数据库 | 存储和查询数据 |

## 三、创建工作流

### 3.1 工作流基础

**创建步骤**：
1. 进入智能体工作空间
2. 选择资源库 → 创建资源 → 创建工作流
3. 命名：Weekly Report
4. 填写工作流描述
5. 单击确认进入创建界面

**工作流组成**：
- 每个工作流必须有开始节点和结束节点
- 中间可添加多个功能节点
- 节点之间通过连接线连接
- 工作流实时自动保存

### 3.2 节点配置基础

| 节点类型 | 配置要点 |
|----------|----------|
| 开始节点 | 设置输入变量（如文件类型） |
| 结束节点 | 设置输出变量（如结果展示） |
| 功能节点 | 配置输入输出变量 |

---

## 四、读取报告功能

### 4.1 读取Word文档

**使用插件**：文件读取 → read

**配置步骤**：
1. 添加read插件节点
2. 将开始节点的文件变量作为read插件的输入
3. read插件输出：code、data、log_id、message
4. 后续节点引用data参数获取文本内容

**节点配置**：
- 输入变量：来自开始节点的input（文件链接）
- 输出变量：data（文档文本内容）

### 4.2 测试运行

上传Word报告文件试运行，验证是否能正确读取文档内容。

> 注意：原文档中的项目符号在智能体中可能无法正常显示，但不影响后续分析使用。

## 五、提取信息功能

### 5.1 添加大模型节点

**配置要点**：
- 模型选择：可尝试豆包1.5pro或DeepSeek V3
- 输入变量：引用read节点的data参数
- 系统提示词：配置文本信息提取专家角色

### 5.2 系统提示词配置

**使用AI自动优化**：

```
你是一个专业的文本信息提取专家，擅长从用户输入的文本内容中精准提取关键信息。
能够从文本内容中提取以下指定字段信息，并以JSON格式输出。
```

**提取字段**：
| 字段名 | 描述 | 类型 |
|--------|------|------|
| report_date | 报告时间 | 文本型 |
| manager_id | 客户经理ID | 文本型 |
| manager_name | 客户经理姓名 | 文本型 |
| department | 所属部门 | 文本型 |
| new_accounts | 新增开户数 | 整数型 |
| am_growth | 资产管理规模净增 | 整数型 |
| corporate_deposit | 对公存款净增 | 整数型 |
| retail_deposit | 零售存款净增 | 整数型 |

### 5.3 输出配置

- 输出格式：JSON
- 变量类型：object
- 子项：每个提取字段

## 六、保存信息功能

### 6.1 创建数据库表

**表名**：Weekly Report

**字段设计**：
| 字段名 | 描述 | 类型 | 必要 |
|--------|------|------|------|
| report_date | 报告时间 | 文本型 | 否 |
| manager_id | 客户经理ID | 文本型 | 否 |
| manager_name | 客户经理姓名 | 文本型 | 否 |
| department | 所属部门 | 文本型 | 否 |
| new_accounts | 新增开户数 | 整数型 | 否 |
| am_growth | 资产管理规模净增 | 整数型 | 否 |
| corporate_deposit | 对公存款净增 | 整数型 | 否 |
| retail_deposit | 零售存款净增 | 整数型 | 否 |

> 注意：字段不设置为必要，因为部分客户经理可能存在某些指标缺失。

### 6.2 添加新增数据节点

**配置步骤**：
1. 添加数据表：Weekly Report
2. 选择并设置字段（全部8个字段）
3. 依次引用大模型输出的对应字段变量

**关键点**：大模型以JSON格式输出，便于准确对应每个字段。

### 6.3 删除数据节点

**用途**：每次上传新报告前清空旧数据

**配置**：
- 添加删除数据节点
- 删除条件：ID >= 0（删除所有记录）
- 放置位置：开始节点之后、新增数据节点之前

---

## 七、查询数据功能

### 7.1 添加查询数据节点

**配置步骤**：
1. 添加数据表：Weekly Report
2. 设置查询字段（全部8个字段 + 系统字段）
3. 设置查询条件

**条件设置**：记录ID >= 0（查询所有记录）

### 7.2 查询缺失数据

**用途**：快速定位信息缺失的周报

**查询条件**：四个关键指标中任一指标 = 0

```sql
WHERE new_accounts = 0 OR am_growth = 0 
   OR corporate_deposit = 0 OR retail_deposit = 0
```

### 7.3 输出变量

- 完整查询结果：output_list
- 缺失记录查询：lost

---

## 八、分析报告功能

### 8.1 添加大模型节点

**输入变量**：
- 完整查询结果：input（查询所有数据）
- 缺失记录：lost（查询缺失数据）

**系统提示词配置**：

```
你是分析报告撰写专家，某银行支行的所有客户经理周报信息已经存储在数据库中。
请根据数据库查询的结果，以Markdown格式撰写一份支行行长视角的分析报告。
```

### 8.2 用户提示词

```
客户经理周报信息：{{input}}
信息缺失记录：{{lost}}
请以Markdown格式输出报告
```

### 8.3 报告结构

| 部分 | 内容 |
|------|------|
| 信息缺失记录说明 | 如存在缺失，表格形式列出 |
| 工作进展总结 | 各客户经理工作推进情况 |
| 业绩情况分析 | 四个关键指标的具体数值 |
| 遇到的问题及解决方案 | 周报中提及的问题 |
| 下周工作建议与展望 | 后续工作计划 |

## 十、批量处理功能

### 10.1 添加批处理节点

**组成**：批处理 + 批处理体

**并行数量**：默认10，建议小于5或10

**循环次数上限**：默认100

### 10.2 批处理配置

**放置节点**：
- read节点（读取报告）
- 提取字段信息节点（大模型）
- 新增数据节点

**输入变量**：
- 开始节点的input改为array类型（file数组）
- 批处理引用开始节点的input数组
- 各节点依次引用前一个节点的输出

### 10.3 工作流优化

```
┌─────────┐    ┌──────────────┐    ┌────────────────────┐    ┌───────────┐    ┌──────────────┐    ┌────────┐
│  开始   │───→│  删除数据     │───→│  批处理(并行运行)   │───→│  查询数据  │───→│  分析报告   │───→│ 结束  │
└─────────┘    └──────────────┘    └────────────────────┘    └───────────┘    └──────────────┘    └────────┘
                                         │
                         ┌───────────┬──┴──┬───────────┐
                         │ read      │ 大模型 │ 新增数据 │
                         └───────────┴──────┴───────────┘
```

## 十三、核心要点总结

1. **何时使用工作流**：当需要实现的功能较多（插件+数据库+大模型），且需要按指定流程执行时
2. **工作流组成**：开始节点、功能节点、结束节点
3. **批处理使用**：处理多个文件时使用批处理节点
4. **大模型选择**：根据运行结果合理选择模型（DeepSeek V3有时更稳定）
5. **数据清空**：批量处理前先删除旧数据，避免重复记录
6. **流程图绘制**：创建工作流前先绘制流程图，明确各节点关系
