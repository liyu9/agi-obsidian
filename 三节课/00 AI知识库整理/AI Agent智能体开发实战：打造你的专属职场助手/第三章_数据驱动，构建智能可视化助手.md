## 一、案例背景：数据可视化分析助手

同学们好，欢迎收看课程数据驱动构建智能可视化助手。本节会涉及以下知识点：介绍案例数据可视化分析助手、表结构数据的分析、数据可视化分析。

### 1.1 需求痛点

| 痛点 | 描述 |
|------|------|
| 数据分析门槛高 | 传统数据分析需要专业技能和编程知识，普通用户难以上手 |
| 分析流程繁琐 | 从数据处理到可视化再到报告撰写，通常需要多个工具和手动操作 |
| 效率低下 | 人工分析耗时长，尤其是面对大量或复杂数据时 |
| 主观影响 | 人工分析容易受主观因素影响，导致结果和分析质量不一致 |
| 成本高昂 | 雇佣专业数据分析师或团队成本较高 |

### 1.2 案例场景

智能数据可视化分析助手需要完成的功能：

1. 上传Excel文件
2. 解析表结构信息（表明、字段名）
3. 根据分析需求撰写SQL代码
4. 执行SQL代码获取分析结果
5. 绘制可视化图表
6. 生成分析报告

## 四、撰写SQL代码功能

### 4.1 添加大模型节点

**功能**：根据分析需求、表名、字段名生成MySQL查询代码

### 4.2 输入变量

| 变量名 | 来源 |
|--------|------|
| table_name | 解析表结构节点的表名 |
| field_name | 解析表结构节点的字段名 |
| question | 开始节点的分析需求 |

### 4.3 系统提示词配置

```
你是一个专业的数据分析师，擅长使用MySQL语言进行数据查询分析。
能够根据给定的数据内容和分析需求，生成精确的MySQL查询代码来满足数据查询需求。

【重要要求】
- 生成纯净的MySQL代码
- 不包含其他不相关的文本内容和各种符号
- 只保留SELECT到分号之间的代码
- 分号代表命令终止符
```

### 4.4 SQL代码示例

**分析需求**：分析每个市场级别的销量合计

```sql
SELECT 市场级别, SUM(销量) AS 总销量 
FROM market_sales 
GROUP BY 市场级别
```

## 五、执行SQL代码功能

### 5.1 添加插件

**插件**：circlon excel

**选择插件**：run_sql_on_excel

**功能**：在Excel上执行MySQL代码

### 5.2 插件参数配置

| 参数 | 配置 |
|------|------|
| count | 返回条数（设置较大值） |
| link | 来自开始节点的Excel文件 |
| sql_code | 来自大模型撰写的SQL代码 |

### 5.3 注意事项

1. 确保SQL代码是纯净的，不包含注释和多余符号
2. 如果执行失败，检查代码是否包含markdown格式符号
3. 分号必须保留

### 5.4 验证结果

在Excel中创建数据透视表验证分析结果准确性。

## 八、循环体处理多需求

### 8.1 问题场景

当用户输入多个分析需求时（如"分析每个市场级别的销量合计，以及每个市场分布的销售合计"），单次执行可能无法准确识别所有需求。

### 8.2 解决方案

使用循环体依次处理每个分析需求：

1. 识别分析需求（拆分为数组）
2. 循环处理每个需求
3. 分别执行SQL、生成图表、输出结论

### 8.3 循环体配置

**添加节点**：循环 + 循环体

**放置在循环体中的节点**：
1. 撰写SQL代码
2. 执行SQL代码
3. 生成Option参数
4. 绘制图表
5. 撰写分析报告

### 8.4 识别分析需求大模型

**系统提示词**：

```
你是一位专业的数据分析师，擅长精准识别用户的分析需求并将其合理划分。
将每个分级需求以字符串形式存放在数组中，然后返回包含分析需求的数组。

【回复示例】
["需求一：分析每个市场级别的销量合计", "需求二：分析每个市场分布的销售合计"]
```

**输出配置**：
- 输出类型：array（数组）
- 变量类型：文本

### 8.5 循环配置

- 循环类型：使用数组循环
- 输入：识别分析需求大模型的输出数组
- 循环体依次接收每个分析需求

### 8.6 变量引用调整

进入循环体后：
- 表名字段名：引用解析表结构节点
- 分析需求：引用循环传入的当前需求（text参数）

### 8.7 完整工作流（带循环）

```
┌─────────┐    ┌────────────┐    ┌──────────────────┐    ┌───────────────┐    ┌─────────────┐
│  开始   │───→│ 解析表结构 │───→│ 识别分析需求     │───→│ 循环(数组)    │───→│ 查询数据    │
└─────────┘    └────────────┘    └──────────────────┘    └───────────────┘    └─────────────┘
                                                             │
                                          ┌──────────────────┼──────────────────┐
                                          │     循环体(依次处理每个需求)            │
                                          │ ┌────────┐ ┌─────┐ ┌─────┐ ┌──────┐│
                                          │ │撰写SQL │→│执行 │→│图表 │→│报告  ││
                                          │ └────────┘ └─────┘ └─────┘ └──────┘│
                                          └───────────────────────────────────┘
```

## 十一、核心要点总结

1. **为什么需要写SQL代码**：直接让AI分析Excel文件结果可能不准确，通过SQL查询能得到更精确的结果
2. **解析表结构的必要性**：必须先让智能体识别表名和字段名，才能准确撰写SQL代码
3. **SQL代码纯净性**：生成的代码必须纯净，不包含注释和多余符号，否则执行会失败
4. **循环体使用场景**：处理多个分析需求时使用，避免结果混淆
5. **ECharts图表**：使用基础图表（柱形图、饼图、折线图）成功率更高
6. **大模型幻觉问题**：AI可能产生不稳定结果，可通过循环体等方式规避
