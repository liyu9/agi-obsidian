# 第一周：接手项目（上）

## 从接手产品项目到中长期产品规划

同学们好，我是傅绵。接下来我们会开始重点来解决从接手项目开始到能够为这个产品去做中长期规划这个事情。

### 产品经理核心能力回顾

产品经理核心能力的差别在于：

- **复杂程度**（P1→P2）：从简单问题到多通道多用途的复杂问题
- **不确定性**（P2→P3）：面对不确定性时，怎么把它变得确定

### 项目的三个来源

| 来源 | 描述 |
|------|------|
| **老板看到新东西** | 老板希望在你已有的项目中落地新模式（如拼团），如何把老板需求提炼为项目 |
| **重点攻坚虚拟项目组** | 作为虚拟项目组leader，如何领导跨部门团队齐心协力 |
| **自己意识到业务发展** | 作为产品负责人，基于中长期规划发起阶段性项目，争取老板支持 |

### 公司级项目的特点

- 相对比较复杂
- 大多数是**业务驱动**的
- **目标导向**的，不是在原有目标基础上做得更好
- 目标可能不够清晰，导致不一定能成功

## 接手项目过程中存在的挑战

### 什么情况下会从P2跑到P3

1. P3的总监离职/被调走，从下一级优先提拔
2. 业绩非常好的人
3. 已经有管理经验的人
4. 跨部门抽调

### 架上去之后如何做好

| 关键因素 | 说明 |
|----------|------|
| **领导信任** | 蜜月期容易信任，但蜜月期过了没做出成绩，信任会慢慢消失 |
| **下属支持** | 规划再好，领导再信任，下属不支持也难以推进 |
| **深度思考** | 自己对项目有深度理解 |

### 核心：争取空间

> P3的重点重点重点就是——**争取空间**，争取项目的资源，然后把整个项目的资源用到一个最好的位置上去。

## [一] 如何给项目定位

### 项目定位的核心问题

1. 项目目前的位置在哪里？
2. 项目未来一段时间发展的大的方向是什么？

### 三种项目类型

| 类型 | 说明 |
|------|------|
| **流量型** | 为流量服务 |
| **收入型** | 为收入服务 |
| **效率型** | 要么辅助流量，要么辅助收入 |

### 如何找准项目定位

1. **列出平行的公司级项目**：看到你与这些项目之间的关联
2. **按流量和收入矩阵排列**：判断你和兄弟项目当前的定位及走向
3. **分析矩阵位置**：
   - 你的目标如果是为收入服务，重点突破收入
   - 上下游关系中找到正确的"大腿"

> 核心：分析"我在哪里？我接下来要去哪里？跟我同行的人会在哪里？"

## [二] 确立项目目标与指标

### 项目目标设定的三步法

**第一步：初步设定目标**（基于项目定位）

**第二步：对上对下沟通**
- 和领导明确目标的**必要性**
- 和团队明确目标的**可行性**

**第三步：拉平预期**（使用"目标四象限"工具）

### 目标四象限分析

| 上级\下级 | 下级清晰 | 下级不清晰 |
|-----------|----------|------------|
| **上级清晰** | **观察为主**：千万别乱搞乱动，先观察了解，以管理人和项目推进为核心 | **向下传达**：把上级目标清晰化后，多次向下传达，让下级逐步理解 |
| **上级不清晰** | **整理上报**：把下级情况整理成上级能理解的方案，定期review，为兄弟们争取空间 | **主动提出**：你先提出初步目标，搞定上级，再向下传达 |

### 产出物

基于项目定位，明确**最多三个核心目标**，每个目标底下设定可计算的指标。

| 核心目标 | 指标一 | 指标二 |
|----------|--------|--------|
| 目标1 | 计算方式 | 计算方式 |
| 目标2 | 计算方式 | 计算方式 |
| 目标3 | 计算方式 | 计算方式 |

## [三] 梳理上下游关系

### 为什么要分析上下游资源

当项目定位明确且有目标的情况下，**资源会限制你的发展**。

### 三个关键动作

| 方向 | 动作 |
|------|------|
| **向上游要资源** | 清晰说明：要什么资源、到什么程度、什么时候给、具体内容是什么 |
| **向下游提供资源** | 清晰说明：能提供什么资源、什么时间点、以什么方式提供、落实到责任人 |
| **横向协调** | 识别哪些团队与项目有竞争关系，提前协调 |

### 产出物

- 梳理上下游流向，明确项目位置
- 列出所需资源清单
- 明确资源在哪里

### 项目分析画布五大模块

```
┌──────────────────────────────────────────┐
│           以项目为中心                      │
│  ┌───────────┐                            │
│  │ 项目定位   │                            │
│  └─────┬─────┘                            │
│        │                                  │
│  ┌─────▼─────┐    ┌───────────────┐       │
│  │ 项目目标   │◄──►│ 上下游资源     │       │
│  └───────────┘    └───────────────┘       │
├──────────────────────────────────────────┤
│          以项目存活和持续为中心              │
│  ┌──────────────────┐                     │
│  │ 业务驱动模型      │                     │
│  └────────┬─────────┘                     │

│  ┌────────▼─────────┐                     │
│  │ 中长期产品规划    │                     │
│  └──────────────────┘                     │
└──────────────────────────────────────────┘
```

### 上半部分总结

| 模块 | 解决的问题 | 产出 |
|------|-----------|------|
| 项目定位 | 明确项目在矩阵中的位置和方向 | 流量/收入/效率的定位判断 |
| 项目目标 | 把不清晰的目标变得逐步清晰 | 最多3个核心目标 + 可计算指标 |
| 上下游资源 | 从资源没规划到逐步有规划 | 资源清单 |

### 核心观点

> 这三个事远远比具体操作项目中的技术问题更重要，如果这三个点做好了，项目大概不会太失败。

### 从项目到业务的思考

- 项目的达成能促进阶段性目标的实现
- 阶段性目标因考虑项目而完成
- 从项目的成败推演出业务的发展
- 让大家相信你的计划是关键

## 学习要点

1. **项目定位**是基础，决定了目标和资源方向
2. **目标设定**需要上下拉平，使用四象限分析工具
3. **上下游资源**分析决定项目能否成功推进
4. 接手项目时，**前三个模块**（定位、目标、资源）是关键

## 总结

第一周的核心是建立接手项目的系统方法：明确项目定位、设立清晰目标、梳理上下游关系。这三个模块构成了以项目为中心的框架，是P3产品经理在接手已有项目时必须掌握的基本功。
