# 第三周：从零到一（上）

## 如何进行新业务的探索

同学们好，我是不眠。这一章我们来重点讲一讲怎么样开始做新业务的探索。

### 什么情况下会面临从零到一

- 有一个老板或高管提出想法，认为非常有价值
- 会找到一个人带领新的业务线（这个人可能就是你）
- 表现好的时候，通常会被抓起来放到新业务里
- 如果突破了，就成为新项目核心leader
- 这些新项目失败率确实非常高

### 新项目成功的三要素

```
            天时（市场环境/风口）
                   │
          ┌────────┼────────┐
          │        │        │
          │  成功  │        │
          │        │        │
    地利（区域/政策） 人和（团队）
```

| 要素 | 说明 |
|------|------|
| **天时** | 市场环境、风口。风口上的项目只要不太差，应该能快速发展。但追风口挂掉概率也很大 |
| **地利** | 区域环境、政策环境、营商环境。是否能提供足够弹药 |
| **人和** | 团队是否愿和你一起往前冲。你能不能让团队看到清晰的未来 |

> 对于P3来说：**尽人事，听天命**。能从10%的成功率提升到20%，就已经非常厉害了。

### 从零到一的核心流程

```
idea（假设）→ MVP验证 → 用户验证 → 循环迭代 → PMF（产品市场匹配）
```

## [一] 假设：让Idea变得具体（上）

### 面对Idea的常见困境

- 工作中会有大量的人给你不同的idea
- 忽阴忽现、忽好忽坏
- 感觉特别有道理，但有时候感觉没啥卵用

### 四个论证层次

| 层次 | 核心问题 |
|------|----------|
| **假设** | 假设这个idea是成立的，用户和场景是什么？ |
| **可行性** | 要实现最佳用户体验，需要哪几个关键因素？这些因素可执行吗？ |
| **可能性** | 投入多少资源？能得到多少回报？商业价值是什么？ |
| **市场分析** | 行业和竞品的状况是什么样？ |

### Idea分析画布

```
┌─────────────────────────────────────────────────┐
│                  IDEA                            │
├─────────────────────────────────────────────────┤
│  一、假设：用户与场景                             │
│  · 什么样的用户在什么情况下解决什么问题           │
│  · 核心用户和发烧友的特征                         │
│  · 极致的用户体验标准（一句话描述）               │
├─────────────────────────────────────────────────┤
│  二、可行性分析：关键因素                         │
│  · 达到最佳体验需要哪些关键因素（最多3个）        │
│  · 每个关键因素的实现条件（可执行、有数值）       │
├─────────────────────────────────────────────────┤
│  三、可能性分析：商业价值                         │
│  · 需求刚需程度、使用频率                         │
│  · 产品服务模式、规模化情况                       │
│  · 商业模式、收入方式、关键驱动因素               │
├─────────────────────────────────────────────────┤
│  四、市场分析：行业与竞品                         │
│  · 竞品数量、竞争热度、技术水平                   │
│  · 天时（市场规模）、地利（区域环境）、人和（用户） │
│  · 典型竞品分析（1-2款），找出秒杀优势             │
└─────────────────────────────────────────────────┘
```

### 关键原则

> 不要去假设这个idea是不是靠谱的。每个idea都值得被尊重。我们先假设它是靠谱的，然后去分析它怎么变得可执行。

### 用户和场景假设方法

| 要素 | 说明 |
|------|------|
| **核心用户** | 什么样的用户在什么情况下需要解决什么问题 |
| **发烧友特征** | 你的脑残粉长什么样？行为特征？标签？ |
| **极致体验** | 一句话描述用户用了之后感觉很爽的那个东西（slogan） |

### 案例：花点时间

创始人朱月怡穷尽了所有送花场景（男人给女人送花、节日送花、看望人送花等），但选择了一个最不可能的场景——**女人花钱给自己送花**。核心用户是在办公室工作压力大、希望用花点缀生活的女性。极致体验是：**每月预定，每周一花**。

## [一] 假设：让Idea变得具体（下）

### 可行性分析

#### 如何找到关键因素

| 分析方法 | 说明 | 示例 |
|----------|------|------|
| **按构成因素** | 要达到理想状态，组成因素是什么 | 建教堂：有钱+有图纸 |
| **按时间顺序** | 先做什么后做什么 | 先有图纸再找钱 |
| **按资源顺序** | 先有A再有B，有AB得C | 先有数据再有算法 |
| **按挑战顺序** | 从难到易或从易到难 | 先搞流量再提转化 |

#### 关键因素的要求

1. **可落地可执行**：有明确路径可以实现
2. **有数值**：至少1-2个关键因素能落实到数值上
3. **可量化可衡量**：遵循SMART原则

### 案例：闪送的关键因素分析

**极致体验**：全城一小时专人送达

| 关键因素 | 实现条件 |
|----------|----------|
| 足够多符合要求的快递员 | 源源不断招人 + 培训上岗 |
| 足够的订单分发机制 | 区域位置与订单比例计算，每个格子匹配订单和快递员覆盖范围 |
| 足够多的订单 | 订单转化力 + 流量 |

### 可能性分析

#### 规模与边界成本分析

| 模式 | 策略 |
|------|------|
| **不规模不经济** | 先不考虑大量用户，把产品价值拉到最大，以价值换价格 |
| **规模经济** | 通过提升效率、商业产品变现走向规模经济 |

#### 商业价值判断矩阵

| 需求刚需 | 使用频率 | 策略 |
|----------|----------|------|
| 高 | 低 | 尽早商业化 |
| 低 | 高 | 先搞用户后搞收入 |
| 高 | 高 | 理想状态，但较少见 |
| 低 | 低 | 需重新评估 |

### 市场分析

#### 天时地利人和

| 要素 | 内容 |
|------|------|
| **天时** | 市场规模、发展速度、竞争热度、技术水平 |
| **地利** | 区域环境、政策环境、营商环境 |
| **人和** | 用户数量、用户素质、用户增速 |

> 三者占其二基本可做，三者占其一也可做但会费劲一些。

#### 竞品分析要点

- 选择龙头企业或典型特点与你有完全相似的产品
- 分析核心业务逻辑和外在表现（增长数据、用户评价、运营动作、产品结构）
- 分析1-2款竞品，明确你与竞品的秒杀优势

## [二] 产品MVP设计该怎么做（上）

### MVP的两个阶段

```
0 → 0.5：验证产品是否有价值   0.5 → 1：让用户能够正常使用
```

### 从0到0.5：验证产品价值的方法

| 方法 | 说明 | 示例 |
|------|------|------|
| **仿真Demo** | 看起来是真的，但实际上是假的 | 用Sketch、墨刀做以假乱真的原型 |
| **产品介绍视频** | 做一个视频发给种子用户看 | Dropbox上线前的宣传视频 |
| **文档** | 做真实有价值的文档吸引用户 | 旅游攻略PDF，看下载量和加微信量 |
| **预售** | 有图文介绍就开始卖 | 众筹、课程预售 |
| **着陆页** | 收集用户信息，加个人微信或群 | Robinhood的排队页面 |

### 从0.5到1：MVP设计三要素

1. **明确用户需求**：聚焦用户故事，解决1-2个明确需求
2. **着陆页/宣传页设计**：测试转化路径，收集种子用户
3. **原型设计（Demo）**：关键流程 + 关键页面原型

### 着陆页设计要点

- 明确受众和出现场景
- 设计多个版本的物料
- 用**真实文案**，让用户感觉是真的
- **情感驱动**，扎心才能触动
- 埋下转化路径（填表单、点赞、付费）
- 做好数据统计
- 上线测试时吸引**陌生用户**，不是好友或粉丝

> 好的转化都是测出来的，不是拍脑袋拍出来的。

### Demo设计要点

- **流程最关键**：用户进入的场景 → 关键动作 → 不超过5步
- **原型做逼真**：真到让用户觉得是真的，点了发现"上当了"
- 先有流程后有原型，不断迭代优化

## [二] 产品MVP设计该怎么做（下）

### MVP设计的三大步骤

| 步骤 | 内容 |
|------|------|
| **明确用户需求** | 用户故事分解：用户→场景→问题→当前解决方案→我们的方案 |
| **着陆页/宣传页** | 测试转化路径、收集种子用户、验证价值主张 |
| **原型设计** | 关键流程（不超过5步）+ 关键页面（不超过3个）+ 真实文案 |

### 用户故事分解示例

以看电影为例：

```
呼朋唤友 → 找片子 → 决定买票 → 获得反馈
```

每个环节都有具体问题，早期切入点是**帮助找片子**这一环节。

### 流程设计原则

| 原则 | 说明 |
|------|------|
| **最小** | 突出关键点，去除不必要功能（如复杂注册登录用第三方授权） |
| **可用** | 基本流程能正常使用，不能出现明显断档 |
| **使用第三方工具** | 减少开发量，提升速度 |

### 案例：Uber的MVP

Uber最早是通过电话派单。招了第一个程序员后，第一个任务是做**能生成账号的信用卡注册流程**——听起来很奇葩，但用了几个月才完成。在此之前整个项目已经跑了好几个月。

### B端产品的MVP方式

| 方式 | 说明 |
|------|------|
| **预告** | 产品上线前预告，征集体验用户 |
| **特权** | 申请成为种子用户可获得特权 |
| **精准投放** | 最小词的精准投放，如"北京最快的快递" |
| **最小实施** | 找一个目标团队打样 |

### 案例：三节课使用企趣

企趣是员工积分系统。最早没有大规模获客，而是先找到"得到"团队进行实验，实验成功后再推广到更多中小团队。

## [三] 从MVP到PMF

### PMF（Product Market Fit）是什么

由Marc Andreessen在2007年提出：**产品和市场所属阶段要匹配**。匹配则进入增长阶段，不匹配则增长不明显。

### PMF不匹配的两种情况

| 类型 | 说明 | 示例 |
|------|------|------|
| **产品脱离市场** | 产品太先进，市场没准备好 | Color、Mirror Cat、Fanfou |
| **市场抛弃产品** | 产品不错但出现了全新市场，未抓住 | MSN、柯达、人人网 |

### 找到PMF的三种方式

| 方式 | 说明 | 示例 |
|------|------|------|
| **提供更好的体验** | 极简、快速、更好用的产品 | Slack、美图秀秀 |
| **抓住细分市场** | 从垂直细分市场切入 | Uber（打不到车）、P2P（小额贷款） |
| **全新的市场** | 定义全新的产品形式 | 微博@、探探左滑右滑 |

### PMF的判断标准

| 类别 | 指标 |
|------|------|
| **C端大众产品** | · 30%次日留存<br>· 新增DAU超过1000（中国）<br>· 平均每周使用超过3天 |
| **B端付费产品** | · 5%付费转化率<br>· LTV/CAC > 3<br>· 月流失率 < 2% |

### MVP与PMF的关系

```
IDEA → MVP → PMF → 增长
  ↑      ↓
  └── 循环 ──┘
```

MVP和PMF是不断提出假设、在市场验证、做快速迭代、找到核心增长点的过程。

> 每一个成功的产品背后，都有个很艰难的开始。这个开始就是MVP。

### 案例：ClassPass

最早做健身课程搜索引擎，不温不火。后提供免费体验包，发现用户会用不同邮箱反复领取。团队没堵漏洞，反而意识到产品有价值。最终做了**80美元/月任选4-6个课程**的付费订阅，找到真正PMF。

### 案例：Zappos（霞服饰）

最早的MVP不是进货，而是把亚马逊上卖鞋的详情页重新设计，推给身边用户。用户下单后再去亚马逊下单发货，验证鞋的描述是否吸引用户。验证成功后开始进货、建仓库。

### 案例：VIPKID

最早的"版本"是微信群上课——找身边人、找几个老师，在微信群完成教学。后来用成熟的学习系统改了logo和形象就放上去。验证效果不错后才花更多精力打磨产品。

### 案例：多抓鱼

最早的MVP是**微信群+Excel表**。把豆瓣里愿意卖书买书的人放在群里，有人卖书告诉小助手更新到Excel表，有人买书在Excel表里挑。

## [案例] Idea分析画布

### 案例：亲子游私人定制

**IDEA**：一站式亲子游私人定制（从线路策划、机票酒店预订到当地地接）

#### 假设分析

| 要素 | 内容 |
|------|------|
| **核心用户** | 有钱没时间、要长途旅行、不想做攻略的有孩家庭 |
| **发烧友特征** | 航空公司金卡、国际学校妈妈 |
| **极致体验** | 专业的路线推荐 + 靠谱的目的地服务 |

#### 可行性分析——关键因素

| 关键因素 | 实现条件 |
|----------|----------|
| 专业的服务设计师 | 培训到位 + 系统支持 |
| 丰富的目的地资源 | 目的地拓展 + 资源熟悉 |
| 足够的地接团队 | 收入保障 + 培训 |

#### 重新调整：去掉地接团队变量

- 去掉"靠谱的地接团队"后，模式变轻
- 专注**专业路线推荐**，目的地资源从"丰富"变为"精细"
- 付费方式变为B端：提供路线推荐，用户到第三方（如携程）预订，从中分成
- 竞品变成"世界邦"等路线推荐产品

## 学习要点

1. **Idea分析画布**不是填空工具，而是不断写、改、调整的思考过程
2. MVP从**0到0.5**验证价值，从**0.5到1**保证可用
3. PMF不是找出来的，是**试出来的**
4. MVP阶段要敢于用第三方工具，减少开发量
5. 从零到一的核心是：**大胆假设、小心求证**，用循环迭代找到产品市场匹配

## 总结

第三周进入"从零到一"的上半部分，核心是**如何把一个idea变得具体并可执行**。通过Idea分析画布的四个层次（假设、可行性、可能性、市场分析）进行系统思考，然后通过MVP设计验证产品价值，最终找到PMF。这是一个循环迭代的过程，每个成功的产品背后都有艰难的MVP阶段。
