# 第二周：接手项目（下）

## 从项目到规划

同学们好，我是傅绵。接下来我们重点解决从接手项目到能够为产品做中长期规划的事情。

### 核心逻辑

阶段性的目标需要用项目来落地，在不同时间阶段有不同的项目：

```
探索期 → 目标：上线（一个大项目＋若干迭代）
成长期 → 目标：快速增长（多个阶段性目标：用户增长、运营需求、产品迭代）
成熟期 → 目标：更复杂（大量目标）
```

### 项目的成败与业务发展

- 项目不一定百分百成功，多数情况下不成功的比例大于成功
- 从项目成败推演业务发展是必须思考的
- 让大家**相信**你的计划，是项目持续存活的关键

## [四] 建立业务驱动模型

### 为什么要建立业务驱动模型

- 让团队相信过程中有节奏地进行
- 让团队能够持续存活下去
- 把资源**All in**到一个点上，将其拉长成你的长板

### 如何分析业务驱动

#### 第一步：确认单边/双边/多边市场

| 类型 | 核心关注点 | 分析方法 |
|------|-----------|----------|
| **单边市场** | 用户体验 | 鱼骨图拆解到二级影响因素 |
| **双边市场** | 现阶段稀缺资源 | 分别分析供给端和消费端 |
| **多边市场** | 混合分析 | 供应端用双边分析，消费端用用户体验分析 |

#### 第二步：找到关键因素（最多三项）

| 优先级 | 因素 | 配套资源 |
|--------|------|----------|
| 第一重要 | 核心因素 | 配套资源 |
| 第二重要 | 次核心因素 | 配套资源 |
| 第三重要 | 辅助因素 | 配套资源 |

#### 第三步：All in发力

- 通过分析找到业务快速发展的引擎
- All in的态度要决心明显
- 让领导和团队感受到你的决心和信心

### 单边市场分析方法

1. 用鱼骨图拆解核心体验的关键因素
2. 遵循两个原则：先A后B，有明显收益
3. 列出所有因素，找到大因素和小因素
4. All in在前几个上

### 双边市场分析方法

1. 分析供给端和消费端的**阶段性稀缺程度**
2. 找到重点发力点
3. 基于发力点做效率提升

## [五] 制定中长期产品规划

### 为什么要做中长期规划

- 让整个团队在公司能看到更大的未来、更远的未来
- 你带的项目有机会成为一个团队
- 让团队能够持续存活
- 让研发同学知道往前走还有很多计划等着他，有助于稳定团队

> 当你有排出的产品计划，你不仅仅是临时项目，更是站在产品角度、全局角度思考问题

### 四个思考维度

| 维度 | 说明 |
|------|------|
| **数量的变化** | 用户数量、商户数量、数据量等的变化 |
| **类型的变化** | 城市拓展、学科内容、用户类型等的变化 |
| **产品发展阶段的变化** | 进入快速增长期时，需要大量的运营规划 |
| **产品走向的变化** | 产品从流量型到收入型的战略调整 |

### 规划方法

1. 根据四个维度分别列出面临挑战
2. 列出解决方向
3. 列出所需资源（前台、后台等）
4. 形成根据业务发展变化、对未来有前瞻性思考的中长期规划

### 关键原则

- 中长期规划是**可实现的**，不是堆功能模块
- 考虑环境变化的中长期规划更有效、更靠谱
- 要应对变化的准备，在团队内外形成共振

## [案例] 中长期产品规划

### 案例一：赶集网生活服务

**背景**：赶集网的生活服务（搬家、保洁、月嫂等100多个大类小类，300多个城市），是一个收入型产品，但流量一直不足。

**关键判断**：
- 产品需要获得更多流量，走向更好的收入来源
- 投放带来新用户，用户和商户数量都会变化

**半年版本规划**：

| 时间 | 项目 | 目标 |
|------|------|------|
| 11月（蓄水期） | 新用户分层 + 商业流量集中 + 动态盘库存 | 为春节后2月高峰做准备 |
| 1月 | 流量增长项目（驱动商家发信息、装修频道上线） | 增加泛流量，在百度获得更好流量 |
| 2-3月 | 小城市类别合并 + 补充帖内容 | 增加内容数量级 |
| 3月底 | 补充帖抓取自动入库 | 抓取竞争对手帖子，补充不热门信息 |
| 4月 | 新手引导 + 快速模板帮助商家完成第一个店铺 | 商家分层运营，带动信息量提升 |
| 5-6月 | 优质商家评估工具（评分模型、内容发布、重复帖子） | 提升质量 |

**结果**：除6月外基本按时完成。当时团队只有4-5个产品经理，10多个研发。

### 案例二：学校APP（学而思培优）

**背景**：从让家长提交作业、看答案的APP，改造为以业务和服务为中心的报名、缴费、查班产品。

**规划历程**：

| 时间 | 项目 | 关键点 |
|------|------|--------|
| 11月 | 跨班报名（跨报） | 一炮而红，服务器不挂了，用户体验提升 |
| 12月 | 在线缴费 | 干掉前台排队，但需重构支付后台（对接银联、支付宝） |
| 3-5月 | 业务系统重构 | 支持二三线小城市，满足5-6月报名高峰 |
| 5-7月 | 应用上线 + 城市拓展 | 拓展5个城市，全面支持全业务链条 |
| 8月后 | 数据面板（分析后台） | 帮助分校校长查看报名情况 |

**关键教训**：
- 后台比前端更重要，大家都不重视后台，但后台数据乱会拖累前端
- 规划要能让领导、下属都相信，否则人才会被调走

### 上半部分：定义问题

| 模块 | 产出 |
|------|------|
| 项目定位 | 明确流量/收入/效率定位 |
| 项目目标 | 最多3个目标+可计算指标，上下拉平 |
| 上下游资源 | 资源清单，明确谁依赖谁 |

### 下半部分：解决问题

| 模块 | 核心 | 方法 |
|------|------|------|
| 业务驱动模型 | All in重点，找到业务引擎 | 单边/双边/多边分析 |
| 中长期规划 | 让大家相信未来 | 四个维度思考 |

### P3核心能力总结

> 独立负责并做好公司级项目的能力——不仅仅是做功能、做版本，而是站在公司级项目去拆解，理解整个业务的运行和发展。

---

## 学习要点

1. **业务驱动模型**帮你在短期找到发力点，All in资源到一个核心方向
2. **中长期规划**让团队看到未来，稳定军心
3. 规划的产出基于**数量变化、类型变化、发展阶段、产品走向**四个维度
4. 好的规划不是堆功能模块，而是考虑环境变化的、可实现的路线图

## 总结

第二周是接手项目的下半部分，重点是"解决问题"——建立业务驱动模型和制定中长期产品规划。这两个模块确保了项目不仅能做成功，还能持续存活和发展。当你能做好这两件事，就能从"做功能"升级到"做业务"，真正承担起P3产品经理的职责。
