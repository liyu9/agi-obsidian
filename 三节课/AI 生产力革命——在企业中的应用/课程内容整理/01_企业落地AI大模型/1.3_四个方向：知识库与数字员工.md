# 1.3 四个方向：知识库与数字员工

## 一、四个方向总体架构

```
┌─────────────────────────────────────┐
│          应用层（应用层）            │
│    智能体  |  数字员工  |  数字人    │
├─────────────────────────────────────┤
│          工作流（中间层）            │
│   基于知识库和大模型的企业内部工作流  │
├─────────────────────────────────────┤
│          基建层（底层）              │
│   企业知识库  |  数据库  |  私有/公有云 │
└─────────────────────────────────────┘
```

### 四个方向说明

| 方向 | 定位 | 说明 |
|------|------|------|
| **知识库** | 基建层 | 企业数据资产建设 |
| **数字员工** | 应用层 | 代替人工执行任务 |
| **智能体** | 应用层 | 自动化代理执行 |
| **私有化部署** | 基建层 | 数据安全和自主控制 |

## 二、方向一：知识库建设

### 1. 企业应关注的核心：数据

根据数据、算力、算法721原则：
- **算法**：大部分企业不需要自己开发，使用开源或商业模型即可
- **算力**：可以使用云端算力或私有化算力
- **数据**：企业应重点投入，占整个AI应用的80%

### 2. 数据建设流程

```
数据清理/清洗 → 数据标注 → 数据训练 → 数据增强
```

### 3. 数据应用场景

企业各业务板块数据不断进行清洗、标注、训练、增强：
- 产品端
- 研发端
- 服务端
- 支撑部门

### 4. 打破数据孤岛

**问题**：企业有很多信息（合同、产品介绍、运维流程等），这些信息形成数据孤岛

**解决方案**：知识图谱

**实现方式**：
- 将产品等不同维度与交付等环节建立关联
- 形成知识图谱
- 搭建复杂的知识库
- 支撑业务流程中的不同环节

### 5. 知识库建设三阶段

| 阶段 | 特征 | 说明 |
|------|------|------|
| **第一阶段** | 知识数字化 | 将各环节信息转换成数字数据，录入文档 |
| **第二阶段** | 知识集中化 | 搭建知识共享平台，集中管理重要资产 |
| **第三阶段** | 知识管理平台 | 智能问答、检索、推荐、训练，实现知识生产力转化 |

### 6. 知识库的终极目标

```
信息（存储） → 数据（查取） → 知识库（学习训练） → AI应用（推理规划） → 可执行Agent
```

### 7. 知识库建设工具推荐

#### 个人知识库：爱记录（腾讯出品）

**功能特点**：
- 笔记功能
- 共享知识库
- 可分享给好友
- 知识库广场
- 整合公众号信息和数据源

#### 企业知识库：乐享（腾讯出品）

**功能模块**：

| 模块 | 功能 |
|------|------|
| **知识生产** | 创作、检测、翻译 |
| **知识组织** | 资产编号、检索、文件架构、知识图谱 |
| **知识分发** | 订阅、权限、知识推荐、知识查找 |
| **反馈完善** | 巡查机制、有效识别 |
| **归档管理** | 归档和下架 |

**接入方式**：
- API接入
- 企业微信接入
- 移动端使用

## 三、方向二：数字员工

### 1. 数字员工定义

数字员工是基于网页数据和本地数据，经过训练后形成的机器人。

### 2. 数字员工架构

```
数据输入（网页数据 + 本地数据）
    ↓
训练
    ↓
数字员工机器人
    ↓
应用场景（企业微信、微信群、公众号、API）
```

### 3. 数字员工核心能力

- 自主学习
- 物料生产
- 角色扮演
- 反馈机制

### 4. 数字员工应用场景

#### 问答场景
- 智能问答
- 图片生产
- 内容查询

#### 客户服务
- 7×24小时服务
- 自动回复

#### 内部协作
- 群的更新和维护
- 信息同步

## 四、学习要点

> - 知识库是基建：数据投入占AI应用的80%，是企业的核心资产
> - 知识库三阶段：数字化 → 集中化 → 智能化
> - 数字员工是应用：基于训练后的机器人，可多场景部署
> - 四个方向协同：底层是知识库，中间是工作流，上层是应用
