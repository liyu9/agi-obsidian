### 一、大模型工具选择

#### 1.1 主流大模型对比

| 大模型 | 类型 | 特点 | 适用场景 |
|--------|------|------|----------|
| **ChatGPT-4** | 海外模型 | 地表最强，中文理解能力强 | 高复杂度任务、代码生成 |

## 第二节 如何高效提问

### 一、大模型底层原理

#### 1.1 AI技术债层级结构

```
┌─────────────────────────────────────┐
│         第5层：应用程序层           │
│   WPSAI、Kimi等具体应用工具        │
├─────────────────────────────────────┤
│         第4层：API封装层            │
│   通过接口接入大模型                 │
├─────────────────────────────────────┤
│         第3层：超本地化模型          │
│   企业内部数据部署                   │
├─────────────────────────────────────┤
│         第2层：特定AI模型           │
│   垂直领域专业模型                  │
├─────────────────────────────────────┤
│         第1层：通用大模型            │
│   GPT、GLM等基础模型                │
└─────────────────────────────────────┘
```

#### 1.2 大模型工作流程

```
知识库文本 → 分割成块 → 嵌入模型转换 → 向量数据库存储
                                              ↓
用户问题 → 嵌入转换 → 向量相似度搜索 → 上下文关联 → 大模型生成回答
```

**关键点**：大模型通过向量检索找到相关内容，结合上下文生成回答。提示词质量直接影响检索和回答效果。

#### 1.3 LLM进化路径

| 框架类型 | 特点 | 代表 |
|----------|------|------|
| Encoder-Only | 编码器直接输出，无解码 | BERT |
| Encoder-Decoder | 编码+解码 | T5 |
| **Decoder-Only** | 生成式，擅长连贯文本 | **GPT系列** |

当前主流模型多采用Decoder-Only框架。

### 三、高效提示词框架

#### 3.1 提示词三板斧（基础框架）

**Somebody to do Something**

| 要素 | 含义 | 示例 |
|------|------|------|
| **Somebody** | 角色设定 | "你是资深产品经理" |
| **to do** | 任务目标 | "请写需求文档" |
| **Something** | 场景描述 | "正在开发电商拼团功能" |

**错误示例**：
```
问：我帅吗？
答：作为AI，我无法直接评价你的智力水平...（废话）
```

**正确示例**：
```
问：我是刚毕业一年的产品经理，喜欢旅游健身打羽毛球。
如果你是我的前辈，请以前辈口吻回答：我帅吗？
答：作为前辈，我观察到...（更贴合语境的回答）
```

#### 3.2 COSTAR框架（进阶框架）

| 要素 | 含义 | 示例 |
|------|------|------|
| **C** Context | 背景信息 | "我是一名资深产品经理..." |
| **O** Objective | 任务目标 | "请写一份需求文档" |
| **S** Style | 写作风格 | "资深产品经理风格" |
| **T** Tone | 语气 | "专业、正式" |
| **A** Audience | 受众 | "开发团队" |
| **R** Response | 响应格式 | "产品需求文档格式" |

**进阶提示词示例**：
```
【背景】
我是一名资深产品经理，目前正在开发电商产品的拼团功能。
拼团业务对平台用户增长至关重要。

【目标】
请写一份拼团功能的需求文档，让研发团队理解背景需求，
同步开发周期，重点关注库存锁单等业务细节。

【风格】
以资深产品经理的写作风格

【语气】
专业

【受众】
开发团队（包括前端、后端、测试工程师）

【响应格式】
产品需求文档形式
```

#### 3.3 分割符使用技巧

**分割符作用**：帮助大模型识别提示词的不同部分

**使用原则**：
- 分割符要足够独特
- 避免普通标点符号
- 复杂任务中使用效果更明显

### 四、实战案例

#### 4.1 拼团需求文档生成

**对比效果**：

| 大模型 | 生成速度 | 内容深度 | 库存细节 |
|--------|----------|----------|----------|
| GPT-4 | 快 | 包含分布式锁等技术细节 | 自动补充 |
