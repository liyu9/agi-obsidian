大家好，欢迎来到第三章AI大模型产品研发流程与能力要求。从这节课开始进入课程的第二篇——产品篇。

## 第一节 AI大模型对产研的挑战

### 变化本质：新技术导入的类比——流水线

当人类刚刚掌握流水线方法时，不只是有了一条线，而是一整套的体系和组织方式：线的速度、工位划分、标准化输出、供应链体系等。AI大模型同样如此——不只是个新技术，它会改变工作方式和组织管理模式。

### 软件研发模式的演进

```
个人英雄主义 → 瀑布模型 → 迭代开发 → 敏捷开发 → AI大模型时代
    ↓              ↓          ↓          ↓             ↓
  靠个人能力     确定性     消解复杂性   应对不确定性   新技术+智能系统
```

### 不同研发模式解决的核心问题

| 模式 | 解决的问题 | 核心特点 |
|------|-----------|---------|
| 瀑布模型 | 确定性 | 需求确定→设计确定→开发确定→测试确定 |
| 迭代开发 | 复杂性 | 拆成若干迭代，消解复杂性 |
| 敏捷开发 | 不确定性 | 强调人和人协同，快速迭代 |
| AI大模型时代 | 新技术+智能系统 | 技术成熟度低+产出结果不确定性 |

### AI大模型作为新技术的挑战

1. **新技术特性**：技术成熟度低、确定性低、支撑工具和实践少、资源投入难预测
2. **智能系统特性**：
   - 数据驱动和算法性质 → 有学习成本和研究成本
   - 对数据清洗有很高的依赖
   - 产出结果不好预期（多次迭代可能前好后差）
   - 部署复杂度较高

### AI大模型对各研发阶段的影响

| 研发阶段 | 传统模式 | AI时代新要求 |
|---------|---------|-------------|
| 规划 | 业务视角+产品视角 | 增加技术视角——做技术前瞻和展望 |
| 需求分析 | 洞察需求、分析场景 | 框架不变，但角色可能被解构甚至消失 |
| 产品设计 | 流程+功能+交互 | 增加AI能力融合，引入大模型能力 |
| 研发 | 功能/流程/界面研发 | 协同模型研发，协调两种不同研发模式 |
| 交付运营 | 让客户会用能用 | 设计匹配AI特性的交付流程、运营指标和策略 |

## 第二节 AI大模型产品研发流程

### 适配AI大模型的产品研发流程

```
传统流程：规划 → 需求 → 设计 → 研发 → 交付 → 运营 → 迭代
                                              ↓
AI时代新增：技术展望（在规划阶段）
                                              ↓
   流程内容变化：需求分析角色重构 → 设计融合AI能力 → 研发协同模型+工程
   → 交付关注组织变化 → 运营关注模型反馈 → 迭代数据+模型驱动
```

### 新增环节：技术展望

在产品规划过程中，除了围绕业务、产品、规划协同的工作之外，还需要：
- 做技术的展望和预言
- 知道落地过程中有哪些能力可用
- 哪些能力成熟度不够，可以关注但暂时用不上

### 需求分析的关键变化

**角色可能被解构甚至消失**。例如：
- 客服提需求要提升人效 → 智能客服直接替代客服，人效提升了因为没人了
- 设计师要被赋能降本增效 → 智能图片生成减掉90%的设计师
- 运营要求提升投放效能 → AI+自动化后只需保留一个运营

### 产品迭代的三重驱动力

| 驱动力 | 描述 | 例子 |
|-------|------|------|
| 场景扩展 | 原来不能做的场景现在可以做了 | 智能营销原来只能做管理，现在能做内容生产 |
| 模型能力提升 | 功能不变但模型能力有提升 | 引入RAG或微调，理解和回复更准确 |
| 数据积累 | 积累更多优质业务数据推动模型优化 | 智能驾驶里程越多，能力越好 |

## 第三节 面向AI大模型产品的产品经理能力要求

### AI时代产品经理能力分层

| 层级 | 核心要求 | 具体能力 |
|------|---------|---------|
| 初级 | 工具使用+AI应用 | 熟练使用AI工具提升个人效能，理解模型特性，将模型应用在工作中 |
| 中级 | 流程再造+架构设计+POC | 通过AI能力整合推动流程优化和再造，做架构设计和升级，做概念验证（POC） |
| 高级/总监 | 技术趋势把握+组织变革 | 把握技术发展趋势，做出正确决策，推动组织变革，打造AI氛围 |

### 中级产品经理——创新落地的核心群体

- 最懂业务也最懂产品
- 最能对新技术的成熟度做判断
- 凡是涉及产品创新和概念验证（POC）的工作，由这个层级的同学来做

> **注意**：这些能力不是原有能力之外的"打补丁"，而是要融合在自己原有的技能当中，尝试用AI大模型的方式去思考和工作。

### 关键行动建议
- 对于**还没有构建AI氛围的组织**：高级产品人才需要站出来，推动新技术在各个领域和职能之间的认知
- 让产品研发团队有空间、有资源去推动创新，拿到更好的结果
