## 第二节 智能视角的需求分析

### JTBD（Jobs to Be Done）方法论

核心思想：**用户不是因为喜欢我们的产品而使用产品，用户是为了完成特定的工作、拿到特定的结果才会使用产品。** 产品是可以取代的，只是取代成本高低而已，而用户要完成的那个任务、那个结果才是永恒的。

### 传统的JTBD分析框架

| 要素 | C端视角 | B端视角 |
|------|---------|---------|
| 任务类型 | 功能任务、支持任务、情感任务、社会任务 | 功能性任务、执行层面、经营层面、管理层面 |
| 核心分析要素 | 角色、价值、约束、行动、变化、成本 | 同上 |

### AI大模型时代JTBD的变化

**不变**：整体结构不变，依然要考虑角色、价值、约束、行动、变化和成本

**变**：**角色可能被解构甚至消失**

传统数字化软件：提供更好的工具，让人的流程更高效 → 45个人变成43个人

AI大模型时代：产品一上线，**岗位本身被重构**。例如客服质检团队：
- 原来50人听录音质检
- AI上线后：质检工作95%由AI完成，剩下3-5人做目标制定、数据看板和优化

**需求分析的新增维度**：

```
角色拆解 → 哪些由人完成，哪些由AI完成？
                                    ↓
能力成熟度评估 → 该任务用的AI模型成熟度如何？
                                    ↓
时间策略 → 短期用人/人机协同 → 长期完全自主智能体？
```

### 案例：客服面对产品活动信息咨询

**场景分析**：客户询问某产品是否参加促销活动、享受什么权益。

**角色拆解**：
- 接待客户进线 → AI能否完成？可以
- 检索信息 → AI能否完成？可以（RAG）
- 组织反馈 → AI能否完成？可以
- 后续确认 → AI能否完成？可以

**能力评估**：
- 正常对话没问题，检索准确率约98-99%
- 1-2%的不准确 → 接受AI犯错，还是人机协同？

**扩展任务分析**（经营管理层面）：
- 功能性：检索和回复
- 经营层面：在服务中做销售，提升转化
- 管理层面：沉淀信息，优化知识库质量

### AI时代需求分析的结论

1. 依然围绕场景展开分析
2. 场景里的角色可能会被拆解甚至消失
3. 价值不只是降本增效，还能创造新价值，解决原来解决不了的顽疾（如客服不愿意做销售）
4. 必须面对技术和组织上的成熟度约束

## 第三节 智能化的流程

### 传统流程设计 vs AI时代流程设计

| 维度 | 传统流程 | AI时代流程 |
|------|---------|-----------|
| 驱动方式 | 强规则驱动 | 规则+模型（带有不确定性） |
| 状态 | 静态（图定后不变） | 动态（节点能力可持续提升） |
| 数据角色 | 数据是副产品 | 数据直接推动模型优化 |
| 设计心智 | 按机器设计 | **按人设计（把AI当成人）** |

### AI流程设计的核心原则

> **把AI当成人一样来设计，当成一个会犯错的正常人一样来设计。**

因为AI的输出存在不确定性（内容上总有可能和预期不一样），所以需要像人对人一样加审核、加判断、加验收。

### 案例：智能客服创建工单

**传统流程**：
```
客户需求 → 客服理解需求 → 判断意图和类型 → 填写标准工单 → 提交处理
```

**AI时代流程**：
```
客户需求 → AI直接解析需求（大部分成功）→ 结构化提交工单
                                  ↓（解析失败）
                            人工兜底处理 → 积累Bad Case → 优化AI表现
```

**流程进化的关键指标**：
- 人工兜底比例：个位数% → 2% → 1% → 千分之几
- 最终人工流程可能只是一个"用来做优化、做运营"的流程，不是业务主流程

### 总结：AI时代流程设计核心
1. 框架没变：目标分析 → 现状分析 → 流程设计 → 验证 → 开发测试 → 运营
2. 基础流程保障**底线产出**，AI能力大幅提升**上限**
3. 数据推动流程的持续优化
4. 全面评估风险、成熟度，明确异常处理方式

## 第四节 AI大模型变革交互

### 交互评估的三要素

| 要素 | 含义 | 最优例子 |
|------|------|---------|
| 效率 | 传递信息的效率 | 眼神——一个眼神传递几百个字的信息 |
| 体验 | 视觉感受、可用性、易用性 | iPhone的Home键设计 |
| 学习成本 | 用户上手难度 | 风格一致的交互降低学习门槛 |

### AI大模型带来的三大交互进化

#### 进化一：多模态交互

从单一交互方式（纯文本表单/纯语音）到综合使用多种形式与AI沟通。

**案例：银行服务机器人**
```
传统：触摸屏点来点去
AI时代：
1. 摄像头识别用户意图 → 主动询问
2. 语音对话（支持方言如粤语、四川话）
3. 屏幕动态呈现沟通过程中需要的信息
4. 根据对话语境自动切换业务选项
```

**案例：工业维修（智能眼镜）**
- 戴上智能眼镜开始检修，系统自动定位设备和工位
- 全程记录操作步骤，确保合规
- 取代传统的理论检、纸质记录、拍照

#### 进化二：对话式用户界面（CUI）

与图形用户界面（GUI）不同，CUI支持：
- 自然语言对话
- 多轮次交互（不限于输入输出一次）
- 上下文理解和情感感知
- 主动交互

**案例：Cursor（AI驱动的IDE）**
```
传统IDE：在代码区写代码 → 编译 → 看错误信息 → 定位修改 → 重新编译
Cursor的CUI交互：在对话区描述需求 → AI直接生成代码
                 抛出错信息 → 问AI哪里有问题 → AI直接定位修改
                 工程师角色从"写代码"变为"管理AI编程"
```

#### 进化三：动态交互（千人千面+场景感知）

| 阶段 | 特点 | 例子 |
|------|------|------|
| 静态交互 | 长期不变，人人相同 | 计算器App |
| 多视图 | 不同角色不同视图 | Boss直聘（求职者/招聘者） |
| 千人千面 | 内容不同但框架固定 | 电商推荐 |
| **AI动态交互** | **感知场景，动态调整交互组件** | OpenCanvas / 智能客服 |

**案例：OpenCanvas**
- 在对话框编辑文字 → 右下角自动出现文本编辑工具（受众、语言、翻译）
- 在对话框写代码 → 右下角自动变为编程工具（语言、注释管理）

**案例：智能客服的终局交互**
```
收到包裹损坏 → 发语音描述
→ 界面自动出现"拍照"按钮（判断需要拍照）
→ AR引导拍摄角度
→ AI识别包裹和订单
→ 自动查询售后政策（618大促政策）
→ 直接给出处理方案按钮（一句话解决问题，无需长篇文字对话）
```

### 交互设计总结

1. 交互目的没有变化——追求可用性、易用性、效率和低学习门槛
2. 交互方式会有翻天覆地的变化
3. 未来的交互会非常紧密地贴合用户场景和上下文，让整个过程变得异常顺畅
4. 交互变化会进一步影响工作流程和工作模式
