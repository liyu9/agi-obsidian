# 第五章 数据治理与资源协调

## 学习要点

- 理解数据在AI中的核心地位——数据比算法更重要
- 掌握"做菜比喻"的完整体系：引入→试吃→买菜→洗菜→切菜
- 理解结构化数据与非结构化数据的区别
- 掌握计算机视觉（CV）三大任务：图像分类、目标检测、语义分割
- 理解自然语言处理（NLP）的主要应用
- 掌握开源数据集的使用方法
- 理解数据治理的完整框架
- 掌握词嵌入（Word Embedding）的核心思想
- 理解数据安全的重要性

## 1. 引入：如何做一道人工智能大餐

### 1.1 AI与做菜的类比

| 做菜要素 | AI要素 | 说明 |
|----------|--------|------|
| 食材 | 数据 | 基础材料 |
| 燃气/火候 | 算力 | 火（算力）可大可小，但不能无限增大 |
| 烹饪水平 | 算法 | 往哪走（方向）、怎么走（路径） |
| 厨师经验 | 人类指导 | 标注数据就是人类指导 |
| 烹饪过度 | 过拟合 | 训练集拟合太好，泛化能力差 |
| 食材新鲜 | 数据质量 | Garbage in, garbage out |

**算力的特点**：
- 算力可调节（用多少GPU可以控制）
- 算力可以往下调，但往上调需要加硬件
- 算力决定模型训练速度

### 1.2 过拟合

> **过拟合**：模型在训练数据上表现极好，但在新数据上表现差——丧失了泛化能力

**形象理解**：
- 训练数据点用一条复杂的曲线完美穿过
- 但新数据点落在这条曲线附近时，预测完全不准确
- 而用一条简单的直线虽然没完美拟合训练数据，却更能预测未来趋势

### 1.3 数据质量——核心原则

> **Garbage in, garbage out**（垃圾进，垃圾出）

- 无论算法多先进，数据质量差，结果一定差
- 数据科学家花费大量时间做数据清洗、解析、挖掘新特征
- 数据质量的两大要素：**干净的数据** + **相关的数据**

**干净的数据案例**：
- 研究肺结节 → 选择单纯的肺结节患者影像
- 避免混入肺部索条影（另一种病变/愈合疤痕）
- 无关数据会干扰计算机分类

## 2. 试吃：认识数据

### 2.1 数据 vs 算法：哪个更重要？

> **吴恩达（Andrew Ng）**：无论算法多好，一定要有更多的数据（have the most data）

**结论**：在AI领域，**数据的重要性远高于算法**

### 2.2 数据处理的"坑"

```
讨论需求 → 数据选择 → 数据提取 → 数据清洗/整合 → 缺失值处理 → 特征工程 → 模型评估
   ↓           ↓            ↓             ↓               ↓            ↓           ↓
  坑1        坑2          坑3           坑4             坑5           坑6         终点
```

**缺失值处理方法**：
- 最简单的删除缺失行
- 更常用的是用**平均值填充**（不影响整体数据分布）
- 注意：填错值会引入数据偏向

**特征工程 vs 深度学习**：
- **机器学习**：需要显式的特征工程
- **深度学习**：特征提取在神经网络内部自动完成（黑盒），不需要单独做特征工程

### 2.3 数据类型

#### 结构化数据

- **特征**：规则的表格形式，四方格整齐排列
- **来源**：系统日志、轨迹信息、行为记录、历史订单、聊天记录、网页爬虫
- **一般规律**：由**系统产生**的数据通常为结构化数据

#### 非结构化数据

##### 计算机视觉（CV）

| 任务类型 | 说明 | 应用案例 |
|----------|------|----------|
| **图像分类** | 判断整张图像的类别 | 猫狗分类、人脸比对 |
| **目标检测** | 定位+分类（识别位置和类别） | 自动驾驶（识别路灯/马路牙子/双黄线） |
| **语义分割** | 像素级别的分类 | 医学影像分割、视频场景分割 |
| **关键点检测** | 检测人体/物体的关键节点 | 运动疾病分析（走路视频自动分析关节问题） |

##### 自然语言处理（NLP）

| 应用 | 说明 |
|------|------|
| **机器翻译** | 日常用语翻译较好，专业领域（如医药）仍不足 |
| **实体识别（NER）** | 识别文本中的人名、地名、药名等实体 |
| **情感分析** | 判断评论的正/负向情绪 |
| **新闻摘要** | 自动生成新闻简短摘要（Attention机制） |

**CV vs NLP发展对比**：
- CV领域发展更快，成熟产品更多（商汤、海康威视、大华等）
- NLP领域**未来前景更大**，但目前成熟产品相对较少

### 2.4 非结构化数据的结构化——医学病历案例

```
门诊病历文本：
"腹部平坦，腹肌软，无压痛，脾脏区无叩击痛"
                    ↓
结构化表示：
腹部 → 部位（K） | 平坦 → 描述（Value）
腹肌 → 部位（K） | 软 → 描述（Value）
无压痛 → 腹肌（部位）+ 压痛（特征）+ 否定关系
```

**临床意义**：将大量病历结构化后，可以快速检索和分析特定病症的特征

## 3. 买菜：数据收集

### 3.1 公开数据集

#### 计算机视觉方面

| 数据集 | 说明 | 内容 |
|--------|------|------|
| **ImageNet** | 李飞飞团队构建，斯坦福大学 | 2.2万类别、1400万图像 |
| **Pascal VOC** | 世界级视觉挑战赛，欧盟出资 | 目标检测标注（XML/JSON格式） |
| **MPI** | 人体关键点检测 | 运动中骨骼关节节点的坐标标注 |

#### 自然语言处理方面

| 数据集/方法 | 说明 |
|-------------|------|
| **AI Challenge** | 机器翻译数据集，1000万+中英对照句子 |
| **爬虫采集** | 电商评论用于情感分析（1000条可做二分类） |
| **业务数据** | 客服对话记录用于问答系统 |

**NER数据标注格式示例**：
```

```

### 3.2 数据的输入输出定义

**CV问题**：输入为图像（像素矩阵），输出为分类/检测结果
**NLP问题**：输入为文本，输出为分类/实体/翻译结果

### 3.3 数据不够时的处理方法

| 方法 | 说明 | 建议 |
|------|------|------|
| **图像合成** | 用工具生成合成图像 | 慎用——无创新性，计算机未突破已有规则 |
| **仿真** | 游戏场景等仿真数据 | 有限使用 |
| **对抗神经网络（GAN）** | 双网络对抗生成逼真数据 | 效果好但复杂度高 |
| **强化学习** | 计算机自我对弈（如AlphaGo） | 适合特定场景 |

### 3.4 数据处理流程总结

```
数据收集 → 数据清洗 → 数据选择 → 标注 → 训练集划分 → 模型训练
```

## 4. 洗菜：数据治理

### 4.1 数据治理的四个步骤

```
收集初始数据 → 描述数据 → 探索数据 → 确认数据质量
```

### 4.2 数据标注的四个角色

| 角色 | 职责 |
|------|------|
| **产品经理** | 确认数据完整性、数据特点、外包结算 |
| **算法工程师** | 确认数据是否可用于模型训练 |
| **行业专家** | 处理边界情况数据、确认数据质量 |
| **标注人员** | 执行具体标注工作 |

> 专家只处理边界数据，因为全部数据由专家标注成本过高

### 4.3 四类数据报告

| 报告类型 | 内容 |
|----------|------|
| **数据收集报告** | 数据出处、样本获取方式 |
| **数据描述报告** | 数据特点（是否均衡等） |
| **数据探索报告** | 数据在模型中的流动过程（机器学习需要；深度学习不需要） |
| **数据质量报告** | 完整性、可用性、缺失性、均衡性 |

### 4.4 数据治理整体框架

```
资产盘点 → 数据处理（ETL） → 数据维护 → 数据资产分级 → 数据服务 → 数据应用
```

**关键环节**：

| 环节 | 说明 |
|------|------|
| **制定数据标准** | 数据治理的本纲，所有数据往里填充 |
| **主数据管理** | 核心数据字段的管理 |
| **原数据管理** | 定义数据的数据——描述数据字段的表 |
| **数据血缘关系** | 表与表之间的关联 |
| **数据质量监控** | Pipeline滚动监控 |
| **数据安全** | 数据安全法已颁布，泄露/售卖数据违法 |

**药品名称消歧案例**：
- 同一药品"北京降压零号"在电子病历中有11种写法
- 如"北京降压〇号"、"北京降压欧号"、"零号"、"欧号"等
- 需要消歧到统一标准名称，才能准确统计药品使用情况

### 4.5 数据不平衡

**常见场景**：
- 欺诈检测：绝大多数交易正常，极少数为欺诈
- 客户流失：留存客户远多于流失客户

**解决办法**：
1. **增加新数据样本**（最优方案）
2. 欠采样/过采样
3. 分层采样
4. 新的评价指标
5. 算法加权重
6. 问题细化（细分人群）

**案例：新药P=0.09的挽救**
- 三期间临床试验已花费10亿美元以上
- P=0.09未达到显著性水平（需<0.05）
- 解决方案：**细分人群**（如将18-60岁细分为50-60岁、30-50岁等）
- 细分后P值可能<0.05，使药物统计学上有效

### 4.6 数据安全——法律红线

- **数据安全法**已颁布
- 泄露、售卖数据**犯法、要判刑**
- 高危数据：医疗数据、银行数据、个人身份信息

## 5. 切菜：特征学习

### 5.1 特征学习的两条路径

| 路径 | 机器学习 | 深度学习 |
|------|----------|----------|
| 方法 | 逐步可解释 | 端到端黑盒 |
| 特征提取 | 显式特征工程 | 神经网络内部自动完成 |
| 维度 | 同维/浅层学习 | 升维/深度学习 |

### 5.2 升维的核心思想

> 低维空间中难以区分的数据，在高维空间中可以用一个超平面完美分开

**形象理解**：
- 在二维平面上，三角形点和圆形点混杂无法用直线分开
- 将圆形点升到三维空间（z轴），就可以用一个平面完美分开

### 5.3 从One-hot到Word Embedding

**One-hot编码（早期方法）**：

```
"欢迎你参加人工智能培训"
                    ↓
词序表：[你, 欢迎, 人工智能, 培训, 参加]
                    ↓
你 → [1, 0, 0, 0, 0]
欢迎 → [0, 1, 0, 0, 0]
人工智能 → [0, 0, 1, 0, 0]
```

**问题**：向量极度稀疏（大量0、少量1），计算不友好

**Word Embedding（词嵌入）**：

| 方法 | 说明 |
|------|------|
| **核心思想** | 用高效的密集向量表示词语 |
| **Skip-gram模型** | 根据当前词预测上下文，学习词的向量表示 |
| **优势** | 向量密集、包含语义信息、可计算相似度 |

**Word Embedding的过程**：
1. 研究目标词左右两边的词
2. 通过神经网络训练得到词的向量表示
3. 语义相近的词在向量空间中距离更近

> **万物皆可Embedding**——文本、声音、图像等序列数据都可以做Embedding

## 总结

| 核心概念 | 关键要点 |
|----------|----------|
| 做菜五步法 | 引入→试吃→买菜→洗菜→切菜，对应数据处理全流程 |
| 数据>算法 | 吴恩达：数据比算法更重要——Garbage in, garbage out |
| 结构化vs非结构化 | 系统产生结构化数据；图像/文本/语音为非结构化数据 |
| CV三大任务 | 图像分类、目标检测、语义分割 |
| NLP核心应用 | 机器翻译、NER、情感分析、新闻摘要 |
| 公开数据集 | ImageNet、Pascal VOC、AI Challenge等 |
| 数据治理框架 | 资产盘点→ETL→维护→分级→服务→应用 |
| 标注四角色 | PM + 算法工程师 + 专家 + 标注人员 |
| 数据不平衡 | 增加样本（最优）、细分人群、加权等方法 |
| 数据安全 | 数据安全法——泄露/售卖数据违法 |
| One-hot→Embedding | 从稀疏向量到密集向量的进化 |
| 升维 | 低维不可分→高维可分，这是深度学习的数学本质 |
