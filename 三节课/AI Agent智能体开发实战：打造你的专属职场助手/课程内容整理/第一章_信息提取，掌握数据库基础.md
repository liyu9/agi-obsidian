## 一、案例背景：销售线索智能管理助手

同学们好，欢迎收看课程智能体开发实战，打造你的专属职场助手。本节会涉及以下知识点：案例销售线索智能管理助手，通过自然语言快速记录信息、数据库的基础概念、数据库的语言分类、表格结构数据的特征以及表结构数据的特征概述。

### 1.1 需求痛点

此类案例可以解决以下的需求痛点：

1. 当销售人员需要手动将客户信息填入多个表单字段，耗时且繁琐，导致信息收集效率低下
2. 重要的细节容易在记录过程当中遗漏或者错误输入，导致信息丢失与不准确
3. 不同销售人员的记录格式和内容不一致，难以形成统一标准，导致数据标准化困难
4. 销售流程碎片化，比如信息记录与CRM系统录入分离，导致流程断点
5. 外勤时难以完整记录客户信息，需要回到办公室二次整理，导致移动办公受限

### 1.2 案例场景

某软件公司开发了一款名为智慧逍客的销售线索管理系统。系统最新的功能是通过自然语言处理技术，让销售人员能够直接通过语音或文字记录客户信息，而不必手动填写多个表单、字段。

销售人员可以在客户拜访后、通话后或者展会结束后，以自然语言方式快速记录线索信息。智能体负责从这些非结构化文本当中提取关键信息，并将其存储到标准化的数据库中，便于后续的跟进和分析。

## 二、扣子数据库操作

### 2.1 创建数据库表

在智能体工作空间选择资源库，单击创建扣子数据库。需要设置以下内容：

| 配置项 | 说明 |
|--------|------|
| 数据表名称 | 必填项且无法修改，如 sales_lead |
| 数据表描述 | 非必填项 |
| 存储字段 | 包括字段名称、字段描述、数据类型、是否必要 |

### 2.2 系统默认字段

前四个字段是智能体数据表默认必须要存在的字段，无法删除：

| 字段名 | 描述 |
|--------|------|
| 数据ID | 数据的唯一标识 |
| 渠道 | 数据产生或使用的渠道 |
| 用户ID | 用户唯一标识 |
| 创建时间 | 数据插入的时间 |

### 2.3 自定义字段

**字段名命名规则**：
- 只能包含小写字母、数字或下划线
- 必须以英文字母开头
- 参考格式：`abc`、`abc_123`、`abc123`

**字段类型**：
- 文本型（string）：用于文本内容
- 整数型（int）：用于整数数值
- 文本型适合存储日期描述（如"下周一"）

### 2.4 销售线索表字段设计

| 字段名 | 描述 | 类型 |
|--------|------|------|
| company_name | 公司名称 | 文本型 |
| contact_name | 联系人姓名 | 文本型 |
| position | 联系人职位 | 文本型 |
| email | 电子邮箱 | 文本型 |
| phone | 电话号码 | 文本型 |
| wechat | 微信号 | 文本型 |
| product_interest | 感兴趣的产品或服务类型 | 文本型 |
| budget | 预算 | 整数型 |
| decision_timeline | 决策时间线 | 文本型 |
| priority | 优先级 | 文本型 |
| next_follow_up | 下次跟进时间 | 文本型 |
| source | 线索来源 | 文本型 |
| note | 备注 | 文本型 |

> 注意：预算字段选择整数型，智能体会自动将"100万"换算成"元"进行存储。

## 四、功能测试

### 4.1 单条信息提取

**测试输入示例**：

> 今天下午两点在国贸大厦遇到了来自阿里巴巴的李明，他是他们采购部门的经理。他对我们的企业软件解决方案很感兴趣，特别是库存管理模块。他提到他们计划在三个月内更新系统，预算大约为100万元。我们交换了名片，他的电话是xxx，邮箱是xxx。

**智能体处理流程**：
1. 从自然语言中提取关键字段
2. 将信息保存到数据库表
3. 返回保存成功提示

### 4.2 批量信息提取

智能体支持批量处理多条自然语言信息，能够依次从每条文本中提取字段并保存。

### 4.3 数据查询功能

添加技能三：查询数据

> 用户输入查询需求后，从数据库中查询相关信息并输出

**查询示例**：

> 请查询字节跳动的销售线索信息

**SQL查询语句**：


## 五、数据库语言基础

### 5.1 关系型数据库管理系统（RDBMS）

| 组件 | 说明 |
|------|------|
| RDBMS | 位于顶层，负责创建、管理和操作多个数据库，提供用户界面、安全控制、并发控制和数据完整性功能 |
| 数据库 | 位于中间层，每个RDBMS可包含多个数据库 |
| 数据表 | 位于最底层，由记录和字段组成 |

**常见RDBMS**：MySQL、Oracle、SQL Server、PostgreSQL

### 5.2 数据表结构特征

- 每个字段有且只有一种数据类型
- 同一数据表中的字段名必须唯一
- 主键字段的记录必须是非空不重复的
- 主键可以是单字段主键，也可以是多字段联合主键

### 5.3 结构化数据分类

| 类型 | 载体 | 最小单位 |
|------|------|----------|
| 表格结构数据 | Excel、WPS Numbers等电子表格 | 单元格 |
| 表结构数据 | 数据库管理系统 | 字段 |

### 5.4 数据库语言分类

| 语言类型 | 核心指令 | 功能 |
|----------|----------|------|
| 定义语言（DDL） | CREATE、ALTER、DROP | 创建、修改、删除数据库对象 |
| 操作语言（DML） | INSERT、UPDATE、DELETE | 对数据进行增删改 |
| 查询语言（DQL） | SELECT | 从表中查询数据 |

## 六、应用场景与价值

### 6.1 适用场景

| 场景 | 描述 |
|------|------|
| 外部销售拜访 | 销售代表在客户拜访后直接口述或发送文字记录访谈内容 |
| 电话销售与跟进 | 通话结束后及时记录谈话要点，智能体分析对话内容并更新客户档案 |
| 展会与行业活动 | 快速记录大量潜在客户信息，智能体自动整理分类 |
| 销售团队协作 | 不同销售人员使用统一的信息记录方式，确保数据标准化 |
| 远程工作 | 通过多种设备和渠道输入销售线索，智能体保证信息同步整合 |
| 销售培训与入职 | 新入职销售人员快速适应工作流程，无需记忆复杂的数据录入规则 |

### 6.2 应用价值

| 价值维度 | 具体收益 |
|----------|----------|
| 节约时间成本 | 销售人员每天可节省大量数据录入时间，转化为更多客户接触机会 |
| 优化人力成本 | 减少对专职数据录入人员的需求 |
| 提升客户体验 | 销售人员更关注客户互动，而非数据录入 |
| 沉淀组织知识 | 形成标准化的客户信息库，积累销售知识 |

## 七、核心要点总结

1. **数据库是表结构数据**：智能体中的数据库存储的是表结构数据，最小单位是字段
2. **字段命名规范**：使用英文小写字母、数字、下划线
3. **数据类型选择**：数值选整数型，日期描述选文本型
4. **自然语言提取**：通过大模型从非结构化文本中提取关键信息
5. **SQL查询**：使用SELECT语句查询数据库
6. **批量处理**：智能体支持批量处理多条信息
7. **系统默认字段**：ID、渠道、用户ID、创建时间四个字段不可删除
