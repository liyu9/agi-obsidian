# 第三章 转型第2步：设计AI产品

> 核心思维：**向人的交付对齐**——思考人完成一个任务的交付物是什么，人是通过什么方案完成交付的。

---

## 本章导入：AI产品设计四步骤

1. 学习AI产品基础设计方法
2. 了解AI产品的交付物和常见形态
3. 进入具体的AI产品设计方案
4. AI产品的局限和常见应对方法

## 第一节 AI产品设计方法

### AI产品的定义

AI产品是指**把AI作为核心驱动力，为用户提供特定功能或服务的应用**。

### 设计AI产品需考虑的两个问题

1. **交付物**：具体的、可视化的东西是什么？
2. **交付方案**：如何通过基座模型+产品方案完成交付？

### 设计思维的转变

| 传统软件思维 | AI产品设计思维 |
|-------------|---------------|
| 前台界面长啥样？按钮大小颜色？ | **向人的交付对齐** |
| 后台有哪些编辑逻辑？ | 人完成一个任务的交付物是什么？ |
| 用逻辑框住功能 | 人是通过什么碳基架构完成交付的？ |

> ChatGPT的前台很复杂吗？最早就是一个输入框。

### 人类的交付物类型

| 类型 | 示例 |
|------|------|
| 计划 | 课纲、时间表 |
| 分析 | 主观分析报告、量化分析报告 |
| 设计品 | 视频、图片、文字 |
| 文档 | PPT、Word |
| 沟通 | 与别人沟通计划 |

**人的交付物分两种：**

| 类型 | 类比 | 特点 |
|------|------|------|
| **直接交付** | 正式员工 | 独立完整交付，检核结果即可 |
| **辅助交付** | 实习生 | 提供环节建议/参考/初稿，需要修改审核 |

> 目前AI技术多还是辅助交付为主。

### 人的碳基架构 vs. 模型的硅基架构

| 人类碳基架构 | AI产品对应方案 |
|-------------|---------------|
| 大脑（信息加工处理） | **基座模型** |
| 记忆（知道要干什么、情景设定） | **Prompt + 知识库 + 微调数据** |
| 环境感知（触发任务） | **输入/感知系统** |
| 使用工具（PPT、剪辑软件） | **业务系统API / MCP** |
| 执行逻辑（串行/并行的工作步骤） | **工作流编排** |
| 协作界面（网页、视频展示） | **前台交互界面** |

### 案例：素材库AI智能打标方案

- **交付物**：辅助交付（像实习生给打标建议），给出"建议标签+原因+可溯源"
- **基座模型**：外采国内基座模型 + 专业标签微调小模型
- **记忆**：提示词限定任务 + 标签库知识库
- **输入**：素材标题、详情、元数据、多模态内容
- **工具**：标签管理系统、素材管理系统
- **工作流**：提交素材→AI理解→查询标签→打标→前台展示→人类确认
- **交互方案**：在素材管理前台展示打标建议，人类确认

## 第二节 设计AI交付物

### AI交付物的四个要素

| 要素 | 说明 |
|------|------|
| **交付物模板** | 输出内容的结构化模板 |
| **交付时机** | 什么条件下触发交付 |
| **人机协作方式** | 直接交付还是辅助交付，需要确认还是仅知会 |
| **用户界面** | 具体的交付界面长什么样 |

### 交付物模板化的价值

1. **提升使用价值**——不然就是玩具
2. **可衡量效果**——知道哪块做得好哪块不好
3. **标准化输出**——可调用其他系统做更大范围自动化

**最关键**：模板必须和**人类业务模板对齐**，不能产研自己意淫。

**负面案例**：某云服务商给车企做的AI用户画像——300多字，上来就是"某女士，四十几岁，几口人，婚姻状况"——三秒判断是玩具。因为销售不是这么工作的，销售第一关注客户的差异点。

### 如何保证模板不是意淫的？

| 对齐对象 | 方法 |
|----------|------|
| 工作标准制定者（管理者/运营） | 梳理客观可衡量的工作标准 |
| 最佳实践一线员工 | 帮他们抽象出模板并核对 |
| 一线主管/培训人员 | ⭐ 最佳选择——本就要传帮带 |

### 三种用户界面形态

| 形态 | 适用场景 | 示例 |
|------|----------|------|
| **独立应用** | AI直接驱动服务，用户奔着AI功能来 | GPT对话界面 |
| **窗口嵌入** | 用户有自己任务，AI实时辅助 | 听课页面右侧AI窗口 |
| **功能嵌入** | 在原系统中单项加入AI输出 | 销售沟通后AI自动生成跟进记录 |

**选择依据**：
1. **产品定位**：帮助获取信息还是辅助完成任务？
2. **协作方式**：多轮交互→独立应用；单向输出确认→功能嵌入

### AI前台界面常见设计区域

| 区域 | 说明 |
|------|------|
| **输入区域** | 输入框、辅助输入、限定输入、多模态输入 |
| **输出区域** | 生成结果展示 |
| **解释区域** | 为什么产生这个结果 |
| **来源区域** | 知识库引用溯源 |
| **反馈区域** | 重做、修改、下载、分享、点赞点踩 |
| **上下文区域** | 历史对话信息 |
| **提示区域** | 工作状态、能力边界、出错提示 |

### 设计AI交付物的工具表

| 要素 | 内容 |
|------|------|
| 模板化的交付物 | 打标建议（建议标签+原因+溯源） |
| 交付时机 | 每次上传完素材自动输出 |
| 协作方式 | 辅助交付，需运营同学确认后才真正完成打标 |
| 用户界面 | 功能嵌入——素材管理系统标签选择区展示打标建议 |

## 第三节 设计AI产品方案

> 历史背景：23-24年行业流行"模型即产品"，后来走不通。原因是模型缺乏专业知识和背景信息、局限在生成内容、一问一答交互门槛高。

### AI产品架构：智能体（Agent）

```
┌─────────────────────────────────────┐
│              前台交互                 │
├─────────────────────────────────────┤
│             工作流编排                │
├─────────────────────────────────────┤
│   工具API  ←  基座模型  →  输入/感知  │
│    (MCP)       ↓                    │
│             记忆系统                  │
│    (Prompt → 知识库 → 微调数据)       │
└─────────────────────────────────────┘
```

### 基座模型选择

| 方案 | 自研/微调 | 外采/调用 |
|------|-----------|-----------|
| **优点** | 任务精准、数据安全、积累壁垒 | 成本低、迭代快、享受新技术 |
| **缺点** | 成本高、复杂、需养算法工程师 | 定制化程度和数据安全有风险 |
| **建议** | 早期MVP阶段 | ✅ **先用外采方案** |

**模型选择三维度**：
1. **性能**：建立业务评测集，评估不同模型表现
2. **成本**：调用成本
3. **数据安全**：海外模型有数据合规风险

**真实案例**：生成私域朋友圈内容的小程序——拉出国内外模型，写好prompt，每个模型生成20次，由销冠打分（主观+客观），综合判断。

### 构建模型记忆能力

#### 1. Prompt提示词

个人常用Prompt格式：

```
角色身份：你是谁？
完成目标：你要做什么？
工作步骤：你的思考步骤/工作步骤
背景信息：你在什么背景下工作
输出约束：输出格式、注意事项
少量样本：2-3条示例
```

> 长度和约束的详细程度并不决定prompt质量——简洁说清楚最重要。

**提示**：按版本管理prompt，每个版本记录并测试。

#### 2. RAG知识库

**流程**：
收集文档 → 按标准格式解析 → 长文档切块（按主题/章节）→ 向量化存储 → 用户请求 → 检索知识库 → 注入prompt → 生成带业务知识的回复

**产品经理职责**：
- 管理和运营知识：知道模型需要哪些知识，采集回来
- 制定知识切块策略
- 做效果评测

**案例**：朋友圈小程序接入"营销日历"知识库，按日期召回节日主题。

#### 3. 模型微调

**数据处理流程**：数据采集 → 数据清洗 → 标注 → 分割（训练/验证/测试）

> 数据量、质量和多样性，都能有效提升训练效果。

### 建立自动化输入系统

```
数据采集（工作手机/智能硬件/爬虫/外采）
    ↓
数据管理系统（结构化/模板化存储）
    ↓
工作流触发 → 模型处理 → 输出结果
```

- 语音等模态数据：先转文字再喂给模型（注意折损）
- 最好有前向管理系统，把数据先处理成结构化/模板化

### 为模型增加工具

所有业务系统的API、增删改查操作数据库的方法，都是模型的工具。

**常见工具示例**：
- 新闻API
- 招聘软件API
- 地图数据API
- Excel增删改查
- 视频剪辑工具API

### 工作流编排

| 方式 | 适用场景 | 特点 |
|------|----------|------|
| **工作流**（代码硬编码） | 明确定义、重复性强、结果可预测 | 一板一眼，稳定可靠 |
| **智能体/Agent** | 灵活性高、任务路径不好枚举 | 自主规划、调用工具 |

**案例**：私域朋友圈小程序工作流
1. 工程定时触发，查用户行业+去重历史主题
2. 模型1联网查行业热点
3. 无热点则查营销日历知识库
4. 模型2确定营销主题
5. 多路模型（3个）各自生成文案
6. 模型3打分评价
7. 文生图模型生成配图

### 交互设计

**核心目标**：管理好用户对产品的价值预期

| 模式 | 说明 | 阶段 |
|------|------|------|
| **Copilot模式** | 人串任务，AI给初稿/建议，人修改确认 | ✅ 目前主流 |
| **Agent模式** | 人设目标，AI自主拆解执行 | 探索中 |

**好的AI产品交互标准**：

**输入**：
- 自动输入 > 预设模板选择 > 手动输入
- 输入补全和辅助

**输出**：
- 符合人类交付物格式
- 足够解释性（不是空口无凭）
- 过程可控（可打断、可看进度）
- 耗时操作可后台运行
- 反馈闭环（点赞点踩）

### ROI与成本结构

| 成本项 | 说明 |
|--------|------|
| 模型调用成本 | 外采模型调用费 |
| 训练成本 | 自研需买卡租卡 |
| 数据成本 | 训练数据、输入数据标准化 |
| 人力成本 | 工程开发 |
| 运维成本 | 模型和产品持续迭代 |

### 设计对齐清单

| 人类操作环节 | AI产品设计思考 |
|-------------|---------------|
| 信息处理/归纳/系统交互/初稿生成 | 能否用模型替代？ |
| 角色设定+任务记忆 | 用Prompt设定 |
| 具体内容输出 | 用知识库/微调数据 |
| 环境感知触发 | 建立感知系统，前向采集数据 |
| 使用工具 | 让工具开放API供模型调用 |
| 多步骤串联 | 工作流/智能体编排 |
| 交付展示 | 新人怎么和老板交互，就怎么设计 |

## 第四节 AI产品的局限和常见应对方法

### AI产品的三大局限

| 局限 | 表现 |
|------|------|
| 幻觉 | 胡说八道 |
| 用户意图对齐难 | 说东他说西 |
| 缺乏解释性 | 结果让人不信任 |

### 应对方法

#### 1. 优化输入

| 方法 | 具体做法 | 案例 |
|------|----------|------|
| 提升输入数据质量 | 换更好的ASR模型 | 外呼语音转文字准确率差→换模型 |
| 控制方言降级 | 方言地区不上自动总结 | 闽南地区降级处理 |
| 减少输入复杂度 | 少交互轮次 | 超5轮+知识库，容易幻觉 |
| 控制上下文长度 | 有选择地输入 | 多年客户沟通→只选关键几条做摘要 |
| 意图规则设计 | 分类+标准化意图改写 | 用户输入先改写为标准意图 |
| 槽位设计 | 先提取字段再生成 | 先填画像槽位→再生成完整画像 |
| 知识库质量提升 | 混合切片方案 | 按章节或按主题切片 |

#### 2. 优化输出

| 方法 | 说明 |
|------|------|
| 多模型协同 | 多路模型同时跑+投票/检查/循环 |
| 增加过程管理 | 展示思考过程（类似DeepSeek R1） |
| 展示检索来源 | 知识库引用 |
| 展示置信度 | 显示预测准确率 |
| 拆分步骤 | 不端到端，拆成多步 | 销售跟进时间分配：先分客户质量→再分配 |

#### 3. 兜底和降级策略

- 保留回退能力：如果AI不灵，让人能回退到手动处理
- 敏感词控制
- 知识库权限控制

### AI问题自查表

| 检查项 | 具体问题 |
|--------|----------|
| 输入数据源 | 数据质量能否提升？ |
| Prompt | 是否还能调优？ |
| 知识库 | 数据质量、标准化、全面性？ |
| 检索召回策略 | 能否提升？ |
| 微调数据 | 多样性、数量、质量？ |
| 业务系统 | 运行稳定？调用失败概率？ |
| 工作流编排 | 步骤是否冗余？串并行是否合理？ |
| 前台交互 | 是否太复杂？用户是否不信任？ |
| 模型选择 | 当前模型是否合理？ |

> 如果一切方案都试完了还不好——回头看场景选择是否有问题。

### 两个心法

1. **找有价值但人做不好的场景**
   - 案例：销售跟进动作自动质检——都知道过程管理好业绩能提升，但谁都干不了
2. **追求实用性和稳定输出**，避免唯创新论、唯技术论

### 本章总结

1. AI产品设计核心解决两个问题：交付物是什么 + 怎么通过产品方案完成交付
2. 交付物和人机协作方式都**向人的交付对齐**
3. 方案包括：基座模型选择 → 记忆构建（Prompt/知识库/微调）→ 自动化输入 → 工具调用 → 工作流编排 → 前台交互
4. 遇到问题用自查表逐项排查，追求实用性和稳定性
