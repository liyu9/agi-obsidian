# 第四章 转型第3步：迭代AI产品

---

## 本章导入：两种常见的迭代失败场景

| 失败场景 | 表现 | 结果 |
|----------|------|------|
| 传统推广方式 | 开宣贯会→上管理手段→使用率低→赖模型→死循环 | 进入复盘 |
| 技术自嗨 | 技术指标很好，但业务不认可价值 | 有使用量但无持续资源投入 |

## 第一节 为AI产品设计指标体系

### 为什么要设计指标体系？

- **理性验证**产品想法
- 在企业内形成**客观的价值共识**
- 验证三个层面：输出的内容好、大家爱用、创造了业务价值

### AI产品三类指标体系

```
┌───────────────────────────────────┐
│       业务价值指标                │
│   （转化率、订单数、利润）        │
│           ↑ 正相关                │
│       产品使用指标                │
│   （采纳率、替代占比、满意度）    │
│           ↑ 正相关                │
│       模型评估指标                │
│   （准确率、召回率、响应速度）    │
└───────────────────────────────────┘
```

#### 1. 模型评估指标

> 衡量AI输出内容与人类最佳实践标准的接近程度。

| 类型 | 指标 | 说明 |
|------|------|------|
| **客观指标** | 准确率 | 打标结果中正确的比例 |
| | 召回率 | 应该输出的正样本中实际输出了多少 |
| | 响应速度 | 首token返回时间 |
| **主观指标** | 可读性 | 是否简洁易懂 |

**案例**：AI自动生成会议纪要的模型评估表

| 原始材料 | 模型生成的纪要 | 要点召回率（五分制） | 自然简洁程度（五分制） |
|----------|---------------|-------------------|---------------------|
| 会议原文 | 生成内容 | 4.2/5 | 3.8/5 |

#### 2. 产品使用指标

> 衡量用户对AI产品的使用情况和接受程度。

| 类型 | 指标 | 说明 |
|------|------|------|
| **客观指标** | 采纳率 | AI结果被用户采纳的比例 |
| | 托管率（自动驾驶概念移植） | 用户一个字不改直接用的比例 |
| | 智能化替代占比 | AI覆盖场景的比例 |
| **主观指标** | 满意度 | 阶段性考核 |
| | 净推荐值 | 阶段性考核 |
| | 负面反馈 | 主要监控负面是否在可控范围 |

#### 3. 业务价值指标

> 衡量AI产品是否为公司带来商业价值。

| 指标 | 说明 |
|------|------|
| 业务目标完成度 | 产品使用带来的交付物数量/质量提升 |
| 商业价值指标 | 转化率、订单数、利润 |
| 人力成本影响 | 节省了多少人多少时间（**辅助指标**） |

> 注意：节省时间在B端是辅助指标，除非真的替代了某个角色。

### 北极星指标的选择

**建议**：用产品使用指标作为北极星指标——**采纳率**或**智能化替代占比**

**为什么？**
- 技术指标：容易陷入"王婆卖瓜"，业务理解不了
- 业务指标：变量太多（转化率受太多因素影响），说不清

**使用指标**：可直接作用、直接影响、反馈产品效果和使用接受度。

### 指标体系工具表（以素材库智能打标为例）

| 指标类别 | 指标 | 关系 |
|----------|------|------|
| ⭐ **北极星指标** | **AI标签采纳率** | 产品做得好不好 |
| 使用指标（补充） | AI标签替代比 | 覆盖场景够不够 |
| 模型评估指标 | AI标签准确率 | 输出客观是否准确 |
| 业务价值指标 | 素材使用率 | 业务目标是否提升 |
| 业务价值指标 | 订单转化率 | 公司商业价值是否提升 |

> 指标体系之间的逻辑：采纳率提升 → 证明技术准且大家爱用 → 素材使用率提升 → 订单转化率提升

## 第二节 建立迭代流程

### 上线基线的划定

**推荐**：看人工操作流程表中的人工平均表现——划在60分或80分。

**基线要满足三个条件**：
1. 对业务有主观或客观量化的贡献
2. 对现有工作流程影响可控（如采纳率80%，十次改两次）
3. 技术有信心达成

**案例**：智能打标基线划在采纳率80%，准确率80%

> **心法**：最重要的是逻辑自洽且有信心达成，不要纠结做数学题。

### 上线前三轮考试

| 轮次 | 名称 | 操作 |
|------|------|------|
| 第一轮 | **验证考试** | 开发过程中用历史数据模拟测试 |
| 第二轮 | **期末考试** | 上线前用产品没见过的新数据测试 |
| 第三轮 | **面试（UAT）** | 真实环境让内部用户（业务负责人、技术负责人、老板）交互体验 |

### AI产品迭代流程闭环

```
问题收集 → 问题诊断 → 问题解决 → 效果验证
                                            ↓
                                      回到问题收集
```

#### 1. 问题收集

- 建立**数据日报和数据追踪流程**（强烈建议上线前一个月开始筹备）
- 定位哪些人用得好、哪些人用得不好
- 早期所有问题**无脑收集**起来

**数据日报示例**：

| 用户 | 第1天 | 第2天 | 第3天 | 趋势 |
|------|-------|-------|-------|------|
| 用户A | 20% | 20% | 20% | 顽固分子 → 访谈 |
| 用户B | 50% | 80% | 85% | 狂热用户 |
| 用户C | 30% | 45% | 60% | 中立者，逐步使用 |

#### 2. 问题诊断

- 按**场景**和**问题类型**分类
- 不要眉毛胡子一把抓

**问题分类**：

| 问题类型 | 说明 | 应对策略 |
|----------|------|----------|
| **模型问题** | 技术瓶颈，换模型也不好使 | 简化场景、改人机协作方式 |
| **产品问题** | 工程手段可调优 | ⭐ **重点迭代**——避免焦虑式改交互 |
| **使用习惯问题** | 用户吐槽不喜欢改变 | 缩小用户范围、建立运营机制 |
| **场景问题** | 场景本身选错了 | 果断调方向，不死磕 |

#### 3. 问题解决

- **每个版本只解决一个高频场景的问题**
- 把该场景的解决方案打磨到极致
- 忽略其他问题，记录在问题管理表中

#### 4. 效果验证

通过数据指标和主观反馈，验证迭代是否有效。

### 案例：智能打标1.0上线后

**上线基线**：AI标签采纳率不低于80%

**上线一周**：采纳率仅45%，团队崩溃

**问题分类**：

| 问题 | 根因 | 类型 |
|------|------|------|
| 图片素材标签不准 | 图片识别模型错误率高 | 产品问题（可调优） |
| 视频素材标签不准 | 视频长，标签少，用户不信任 | 产品问题（可调优） |
| 专业标签不准 | 通用模型不认识公司内部专业名词 | 模型问题（突破性能上限） |
| 交互界面不好看 | 展示层面设计不佳 | 产品问题（但非核心） |

**解决策略**：先挑**图片素材**这个高频场景，用一个版本解决：
1. 替换图片识别模型，提升准确率
2. 增加一路工作流：先识别图片→形成文字摘要→通过摘要打标→合并模型直接打标结果

有效提升北极星指标。

## 第三节 你将经历的迭代阶段

### 阶段一：上线前

| 维度 | 内容 |
|------|------|
| **特点** | 非常纠结，第一次干，拿不准 |
| **应激反应** | 过度设计、堆砌功能、无限拔高预期 |
| **唯一目标** | 定一个上线日期，**按时上线** |
| **关键任务** | 控制各方预期，快速推进上线 |
| **避免** | 求大求全、焦虑式加功能 |

### 阶段二：0到1打磨阶段

| 维度 | 内容 |
|------|------|
| **特点** | 无人问津或疯狂吐槽 |
| **唯一目标** | **专注打磨一个场景**的解决方案和使用体验 |
| **关键任务** | 控制用户范围，快节奏迭代打磨 |
| **真实案例** | 做一个独立销售AI应用，全北京发问卷只有1个人愿意用，对着一个人打磨了两周 |
| **避免** | 快速扩量、像没头苍蝇一样瞎做功能、焦虑式重构交互 |

> AI产品早期阶段，价值不在于前端界面的美观度，甚至易用程度都没那么重要。

### 阶段三：1到100野蛮增长

| 维度 | 内容 |
|------|------|
| **特点** | 用户群变复杂、问题涌现、内部协作混乱、传统声音表达不满 |
| **唯一目标** | **尽可能快地增长**，直到覆盖所有业务场景 |
| **关键任务** | 固化迭代流程（三张表）、强化分工、分用户群运营、做好价值传递 |
| **分用户运营** | 不同方言区、不同数字化接受度——不同推广策略 |
| **版本策略** | 早鸟版（尝鲜）→ 大众版 → 回退版（完全不用AI功能） |
| **避免** | 忽视环境差异、追求技术完美主义、闭门造车 |

### 阶段四：价值扩张

| 维度 | 内容 |
|------|------|
| **目标** | 将单点能力放大为体系化产品，在企业内扎稳脚跟 |
| **策略一** | 同一能力覆盖更多场景（外呼→即时聊天→线下接待→交付→售后） |
| **策略二（推荐）** | **闭环上下游业务流程**，增强自动化价值 |

**闭环案例**：
```
智能跟进纪要 → 智能客户画像 → 智能客户分配 → 智能跟进节奏安排
   ↑                                                          ↓
   └────────────────── 跟进沟通形成纪要 ──────────────────────┘
```

### 工具：AI能力地图（以智能打标为例）

| 流程环节 | 能力 | 目标 | 开发状态 |
|----------|------|------|----------|
| 打标 | 智能打标 | 所有素材都能打上标签 | ✅ 已推广 |
| 标签管理 | 自动标签挖掘 | 挖掘新标签，更细分多样 | 🔄 下季度 |
| 素材分析 | 素材分析报告 | 分析标签下素材使用情况，影响上游生产 | 📅 Q3启动 |

### 迭代心态总结

| 要做什么 | 不要做什么 |
|----------|-----------|
| 不要求大求全 | 不要焦虑式改交互 |
| 守好高频场景 | 不要技术完美主义 |
| 一个版本打磨极致 | 不要追求中台化 |
| 快节奏迭代（三天一次更好） | 不要闭门造车 |
| 流程透明、信息同步 | 不要忽视环境差异 |

### 本章总结

1. **建指标体系**：模型评估指标 + 产品使用指标 + 业务价值指标，用采纳率做北极星指标
2. **建迭代流程**：问题收集→诊断→解决→验证，用三张表（数据日报、问题管理表、需求管理表）
3. **分阶段专注**：上线前→0→1打磨→1→100野蛮增长→价值扩张，每个阶段专注不同任务
