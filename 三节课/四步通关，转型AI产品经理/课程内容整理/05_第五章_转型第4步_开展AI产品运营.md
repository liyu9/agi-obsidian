# 第五章 转型第4步：开展AI产品运营

---

## 第一节 企业内产品运营的必要性

### 传统B端推广方式为什么行不通？

传统方式：接需求→功能上线→开宣贯大会→上管理手段推着用

**问题**：
- 原来的软件大家有功能预期
- AI是新技术，要改变工作方式
- 大家不知道有没有用，天然觉得你在瞎折腾
- 只有约10%的人愿意尝试新事物

> 你自己的感受：每天来上班，你天天想换工作软件吗？你巴不得什么都别变——除了工资。

### 各方角色分析

#### 1. 用户（要用新产品的人）

| 想要 | 担心 |
|------|------|
| 少时间少精力但有更高业绩产出 | 浪费时间 |
| | 打破工作习惯 |
| | 被替代 |

**真实案例**：只是把蓝色界面改成绿色、缩小了一些不重要的信息，用户就在大群里形成声浪抵制。

#### 2. 管理层（投钱给资源的人）

| 想要 | 担心 |
|------|------|
| 对公司业务有帮助 | 没价值 |
| 创新和解决问题的口碑 | 自己形象受损，显得不专业 |

#### 3. 项目团队（跟着干的同学）

| 想要 | 担心 |
|------|------|
| 工作成果产生价值→升职加薪 | 没成果 |
| 个人成长和未来增值 | 没参与感，跟着瞎折腾 |

### 运营心法

**对他人的运营心法：**

| 心法 | 说明 |
|------|------|
| **分群体运营** | 不能眉毛胡子一把抓 |
| **师出有名** | 强调做的事和公司战略契合 |
| **过程可视化** | 书面化、发出去，让对方有掌控感 |
| **绑定利益** | 有好处大家分享，出事了第一个担责 |

**对自己的运营心法：**

| 心法 | 说明 |
|------|------|
| **管好嘴，控制预期** | 永远说"我们做个小实验"，有70%信心就开干 |
| **多谈业务痛点，少画饼** | 不要说明年就晋升了 |
| **发动社交关系** | 在不同用户群体里寻找早期支持者 |
| **做布道者** | 不厌其烦地给大家讲价值和新的资讯 |

## 第二节 运营你的用户

### 三类用户

| 用户类型 | 特点 | 运营目的 |
|----------|------|----------|
| **最佳实践** | 一线业务专家/主管 | 建立交付标准和模板，做标注 |
| **种子用户** | 有绩效动力、愿尝鲜的腰部员工 | 打磨创新产品，验证价值 |
| **大众用户** | 普通员工群体 | 推广使用，改变工作习惯 |

### 运营最佳实践

**他们是什么人**：
- 过程管理做得好的top员工（不是天才型，是勤奋标准型）
- 已在从事代教的一线主管
- 表达欲强、存在感强的员工

**来源**：管理者层层推荐 + 优秀案例/优秀员工分享

**运营策略**：
1. **激发分享欲**——把自己变成求知的学生
2. **降低交互门槛**——避免让人写长篇大论，建立标准让人确认
3. **建立荣誉感**——标注"生成策略来自XXX员工"

### 运营种子用户

**他们是什么人**：
- 对绩效提升有冲动
- 对新技术好奇（用过豆包、ChatGPT）
- 承担重复性工作已经烦了
- 爱吐槽但对公司有感情

**来源**：社交关系 > 问卷 > 管理者推荐 > 人传人

**运营策略**：
1. **激发参与感**——让用户参与每个环节（从概念验证到宣贯）
2. **提供高级甜点功能**——别人没有的专属功能
   - **案例**：App提供"其他销售搜了你客户时给你发通知"的甜点功能
3. **建立个人关系**——请喝咖啡、送小甜点

### 运营大众用户

**推广节奏**：

```
1人（确保不拉垮）→ 3-10人（打磨基础体验）
    → 100人（验证业务价值）→ 1000人（分场景运营）
    → 全部用户（稳定迭代）
```

**大众用户三种群体**：

| 群体 | 占比 | 心态 |
|------|------|------|
| **尝鲜者** | ~10% | 愿意聊天、愿意试 |
| **无所谓者** | ~70% | 你让用我就用，大家不用我也不用 |
| **强烈反对者** | ~10-15% | 会骂街、会赖你影响业绩 |

**推广策略**：

| 策略 | 说明 |
|------|------|
| **抓前10%推广** | 介绍创新背景，营造"兄弟我懂你"的感觉 |
| **实机演示** | 有剧本的真实场景演示，不要只发图文 |
| **明星效应** | 把种子用户树为明星，展示他们的数据 |
| **制造稀缺** | "只给20%的管理团队用"→让管理者抢着要 |
| **持续刷存在感** | 每天/每周发新版本和数据 |
| **管理手段** | 进入1000名用户范围后谨慎使用 |
| **保留回退能力** | 给10%的强烈反对者开白名单回退 |

**心态分享**：第一次落地AI应用，长达半年都在被骂。只要三个指标在持续正向增长、种子用户反馈在变好，就要扛住吐槽，等待习惯迁移。

> 真实案例：一开始有几个用户死都不用，还阻止别人用；一个季度后说"给你下了"，全都抢着要。使用率从20%涨到90%。

## 第三节 运营管理者和团队

### 管理者心理：两要两怕

| 角色 | 想要 | 怕 |
|------|------|----|
| **直线老板** | 成绩、口碑 | 偏离方向、团队不专业、项目失败 |
| **业务老板** | 对业务有帮助 | 新技术没价值、影响现有流程、被替代 |
| **技术老板** | 技术产出 | 预期过高兜不住、人力浪费、被干预技术方案 |

### 运营管理者的策略

#### 1. 书面文档 + 面对面沟通

- 详细写下为什么做、方案、周期
- 面对面沟通时**不要念文档**，拿笔画、当面聊
- 文档体现正式，沟通体现参与感

#### 2. 师出有名

- ❌ 不要说"AI要来了，我们要技术创新"
- ✅ 讲"公司商业目标是什么→业务目标是什么→遇到什么问题→想用新技术试试"

#### 3. 永远管理预期

- "先试一试：小成本、短周期、小团队"
- 做开门红项目，不要憋大招

#### 4. 理性+感性混合说服

| 说服方式 | 说明 |
|----------|------|
| **理性说服** | 量化的业务价值——用第一章找到的价值量化关系 |
| **感性说服** | 一线原生话——"现在就像个机器人，每天在那打标" |

#### 5. 合伙创新

邀请各合作团队出有分量的人，以**合伙人身份**加入项目。

#### 6. 体系化信息传递

**传递内容**：
- 项目过程和细节
- 成果马上传递
- AI能解决公司问题
- 先进经验可以沉淀复制

**传递方式**：以**定期抄送邀请**的方式进行

| 方式 | 说明 |
|------|------|
| **日报/周报/例会抄送** | 立项时说好，每天发，不看不重要，要有掌控感 |
| **产品和方案演示会** | 让业务老板实打实看到成果 |
| **案例分享会** | 分享成功案例，正向信号 |
| **复盘会** | 分享先进经验，指出团队问题 |

**需要避免**：
1. ❌ 闭门造车
2. ❌ 所有场合自己汇报——让合伙人轮流汇报
3. ❌ 夸大事实——符合事实传递
4. ❌ 讲技术语言——尤其对业务老板
5. ❌ 单向输出——营造"请老板们帮忙解决问题"的氛围

### 案例：素材库团队运营管理者

1. **师出有名**：公司要提升销量、建设品牌营销能力→需要加大素材库投入→提升管理效率→所以做AI打标
2. **管理预期**：只说做一个月小项目试一试
3. **理性说服**：标签准确率→素材使用率→转化率提升
4. **感性说服**：一线原声——"每天在那打标，糊弄事儿"
5. **项目日报抄送直属领导**
6. **业务老板担任项目投资人**——"没有你就没有这个项目"
7. **技术同学负责对外演示**——增加中后台团队的参与感

### 运营项目团队

#### 团队构成

```
           管理层（直线老板/业务老板/技术老板）
                      ↑
                项目负责人/产品经理
                    /    |    \
             运营代表  产品代表  技术合伙人
              (业务)   (设计/产品) (工程/算法/测试)
                      ↑
             用户代表（最佳实践/种子用户）
```

#### AI项目协作特点

| 特点 | 说明 |
|------|------|
| **有分工无边界** | 知道各自角色，但问题出现一起上 |
| **快节奏试错** | 不互相苛责，宽容错误 |
| **不怕吐槽** | 一起解决问题 |

#### 运营团队策略

1. **源头筛选**——找有创新意识、有成长动力的核心成员
2. **合伙人制**——邀请以合伙人身份加入
3. **鼓励专业主导权**——"这块我不懂，你给我讲讲"，鼓励在自己领域多尝试
4. **透明协作**——问题不藏着掖着，建立迭代机制一起Review
5. **带头担责**——有问题你冲上去，出错名字先写你
6. **持续布道**——不断分享AI新资讯、实际作用和价值

### 本章总结

1. **产品运营决定生死**——要提升到和做产品方案、迭代机制同样的高度
2. **运营三类用户**：最佳实践（建标准）→ 种子用户（打磨）→ 大众用户（推广使用）
3. **运营三类管理者**：直线老板（过程透明）→ 业务老板（师出有名）→ 技术老板（合伙创新）
4. **运营项目团队**：营造有分工无边界、快节奏试错、一起解决问题的氛围
