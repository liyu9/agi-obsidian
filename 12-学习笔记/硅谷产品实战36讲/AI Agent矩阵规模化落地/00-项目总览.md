> 方法论映射：需求验证三步法 → 成功指标4步法+反指标 → 数据驱动迭代 → P0/P1/P2优先级

## Agent搭建全流程标准（6步流水线）

```
Step 1：场景分析与对话流程设计
  ├── 业务场景拆解（高频问题/痛点/流程）
  ├── 多轮对话流程图绘制
  └── 人工介入节点标注
Step 2：意图识别体系梳理
  ├── 意图分类树（一级/二级/三级）
  ├── 意图识别训练数据准备
  └── 边界意图处理策略
Step 3：RAG知识库搭建
  ├── 知识源梳理与质量评估
  ├── 文档切片与向量化策略
  └── 检索效果测试与调优
Step 4：分层Prompt工程
  ├── 系统层Prompt（角色/边界/安全）
  ├── 场景层Prompt（业务规则/流程）
  └── 对话层Prompt（话术/语气/转人工）
Step 5：多渠道接入与工单联动
  ├── 多渠道统一接入
  ├── 工单自动创建与流转
  └── 人工转接与上下文传递
Step 6：上线→监控→迭代
  ├── 灰度发布与效果基线
  ├── Bad Case自动发现与分类
  └── 闭环修复与效果回归
```

## 规模化落地路径（P0/P1/P2优先级 + 增长代价评估）

> 参照"优先级与权衡取舍"方法论：P0/P1/P2分级 + "一定不优先"板块 + 增长代价量化

### 场景优先级矩阵

| 优先级 | 场景 | 判断依据 | 增长代价评估 |
|--------|------|---------|-------------|
| **P0** | 智能客服Agent | 痛点最明确、ROI可量化、技术成熟度最高 | 低：客服人力释放可自然转化为高价值服务 |
| **P0** | 对外客服Agent | 高模板化问题占比大，MVP方案（模板同步）成熟度高 | 低：模板方案合规风险小 |
| **P0** | 数据分析Agent | 取数需求高频、NL2SQL技术成熟 | 中：需防范口径不一致导致决策失误（反指标管控） |
| **P1** | 产品需求Agent | 降本明确但验证周期长 | 中：PRD质量不达标会增加下游返工（侵蚀效应） |
| **P2** | 运维自愈Agent | 主动执行能力要求高、安全风险大 | 高：误操作可能造成生产事故（必须量化安全反指标） |

### "一定不优先"板块

- 需要强实时性的风控决策场景（误判代价不可控）
- 涉及用户隐私数据直接处理场景（合规风险高）

### 核心优化机会

| 机会 | 估测影响 | 优先级 |
|------|----------|--------|
| 意图体系模板化（按行业预置意图分类树） | 梳理耗时5天→1天 | P0 |
| RAG知识库搭建向导化 | 减少50%返工 | P0 |
| Bad Case自动发现与分类 | 修复周期7天→3天 | P0 |
| 跨场景意图复用 | 降低新场景成本30% | P1 |

## 多Agent编排模式选择

| 模式 | 架构 | 适用Agent场景 |
|------|------|-------------|
| Pipeline（流水线） | Stage1→Stage2→Stage3 | 产品需求Agent（调研→MRD→PRD） |
| Supervisor（监督者） | Supervisor→[专家A/B/C] | 数据分析Agent（Plan→SQL/Code/RAG） |
| Swarm（蜂群） | Task→[Worker1...N]→Merge | 智能客服（批量意图分类+知识检索） |

**选择原则**：用满足需求的最低复杂度方案（参照MVP原则——最小化降低试错成本）

## Bad Case闭环迭代机制（通用）

```
自动发现 → 分类 → 归因 → 修复 → 回归验证
```

### 数字员工自我进化——五步漏斗

| 步骤 | 问题 | 数据源 | 输出 |
|------|------|--------|------|
| 1 | 哪些任务做得差？ | L2定量评估 | 最差的N条任务 |
| 2 | 差在哪一步？ | L3步骤下钻 | 具体失败的ReAct步骤 |
| 3 | 人类怎么看？ | L1交叉验证 | 人类纠正记录 |
| 4 | 根因是什么类型？ | 枚举分类 | sop_gap / prompt_ambiguity / ability_gap / integration_issue |
| 5 | 改哪个文件的哪一段？ | 精确改动 | before/after锚点替换 |

### 根因枚举与改动对象

| 根因 | 含义 | 改动对象 |
|------|------|---------|
| sop_gap | 流程缺步骤 | agent.md / skills/*.md |
| prompt_ambiguity | 指令模糊 | soul.md |
| ability_gap | 经验不足 | memory.md |
| integration_issue | 协作问题 | agent.md协作部分 |

## Sub-Agent契约模式

每个Sub-Agent应定义6项契约：

| 契约项 | 说明 |
|--------|------|
| Specific scope | 处理范围 |
| Clear goal | 成功标准 |
| Constraints | 约束条件 |
| Expected output | 输出格式（JSON Schema） |
| Timeout | 超时策略 |
| Retry | 重试策略 |
