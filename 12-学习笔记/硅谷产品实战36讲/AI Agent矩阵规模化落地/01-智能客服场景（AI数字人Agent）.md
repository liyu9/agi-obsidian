# 智能客服场景（AI数字人Agent）— 详细设计

> **产品设计方法论映射**：本场景严格按照"需求验证三步法→成功指标4步法+反指标→数据驱动迭代"闭环设计
> 方法论来源：[[产品设计核心知识总结]]

---

## 1. 需求验证（三步法）

| 步骤 | 内容 |
|------|------|
| **确认用户** | 企业客服侧（B端企业员工：IT/行政/人事咨询）、游戏客服侧（C端玩家） |
| **痛点假设** | ①重复性咨询占比高（70%+为通用问题）②人工响应慢（平均10分钟）③夜间/节假日无人值守 ④情绪识别粗放（负面→直接转人工，30%不必要转人工）⑤传统FAQ机器人无法执行操作（只能回答，不能闭环解决） |
| **验证假设** | 历史工单数据：70%+为通用咨询可自动化处理；响应时长达10分钟；传统情绪策略"负面→转人工"导致30%不必要转人工 |

**用户问题说明**：作为企业员工/游戏玩家，我想快速获得7×24小时咨询服务，从而帮助我减少等待时间、一次性解决问题

---

## 2. 产品定位与核心能力

**定位**：企业内部智能服务平台，为员工提供7×24小时的IT、行政、人事等咨询服务，提升内部服务效率

**核心能力矩阵**：

| 能力 | 说明 | 技术实现 |
|------|------|---------|
| 多渠道接入 | 支持多系统、多软件统一接入 | 统一入口层 + 适配器模式 |
| 意图识别 | 基于大模型语义理解，准确识别咨询意图 | 原生意图识别节点（从"大模型JSON解析"升级） |
| 知识库管理 | 支持结构化和非结构化知识导入，自动更新维护 | 混合检索（语义+全文）+ Rerank |
| 多轮对话 | 支持上下文理解，处理复杂多轮咨询 | 上下文追踪 + 智能追问 |
| 工单自动流转 | 无法自动解决的问题，自动生成工单并分配给对应部门 | 工单自动创建 + 部门路由 |
| 情绪分级处理 | 两级情绪分级，非简单"负面→转人工" | 情绪检测 + 分支路由 |
| 运维MCP | 从问答升级为执行，主动运维能力 | MCP Server对接Log系统/控制中心 |

## 3. 五层架构设计

```
┌──────────────────────────────────────────────────────────┐
│  入口层                                                    │
│  用户输入 → 缓存规则读取 → 缓存匹配                          │
│  └─ 找人工两次触发机制 + 挽留引导                             │
├──────────────────────────────────────────────────────────┤
│  意图层                                                    │
│  意图识别 + 情绪检测 + 分支路由                               │
│  └─ 原生意图识别节点（速度更快、配置更简单）                    │
├──────────────────────────────────────────────────────────┤
│  知识层                                                    │
│  知识库检索 + 命中判断                                       │
│  └─ 混合检索（语义+全文）+ Rerank，防无限引导                  │
├──────────────────────────────────────────────────────────┤
│  生成层                                                    │
│  答案生成 + 审核 + 重试                                      │
│  └─ 循环节点2次循环 + 中间变量跨轮传递修订建议                  │
├──────────────────────────────────────────────────────────┤
│  输出层                                                    │
│  转接原因生成、联系方式引导、对话记录、回复输出                   │
│  └─ 全链路数据落库（6字段），支持后续分析优化                    │
└──────────────────────────────────────────────────────────┘
```

### 3.1 入口层

| 组件 | 机制 | 设计要点 |
|------|------|---------|
| 缓存规则读取 | 语义缓存（Semantic Cache） | 三层缓存架构：Embedding缓存→检索结果缓存→答案缓存 |
| 缓存匹配 | 精准匹配（Key-Value）+ 语义检索（向量Top-K） | 高频问题命中响应10-50ms，目标命中率>60% |
| 找人工触发 | 两次触发机制 | 首次"找人工"→挽留引导，二次确认→转人工，减少误触 |
| 挽留引导 | 展示Agent可解决能力 | "我可以帮您处理XX问题，是否先试试？" |

**语义缓存三层架构**：

| 层级 | 缓存内容 | 存储方式 | TTL策略 |
|------|---------|---------|---------|
| L1 答案缓存 | FAQ类问题完整回答 | Redis，毫秒级读取 | 永久/知识库更新时清除 |
| L2 检索结果缓存 | 文档ID列表 | 内存，避免重复向量库查询 | 24h/知识库更新时清除 |
| L3 Embedding缓存 | 常见查询向量表示 | 离线预计算 | 静态，模型更新时重建 |

> **行业数据**：80%请求集中在20%问题类型（二八法则），缓存命中率<30%说明策略有问题

### 3.2 意图层

| 组件 | 机制 | 关键指标 |
|------|------|---------|
| 意图识别 | 原生意图识别节点（非大模型JSON解析） | 通用准确率80%，垂直场景90% |
| 情绪检测 | 三级分类：正向/中性/负向 | 准确率目标≥90% |
| 分支路由 | 意图+情绪→路由决策 | — |

**情绪分级处理（项目亮点）**：

| 情绪级别 | 处理策略 | 效果 |
|----------|---------|------|
| 正向/中性 | 正常Agent流程 | — |
| 轻微负面 | 正常流程（带情绪安抚话术） | **减少30%不必要转人工** |
| 强烈负面 | 自动转人工 + 上下文传递 | 保证服务质量 |

> **行业对比**：业界常见方案是"负面情绪→转人工"，本方案做了两级分级，是差异化亮点。Gartner数据：情绪识别当前准确率49%尚不成熟，三级分类（正/中/负）是当前可行路径

**意图识别升级路径**：

```
V1: 大模型JSON解析（慢、配置复杂、易出错）
  ↓ 升级
V2: 原生意图识别节点（速度快、配置简单、垂直场景90%准确率）
  ↓ 规划
V3: 意图体系模板化（按行业预置意图分类树，梳理耗时5天→1天）
```

### 3.3 知识层

**混合检索策略（项目亮点）**：

| 检索方式 | 权重 | 适用场景 |
|----------|------|---------|
| 语义检索（向量） | 70% | 自然语言表述、模糊匹配 |
| 全文检索（关键词） | 30% | 精确匹配代码/错误码/时间约束 |

> **核心公式**：`score = 向量得分 × 0.7 + 全文得分 × 0.3`
> **效果**：从纯语义检索升级为混合检索，**召回率提升35%**
> **行业结论**：生产级方案是混合检索，不是纯向量；召回效果80%取决于chunk质量，20%取决于embedding模型

**降级重试策略**（防无限引导）：

```
搜索结果为空
  → Step1: 去掉时间限制重试
  → Step2: 去掉标签限制重试
  → Step3: 切换纯语义搜索模式
  → Step4: 返回兜底话术 + 转人工引导
```

**知识库覆盖率**：95%（当前基线）

### 3.4 生成层

**循环节点审核重试（项目亮点）**：

```
答案生成 → 质量审核 → {
  通过 → 输出层
  不通过 → 携带修订建议重试（最多2次）
    → 第1次重试：中间变量传递审核反馈
    → 第2次重试：降低自由度（高匹配→复述；低匹配→推理）
    → 仍不通过 → Fallback转人工
}
```

| 参数 | 设定 | 原因 |
|------|------|------|
| 最大循环次数 | 2次 | 兼顾质量与响应时间 |
| 审核维度 | 准确性+完整性+安全性 | — |
| 跨轮传递 | 中间变量传递修订建议 | 避免从零重试，提升修正效率 |
| Fallback | 转人工 | 兜底保障 |

### 3.5 输出层

**全链路数据落库（6字段）**：

| 字段 | 用途 | 后续分析价值 |
|------|------|-------------|
| 用户问题 | 原始输入 | 意图覆盖率分析 |
| 意图 | 识别结果 | 意图准确率评估 |
| 场景 | 路由结果 | 场景分布统计 |
| 答案 | 生成结果 | 质量抽检 |
| 转接原因 | 转人工根因 | Bad Case归因 |
| 时间戳 | 时序数据 | 趋势分析 |

## 4. 分层Prompt工程体系

| 层级 | 内容 | 职责 | 示例 |
|------|------|------|------|
| 系统层Prompt | 角色/边界/安全 | 定义Agent身份、行为边界、安全红线 | "你是XX企业智能客服，不可透露内部工号、系统架构" |
| 场景层Prompt | 业务规则/流程 | 定义特定场景的业务逻辑和决策规则 | "IT故障场景：P0级→立即转人工；P1级→先自查日志再回复" |
| 对话层Prompt | 话术/语气/转人工 | 定义交互风格和转人工策略 | "语气亲和专业，检测到用户强烈负面情绪→自动转人工" |

## 5. 运维MCP：从问答升级为执行

**核心架构**：

```
MCP Client（Agent端）                    MCP Server（运维系统端）
  ├── 理解用户意图                        ├── 暴露Log查询能力
  ├── 推理决策                            ├── 暴露控制中心读取能力
  └── 调用运维工具                        └── 暴露诊断报告生成能力
           │                                        │
           └──────── X-User-Id鉴权 + Tool白名单 ────┘
```

**执行闭环**：

```
用户反馈问题 → Agent自动查询日志 → 识别根因 → 输出诊断报告 → 指导用户处理 / 自动执行运维操作
```

**分阶段实施策略（MVP原则）**：

| 阶段 | 能力范围 | 风险控制 |
|------|---------|---------|
| MVP | 仅"指导处理"（输出诊断报告+操作建议） | 不自动执行，人工确认后操作 |
| P1 | 开放"自动执行"低风险运维操作 | 白名单控制 + 操作审计 |
| P2 | 扩展高价值运维场景自动闭环 | 灰度验证 + 回滚机制 |

## 6. Bad Case闭环迭代机制

```
自动发现 → 分类 → 归因 → 修复 → 回归验证
```

| 步骤 | 方法 | 数据源 | SLA |
|------|------|--------|-----|
| 发现 | 全链路数据落库 + 自动质量巡检 | 6字段对话记录 | 实时 |
| 分类 | 意图错误/知识缺失/生成错误/情绪误判 | Bad Case标签体系 | ≤4h |
| 归因 | 根因枚举：sop_gap / prompt_ambiguity / ability_gap / integration_issue | L3步骤下钻 | ≤1天 |
| 修复 | 精确改动：before/after锚点替换 | Prompt/知识库/意图体系 | ≤2天 |
| 验证 | 回归测试 + 线上灰度 | 效果对比 | ≤3天 |

> **目标**：Bad Case修复周期≤3天，同类错误复发率≤10%

## 7. 成功指标体系（4步法 + 反指标）

**第一步：产品最高目标** → 承接70%+通用咨询问题，实现7×24小时智能服务

**第二步：子指标分解**

| 类别 | 指标 | 当前值 | 目标值 | 行业对标 |
|------|------|--------|--------|---------|
| 效率 | 平均响应时间 | 10分钟 | 1分钟 | AI客服≤1.5秒 |
| 效率 | 人工客服成本降低 | — | 60% | 行业60%-80% |
| 效率 | Bad Case修复周期 | 7天 | ≤3天 | — |
| 质量 | 意图识别准确率 | 80%（垂直90%） | 90%+ | 大厂93% |
| 质量 | 知识库覆盖率 | 95% | 维持95%+ | — |
| 质量 | 一次性解决率(FCR) | 35% | 62%（企业）/ 55%（游戏） | Agentic AI 80%自闭环 |
| 体验 | 客户满意度(CSAT) | 60%+（有下降趋势） | 75%+ | Agentic AI相对提升20% |
| 规模 | 游戏客服月处理会话 | — | 10万+ | — |

**第三步：功能与指标关系**

| 功能模块 | 影响指标 | 影响方向 |
|----------|---------|---------|
| 混合检索 | 知识库召回率 | +35% |
| 情绪分级处理 | 不必要转人工率 | -30% |
| 循环节点审核重试 | 答案质量/FCR | 正向 |
| 语义缓存 | 响应时间 | 缓存命中时10-50ms |
| 运维MCP | FCR/问题闭环率 | 正向（从回答升级为执行） |
| 原生意图识别节点 | 意图识别准确率 | 通用80%→垂直90% |

**第四步：反指标（必须量化）**

| 反指标 | 安全阈值 | 降级策略 |
|--------|---------|---------|
| Agent幻觉率 | ≤5% | >8%自动降级为保守模式 |
| 误转人工率 | ≤10% | >15%暂停转人工自动化 |
| 客户投诉率 | ≤3% | >5%暂停自动回复全部转人工 |
| 知识库漂移率 | ≤5% | 知识库定期校验 + 更新触发缓存清除 |
| Bad Case复发率 | ≤10% | 复发率高说明闭环无效，需重新归因 |
| 缓存命中率 | >60% | <30%说明缓存策略有问题，需调整 |
| CSAT下降率 | ≤5%/月 | 持续下降需全面Review |

## 8. 项目亮点总结

| 亮点 | 业界常规方案 | 本方案差异 | 量化效果 |
|------|------------|-----------|---------|
| 情绪分级处理 | 负面→转人工 | 两级分级：轻微负面走正常流程 | **减少30%不必要转人工** |
| 循环节点审核重试 | 单次生成输出 | 2次循环+审核+修订+Fallback转人工 | 兼顾质量与体验 |
| 混合检索策略 | 纯语义检索 | 语义(70%)+全文(30%)+Rerank | **召回率提升35%** |
| 全链路数据落库 | 仅记录问答 | 6字段结构化落库 | 支持Bad Case闭环归因 |
| 原生意图识别节点 | 大模型JSON解析 | 原生节点 | 速度更快、配置更简单 |
| 运维MCP | 仅问答 | MCP对接运维系统 | 从回答升级为执行 |
| 语义缓存 | 无缓存 | 三层缓存架构 | 命中时10-50ms响应 |

## 9. 后续规划（P0/P1/P2优先级）

| 优先级 | 规划项 | 预期效果 | 依据 |
|--------|-------|---------|------|
| **P0** | 语义缓存优化 | 命中率>60%，高频问题10-50ms响应 | 80%请求集中在20%问题 |
