# 项目成果与验证

> 来源课程：硅谷产品实战36讲（PRD/项目验证）、三节课-产品经理高阶课（从MVP到PMF）、PM需求方法论

---

## 一、核心理念

项目验证的核心是**通过MVP不断提出假设、在市场中验证、快速迭代，找到PMF（产品与市场匹配）**。

> PMF不是找出来的，而是试出来的。

---

## 二、方法论：产品需求文档（PRD）

PRD不要求面面俱到，但必须写出团队真正需要的内容。

### PRD五大内容

| 序号 | 内容 | 说明 | 常见坑 |
|------|------|------|--------|
| 1 | **要解决什么问题** | 让团队对痛点保持一致 | 成员对问题理解不在一个频道 |
| 2 | **论证痛点确实存在** | 用数据验证，不能想当然 | 最容易踩的坑——没有验证就写痛点 |
| 3 | **成功指标和反指标** | 明确衡量标准，包括负面影响 | 忽略反指标和侵蚀效应 |
| 4 | **用户场景** | 不同场景差别很大，需分别描述 | 场景信息丰富度不同，设计思路也应不同 |
| 5 | **产品功能方案** | 六个方面（见下表） | 事先没想清楚的地方最容易出问题 |

### 功能方案六个方面

| 方面 | 说明 |
|------|------|
| 如何开启功能 | 入口点 |
| 流程图 | **最重要的部分**，每种场景的步骤流程 |
| 复用已有架构 | 大大节约开发时间 |
| 跨组协作 | 提前沟通 |
| 异常情况方案 | 功能无法达到预期时的兜底 |
| 可能的坑 | 事先没想清楚的地方会出问题，可能导致从头来 |

### 案例：豆瓣图书推荐 — PRD完整推演

1. **问题：** 用户渴望通过个性化方式找到感兴趣且评分高的书
2. **验证：** 35%豆瓣用户已习惯通过豆瓣找书，特别是探索新书 → 痛点真实存在
3. **成功指标：** 通过推荐功能下载/购买图书的次数
4. **反指标/侵蚀效应：** 豆瓣其他产品（电影、电视剧）的使用频率是否降低
5. **场景：** 已选书推荐（信息丰富）/ 选主题推荐（信息有限）/ 首页个性化推荐（信息最少）
6. **坑：** 重复推荐（《爱的教育》有无数版本，评论分散导致畅销排名失真）

## 三、方法论：从MVP到PMF

### 什么是PMF

PMF（Product-Market Fit）= 产品与市场匹配。由马克·安德森2007年提出：**你的产品和市场所属的阶段要匹配，如果匹配会进入增长阶段，不匹配增长不会明显。**

### PMF不匹配的两种情况

| 类型 | 说明 | 案例 |
|------|------|------|
| **产品脱离市场** | 产品先进但市场没准备好 | Color（照片分享）、Meerkat（直播鼻祖）、饭否（中国推特） |
| **产品被市场套牢** | 产品还行但出现全新市场没抓住 | MSN（错过移动社交）、柯达（错过数码市场）、人人网（错过移动端） |

### 找到PMF的三条路径

| 路径 | 说明 | 案例 |
|------|------|------|
| **提供更好体验** | 比现有方案更好 | Slack（极简项目管理）、美图秀秀（更易用的手机P图） |
| **抓住细分市场** | 从非常垂直的细分切入 | Uber（大城市打不到车的人）、P2P（银行看不上小额贷款） |
| **定义全新市场** | 创造全新功能/交互，用户逐步接受 | 微博的@、探探的左滑右滑 |

> 抄不到点上的原因：只抄了形式，没抄到用户体验的核心价值点。

### PMF的判断标准

**C端产品（满足任一即可谨慎推广，全部满足可大力投放）：**

| 指标 | 临界点 |
|------|--------|
| 次日留存 | ≥30% |
| 新增DAU | ≥1000/天（中国市场） |
| 用户量 | 达到10万 |
| 平均使用天数 | 每周超过3天 |

**付费产品：**

| 指标 | 临界点 |
|------|--------|
| 付费转化率 | ≥5%（非常难达到） |
| LTV/CAC | 客户收入/获客成本 > 3 |
| 付费用户月流失 | <2% |
| 月毛利收入 | 达到10万（美金） |
| 客户回本时间 | <12个月 |

> **核心原则：** PMF没到千万别砸钱推广。砸钱 = 打水漂。

### MVP与PMF的循环关系

```
Idea → MVP验证 → 找到关键增长点 → PMF
                    ↑                    ↓
                    ← 迭代优化 ←─────────┘
```

1. 明确用户需求 → 设计MVP
2. 小范围推广测试 → 观察用户接受度
3. 在那么难用的情况下，用户是否还愿意继续使用？
4. 找到不错的点 → 上线测试 → 循环迭代
5. 让更多用户进来 → 找到增长点 → 进入成长期

## 四、方法论：A/B测试验证

### 流程

1. 设定实验组和对照组
2. 实验组加新功能，对照组不加，其他条件一样
3. 观察成功指标和反指标变化
4. 设定量化提升目标（如5%）

### 决策逻辑

| 情况 | 决策 |
|------|------|
| 成功指标增加显著 + 反指标控制住 | 发布功能 |
| 成功指标提升低于目标（如5%） | 砍掉功能 |
| 成功指标增加但反指标恶化 | 权衡取舍，可能需高层决策 |

### 关键注意事项

1. **警惕新鲜感效应** — 刚上线指标好看不等于真的好，等数据稳定
2. **多指标按重要性排序** — 出现矛盾时可以权衡
3. **量化标准不可少** — "感觉还行"不是决策依据

## 五、案例

### Dropbox — 零代码验证PMF

- 上线前做3分钟演示视频 + 邮箱注册
- 一夜之间5000人飙升至75000人等待邀请
- 零代码就验证了需求，获得信心投入开发

### VIPKid — 用微信群验证

- 最早没有产品，在微信群里面上课
- 后来用第三方学习系统，改了logo就上线
- 用户上完体验不错 → 验证产品价值 → 再投入开发

### 霞服饰（Zappos）— 用别人的货验证

- 最早不进货，把亚马逊卖鞋页面重新做详情页
- 用户下单后，再去亚马逊下单发货
- 验证了"对鞋的描述能吸引用户" → 开始进货建仓库 → 最终被亚马逊收购

### 丁东小区 — PMF没到就砸钱的反面案例

- 产品刚上线就在北上广深地铁砸广告
- 砸完广告后次日留存只有个位数
- 用户兴冲冲下载后发现是空的 → 卸载
- 教训：产品本身没给用户带来价值就推广 = 烧钱

### ClassPass — 从PMF不符到找到PMF

- V1：健身课程搜索引擎 → 不温不火
- V2：免费体验包 → 效果不错，用户换邮箱重复领
- V3：付费订阅80美金/月 → 找到PMF
- 关键洞察：用户愿意花更大成本薅羊毛 = 产品有价值，把价值放大变成可接受的产品

### 明星用户功能发布危机 — 权衡取舍

- iOS发现Bug导致95%用户看不到新功能，修复需2周
- 安卓已测试完毕，明星好评如潮
- 方案：其他产品照常发布，iOS普通用户部分推迟2周
- 先让明星形成使用习惯，2周后再展示完整数据激励

## 六、要点速查

| 概念 | 一句话定义 |
|------|-----------|
| PRD五大内容 | 痛点 → 论证痛点 → 指标+反指标 → 场景 → 功能方案 |
| PMF | 产品与市场匹配，不是找出来的而是试出来的 |
| PMF判断 | C端：30%次日留存+DAU≥1000；付费：5%转化率+LTV/CAC>3 |
| PMF未到不推广 | 没找到PMF就砸钱 = 打水漂 |
| 三条PMF路径 | 更好体验 / 抓细分市场 / 定义全新市场 |
| A/B测试 | 实验组vs对照组，量化目标（如5%），等数据稳定 |
| 侵蚀效应 | 新功能挤占原有产品成绩（cannibalization） |
