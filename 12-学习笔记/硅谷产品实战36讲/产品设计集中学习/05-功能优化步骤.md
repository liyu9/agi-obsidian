# 功能优化步骤

> 来源课程：三节课-产品经理高阶课（业务驱动模型/产品规划）、硅谷产品实战36讲（优先级/权衡取舍）

---

## 一、核心理念

功能优化的关键不是"什么都做"，而是**找到业务驱动因素，集中资源攻克关键点**。

> 小明的教训：看到产品问题很多，马上大改版、调动全公司资源，搞了两个月每件事都没做到头，没做出明显产出。他没有找到整个产品里最关键的那个点。

---

## 二、方法论：建立业务驱动模型

### 什么是业务驱动模型

通过不同的归因和分析方式，找到整个业务快速发展的**引擎**。这个引擎让你一脚油门踩下去真正往前跑，而不是一脚油门一脚刹车。

### 三步法

#### 第1步：确认驱动方式（单边/双边/多边）

| 类型 | 定义 | 优化方向 | 案例 |
|------|------|---------|------|
| **单边** | 向一类角色提供价值 | 做好用户体验 | 美图相机、讯飞语记、腾讯新闻 |
| **双边** | 两类不同角色完成交易/服务 | 平衡供需两端 | 滴滴（司机+乘客）、微博（创作者+读者） |
| **多边** | 三类及以上角色在平台完成交易 | 协调多方利益 | 微博+MCN、商场+服务商+顾客 |

#### 第2步：按驱动模型分析核心影响因素

**单边驱动 → 鱼骨图分析法**

1. 提出用户的核心体验是什么
2. 列出5个以内关键因素（不超过5个）
3. 每个因素下列出子因素
4. 分析哪个是最重要的

> 案例：共享单车
> - 核心体验：下楼就有车骑，最好便宜或免费
> - 关键因素：车辆覆盖率、APP易用性、骑行体验、硬件质量、价格
> - 子因素（覆盖率）：投放能力、车辆生产速度、BD能力（政府审批）

**双边/多边驱动 → 找到飞轮效应的关键起点**

> 案例：Uber
> - 用户需求 = 快速接单 + 价格不贵
> - 推导链条：更低价格 → 司机接更多活 → 缩短空闲时间 → 更小的区域覆盖 → 更集中的订单 → 司机接单意愿更强 → 更多需求
> - **关键因素：更好的区域覆盖（更多司机）**
> - 第一阶段策略：获取更多司机
> - 第二阶段策略：邀请制刺激需求（邀请双方各得25美金）

#### 第3步：集中资源倾斜到关键因素

找到当前阶段最关键的因素，做资源集中倾斜。一个阶段all in一个事情效果最好。

## 三、方法论：功能优先级与权衡取舍

### 优先级等级

| 等级 | 含义 |
|------|------|
| P0 | 现在要做 |
| P1 | 有空就做 |
| P2 | 一定来不及做 |

> 10个功能中最多3个最优先，一定有3个不优先。

### 四大误区

1. **认为所有功能都优先** = 所有都不优先
2. **优先的功能是最简单的功能** — 应该是最有价值的功能
3. **只考虑工程难度和效果，忽略潜在风险** — 尤其是跨组合作的风险
4. **没有明确"最优先"的定义** — 是否重要到推迟发布也要等？

### 产品发布前权衡取舍四步法

1. **明确功能问题的风险和受影响的人群**
2. **列出所有可行选项及对每个群体的影响**
3. **分析各选项的风险**
4. **有大局观，选择代价最小的方案**

> 判断标准："这个是不是launch blocking？" — 没有这个功能会不会影响产品发布？

### 产品经理三原则

- **无知**：不马上下结论，保持好奇心，提出假设再验证
- **无畏**：制定有难度的成功指标，激发团队潜力
- **无情**：不管想法多好，都分出主次，明确一定不做什么

> Instagram老板在路线图中加"一定不优先"板块，专门写明确不做的事情，减少干扰。

## 四、方法论：中长期产品规划

### 靠谱规划的三要素

1. **业务发展与环境匹配** — 供应链、后端、培训、销售是否准备好了？不能只看前端功能
2. **解决阶段性问题/挑战** — 不是功能罗列，而是为了应对挑战的可解决的方案
3. **与公司和其他部门步调一致** — 功能和上下游、公司整体有直接关系

### 四种思考方向

| 方向 | 说明 | 典型场景 |
|------|------|---------|
| **数量的变化** | 用户量/订单量/数据量剧增带来新问题 | 订单暴增冲击后端 |
| **类型的变化** | 用户群/品类扩展，对老用户和模式带来冲击 | 一线城市→下沉市场；卖书→卖电器 |
| **产品阶段变化** | 不同生命周期侧重点不同 | 探索期→成长期→成熟期 |
| **产品走向** | 根据产品定位和未来走向思考 | 边缘项目→流量项目→收入项目→明星项目 |

### 规划的核心价值

- **方向清晰**：明确阶段目标、困难挑战、项目与方向匹配
- **上传下达**：清晰持续说明计划，让资源倾斜，让同事达成一致
- **提前思考**：不一定马上动手，但碰到好的案例/反馈会自然归拢到未来项目

> 不要骑墙——既要做A又要做B又要做C。而是说进阶段重点解决A，下一阶段重点解决B。

## 五、案例

### Uber — 业务驱动模型的经典推演

- 关键因素：更好的区域覆盖（更多司机）
- 第一阶段：获取更多司机
- 第二阶段：邀请制刺激需求（邀请双方各得25美金→15美金→几美金）
- 结果：司机增加→覆盖提升→接单更快→需求增加→更多司机

### 小明的反面案例 — 没找关键点

- 看到二手交易平台问题很多：卖家不好用、买家吐槽、审核问题、客服缺失
- 上手就大改版，调动全公司资源同时做所有事
- 搞了两个月，每件事都没做到头
- 教训：拆了并没有解，没有找到最关键的那个点

### ClassPass — PMF的迭代优化

- V1：健身课程搜索引擎 → 不温不火，PMF不符
- V2：免费多课程体验包 → 效果不错，但用户换邮箱重复领取
- V3：付费订阅（80美金/月，任选4-6个课程）→ 找到PMF
- 关键洞察：用户愿意花更大成本薅羊毛 = 产品有价值

## 六、要点速查

| 概念 | 一句话定义 |
|------|-----------|
| 业务驱动模型 | 找到业务快速发展的引擎，一脚油门踩下去真正往前跑 |
| 单边驱动 | 一类角色，优化用户体验即可 |
| 双边驱动 | 两类角色，平衡供需两端 |
| 多边驱动 | 多类角色，协调多方利益 |
| 优先级 | P0现在做、P1有空做、P2不做，10个功能最多3个最优先 |
| 三原则 | 无知（不妄下结论）、无畏（有难度指标）、无情（分主次） |
| 靠谱规划 | 业务与环境匹配 + 解决阶段性问题 + 与公司步调一致 |
