## 一、如何用数据做出产品决定（第14讲）

### 核心理念

用数据做产品决定不是拍脑袋，而是通过**形成具体假设 → A/B测试验证 → 找到影响规律 → 决定产品功能**的系统流程。每一步都要有数据支撑，避免想当然。

### 案例详解：通过提高新用户留存率来提高日活数

#### 背景与指标定义

团队发明了一个指标：**七天活跃天数（D7）**，直观体现留存率：
- D7=1：过去7天只使用了1天
- D7=7：过去7天每天至少使用1次
- D7>4：高活跃度用户
- 2<D7<4：中等活跃度用户
- D7<2：低活跃度用户

通过对已有数据的分析，发现很多低活跃度用户并没有关注其他用户，他们的朋友圈根本没有任何内容，只能通过搜索来看内容。

**初步假设：** 用户关注其他用户的数量会影响到用户留存率。但此时并不清楚其他因素是否会影响留存率。

### 第一步：形成具体假设

**问题1：影响用户留存率的原因是什么？**

这个问题需要分两种情况考虑：
- **假设A：** 用户没有关注其他用户（或关注数量非常少），朋友圈没有足够内容，在APP里停留时间非常短
- **假设B：** 用户没有被其他用户关注（或关注他的人非常少），虽然朋友圈有内容，但自己发内容时很少有人回复，久而久之丧失了对APP的激情

> **关键提醒：** 形成假设时要避免的坑是，切记要分情况考虑。不能简单地归类为"增加关注数"，而是要考虑清楚增加关注数其实影响了两类人——关注别人的人 vs 被关注的人，这两种情况带来的结果可能完全不一样，所以要分开考虑、分开假设。

**问题2：用户的关注数量到底会不会影响留存率？**

当用户关注100个人、1000人和只关注1个人时，对留存率的影响是同一个级别的吗？用户自己的粉丝数量会不会影响留存率？100个、1000个和1个粉丝时，是不是也会不同程度影响留存率？

### 第二步：A/B测试验证假设

**验证"关注其他用户"对留存率的影响：**
- 实验组：朋友圈推荐好友关注，可以直接一键关注所有人。推荐内容在每次打开朋友圈时出现在第一条状态上面，增加使用功能的概率
- 对照组：朋友圈没有这个功能，只显示已关注朋友的内容

**验证"被其他用户关注"对留存率的影响：**
- 实验组：把用户账号作为推荐放到其他用户朋友圈第一条，增加被关注概率
- 对照组：避免其账号被推荐给其他好友

**实验结果：**
- 帮助用户关注更多其他用户后，D7增加了**6%**
- 帮助用户获取更多粉丝后，D7增加了**4%**
- 说明帮助用户关注更多人或帮他们吸粉，都可以增加留存率

**时间维度验证：** 分别在用户使用APP的第一周、第二周、第三周和第四周帮助他们关注更多其他用户。
- **在用户开始使用的第一周就让他们关注更多人，效果最好**，否则非常容易流失，而且再也不回来了
- 第一周帮用户吸粉效果会好一些，但影响没有很明显

**产品策略决定：** 增加一个"你可能想关注"的版块，在新用户第一周使用APP时向他们推荐其他用户，并在板块里预留几个名额给其他新用户。这样既可以帮助新用户关注更多其他用户，又可以帮助新用户吸粉，**一箭双雕**。

后续优化：增加推荐系统，根据新用户提供的个人信息进行推荐，或根据新用户所在位置、年龄、手机类型等进行推荐。

### 第三步：找到影响规律（魔法数字）

**针对"关注其他用户"的假设：**
- 横轴：新用户第一周内关注其他用户的数量
- 纵轴：D7

发现当用户关注的其他用户数量在**20个左右**的时候就到了临界点，D7逐渐趋于平坦，增速显著放缓。

**"20"就是魔法数字。** 策略从"帮助新用户在第一周内关注更多的其他用户"调整为"帮助新用户在第一周关注20个其他用户"。

通过这个发现，又做出了另一个重要决定：开发一系列功能，帮助新用户快速发现、搜索其他用户，探索值得关注的主题以及每个主题对应的活跃用户，最终达到一周关注20个其他用户的目的。

**针对"用户粉丝数量"的假设：**
- 横轴：用户的粉丝数量
- 纵轴：D7

发现用户的粉丝量不在多，如果有几个**特别忠实的粉丝**给你评论、发消息，照样可以坚持在APP上发状态，增加D7。

**结论：** 需要帮助忠实粉丝找到你，让忠实粉丝在你刚使用APP发东西时就能找到你、关注你。

> **重要提醒：** 当你验证了某个指标对成功有影响时，不要仅仅停留于此，还要更深入研究这个影响是正面还是负面的、到底有多大、在什么情况下影响最大。你要找到那个可以发挥最大影响力的点（如"20"），否则会出现效果未达到预期或事倍功半的结果。

### 第四步：根据验证结果决定产品功能

基于上面的数据分析，决定做以下产品功能：
1. 将"你可能想关注"板块作为重点，特别是针对第一周使用APP的新用户
2. 板块中涵盖高质量老用户（帮助新用户找到有意思的内容）+ 其他新用户（帮助他们增加粉丝量）
3. 通过优化搜索推荐，给新用户推荐更有价值的用户
4. 引领他们到广场上发现有意思的内容，增加关注其他用户的数量

### 要点速查

| 概念 | 一句话定义 |
|------|-----------|
| 数据决策4步 | 具体假设 → A/B验证 → 找影响规律 → 决定功能 |
| 分情况假设 | 不要合写一个泛泛的假设，要分开不同情况 |
| 魔法数字 | 找到影响力最大的临界点（如"20"） |
| 第一周法则 | 新用户第一周是最关键的留存窗口期 |
| 一箭双雕 | "你可能想关注"同时帮助关注和吸粉 |

## 二、如何搞定A/B测试（第18讲）

### 核心理念

A/B测试，是用两组及以上随机分配的、数量相似的样本进行对比，如果实验组和对比组的实验结果相比，在目标指标上具有统计显著性，那就可以说明实验组的功能可以导致你想要的结果，从而帮你验证假设或者做出产品决定。

小到一个按钮用红色好还是黑色好，大到有没有朋友圈这个功能对微信日活数的影响，都可以通过A/B测试来解决。

### 测试前必须明确：要测什么、如何测

无论采用哪种测试方法，都必须在产品测试前弄清楚要测试什么、如何测，这就要求在设计产品时先从问题出发做出假设。

**案例：微信"加好友"按钮位置**

假设："微信中'加好友'按钮不好找，导致用户加好友次数不够，我认为把按钮从屏幕上方改到下方，可以让体验更顺畅，以增加用户加好友的次数。"

这时已经明确了：
- 需要测试什么（按钮位置）
- 如何测（对比上方和下方）
- 用什么指标衡量（用户使用次数）

可以开始A/B测试了。

> **如果不能100%清楚你要改变的是什么、提高的是什么，以及用什么指标来衡量，那么A/B测试并不适合你。**

### 验证因果性的唯一途径是A/B测试

**相关性 ≠ 因果性：**
- **因果性：** 因为有X，才会有Y。如：因为用户没有内容可以看，所以他们流失了
- **相关性：** X变化会导致Y变化，但不能明确Y的变化是由X的变化引起的。如：发现没有内容可以看的用户流失比例更高，但不能确定是因为没有内容所以流失

#### 案例：隐私设置与用户活跃度

数据显示启用了"隐私设置"的用户中，活跃用户的比例比较高。

单单这个数据，只能说明用户活跃程度和"隐私设置"功能具有**相关性**，不能说明二者之间有**因果关系**。

- 相关性解释：启用"隐私设置"功能的更可能是活跃用户
- 因果性解释：用户开启"隐私设置"后，可以控制谁能看到他们的内容，不用担心被不相关的人看到，所以更放心、更大胆地发新内容，变得更活跃

**A/B测试设计：** 实验组用户可以使用"隐私设置"，对照组无法使用，其他条件完全一致。

**结果：** "隐私设置"并不能提升用户活跃程度，二者没有任何因果关系。而活跃用户启用"隐私设置"的比例比较高，原因竟是**这个按钮不好找**。

> 如果没有进行A/B测试，而草率地下决定把"隐私设置"按钮做得非常大，鼓励更多用户启用来提升活跃度，最终就是花费大量时间改设计、重新开发，却"竹篮打水一场空"。

**A/B测试的魔力：** 某些功能优化可能需要整个团队花费很多时间精力去改设计、重新开发，但优化后并不能达到预期效果。这种情况下，可以先进行A/B测试验证因果关系。这就是A/B测试的魔力——帮助你做出科学、合理的产品决定。

### 两种不适合A/B测试的情况

#### 情况1：无论新功能上线后数据怎么样，都要发布

比如法律规定的功能，或属于公司策略性的功能，这些功能无论如何都要发布。这时要做的是如何优化用户体验，完全没有必要进行A/B测试。

#### 情况2：样本数量太少

如果要测试某个按钮颜色红色、绿色、蓝色还是紫色效果好，至少需要4组对比实验，且每组都要有足够样本保证统计显著性。

如果按钮一共才20个人用，每组只有5个用户，结果必然带有很大偶然性，无法做出科学结论。

**样本规模取决于实验组和对比组之间的区别有多大：**
- Facebook的朋友圈，如果增加新功能可以让日活增加1%就是巨大成功，需要的样本数量非常大才能保证这1%的进步具有统计显著性
- 创业公司产品思路还没定型，新功能可能将指标提升100%，即使没有那么多样本，也可以肯定给产品带来质的飞跃

### 短期数据 vs 长期数据

#### 案例1：微信"摇一摇"放开启页

如果微信"摇一摇"突然出现在微信开启页面，"摇一摇"的用户使用量会直线上升。

A/B测试：实验组"摇一摇"在开启页面，对照组在"发现"页面。短期肯定是实验组数据更好看。但根据前两天的数据就直接得出"摇一摇在开启页面效果更高"的结论，是不可信的。

**原因：** 没有意识到新功能的短期新鲜感和长期的生态系统影响。微信开启页面突然出现"摇一摇"，用户使用数据会因为刚开始的新鲜感而非常好看，但这个"好看"的数据可以延续吗？

> 大部分产品的新鲜感只能持续一个星期，最多一个月。新鲜感的劲儿头过后，数据会直线下降，成了"扶不起的阿斗"。

很多产品经理就是踩了这个坑，因为前几天"好看"的数据过早地下了结论，最终产品发布后的表现远不如预期。

**建议：** 判断一个功能是否值得发布时，等至少一个星期、短期新鲜感褪去后再衡量。

#### 案例2：Instagram"超级赞"功能

假设Instagram要增加一个给好友点"超级赞"的功能，目的是提高用户分享频率。

- **短期：** 刚开始活跃程度确实提高了，因为有了"超级赞"，发新鲜事倍儿有精神，分享数量大幅提升，短期数据棒极了
- **长期：** 增加了"超级赞"后，用户会因为只得到了"赞"而没有获得"超级赞"，感觉自尊心受损，最终不愿意也不敢分享了，长期数据反而下降了

**建议：** 发布后保留一个长期的对比实验组，比如1%的用户无法使用新产品，来观察产品对整个生态系统产生的影响，并适时作出调整。

### 要点速查

| 概念 | 一句话定义 |
|------|-----------|
| A/B测试 | 随机分组对比，验证因果关系 |
| 相关性 ≠ 因果性 | 相关只能说明一起变化，因果才能说明谁导致谁 |
| 验证因果性唯一途径 | 只有A/B测试能验证因果关系 |
| 不适合A/B测试 | 必须发布的功能 / 样本太少 |
| 短期 vs 长期 | 新鲜感效应持续1周~1个月，等稳定后再决定 |
| 长期对比组 | 发布后保留1%对照组，观察生态系统影响 |

## 三、5步科学迭代法（第21讲）

### 核心理念

硅谷最神奇的产品经理（增长黑客）看似"点石成金"——改改按钮颜色、增大字体就能增长百万用户，但这种能力靠的绝不是拍脑袋，而是**科学实验的过程**。

> 顾客就是上帝，但这种上帝是非常非常懒的。他们不愿意多做一件事，不愿意多看一句话，不愿意多按一个按钮，所以做增长的产品经理需要思考：如何让产品的体验简单简单再简单。

#### 案例1：Amazon"一键购买"按钮

世界上最值钱的按钮。只要以前在Amazon下过单，就会自动记下你的名字、邮寄地址和信用卡号，下次购买直接选择"一键购买"即可完成下单。

**至少帮Amazon赚了10亿美元。** 想想有多少冲动消费的"单身党"因为"手贱"点了一下就完成了几百元的订单。而如果让用户先加入购物车，再下单、填写或确认地址和信用卡号，至少多五步操作。

#### 案例2：NerdWallet信用卡推荐页

盈利方式是靠向用户推荐信用卡赚取佣金。本来"现在申请"（Apply Now）按钮没有"锁"的图标，**加上锁图标后，点击量一下就增加了10%。**

**原因：** 抓住了用户希望有安全保密的信用卡申请体验的需求，用一个锁的小图标"聪明地"满足了用户需求。

### 5步科学迭代流程

#### 第1步：了解清楚要优化的是什么指标

以NerdWallet信用卡推荐页面为例，要增加的指标就是**通过网站提供的链接申请信用卡的次数**。

#### 第2步：了解已有的产品工作流

首先，思考现在整个网站有多少种方式能够把用户引流到申请信用卡的页面。比如有三个：
- 信用卡推荐页
- 刚登录网站时的右侧广告
- 博客文章中嵌入的链接

然后，了解通过哪一步申请信用卡的人数最多。可能会发现，虽然信用卡推荐页占的篇幅很大、很显眼，但还不如博客文章嵌入的链接点击量高，这让人感到奇怪。

另外，还应该进一步细分，对比不同用户群在每一步的使用情况。比如发现：
- 用户终于点击了链接、填入个人信息，在点击"申请"按钮时，**女性用户的点击量远远低于男性**
- **年长用户远远低于年轻用户**

> 这个过程不需要急着马上找原因，而是要全面了解整个产品的体验信息，思考用户能够进行目标动作的所有途径。

#### 第3步：深挖找出最有价值的机会

经历了对目标指标和已有产品工作流的思考，已经发现了几个奇怪的点，下面就要开始权衡取舍，筛选出最有价值的机会，提出合理的假设。

**假设形成：**
- 信用卡申请安全性和保密性是关键
- 推荐页里随随便便的链接，用户可能怀疑安全性和可靠性
- 博客文章嵌入链接时，作者已取得读者信任，所以更有可能点击
- 女性用户和年长用户点击量低，原因可能是女性对财政问题更谨慎，年长用户更怕受骗
- 信用卡推荐页浏览人数远远高于其他两个部分

**结论：** 应该把重心放在怎样把信用卡推荐页设计得更能取得用户信任上，这才是最应该抓住的机会。

#### 第4步：头脑风暴

现在已经得出了"安全性和保密性是关键"的假设，怎么获得用户更多信任？

- 加一行字告诉用户，所有信用卡推荐页都是官方申请页面
- 在信用卡申请按钮上增加一些表示安全的图标
- 在按钮旁边写上多少人已经通过这个链接完成了申请

#### 第5步：快速执行，高效比对

激励团队快速动手，把三个想法尽可能快地设计开发出来，并发布给少量用户进行A/B测试。对比实验组和对照组的数据，如果实验组比对照组的数据更好，起码说明假设是正确的。如果实验组1比实验组2强，那就发布实验组1。

> 亚马逊的"一键购买"按钮和NerdWallet的锁图标，这些天才的想法其实经过了非常多的测试，经历了无数次失败后才有了现在的成功。

### 两个特别注意

1. **一定要系统地过一遍整个产品的工作流**，弄清楚用户可能会在哪一步流失、什么用户在这一步更容易流失，而不是一上来就提出假设
2. **迭代重在试错**，可以多做几次实验，每次设置多个对照组，找到最正确的方式，而不是指望一次就成功

### 要点速查

| 概念 | 一句话定义 |
|------|-----------|
| 天才想法 | 不是拍脑袋，而是科学迭代的结果 |
| 5步科学迭代 | 指标 → 工作流 → 机会 → 头脑风暴 → 快速执行比对 |
| 系统过一遍 | 先全面了解工作流，不要一上来就提假设 |
| 试错精神 | 多做实验，每次多设对照组，不指望一次成功 |

## 四、UIE增长论（第22讲）

### 核心理念

作者在Facebook刚做产品经理时，干劲儿很足，经常跟导师说"我想到一个方法，肯定能帮产品增长，试试吧"。导师指出：

> "我发现你经常会有一个新想法，然后找证据证明这个想法是对的。但是，你并没有全盘考虑所有可能的机会，而是直接跳到了这一个想法上。"

导师介绍了**UIE增长论：**
- **Understand（了解）：** 综合理解用户体验的每一步，然后深挖每一步中每一类用户群体的数据
- **Identify（找到）：** 在了解之后，找到有意思的数据点，挖掘出具体的想法，并且选定最重要的想法
- **Execute（执行）：** 设计开发，然后进行实验验证，如果结果靠谱就发布

> 我的问题是只做了"找到"和"执行"，但没有"了解"。**如果没有充分了解产品每一步用户流的表现情况，就不能找到最具价值的想法。结果可能会对产品指标有积极影响，但忽略了更好的主意。**

### UIE增长论详解

#### Understand（了解）—— 最好用的方法：完成率表格

推荐一个最好用的"了解"方法：**产品流程的每一步完成率的表格**。

表格描述了新用户如何开启使用APP的体验，包括注册账号、设定密码、关注朋友等。每完成最后一步，新用户就完成了设定，可以开始使用APP了。

如果用户没能坚持到最后一步，每一步都会降低用户的活跃度：
- 没注册成功 → 后面体验无法开始
- 没开启消息提醒 → 没有通知新消息的途径
- 没得到好友关注 → 无法体会APP的价值

**表格结构：**
- 每一列代表不同平台（iOS、Android、网页版设计界面不同）
- 每一行代表进行到这一步的用户中，百分之多少完成了相关操作

**发现的数据点：**
1. 用户在网页版"绑定手机"这一步流失极其严重
2. 用户在iOS版开启提醒消息的比例非常低
3. 用户在iOS版点击注册后，使用Facebook登录的比例非常低

**原因分析和解决方案：**

**问题1：网页版"绑定手机"流失严重**
- 原因：网页版用户一般用电脑或iPad登录，手机不一定在身边，绑定手机需要找手机验证，比较麻烦
- 解决方案：增加"邮件验证"功能，方便在同一台设备完成验证

**问题2：iOS版开启消息提醒比例低**
- 原因：iOS系统在开启消息提醒时会询问用户是否愿意开启，此时大部分用户并不了解产品，也没介绍功能，所以选择不开启
- 解决方案：要么在用户刚开始使用时就介绍产品功能，要么等用户体会到APP价值、建立信任后再询问

**问题3：iOS用户使用Facebook登录比例低**
- 原因：iOS使用Facebook登录时会跳转到Safari浏览器打开网页版Facebook，很多用户还没登录网页版需要重新登录；而Android用户可以直接跳转Facebook APP无需重新登录
- 解决方案：要么修改iOS逻辑跳转到Facebook APP而非网页，要么在网页版增加根据APP自动同步用户名密码的功能

#### Identify（找到）—— 估测机会价值

首先要知道最高层指标是什么，然后估测每一个新功能可能带来的价值有多大。

**问题1：网页版绑定手机优化**
- 网页版用户在所有用户中比例非常低，只有5%左右
- **价值：一般**

**问题2：开启消息提醒优化**
- 与新增用户无关，更多是留存
- 假设开启消息提醒用户比例提高20%，可以让7天留存天数增加5%
- 现在只有50%的用户开启了消息提醒，优化提升的极限是50%（即100%用户开启）
- **价值：中等**

**问题3：Facebook登录优化**
- 可以让更多用户轻松创建用户名和账号，直接提升新增用户数量
- 现在85%的用户能完成新增用户名，需要让剩余15%的流失用户完成这一步
- 但这个功能只有iOS适用，iOS端用户占50%，需综合计算对总指标的贡献
- **价值：较高**

**结论：** 第一项没那么重要（5%比例太低）。着重分析第二项和第三项，对比优化哪个价值更高。一个是通过留存帮助增长，一个是通过新增帮助增长，到底哪个对增长贡献潜力更大？

> 注意这里用的是"潜力"，因为没人能在这一步确定新设计对总指标的影响到底是多少，需要做好潜力计算后再做产品决定。最好情况的假设是让所有用户都不流失，来判断到底能增加多少。

#### Execute（执行）

假设产品薄弱环节是新增用户量，决定先优化"使用Facebook登录/新建用户"这一步。

解决方案：用户点击"使用Facebook登录"后，新增功能让用户可以直接跳转到Facebook的APP中，不用再去Facebook网页版重新登录。

成功指标：用户在这一步的完成率 + 新增用户数量。

明确这些问题后，就可以进行设计和开发了。

### UIE增长论的重点

**了解的过程要尽可能全面：**
- 不仅可以分安卓、iOS和网页版，还可以分不同国家、不同年龄层、付费或免费
- 例如在印度，女性对隐私保护比较重视，一开始就通过通讯录加好友可能有所顾虑，不如先推荐比较火的印度账号，先提起兴趣

> 重点不是划分结果是否理想，而是了解的过程，要把可能性想得更全面一些，一点点地分析机会在哪里。

**找到的时候注意怎么看数据：**

**1. 左右对比 — 看不同平台的用户流失情况**
- 如果知道iOS在某一步的流失率高于Android，就可以仔细研究两者在这一步体验有何不同，包括设计、运行速度、语言、产品流程的系统区别等

**2. 上下对比 — 看产品流中每一步的用户流失情况**
- 如果某一步流失率非常高：
  - 一方面考虑是否可以想办法提升（如增加消息提醒开启率）
  - 一方面考虑这一步到底值不值得，或是否可以换顺序（如让用户先加好友，再开启消息提醒？或者去掉消息提醒这一步？）

**3. 看整体的数据**
- 从这一步到下一步的完成率写出来了，但整个产品体验的完成率是把每一步完成率做乘法，最终会是一个非常非常小的数字，说明大部分用户都在一步一步中流失了
- 所以，是不是应该把某几个步骤整合成一个，或者直接让用户选择"默认"然后我们把该做的都做好
- 整体看可以让你不拘泥于每一步的优化，而是整个产品体验的优化

### 要点速查

| 概念 | 一句话定义 |
|------|-----------|
| UIE增长论 | 了解（每步数据）→ 找到（最大机会）→ 执行（验证发布） |
| 核心教训 | 不要跳过"了解"直接"执行"，否则会忽略更好的主意 |
| 完成率表格 | 最好用的"了解"方法，列每步完成率 + 分平台/群体 |
| 潜力估测 | 用最好情况假设估测功能最大价值 |
| 左右对比 | 不同平台/群体的流失差异 |
| 上下对比 | 产品流中每步的流失情况 |
| 整体数据 | 每步完成率做乘法 = 总完成率，考虑整合/简化步骤 |
