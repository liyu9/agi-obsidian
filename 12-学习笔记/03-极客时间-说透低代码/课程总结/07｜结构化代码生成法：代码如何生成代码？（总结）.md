# 07｜结构化代码生成法：代码如何生成代码？

> **核心方法**：将人工编码过程抽象为向有限种类"插入点"添加结构化数据片段的过程，再按语法规则拼装成完整代码。适用于任何指令式语言。

---

## 一、人工编码过程分析

人工写代码的特征：

- **按需、跳跃式**：不会自上而下顺序写，而是在不同位置插入片段
- 但**插入点的类型总是有限的**——每种语言/框架的插入点种类可以穷举

### 开发一个视图组件涉及的插入点类型

| 插入点 | 说明 |
|--------|------|
| import 区 | 导入其他类（含第三方） |
| HTML 模板区 | 组件的视图模板 |
| 样式区 | 组件样式 |
| 类声明区 | extends / implements |
| 构造函数区 | 注入依赖、初始化 |
| 成员变量区 | 属性定义与初始化 |
| 成员方法区 | 方法定义 |
| 输入属性区（Input） | 组件外部传入参数 |
| 输出属性区（Output） | 组件对外事件 |

> 示例基于 Angular，但方法通用——不限于 Angular，可用于生成 Vue/React/Java/C/C++ 等任意指令式语言的代码。

## 二、结构化代码生成法

### 2.1 核心思路

```
人工编码过程 → 逆向工程 → 抽象出插入点模型 → 代码生成器按模型拼装代码
```

**关键洞察**：虽然写代码时东一榔头西一棒，但插入点的类型是有限的 → 只需定义好插入点，再往各个插入点添加结构化数据片段即可。

### 2.2 实现步骤

**Step 1**：将代码片段拆解为结构化数据

以这段伪代码为例：

```typescript
import {EventEmitter} from "@angular/core";
export class MyComp {
  public select: EventEmitter;
  constructor() {
    this.select = new EventEmitter();
  }
}
```

拆解到3个插入点：

| 插入点 | 结构化数据 |
|--------|-----------|
| importSection | `[{identifier: 'EventEmitter', from: '@angular/core'}]` |
| constructorSection | `[{statement: 'this.select = new EventEmitter()'}]` |
| memberSection | `[{modifier: 'public', identifier: 'select', type: 'EventEmitter'}]` |

**此时的数据片段没有任何语义和功能**，只是普通的结构化文本。

**Step 2**：继续添加功能时，往对应插入点追加数据

例如让 MyComp 继承 Base 类并实现 OnInit/OnDestroy 接口：

- importSection 追加：`{identifier: 'Base', from: './base'}` 等
- extendSection 追加：`{identifier: 'Base'}`
- implementSection 追加：`{identifier: 'OnInit'}`, `{identifier: 'OnDestroy'}`

**Step 3**：校验、去重、拼装

### 2.3 插入点的去重与排序规则

| 插入点类型 | 去重规则 | 顺序敏感 |
|-----------|---------|---------|
| import 区 | 重复项需过滤；相同 from 值可合并 | 不敏感，可按特定顺序排列 |
| 成员变量区 | modifier/identifier/type 三者完全相同 → 去重；三者之一不同 → 报错（避免生成冲突代码） | — |
| 构造函数区 | 不去重，按顺序依次生成 | **敏感**，不应调整顺序 |

## 三、HTML 模板的生成（难点）

### 3.1 问题

Web 组件形成**树形结构**（容器可嵌套普通组件和容器），每个节点**相互独立**：

- 每个节点只能生成自己的 HTML **片段**，不知道父级和子级
- 目标是生成**完整** HTML

### 3.2 约束条件

1. 各节点生成的 HTML 片段不同
2. 需要把独立节点的片段融合成一个整体
3. 节点树具有递归结构（容器内可再嵌套容器）
4. **不允许用 if-else 解决节点差异**（保持封装内聚性）

### 3.3 解决方案：递归 + 接口约束

每个节点实现相同的 `htmlCoder` 函数签名：

```typescript
export interface IHtmlCoder {
  htmlCoder(sCode: StructuredCode, env: ProjectEnv): string;
}
```

**执行流程（深度优先递归）**：

```
树叶节点生成 HTML 片段 → 一级一级向树根递归 → 树根时获得完整 HTML
```

每个节点的 `htmlCoder` 只做两件事：

1. 如果有子级 → 调用子级的 `htmlCoder`，驱动子级生成 HTML 片段
2. 生成自己的 HTML 包裹片段 → 与子级返回的片段正确组装 → 返回给父级

**优势**：节点间松耦合、无 if-else、无论节点自身 HTML 多复杂都能满足。TypeScript 的 OOP 实现在编译时约束所有节点必须实现该接口。

## 四、编辑器如何使用此方法

### 4.1 工作流程

```
新建 App → 创建空白插入点结构 → 各编辑流程按需往不同插入点写入数据 → 校验 → 拼装 → 生成代码
```

空白结构示例：

```json
{
  "importSection": [], "constructorSection": [], "memberSection": [], ...
}
```

### 4.2 推广验证

| 目标语言 | 推广结果 |
|---------|---------|
| TypeScript + Angular（原始） | ✅ 正常 |
| JavaScript + Vue | ✅ 相似原理可直接实现 |
| JSX + React | ✅ 相似原理可直接实现 |
| TypeScript + Node.js（后端 Rest 服务） | ✅ **几乎零修改直接切换** |
| Java / C / C++ / Python | ✅ 理论可行（任何指令式语言） |
| 函数式编程语言（如 Scala） | ❓ 理论上可行但未验证 |

## 五、核心认知

1. **结构化代码生成法与人工编码过程本质上是一致的**：人工编码时逻辑上存在永不交织的"代码片区"，结构化生成法只是把这些片区显式化为数据结构
2. **结构化数据是低代码平台持久化的基本格式**：计算机擅长读写结构化数据，没有二义性；DSL/自然语言/编程语言都有二义性
3. **生成的代码与手写代码接近**，人类可读，但应保持只读——任何手工编辑难以反向同步到输入的结构化数据
4. **此方法有几乎无限的推广空间**，因为其本质与人工编码过程一致
