# 21｜低代码平台如何帮助应用做测试？被测功能的发现

> **核心问题**：低代码平台如何利用对 App 结构和交互关系的深度理解，实现应用的零代码自动化测试？
> - 开发能力决定平台能力**上限**，开发之外的能力决定**下限**，两者一样重要。

---

## 一、页面自动化测试的困境

### 1.1 传统测试流程

```
开发页面功能 → 编写测试用例 → 页面迭代 → 用例同步维护 → 废弃功能用例清理
```

### 1.2 核心痛点

| 痛点 | 原因 |
|------|------|
| 用例优先级最低 | 老板认为功能代码才是交付特性，测试用例不是业绩；满负荷时第一个被砍 |
| 维护成本极高 | UI 是软件系统中需求最多变、细节最多的部分 → 稍有风吹草动代码就动 → 用例同步修改 |
| 维护量显著大于 API/单测 | 页面作为 UI 面向人类，变化频率远高于 API 接口和单测 |
| **"笑着进去哭着出来"** | 初期容易坚持，累计用例数量可观后维护需求压垮团队 |

---

## 二、低代码平台的优势

**核心推理**：整个 App 都是低代码平台生成的 → 平台对 App 的结构和交互关系理解比开发人员更深刻 → 平台有足够数据**自动生成**测试用例 → 还能**自动更新和维护**测试用例。

---

## 三、被测功能的定义

### 3.1 归纳过程

从一个典型交互（查询条件 → 点击查询 → HTTP 请求 → 图形更新）开始归纳：

1. **具体流程**：按钮点击 → HTTP 请求 → 图表更新
2. **替换组件**：图形换表格 → 流程几乎一样 → 说明流程仍然太具体
3. **考虑更多场景**：
   - 触发方式不限于按钮（键盘事件、自定义事件等）
   - 不是所有功能都需要网络 I/O（如抽屉 open 属性从 false 变 true）
4. **高度抽象**：

### 3.2 被测功能定义

```
输入数据 → 触发功能 → （发生一些事情，不关心）→ 产生副作用
```

**关键抽象**：
- 按钮点击/键盘按键/自定义事件 → 归纳为**触发方式**
- 组件发起 HTTP 请求/属性值变更 → 归纳为**发生了一些事情**（中间环节不关心）
- 图表更新/抽屉打开 → 归纳为**副作用**（中性词）

**一个交互 = 一个被测功能**

## 四、被测功能的自动发现

### 4.1 为何要枚举被测功能

| 作用 | 说明 |
|------|------|
| 告知开发人员有多少功能点需要测试 | 基本需求 |
| 给出自动化测试覆盖率统计 | 质量指标 |
| 被测功能全集是可视化操作的基础 | **可视化是低代码平台的典型操作套路** |

### 4.2 发现方法：抓住交互事件

**为何抓事件**：
- 事件机制是几乎所有界面交互模型的核心 → **抓住交互事件就不会遗漏任何被测功能**
- App 开发过程中用户配置的各种事件已保存在配置数据中 → 稍微遍历即可全部找出 → 无遗漏无冗余

### 4.3 事件分类

| 类型 | 示例 | 创建者 | 在事件链中的位置 |
|------|------|--------|------------------|
| 原生 DOM 事件 | click、keyup、load | 系统 | **事件链起点** |
| 组件事件 | 组件内部发出的自定义事件 | 系统 | **事件链起点** |
| 应用生命周期事件 | App 生老病死各阶段 | 系统 | **事件链起点** |
| 应用自定义事件 | 如 Query 事件 | **应用开发人员** | **事件链中间**（可选） |

**分组意义**：第一组（系统创建）往往是事件链起点 → 第二组（自定义事件）只出现在中间 → **只需在 AST 中寻找发送自定义事件的 API 节点** → 大幅降低发现复杂度。

### 4.4 事件链 → 事件树

**简单事件链**：按钮点击 → HTTP 请求 → HTTP Response → 表格更新

**引入自定义事件后**：按钮点击 → 自定义事件(Query) → HTTP 请求 → HTTP Response → 表格更新

**一个自定义事件驱动多个 HTTP 请求** → 事件链变为**事件树**

**实际复杂度**：一个商用 App 的事件树复杂度是示例图的几倍甚至十几倍。

---

## 五、事件树的附加价值

事件树 = App 的**交互概览图**，可视化展示交互概要。

**场景**：企业级 App 生命周期长达数年 → 维护人员一波波换 → 新接手开发人员打开事件树即可快速了解 App 交互逻辑 → 掌握大半 App 逻辑关系。

还支持模糊搜索 → 快速定位局部组件交互细节。
