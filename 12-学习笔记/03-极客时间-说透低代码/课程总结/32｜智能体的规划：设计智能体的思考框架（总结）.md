# 32｜智能体的规划：设计智能体的思考框架

> **核心主题**：纯设计篇，不写代码。为 Agent 的"大脑"——任务规划器，设计完整的思考框架。

---

## 一、顶层架构：指令/目标分流器（Router）

### 问题

不是所有用户请求都需要启动复杂规划。需要区分两类输入：

| 类型 | 定义 | 示例 | 处理方式 |
|------|------|------|---------|
| **简单指令** (single) | 单一、明确，一步可完成 | "把按钮变红" | 走"观察-执行"快速通道（第31讲） |
| **复杂目标** (multi) | 需多步骤组合达成 | "创建登录页面" | 交给规划器 |

### 分流器实现思路

通过 Meta-Question 让 LLM 做二元分类：

> "请判断用户请求是 single 还是 multi？只回答 'single' 或 'multi'。"

根据结果导向两个处理管道。

## 二、核心：元提示（Meta-Prompt）的五大要素

规划器的质量取决于元提示的设计。元提示 = 给 LLM 的"项目需求文档"，必须包含五个要素：

### 要素一：角色扮演（Role-Playing）

为 LLM 设定专家身份 → 引导其以专业、结构化的方式思考：

> "你是一位资深的低代码应用架构师。"

**作用**：将 LLM 从泛泛的聊天机器人"提拔"为领域专家。

### 要素二：最终目标（The Goal）

清晰、无歧义地告知用户的原始需求。

### 要素三：环境感知（Environmental Awareness）

**不能直接给原始 JSON** → 信息噪音大、Token 消耗高、LLM 抓不住重点。

**必须提供"状态摘要"** → 用 Markdown 列表描述页面核心结构：

| 格式 | 示例 | LLM 友好度 |
|------|------|-----------|
| 原始 JSON | 嵌套的 props/style/children | ❌ 噪音大 |
| Markdown 摘要 | `- Page (id: root)\n  - Header (id: header_123)` | ✅ 清晰 |

**关键原则**：摘要只保留**组件类型、ID、层级关系**，剔除样式等细节。

### 要素四：可用工具（Available Tools）

向 LLM 亮出"家底"——工具名称 + 功能描述 + 参数说明：

```
- find_components(filters: array): 按属性条件查找组件
- createComponent(parentId, componentType, properties): 创建组件
- updateProperty(componentId, propertyName, propertyValue): 更新属性
- deleteComponent(componentId): 删除组件
```

### 要素五：输出契约与行动纲领

**输出契约**：要求 LLM 输出结构化 JSON Plan：

```json
{
  "plan": [
    {
      "step": 0,
      "reasoning": "思考过程...",
      "tool_name": "createComponent",
      "parameters": { ... }
    }
  ]
}
```

**行动纲领**（注入"灵魂"的规则）：

| 原则 | 说明 |
|------|------|
| **ReAct 原则** | 思考（Reason）+ 行动（Act）结合，每步必须写 reasoning |
| **观察优先** | 执行修改前，先用观察工具核实当前状态 |
| **经济原则** | 用最少步骤完成目标 |

## 三、步骤间引用语法：`$steps.N.result.path`

### 问题

LLM 生成计划时，前面步骤创建的组件尚未存在 → 没有ID → 后续步骤的 `parentId` 无法填写。

### 解决方案

设计引用语法 `$steps.N.result.path`，允许后续步骤引用前面步骤的执行结果：

| 部分 | 含义 |
|------|------|
| `$` | 标记：这是需要解析的引用，非普通字符串 |
| `steps` | 计划的步骤数组 |
| `N` | 步骤索引（从0开始） |
| `result` | 第N步成功执行后的返回对象 |
| `path` | 从结果对象中提取值的路径（点表示法） |

### 示例

```
Step 0: createComponent(parentId: "root", componentType: "Form")
  → 返回 {"id": "form_1a2b3c", ...}

Step 1: createComponent(parentId: "$steps.0.result.id", componentType: "Input")
  → 执行时自动解析为 "form_1a2b3c"
```

## 四、干跑（Dry Run）验证

**目标**：创建包含标题（"用户登录"）和提交按钮的表单。

### 手动拼装元提示

1. **状态摘要**（假设空页面）：`- Page (id: root)`
2. **拼装五大要素**：角色 + 目标 + 状态摘要 + 工具列表 + 输出契约
3. **人脑模拟 LLM 生成计划**：

```json
{
  "plan": [
    {
      "step": 0,
      "reasoning": "首先创建Form容器，放在root下",
      "tool_name": "createComponent",
      "parameters": {"parentId": "root", "componentType": "Form"}
    },
    {
      "step": 1,
      "reasoning": "在表单内添加标题",
      "tool_name": "createComponent",
      "parameters": {
        "parentId": "$steps.0.result.id",
        "componentType": "Text",
        "properties": {"text": "用户登录"}
      }
    },
    {
      "step": 2,
      "reasoning": "在同一个表单中添加提交按钮",
      "tool_name": "createComponent",
      "parameters": {
        "parentId": "$steps.0.result.id",
        "componentType": "Button",
        "properties": {"text": "提交"}
      }
    }
  ]
}
```

**验证结果**：框架完备、自洽，`$steps` 引用语法正确使用。

## 五、设计总结

| 模块 | 职责 |
|------|------|
| 分流器 (Router) | 区分 simple/multi，决定流量走向 |
| 元提示 (Meta-Prompt) | 五要素（角色+目标+环境+工具+契约）指导 LLM 规划 |
| `$steps` 引用语法 | 解决步骤间依赖，使计划拥有上下文 |
