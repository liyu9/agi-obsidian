# 20｜如何仅通过元素间的相对位置来生成有弹性可维护的UI代码？

> **核心问题**：给定一个界面上各组件的相对位置和尺寸，如何自动生成符合人类思维习惯、可维护、有弹性的 UI 布局代码？
> - 与第07讲的关系：第07讲处理**单个组件**的代码生成；本讲处理**组件之间**的关系（布局），两讲相辅相成。

---

## 一、基础概念

### 1.1 组件

- **组件是界面的最小单元，不可拆分**
- 对界面做抽象：一个界面 = 多个组件组成

### 1.2 边（Edge）

**定义**：在给定界面上，能够在**不贯穿任何组件**的前提下，将该界面切开的线。

**推论**：边只存在于**水平或垂直方向**（因为组件被抽象为矩形盒子，任何斜线都会贯穿至少一个组件）。

### 1.3 组（Group）

一个边把界面分为两部分，每一部分称为一个**组**。

## 二、切蛋糕法

### 2.1 算法目标

**给定的任何界面，自动生成它的布局代码**，额外要求：
1. 生成的代码符合人类编码思维习惯
2. 人工可在生成代码基础上做开发迭代
3. 生成的页面布局具有**良好的弹性效果**

### 2.2 算法流程

**核心思想**：从全局到局部，由外而内，由大到小，逐层切分到组件粒度。

```
步骤1：确定切的方向（水平 or 垂直）
  → 优先选择可用边多的方向（收敛更快）

步骤2：按边切分，得到 N+1 个分组（N = 边数）

步骤3：生成本层级的代码骨架

步骤4：遍历每个分组，递归重复步骤1~3

终止条件：无法继续切分（已到单个组件）
```

**示例**：

原始界面 → 垂直方向有2条边（水平1条）→ 先从垂直切 → 得到左中右3个分组：

```html
<div class="col-1">??</div>
<div class="col-2">??</div>
<div class="col-3">??</div>
```

左侧分组 → 水平方向有2条边 → 切出3个子分组：

```html
<div class="col-1">
  <div class="row-1-1">??</div>
  <div class="row-1-2">??</div>
  <div class="row-1-3">??</div>
</div>
```

继续递归直到无法切分。

## 三、弹性布局实现

### 3.1 弹性的两个原则

**原则一：无弹性组件尺寸优先分配**

固定尺寸组件优先获得空间，弹性组件分配剩余空间。

**原则二：剩余尺寸按比例分配**

多个弹性组件按画布上的尺寸比例分摊剩余宽度。

> 界面上的留白 → 当作固定尺寸组件处理。

### 3.2 复杂场景分析

**场景**：一行上有固定组件A、弹性组件B、弹性组件C、固定组件D。

- 浏览器宽度 > 4n 时：直接套用两原则
- 浏览器宽度 < 4n 时：
  - 切蛋糕法将4个组件分为左中右三列
  - A 无弹性 → A/B 所在组最小尺寸 = A 的尺寸 → **B 获得保护**
  - C 所在组为完全弹性组 → **C 被优先压缩**

### 3.3 技术实现：CSS Flex 布局

选择 flex 的原因：
- `flex-basis` → 控制固定尺寸组件
- `flex-grow` → 按比例控制弹性组件尺寸
- flex 有良好的**嵌套支持**
- 几乎所有浏览器（含 IE）都支持

**实现约定**：
- 画布上所有组件采用绝对尺寸渲染
- `flex-basis` = 设计时组件的 px 值
- `flex-grow` = 设计时组件的 px 值（支持浮点数）
- 有弹性 → 用 `flex-grow`；无弹性 → 用 `flex-basis`

## 四、布局约束与解决方法

### 4.1 垂直方向弹性

- 垂直方向直接套用两原则 → 页面高度**过度弹性** → 无法撑出滚动条
- **解决方案**：垂直方向保持内容高度优先，不应用弹性原则
- **例外**：大屏类页面要求水平和垂直都完全弹性 → 两原则同时应用

### 4.2 组件靠右/靠下

**问题**：所有组件固定尺寸 → 右侧图标无法停靠页面右边。

**解决方案**：**占位符组件** — 渲染为有弹性的空白 → 吃掉多余尺寸 → 将右侧组件顶到页面右侧。

### 4.3 重叠组件（切蛋糕法的缺陷）

**问题**：两个组件位置重叠且其中一个是弹性组件 → flex 布局无法处理。

**简化处理**：取消所有组件弹性特性 → 归入一组 → 组内采用绝对布局定位。

> 此缺陷对 D2C 影响不大，但对低代码平台布局编辑器不能忽视。

---

## 五、切蛋糕法的适用范围

| 场景 | 说明 |
|------|------|
| D2C 自动生成代码 | 输入 = UX 设计稿中组件的位置和尺寸；输出 = 人类友好的布局代码 |
| 低代码布局编辑器 | 开发人员拖入组件、调整位置和尺寸 → 喂给切蛋糕法 → 生成布局代码 |

**核心优势**：输入仅需平面相对位置和尺寸，无需分组信息 → 生成的代码符合人类思维 → 优雅处理页面弹性。
