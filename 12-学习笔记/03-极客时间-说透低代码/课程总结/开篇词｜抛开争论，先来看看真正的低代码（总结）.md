# 开篇词｜抛开争论，先来看看真正的低代码

> **作者背景**：陈旭，中兴通讯软件研发资深专家，低代码平台 Awade 架构负责人。2018 年初启动低代码平台研发（前置工作可追溯至 2017 年 4 月），属于国内最早一批实践者。

---

## 一、低代码的两极化争议

- **银弹论**：做得好的企业确实通过低代码获得了显著收益（降本/提效/兼而有之），大力推广
- **毒瘤论**：未能解决实际问题的低代码实现，反而降低效率，被贬为毒瘤
- **共同指向**：两种极端评价说明 **Pro Code 开发模式与高速增长的业务需求之间的矛盾越来越尖锐**，低代码是业界给出的新模式

**结论**：用语言争论银弹/毒瘤无意义 → 回归技术理性 → 看一线平台的真实架构和思路

---

## 二、学习低代码的难点

| 维度 | 说明 |
|------|------|
| **系统复杂度** | 涉及大量通用技术、架构设计，代码量达数十万~百万行级别，集成数以千计的开源技术 |
| **无公认标准** | 没有技术标准、白皮书 → **没有清晰的学习目标** |
| **对比通信协议** | 4G/5G 极其复杂但有标准可循；低代码复杂度没那么高，但**没有起点也没有终点，没有正确也没有错误** |
| **最合适的学习方式** | 倾听他人经验（成功+失败），而非碎片化的演讲 |

## 三、专栏知识地图

低代码编辑器是低代码平台的**核心功能模块**和**所有功能的锚点**：

```
              ┌─ 代码生成器（编译器）
              │
低代码编辑器 ──┼─ 插件系统（扩展/定制）
   （核心）    │
              └─ 基础设施（基石，研发先于编辑器，集成时融入编辑器）
```

### 专栏三部分结构

| 部分 | 内容 | 要点 |
|------|------|------|
| **一、认知基础与架构策略** | 不涉及具体技术，从架构设计和演进策略角度学习 | 包括启动前需要的"家底"（必备/可选/自主掌握/借力开源） |
| **二、核心模块开发** | 低代码编辑器技术实现要点，占专栏绝大部分 | 以 App 开发三部曲（**布局、交互、数据**）为线索；从代码生成器开始 → 因为它与编辑器的关系决定长期演进空间 |
| **三、平台功能拓展** | 开发能力之外的内容 | 全生命周期支持 + 插件系统 + 生态圈 |

### 代码生成器为何先讲——因果链

代码生成器与编辑器无良好松耦合 → 无法提供插件扩展能力 → 通用型平台在具体场景效率无法保证 → 效能打半折
