# 10 | 可视化编程：如何有效降低App前后端逻辑开发的技能门槛？

> **核心思路**：可视化编程 = 可视化逻辑编排 + 功能节点（填空即开发）。逻辑编排解决流程组织问题，功能节点凝聚专家经验，让无技能者也能获得专家级代码。**本讲内容同时适用于前端和后端低代码场合。**

---

## 一、可视化逻辑编排

### 1.1 流程图式编排

**理论依据**：BOHM & Jacopini（1966）证明，只要同时支持3种基本控制结构，就可以表达任何复杂程序逻辑：

| 结构 | 说明 |
|------|------|
| 顺序结构 | 语句依次执行 |
| 选择结构 | 条件分支 |
| 循环结构 | 重复执行 |

**人脑认知优势**：人脑 **80%** 功能用于处理视觉信息，对可视化信息处理效率远高于文字。

### 1.2 函数定义与复用

可视化编程只需实现**极少量编码技巧**——函数定义和调用即可（连类都用不上），原因：

- App 架构/框架代码由低代码编译器 **100% 自动生成**
- 可视化编程只需完成交互逻辑部分，逻辑简单而少量

函数定义的两种方式：

| 方式 | 说明 | 适用人群 |
|------|------|---------|
| 显式定义 | 独立流程定义函数逻辑，另一个流程里调用 | 通用方法 |
| 融合式 | 多进多出流程图中，多个工作流的重叠部分即为函数 | 无编程经验者友好 |

**融合式的优势**：函数"在图上又不在图上"，无需理解"函数"概念即可自然复用。

### 1.3 流程图的可读性瓶颈与解决方案

**问题**：逻辑复杂后，流程图可读性和可维护性**极大下降**。

| 解决方案 | 说明 |
|---------|------|
| 折叠/展开 | 框选节点 → 一进一出时可折叠为子流程 → 减少细节展示 |
| 树状形式 | 逻辑用树状组织，几乎任何复杂度呈现后都差不多，折叠展开方便，支持拖放重排 |

**折叠规则**：框住的所有节点**一进一出**时可折叠，否则不能。

**两种方式的转换条件**：选中节点只有**一个入口**（出口数量不限）时，流程图和树状形式等价，可相互转换。

## 二、功能节点（填空即开发）

### 2.1 代码 vs 节点

| 概念 | 类比 | 特征 |
|------|------|------|
| 代码 | 原子 | 无化学性质（无业务意义） |
| 功能节点 | 分子 | 由多行代码组合而成，具有特定功能（业务意义） |

**设计方法**：找**功能**（而不是找代码）→ 如"创建订单""订单审批""发送电邮"等。

### 2.2 功能粒度

```
功能越大 → 使用条件越苛刻 → 所需节点数量越多
功能越小 → 可用场景越多 → 通过组合形成新功能 → 节点数量需求越少
```

### 2.3 通用功能节点分类

| 类别 | 示例 |
|------|------|
| 变量操作 | 赋值、读取 |
| 条件判断 | if/else、switch |
| 循环 | for、while、forEach |
| 数组操作 | map、filter、reduce |
| 字符串操作 | 拼接、截取、正则 |
| 数学运算 | 加减乘除、取整 |
| 类型转换 | 字符串↔数字等 |
| 组件操作 | 读写组件属性 |
| 异步操作 | Promise、定时器 |

> 业务功能型节点建议全部移到**插件**中定制——数量多且平台团队不知道业务逻辑。

### 2.4 功能节点的配置

**输入条件可视化配置**（以条件判断为例）：

| 判断方法 | 适用人群 |
|---------|---------|
| 表达式（**默认值**） | 有少量编程技能的用户 |
| 其他可视化方式（下拉选择等） | 无编程技能者 |

**结果可视化配置**：

- 开发者提供**变量名** → 功能节点将计算结果直接赋值给该变量
- 上一个节点的结果可作为下一个节点的输入 → 形成**逻辑链条**

**填空即开发**：每个功能节点定制一个表单 → 开发者填表单（填空）→ 节点自动生成代码（开发）。

## 三、兜底策略

无论可视化编排多强大，都无法解决所有问题 → 需要兜底。

### 实现方式

```
给开发者一个代码编辑器 → 直接编写代码
```

| 特性 | 要求 |
|------|------|
| 基础功能 | 代码输入、运行 |
| 进阶功能 | 智能提示、出错提示、编译错误（占 IDE 功能 **90%**） |
| 定位 | 应当作 **WebIDE** 来理解 |
| 实现弹性 | 根据资源决定做到什么程度 |

## 四、关键认知

1. **可视化编程只需解决交互逻辑**：框架代码由编译器100%生成，可视化编程范围有限且简单
2. **流程图 + 树状可结合使用**：不是非此即彼，满足条件时可相互转换
3. **功能节点凝聚专家经验**：即使无技能者正确填表单，也能得到专家级代码
4. **通用节点 vs 业务节点**：平台负责通用节点，业务节点通过插件定制——平台团队不知道业务逻辑，本就是业务团队的知识
5. **流程图式编排可扩展为 BPMN 场景**：加上泳道、事件等功能，几乎可直接实现符合 BPMN 规范的流程审批场景
