# 31｜从Copilot升级到Agent：观察-规划-执行

> **核心主题**：为 AI Agent 安装"观察层"，建立"观察 - 规划 - 执行"闭环，从 Copilot 进化为 Agent。

---

## 一、问题：为什么需要"观察"能力

此前 AI 助手（Copilot）只能接收指令→生成 JSON Patch→前端执行，**从未"看过"画布**，是"盲人摸象"的执行者。

| 失败场景 | 根因 |
|----------|------|
| 无法回答"页面上有几个按钮？" | 从未读取画布状态 |
| 对不存在的组件执行修改 → 报错或机械回复"无法执行" | 不验证目标是否存在 |
| "在用户注册表单里加一个确认密码输入框"→ 混淆 | 不了解页面结构 |

**统一根因**：缺乏"观察"能力 → Agent 在执行修改前**无法核实事实**。

---

## 二、解决方案：多维观察工具集

设计三个**只读**观察工具，构成 Agent 的"视觉系统"：

### 工具一览

| 工具 | 类比 | 功能 | 输入 | 输出 |
|------|------|------|------|------|
| `get_page_outline` | **广角镜** | 获取页面组件树状结构（不含详细属性） | 无 | 组件层级 JSON |
| `get_component_details` | **放大镜** | 查看指定组件的完整属性 | `component_id` | 组件属性清单 |
| `find_components` | **搜索引擎** | 按条件筛选组件 | `parent_id`(可选) + `filters`数组 | 匹配组件数组 |

### 示例：`find_components` 用法

```json
// 输入：查找 form_abc 内所有蓝色按钮
{
  "parent_id": "form_abc",
  "filters": [
    {"property": "type", "value": "Button"},
    {"property": "color", "value": "blue"}
  ]
}

// 输出
[
  {"id": "btn_1", "type": "Button", "properties": {"text": "确认", "color": "blue"}},
  {"id": "btn_2", "type": "Button", "properties": {"text": "提交", "color": "blue"}}
]
```

### 关键原则

**观察工具必须是只读的** → 职责有且仅有"观察" → 清晰划分"读"和"写"工具 → 构建稳定可靠 Agent 的前提。

## 三、架构升级：指令分诊模块（Triage Module）

在 `/chat` 主流程中，**调用规划器之前**插入分诊模块，对用户指令做智能预处理。

### 分诊逻辑

通过 Meta-Prompt 让 LLM 判断意图性质：

> "请分析用户指令，判断其意图是'查询状态'还是'修改状态'？"

### 两个分支的处理流程

#### 分支一：查询状态

```
用户提问 → 分诊判断"查询" → LLM 选择观察工具 → 执行观察 → LLM 基于数据生成自然语言回答
```

**示例**："页眉里现在有什么？" → 调用 `find_components(parent_id='header')` → 返回组件列表 → 生成自然回答。

#### 分支二：修改状态（含事实核查）

```
用户指令 → 分诊判断"修改" → 【行动前事实核查】→ 根据核查结果决策
```

**事实核查的三种结果**：

| 核查结果 | Agent 行为 |
|----------|-----------|
| 找到**唯一**目标组件 | 继续执行修改操作 |
| 找到**多个**匹配组件 | 发起澄清式多轮对话，让用户选择 |
| **未找到**任何匹配 | 友好报错，提示用户确认 |

**因果链**：引入基于观察的事实核查 → **极大提升 Agent 行为可靠性** → 从盲目执行者变为行动前三思的智能体。

---

## 四、典型场景演示

### 查询类："页面上有多少个输入框？"

| 环节 | 动作 |
|------|------|
| 分诊 | 判断为"查询状态" |
| LLM 决策 | 使用 `find_components(filters=[{type: Input}])` |
| 执行 | 返回 3 个组件对象 |
| LLM 回答 | "页面上总共有 3 个输入框。" |

### 修改类（含事实核查）："把页脚版权信息文字改大"

| 环节 | 动作 |
|------|------|
| 分诊 | 判断为"修改状态" |
| 事实核查 | `find_components(parent_id='footer', filters=[{text: '版权信息'}])` |
| 核查通过 | 定位到 `text_copyright`，当前 fontSize="small" |
| 执行修改 | `updateProperty(componentId='text_copyright', fontSize='large')` |

---

## 五、关键认知

1. **Copilot → Agent 的决定性一步**：安装"观察层"，使 Agent 具备环境感知能力
2. **"观察 - 推理 - 响应"循环**：一次观察对应一次响应，适用于简单场景
3. **复杂任务的局限**：如"把注册表单里所有输入框都加上非空校验"需要**多次观察、多次行动** → 引出下一讲主题：任务规划器
