# 03｜低代码的天花板：一个完备的低代码平台应该具备哪些条件？

> **核心命题**：从适用领域、适用人员、基础设施、全生命周期四个维度描绘天花板级别的低代码平台样貌。不一定要触及天花板才有生产力，但了解天花板有助于精确评估资源投入。

---

## 一、适用领域

### 1.1 双模式支撑

低代码平台必须同时支持：
- **以数据为中心**的开发模式
- **以流程为中心**的开发模式

→ 覆盖多数企业的业务需求

### 1.2 不同复杂度的业务策略

| 业务复杂度 | 策略 |
|-----------|------|
| **简单业务** | 简洁的开发实现方式 + 非常高效的开发效率，应对数量庞大的特征 |
| **复杂业务** | 良好的分步实施策略 + 自然的衔接方式 + **兜底策略** |

### 1.3 兜底策略（应对复杂业务的关键方法）

**定义**：当业务复杂度超过平台能力边界，或可视化模式效率低于 Pro Code 临界值时，允许**回退到传统 Pro Code 模式**继续开发。

**关键要求**：
- 回退过程**自然且内聚**
- 尽可能不影响其他功能的开发
- **前提**：低代码平台需要一个**足够强大的编译器（代码生成器）**
- 完全回退时，代码人工产生而非自动生成 → 平台要做的事反而更少

**极端运用**：可要求低代码平台完全回退到 Pro Code 模式 → 此时平台变为事实上的 **Web Online IDE**

**通用性结论**：低代码平台**必须具有充分的通用性**

## 二、适用人员

### 2.1 不同技能水平的需求差异

| 用户类型 | 需求特征 |
|---------|---------|
| **业务技术员**（无软件开发技能） | 傻瓜化操作、简洁流程、"说人话"（少用编程术语） |
| **专业软件研发人员** | 对熟悉领域要求底层代码掌控/直接编码，对其他领域要求良好可视化辅助（前端要可视化获取业务数据，后端要可视化画 UI） |
| **水平不济的研发人员/职场新手** | 更青睐可视化，希望全流程可视化辅助 |

### 2.2 消除职业危机感

专业研发人员的担忧：
- 失去职业竞争优势 → 失去与公司议价能力
- 技能越强 → 担忧越强烈 → 越抵触低代码

→ 影响团队稳定，需专门应对

### 2.3 各类用户的共同诉求

| 诉求 | 说明 |
|------|------|
| **平缓的学习曲线** | 功能/流程众多 → 采用渐进式设计管控知识要求 |
| **尽可能自动化** | 低代码的魔力所在；但需留一手：自动化不满足时可切换手动模式（兜底策略的应用）；出错时给出准确说明 |
| **可以"抄作业"** | 提供数量众多的典型应用范例；平台构建初期易忽视，成熟后必须恶补 |
| **视频形式教材** | 最好采用无音频 + 外挂字幕方式（便于剪辑和搜索定位） |
| **第一时间帮助** | 建立客服群、首问责任制、开发者与使用者互动 |

## 三、与基础设施和谐相处

### 3.1 运行环境

| 部署方式 | 说明 |
|---------|------|
| 公有云运行时 | 开箱即用，但需照顾客户数据/信息安全担忧 |
| 虚拟镜像/PaaS 安装 | 私有云部署，应对信息安全担忧 |

**要求**：两种方式都需要支持，**特别是私有化部署**。

### 3.2 与已有系统的关系

| 关系类型 | 说明 |
|---------|------|
| 被其他系统集成 | **优先发展** |
| 将其他系统集成到平台 | — |
| 保持相互独立 | — |

**优先发展"被集成"的理由**：低代码是开发工具 → 不具备直接创造价值的能力 → 一般作为子系统被集成 → 难以冲到前面

### 3.3 与存量数据的关系

低代码平台 → 提供**多种能力获取外部数据** → 不将自身封闭成数据孤岛

**难点**：外部数据的结构、存储介质、数据量、获取渠道均无法事先确定 → 定制化融合 → 通过架构设计将定制部分与核心解耦 → **插件系统**解决

### 3.4 权限与安全

- 支持单点登录、对接权限系统
- **区分开发态和运行态**权限
- 开发态与运行态**物理隔离** → 杜绝开发人员利用开发账号越权访问数据

## 四、全生命周期

低代码平台能力必须**覆盖从需求端到应用下线消亡的全过程**：

| 环节 | 说明 |
|------|------|
| **D2C（Design to Code）** | 业界已有成熟实践；低代码平台从设计稿识别关键信息后对接编辑，比纯 D2C 更容易 |
| **UX 设计即开发** | 有 D2C 后，UX 设计师可直接提供模板和业务组件，起到类似研发人员的作用 |
| **App 开发能力** | 低代码的基本作用 |
| **App 自动化测试** | 自动生成测试代码 + 一键式测试环境构建/执行/报告/出错定位 |
| **应用版本管理** | 独立的开发/测试/生产环境 + 测试/灰度发布/正式上线/紧急回退 |
| **应用生产环境监控** | 运行时基础信息监控告警 + 埋点数据植入/采集/分析 |

**所有功能都可以实现低码化和自动化**

---

## 五、关键认知

1. **通用性是根本**：必须同时支撑数据为中心和流程为中心，兼顾不同复杂度
2. **兜底策略是核心方法**：不是通用架构方法，而是在各功能点因地制宜实现的思路
3. **人是最重要的因素**：不同技能水平需差异化对待，共同诉求需统一满足
4. **开发能力只是基本盘**：全生命周期覆盖（D2C → 开发 → 测试 → 部署 → 监控）才是完备平台
