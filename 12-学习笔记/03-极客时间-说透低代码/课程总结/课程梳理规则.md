# 课程梳理规则

> 适用范围：极客时间《说透低代码》课程总结文档

---

## 一、内容取舍原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **保留全部知识性内容** | 概念定义、分类维度、因果逻辑、判断依据、数据结论——一个不删 | 四维分类法、Gartner数据、演进策略三阶段 |
| **砍掉对话式口语** | 所有问候、寒暄、过渡性口语表达 | "你好，我是陈旭"、"你可以看看"、"咱们一起来看看" |
| **保留推理过程** | 作者得出结论的推导逻辑不能只给结论 | 通用→个性化少→配置量大→效率低→需要插件（完整因果链） |
| **保留关键数据** | 量化信息必须保留 | "41%员工"、"3-6个月MVP"、"60-70%工作量" |
| **保留必要案例** | 用来说明观点的实际案例必须保留 | 表单vs模型驱动、烟囱系统、Awade平台经验、WebGIS封装案例 |
| **补充材料精简保留** | 概念解释性内容精简保留，外部链接省略 | IaaS/PaaS/SaaS概念保留，报告链接省略 |
| **思考题省略** | 课程思考题不纳入总结 | — |

## 二、结构化原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **结构化重点** | 用标题/表格/列表/因果链替代大段文字叙述 | Pro Code vs Low Code vs No Code 用表格对比 |
| **但不是所有内容都用表格** | 需要解释逻辑的内容保留段落形式 | "通用型为何必须配插件"用因果链段落而非表格 |
| **重点加粗** | 关键结论、核心概念加粗标注 | **Low Code ≠ No Code，二者完全不是一种东西** |
| **因果链用箭头** | 推理过程用 → 串联 | 越通用 → 个性化越少 → 效率越低 → 需要插件 |
| **每讲开头放课程定位** | 如果该讲涉及本课定义/定位，在开头标注 | > 本课程定义：通用型低代码平台，以专业技术人员为主 |

## 三、格式规范

| 项目 | 规范 |
|------|------|
| 文件命名 | `{原标题}（总结）.md`，与原文同目录 |
| 标题层级 | 一级标题=课程标题，二级=大章节，三级=小节 |
| 分隔线 | 各大章节之间用 `---` 分隔 |
| 表格 | 对比类内容用表格，解释类内容不用表格 |
| 代码块 | 架构图、演进路线等用代码块 |
| 文末 | 保留来源、链接、日期 |

## 四、质量检查清单

每篇总结完成后，对照以下清单自检：

- [ ] 原文所有知识性内容是否保留？（对照原文目录逐项检查）
- [ ] 作者的推理过程是否完整？（不能只给结论）
- [ ] 关键数据是否保留？（百分比、时间周期、数量等）
- [ ] 必要案例是否保留？（用来说明观点的实例）
- [ ] 对话式口语是否清除干净？
- [ ] 重点是否加粗？
- [ ] 因果链是否用箭头串联？
- [ ] 格式是否统一？（标题层级、分隔线、表格风格）
