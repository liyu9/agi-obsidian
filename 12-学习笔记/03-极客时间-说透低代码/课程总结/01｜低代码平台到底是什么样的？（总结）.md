# 01｜低代码平台到底是什么样的？

> **本课程定义**：以专业技术人员为主要用户群的通用型低代码平台，具有通用性底座和完善的插件机制。
> - "低代码工具"= 规模小、成熟度低；"低代码平台"= 规模大、功能完善。两者内涵一致，区别在规模和成熟度。

---

## 一、低代码的四维分类

低代码概念至今没有业界共识，不同人带着不同业务背景来理解，会得到差异很大的结论。通过多维度分类，可以建立清晰认知。

### 1. 按代码量：Pro Code / Low Code / No Code

| | Pro Code（纯代码） | Low Code（低代码） | No Code（无代码） |
|---|---------|----------|---------|
| 代码角色 | **关键输入** | **中间产物**（副产品） | 无代码参与 |
| 开发思维 | 指令式：告诉计算机如何一步步实现 | 描述式：不停描述和细化业务最终样子 | 组合式：对已有原子业务能力二次组合 |
| 框架性代码 | 手工编写 | 100%自动生成 | 不涉及 |
| 业务代码 | 全部手写 | 只需填表达式或少量复杂逻辑 | 不涉及 |
| 开发者需要做的事 | 思考业务最终样子 + 将其翻译成一条条计算机指令 | **只需**思考业务最终样子（无需翻译成指令） | 选择和组合已有功能 |

**Low Code 与 No Code 的关键区分**：

- 低代码开发过程**有代码参与**，特别是复杂业务逻辑，通过表达式或直接编码来表达反而更清晰
- 无代码开发过程**无任何代码参与**（包括内部实现），严格来说不应称为"开发"，只是对已有业务的二次组合
- **因此低代码和无代码完全不是一种东西，切不可混为一谈**

**容易混淆的场景**：低代码成熟度到一定高度时，某些细分场景可实现零代码开发，此时外观与无代码差异微小。部分厂商故意将二者混为一谈，把无代码当噱头宣传。实际上低代码要将一个场景做到零代码，难度非常大，且有诸多业务前提。

### 2. 按适用范围：专用型 / 通用型

| | 专用型 | 通用型 |
|---|-------|-------|
| 底座 | 绑定特定业务场景 | 纯技术底座，不依赖特定业务，只与业界标准协议/技术标准耦合 |
| 效率 | 特定场景效率极高 | 通用代价：默认配置个性化少 → 特定场景配置量大 → 效率低 |
| 扩展 | 插件少或无 | **必须有完善的插件机制** |
| 识别方法 | — | 插件数量众多（插件廉价，可填满通用功能覆盖盲区） |

**通用型为何必须配插件——因果链**：
越通用 → 默认配置里的个性化信息越少 → 为形成具体场景所需配置量越大 → 从该场景看效率越低 → **用插件的定制化和扩展性来解决效率问题**

相对高通用性的技术底座来说，插件是廉价的。因此通用型平台往往有数量众多的插件，定制出各式各样具体的业务场景。

### 3. 按输出App类型

通用型平台不局限输出某一种类型的App——支持各种类型只是时间问题。当前业界低代码平台输出的App类型：

| App类型 | 说明 |
|---------|------|
| 流程驱动型 | 以流程为主线，支持审批、流转 |
| 表单驱动型 | 以数据为中心，通过表单收集/呈现数据 |
| 模型驱动型（ORM） | 以数据模型和关系为核心，配置数据关系后方便创建CRUD类App |
| BI分析型 | 以数据可视化和分析为中心 |

**表单驱动 vs 模型驱动的关键差异**（容易混淆）：

- **模型驱动**：模型=数据模型/数据关系（符合三范式的关系型数据库关系）。在正确配置各种数据关系之后（数据建模），页面上就可以方便地创建CRUD类App
- **表单驱动**：仅以数据为中心，创造各种表单来收集或呈现数据。**不关注数据之间的关系** → 非常容易形成数据孤岛，存在大量冗余数据和数据不一致性问题
- **趋同性**：如果将表单类App做得比较完善，实际上它就会逐渐转型成模型驱动类App。完成数据建模之后，差异只剩前端用表单展示还是表格展示

### 4. 按使用者类型

| 用户类型 | 定义 | 适用平台 |
|---------|------|---------|
| 专业技术人员 | 掌握软件研发技能 | 低代码（**主要用户**） |
| 业务技术人员 | 非IT部门员工，构建供内外部业务使用的技术或分析功能，担任装备和赋能非IT资源的战略角色 | 低代码（次要）+ 无代码（**主要用户**） |
| 无专业技能人员 | 无任何软件技能 | 无代码 |

**业务技术人员数据**（Gartner研究）：41%的员工可以被称为业务技术人员，不同行业差异很大：
- 政府部门等技术密集度较低的行业：约25%
- 能源等IT密集型行业：约50%

**用户群演进规律**：
- 低代码平台成熟度↑ → 可视化工具更丰富 → 研发生命周期各环节覆盖更完整（开发→测试→上线→运维全链路可视化/自动化）→ 业务技术员独立开发成为可能 → 业务技术员占比↑
- 同时，完善的可视化自动化能力不仅会牢牢抓住已有的专业技能用户，还会吸引更多专业技能用户加入

## 二、低代码的发展

### 2.1 基础设施演进

```
物理设备 → IaaS → PaaS → SaaS → aPaaS
```

| 概念 | 全称 | 说明 |
|------|------|------|
| IaaS | Infrastructure as a Service | 提供计算、储存、网络等基础运算资源 |
| PaaS | Platform as a Service | 将软件研发平台作为服务提供 |
| SaaS | Software as a Service | 软件即服务，通过网络直接使用，无需安装 |
| **aPaaS** | application Platform as a Service | 为应用程序提供开发和部署环境 |

**aPaaS是关键演进节点**：SaaS高度封装为行业提供了巨大便利，但定制性太弱，由此演进到aPaaS。

aPaaS平台提供的功能：迭代构建应用、即时提供应用、按需扩展应用、集成应用与其他服务。

**作者观点**：aPaaS中的"a"理解为 **ability（赋能）** 比 application 更恰当——aPaaS赋予了软件服务体系**开发和部署的能力**。

### 2.2 时间与地域

- **国外**：低代码头部解决方案中已有 OutSystems、Microsoft 等通用型低代码巨无霸
- **国内**：多数提供商还在探索如何有效为某个垂直行业、细分领域提供低代码服务
- **国内落后约一个时代**
- **对从业者而言是好事**：仍是蓝海，大有可为

### 2.3 中台演进

低代码与中台为何相关？

**背景**：传统企业中每个部门有不同的系统需求，各自采购自己的系统，但这些系统彼此孤立、独立运作，导致企业软件系统冗杂（"烟囱系统"）。

**低代码能做什么**：让绝大部分部门的业务系统都能在一个平台里搭建，彼此联系，打破信息系统孤岛，降本增效，提升内部生产力。

**与中台的三个重合点**：
1. 低代码有助于横向打破传统企业的烟囱系统，将它们串联到一起 → 与中台目标不约而同
2. 低代码对外赋能的职能 → 也是中台建设目标之一
3. 中台的发展过程，有相当一部分线路与低代码是重合的

**结论**：如果企业同时在架构中台和低代码，应放到一起来考虑。二者可以相互促进、良性共生。

## 三、行业竞品调研

### 3.1 调研方法

- **只看专业调查机构的报告**，网上信息太多且真假难辨
- 以竞品调研为目的时，**只研究Leader象限/波的厂商**即可——技术能力强、规划清晰、产品被市场广泛认可，有极强参考价值

### 3.2 全球竞品调研

| 报告 | 关键内容 |
|------|---------|
| Gartner 魔力四象限 | Leaders象限：技术能力强、规划清晰、市场广泛认可 |
| Forrester Wave™ | Leaders波：同上 |

**关键发现**：两家头部机构对低代码的Leaders给出了**几乎一致的结论** → 为竞品调研提供了非常明确的指引，直接研究这些Leader即可。

### 3.3 国内市场

| 报告 | 关键内容 |
|------|---------|
| Forrester《The State Of Low-Code Platforms In China》 | 低代码在国内主要应用于：银行、保险、零售、医疗、政府、制造、电信、建筑等行业，集中在9个领域 |
| 艾瑞咨询《2021年低代码行业研究报告》 | 包含概念界定、应用场景、竞争要素、市场规模、趋势洞察；将厂商分为通用型和垂直型 |

**国内市场判断**：
- 大小厂商众多、"百花齐放" = 仍处于投资风口早期阶段
- 按行业规律：风口褪去后，厂商会快速聚集（大鱼吃小鱼/抱团取暖）→ 寡头化
- 当前百花齐放 = 风投仍在持续注入，大家还能坚持得住

## 四、关键认知

1. **低代码概念无共识**：是个大框，什么都能往里装。不同人带着不同业务背景理解 → 差异很大的结论，甚至连什么不能算低代码都说不清楚。通过四维分类建立清晰认知
2. **本课定位**：通用型低代码平台，以专业技术人员为主，通用底座 + 完善插件机制
3. **竞品调研起点**：Gartner和Forrester的Leader是最佳研究对象，两家结论一致，目标明确
