# 29｜当自然语言遇上可视化：打造新一代低代码开发体验

> **核心内容**：从"理解"到"行动"的关键一跃。确立**自然语言与可视化协同互补**的核心战略，设计从意图到 UI 变更的端到端技术链路：契约制定 → 后端翻译（JSON Patch）→ 前端执行。

---

## 一、顶层设计：自然语言与可视化的协同互补

### 1.1 两种模式对比

| | 可视化操作 | 自然语言驱动 |
|---|----------|------------|
| 核心优势 | **直观** + **确定性**，所见即所得 | **低门槛** + **高效表达复杂意图** |
| 最佳场景 | 调整布局、颜色、字体等视觉样式（移动13px、取色） | 跨多面板操作、复杂业务逻辑（条件/分支/状态变更） |
| 致命短板 | **复杂性**："配置地狱"，难以描述复杂逻辑流 | **模糊性** + **非精确性**，微调任务笨拙低效 |

### 1.2 理想工作流

```
自然语言：完成"从 0 到 1"的快速搭建 + 复杂逻辑定义
    ↓
可视化：完成"从 1 到 1.1"的精细化调整 + 最终确认
```

## 二、技术架构：从意图到 Action 的完整链路

### 2.1 制定契约

#### 页面蓝图（Page Schema）

页面的**唯一真实来源**，JSON 格式描述页面上所有组件及其属性。

```json
{
  "pageId": "page_001",
  "title": "首页",
  "components": [
    { "id": "comp_001", "type": "Heading", "props": { "level": 1, "text": "欢迎" } },
    { "id": "comp_002", "type": "Button", "props": { "text": "点我", "color": "primary" } }
  ]
}
```

**AI 助手的核心任务**：通过"行动"来**修改这份 JSON**。

#### AI 能力清单（Actions/Intents）

| 动作 | 说明 | 必需参数 |
|------|------|---------|
| `createComponent` | 创建新组件 | `componentType` 等 |
| `updateProperty` | 更新组件属性 | `componentId` + prop 键值对 |
| `deleteComponent` | 删除组件 | `componentId` |
| `moveComponent` | 移动组件位置 | `componentId` + 目标位置 |
| `bindData` | 属性与数据源绑定 | — |
| `setInteraction` | 设置交互逻辑 | — |

### 2.2 后端：意图 → JSON Patch

#### Action 处理器分发器

```python
def handle_action(intent_data):
    intent = intent_data.get("intent")
    if intent == "createComponent":
        return handle_create_component(entities)
    elif intent == "updateProperty":
        return handle_update_property(entities)
    # ...
```

#### 为何选择 JSON Patch（RFC 6902）

| 方案 | 问题 |
|------|------|
| 返回整个页面 JSON | 页面100个组件只改1个按钮 → **网络开销大，效率低** |
| **JSON Patch** | **精确、轻量、标准**，只描述"发生了什么变化" |

JSON Patch 操作对象包含：`op`（操作类型：add/remove/replace）、`path`（修改位置）、`value`（新值）。

#### 完整流程示例

用户输入："添加一个蓝色的登录按钮"

```
DSPy 输出:
  intent: createComponent
  entities: { componentType: Button, text: "登录", color: "blue" }

后端生成 JSON Patch:
  [{ "op": "add", "path": "/components/-", "value": { id, type, props } }]

前端收到 Patch → applyPatch 更新状态 → UI 实时渲染
```

`path` 中 `-` 表示数组末尾添加元素。

### 2.3 前端：接收 Patch → 响应式渲染

```javascript
import { applyPatch } from 'fast-json-patch';

const [pageSchema, setPageSchema] = useState(initialSchema);

const handleApiResponse = (patch) => {
  const newSchema = applyPatch(pageSchema, patch).newDocument;
  setPageSchema(newSchema);
};
```

**核心简化**：前端只需接收 JSON Patch → 应用到 state → 框架自动响应式重渲染。

### 2.4 端到端完整流程

```
用户输入 → 前端发送到 /chat API
  → 后端 DSPy 分析（意图 + 实体）
  → Action 处理器生成 JSON Patch
  → 返回 JSON Patch
  → 前端 applyPatch + setPageSchema
  → UI 实时更新
```

## 三、关键认知

1. **非替代，而是协同**：自然语言做"0→1"搭建，可视化做"1→1.1"微调
2. **契约是基础**：Page Schema（页面蓝图）+ Actions（能力清单）= AI 和编辑器的通用语言
3. **JSON Patch 是关键利器**：精确、轻量、标准，避免全量传输
4. **前端几乎无需改造**：只需判断响应类型（JSON Patch vs 文本），职责极简
5. **麻雀虽小五脏俱全**：核心骨架已搭建，后续在骨架上添砖加瓦
