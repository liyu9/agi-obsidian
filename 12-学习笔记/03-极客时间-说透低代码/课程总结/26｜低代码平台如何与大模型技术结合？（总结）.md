# 26｜低代码平台如何与大模型技术结合？

> **核心结论**：低代码平台与大模型结合主要有两种模式——**Copilot 模式**（当前最佳）和 **Agent 模式**（未来方向）。两者不是二选一，而是技术发展不同阶段的产物，Copilot 是 Agent 的基础。

---

## 一、两个关键概念

| | Copilot（助手） | Agent（智能体） |
|---|----------------|----------------|
| 输入 | **指令**（人类拆分任务后逐步下达） | **目标**（人类只描述最终目标） |
| 智能水平 | 低智：理解"人话"，提取信息，执行指令 | 高智：自主规划步骤，直接实施 |
| 人类角色 | 任务拆解者 + 指令下达者 | 监督者 + 授权者 |
| 关键能力 | NLU → 意图分类 + 实体提取 | **推理能力**（自主规划 + 动态调整） |
| 当前可用性 | **成熟可靠**，已广泛落地 | 推理能力尚不足，探索期 |

**Agent 的本质**：在 Copilot 基础上增加了自动拆解任务、规划步骤的能力 → 每个具体任务仍交给 Copilot 执行。

---

## 二、三种结合模式（由低到高）

### 2.1 知识问答模式（入门级）

- 技术：RAG 知识库 + 外接大模型
- 难点：领域知识整理和切片（人力密集型）
- 可边用边整理，文档整理程度只影响问答效果

### 2.2 Copilot 模式（当前最佳）

**核心**：指令式 AI 助手，依赖大模型的**意图分类**和**实体提取**能力。

| 特点 | 说明 |
|------|------|
| 任务分解由人类主导 | 用户自行拆解步骤，逐步输入具体指令 |
| 高效执行能力 | 快速生成代码片段、配置文件，重复性任务表现更好 |
| 适合初学者 | 自然语言下指令 > 阅读手册，降低试错成本 |

**解决逻辑性任务的路径**：
用户通过自然语言描述业务逻辑 → 大模型生成代码 → 通过提示工程打通私域业务知识

**定位**：在大模型推理能力足够强大且足够便宜之前，**必然是最佳结合方式**。虽未提供端到端解决方案，但已有足够多的价值，是里程碑式提升的基础。

### 2.3 Agent 模式（未来方向）

| 特点 | 说明 |
|------|------|
| 目标驱动 | 用户描述目标，Agent 自主规划并执行 |
| 自主规划与动态调整 | 依托更强推理能力，根据任务情况动态调整 |
| 人类角色简化 | 监督与授权，不必参与细节 |

**对低代码平台架构的影响**：
- LUI（Language-based User Interface）将替代 GUI 成为人机交互主要模式
- GUI = 以流程为中心的业务架构；LUI = **以人为中心**的业务架构
- LUI 下 UI 生命周期极短，甚至**阅后即焚**
- GUI 不会完全消失，两者相辅相成

**现状判断**：大模型能力离实现 Agent 还有距离，OpenAI o1 将推理能力训练到大模型中开了好头，但趋势未根本改变。

## 三、可视化与自然语言的结合策略

### 3.1 已有成熟低代码平台

**可视化为主，自然语言为辅**：
- 最大化可视化技术的（剩余）价值
- 积极引入自然语言弥补可视化缺陷
- 理想方式：**可视化设计全局操作流程 + 局部用自然语言落地**

### 3.2 低代码工具刚起步

**自然语言为主，可视化为辅**：
- 从头研发完善低代码工具已不明智
- 但非全盘自然语言化，物极必反

| 场景 | 推荐方式 |
|------|---------|
| 业务流程概要设计（全局脉络） | **可视化**（图表、流程图，直观呈现整体） |
| 细分业务流程（信息采集、任务编排） | **自然语言**（灵活表达复杂逻辑） |
| 数据展示（编排、关联展示） | **自然语言**（命令定制复杂数据展示逻辑） |
| UI 布局调整、界面设计微调 | **可视化**（直观微调组件位置、图表样式） |

---

## 四、关键认知

1. **Copilot 是 Agent 的基础**：没有 Copilot 支持下，不可能通过一段话端到端自动生成产品所有功能
2. **两种模式具有继承性**：不是矛盾或不可调和的结论，而是不同发展阶段的产物
3. **可视化与自然语言互补性极强**：可视化成熟/形象/全局观，自然语言便利/零门槛/灵活，必须结合使用
