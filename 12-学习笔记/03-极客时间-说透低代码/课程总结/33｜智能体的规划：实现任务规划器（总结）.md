# 33｜智能体的规划：实现任务规划器

> **核心主题**：将第32讲的设计蓝图用 Python 代码实现，让 Agent 拥有能"思考"的规划器。

---

## 一、状态摘要生成器 `summarize_page_state()`

**目标**：将原始页面 JSON 转换为 LLM 友好的 Markdown 摘要。

**本质**：树的递归遍历，按 `- 组件类型 (id: 组件ID)` 格式输出。

**核心逻辑**：

```
输入: 页面状态 JSON（嵌套 children 结构）
  → 递归遍历每个节点
  → 格式化: "  " * 缩进层级 + "- {type} (id: {id})"
输出: Markdown 文本
```

**转换效果**：

```
原始 JSON（嵌套 props/style）→ Markdown 摘要（仅保留类型+ID+层级）
- Page (id: root)
  - Header (id: header_123)
    - Image (id: logo_456)
  - Form (id: form_abc)
    - Input (id: input_456)
    - Button (id: btn_789)
```

## 二、指令/目标分流器 `route_request()`

**实现**：构造轻量级 Prompt → LLM 二元分类 → 返回 `single` 或 `multi`。

**关键设计决策**：

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 模型选择 | `gpt-3.5-turbo` | 速度快、成本低，分类任务无需强模型 |
| temperature | 0.0 | 需确定性输出 |
| max_tokens | 5 | 只需返回 single/multi |
| 异常兜底 | 默认返回 `single` | 异常时走轻量通道，系统更稳定 |

## 三、规划器主类 `Planner`

### 架构

```
Planner 类
  ├── __init__(): 加载工具定义
  ├── _load_tools_definition(): 返回格式化的工具清单字符串
  ├── _build_meta_prompt(goal, state_summary): 动态拼装元提示
  └── generate_plan(goal, page_state): 核心方法 → 调用 LLM → 返回 JSON Plan
```

### `_build_meta_prompt()` —— 五要素的程序化拼装

| 要素 | 代码变量 | 内容 |
|------|---------|------|
| 角色扮演 | `role_prompt` | "你是资深低代码应用架构师" |
| 最终目标 | `goal_prompt` | 用户的原始需求 |
| 环境感知 | `env_prompt` | Markdown 格式的状态摘要 |
| 可用工具 | `tools_prompt` | 工具名称+参数+描述 |
| 输出契约 | `contract_prompt` | JSON 结构 + ReAct/观察优先/$steps/经济原则 |

### `generate_plan()` 核心流程

```
page_state → summarize_page_state() → state_summary
goal + state_summary → _build_meta_prompt() → meta_prompt
meta_prompt → litellm.completion(model="gpt-4o") → plan_text
plan_text → json.loads() → JSON Plan
```

**关键设计决策**：

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 规划模型 | `gpt-4o` | 规划任务复杂，需强模型 |
| response_format | `{"type": "json_object"}` | 强制 JSON 输出 |
| temperature | 0.1 | 近乎确定性但保留微小灵活性 |
| 错误处理 | 捕获 `json.JSONDecodeError` | LLM 偶尔返回非标准 JSON |

## 四、端到端验证

**测试场景**："创建一个包含标题（'用户登录'）和提交按钮的表单"

**流程**：

```
user_goal → route_request() → "multi"
          → Planner().generate_plan(goal, page_state)
          → LLM 生成 JSON Plan
```

**生成结果**与第32讲手动设计的"干跑"结果**几乎一致**：
- Step 0: 创建 Form 容器
- Step 1: 在 Form 内创建 Text（`parentId: $steps.0.result.id`）
- Step 2: 在 Form 内创建 Button（`parentId: $steps.0.result.id`）

**验证通过**：`$steps` 引用语法被准确使用，reasoning 字段逻辑清晰。

## 五、关键认知

1. **从理论到实践**：元提示五要素 → 程序化拼装 → `_build_meta_prompt()` 函数
2. **模型分级使用**：分流器用 gpt-3.5（轻量），规划器用 gpt-4o（重量）
3. **健壮性**：JSON 解析必须有 try-except，LLM 输出不可完全信任
4. **下一步**：计划已生成但无法改变世界 → 需要执行引擎（第34讲）
