# 27｜低代码助手第一步，Chatbot的实现

> **本讲目标**：实现低代码平台智能化转型的第一步——搭建一个完整的 Chatbot，作为人机交互入口。Chatbot 不仅是文字对话，更需要**理解人类意图并执行 Action**。

---

## 一、Chatbot 的三大需求

| 需求 | 说明 |
|------|------|
| 多模态输入 | 接受文字及其他模态提示信息，正确转发给大模型 |
| 意图理解 + Action 执行 | 理解人类意图并执行操作，而非仅仅返回文字（与 ChatGPT 直接显示文字不同） |
| 易于集成 | 技术上可对接服务端，UX 风格可融入现有平台 |

**关键约束**：需要在后台执行 Action → 必须能和服务端对接 → 排除所有在线大模型 Hub。

---

## 二、前端技术选型

### 候选方案

| 方案 | 评价 |
|------|------|
| ChatUI | 智能对话领域的设计开发体系，仅前端 |
| **Pro Chat** | **蚂蚁开源**，仅前端，基于 React |
| 自研 | Awade 的选择：因 UX 灵活性需求高 + 市面无合适方案，但无开源计划 |

**最终选择**：**Pro Chat**（前端） + **Vercel AI SDK**（辅助）

- Pro Chat 基于 React → 与 Vercel AI SDK（React 友好）可共存
- Vercel SDK 有服务端能力但仅 TS 版 → 服务端另选

---

## 三、服务端技术选型

| 选项 | 说明 |
|------|------|
| 语言 | **Python**（因青睐的提示词优化工具仅有 Python 版） |
| 框架 | **不使用任何框架**，直接用 Python 基础能力 |
| LangChain | 不采用——简单 AI 应用太复杂，低代码智能体又太简陋。但其**理念**值得学习（如何通过话术实现代码与大模型交互） |

---

## 四、代码架构

### 前端

- 典型 React 工程
- 关键文件：`src/App.js` → 首页放置 ProChat 组件 + 少量配置

### 后端

- 仅 `main.py` 一个文件
- 关键服务：`/chat` 接口供前端调用
- `@app.options("/chat")`：跨域配置（开发用，**切勿放线上**，有安全风险）
- 默认使用不知名大模型（调试用），如有 OpenAI API Key 修改代码即可

### 代码仓库

- GitHub：`https://github.com/rdkmaster/low-code-copilot.git`
- 切换到本讲 tag：`git checkout lecture-27`

---

## 五、关键认知

1. **Chatbot ≠ 聊天机器人**：核心是理解意图 + 执行 Action，文字输出只是副产品
2. **前后端分离选型**：前端选 React 生态组件（Pro Chat），后端选 Python（工具链优势），各自独立
3. **从简开始**：本讲不使用任何后端框架，随着复杂度增加再引入
