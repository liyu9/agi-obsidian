# 28｜文本分类和实体提取

> **核心内容**：意图分类和实体提取是一切 AI 应用的基础能力。意图分类搞清"用户要做什么"，实体提取找出"做这件事需要什么参数"。推荐使用 **DSPy 框架**替代传统提示词工程，提升可维护性和准确率。

---

## 一、意图分类

### 1.1 定义与关键特征

- **目标**：将用户自然语言文本归类为某一**预定义意图**
- **关键隐含信息**：意图都是**预设的、可枚举的**（低代码系统中用户操作总是可预知的） → 大幅降低实现难度

### 1.2 处理流程

```
用户输入 → 意图分类（找到最佳处理流程） → 实体提取（获取流程所需参数） → 执行
```

### 1.3 DSPy 框架

**为何选择 DSPy 而非传统提示词**：

| 传统提示词的问题 | DSPy 的解决方式 |
|-----------------|----------------|
| 文字逻辑**非常脆弱**，微小修改即可导致大模型行为大变 | 通过**编码**而非自然语言实现逻辑 |
| 提示词与大模型**强耦合**，换模型几乎要重写 | 结构化、声明式模块编程，降低耦合 |
| 难以测试和维护 | 代码可测试、可维护 |

DSPy 核心定位：用于**编程**（而非提示）语言模型的框架，重点从修补提示字符串转移到使用结构化和声明性自然语言模块进行编程。

### 1.4 实现示例

```python
class Classify(dspy.Signature):
    """对句子进行分类。"""
    sentence: str = dspy.InputField(desc="输入句子")
    sentiment: Literal['科技', '教育', '健康', '建议', '其他'] = dspy.OutputField(
        desc="只输出句子类型，并且必须是 '科技'、'教育'、'健康'、'娱乐'或'其他' 之一"
    )
    confidence: float = dspy.OutputField(desc="分类的置信度 (0-1)")

classify = dspy.Predict(Classify)
res = classify(sentence="最新的AI模型已经可以生成非常逼真的图片了。")
```

## 二、实体提取

### 2.1 定义

- **目标**：从用户输入中识别并提取特定信息
- **发生时机**：意图分类**之后**（脱离具体流程的参数实体没有意义）
- **示例**："我想明天预订一张从北京到上海的机票" → 日期"明天"、出发地"北京"、目的地"上海"

### 2.2 参数实体的分类

一个具体的处理流程不仅定义了参数实体的**实际意义**，还定义了：
- 哪些是**必须的**
- 哪些是**可选的**

### 2.3 缺失参数的处理策略（多轮对话雏形）

```
从已有输入中提取已知参数 → 检查必选参数是否有值 → 缺失则推送问题询问 → 重复直到所有必选参数合法
```

- 对话节奏在 **AI 助手掌握之中**
- 正常用户都会配合提供参数值

### 2.4 实现示例

```python
class ExtractInfo(dspy.Signature):
    """Extract structured information from text."""
    text: str = dspy.InputField()
    title: str = dspy.OutputField()
    headings: list[str] = dspy.OutputField()
    entities: list[dict[str, str]] = dspy.OutputField(desc="实体及其元数据的列表")

module = dspy.Predict(ExtractInfo)
response = module(text="...")
```

## 三、评估与优化

### 3.1 准确率问题

- 意图分类和实体提取都有准确率问题
- **过低准确率 → AI 助手不可用**
- 简单方案（更聪明模型）代价：更高费用 + 更长推理时延

### 3.2 DSPy 优化方案

**量化评估**：
- 使用 DSPy 的 `Evaluate` 实用程序处理并行性和可视化
- 评估数据集：CoNLL-2003（实体提取标准数据集）

**MIPROv2 优化器**：
- 自动调整提示词指令
- 基于训练集构建 Few-Shot 示例
- **模型不变前提下，准确率提高约 15%~25%**

**优化流程**：
```
构建训练数据集 → MIPROv2 编译优化 → 重新评估 → 不满意则调整数据集再优化
```

### 3.3 训练数据集构建经验

- **人工构建 30 条左右**高质量数据 → 让更聪明的模型（如 ChatGPT o1）**合成额外数据集**
- 注意：训练使用的模型与合成数据的模型**不能相同**，否则可能无效
- 优化结果可保存为 JSON：`optimized_extractor.save("optimized_extractor.json")`
- 运行时可 load 避免重复优化

### 3.4 可量化评估的价值

- **品控手段**：正规项目化运作的产品必备
- **可信的宣传手段**：量化结果比主观描述更有说服力

## 四、Copilot vs Agent 的意图处理差异

| | Copilot 模式 | Agent 模式 |
|---|------------|-----------|
| 意图范围 | 只允许**预设的、有限数量**的意图 | 引入推理能力更强的大模型，**推断预设之外的意图** |
| 处理方式 | 按预设流程处理 | 基于已有能力 + 用户历史操作 + 推理，推断实现步骤 |

---

## 五、关键认知

1. **意图分类 + 实体提取 = AI 应用基础**：一切 AI 应用的起点
2. **DSPy > 传统提示词**：编码方式替代文字逻辑，解决脆弱性和耦合性两大痛点
3. **可量化是关键**：DSPy 提供评估 + 优化 + 保存的完整闭环
4. **DSPy 不能完全替代提示词**：后续低代码 Copilot 实现中仍有许多地方需要文字提示
