# 23｜低代码平台如何帮助应用做测试？配置即测试

> **核心问题**：基于前三讲的理论和算法，如何通过简单配置自动生成完整的测试用例代码，实现"配置即测试"？

---

## 一、被测功能的顺序

### 1.1 功能之间的关系

被测功能之间**可以有序，也可以无序**：

- 无序 → 天然可并行执行
- 有序 → 前一个功能的副作用 = 下一个功能的输入数据基础

**关键问题**：哪些功能属于同一业务 → 需要串行执行？

**答案**：由业务决定 → 低代码平台无法自动判断 → **需要开发人员配置**。

### 1.2 功能树 vs 功能拆分

- 所有功能组成一棵功能树 → 太复杂 → 只能串行 → 调试困难 → 试错周期太长
- **尽可能拆散** → 能独立的就独立 → 并行执行 → 提高效率
- 独立的根本条件：**能否提供所需的输入数据**

### 1.3 对应概念

| 自动化测试概念 | 对应关系 |
|----------------|----------|
| 用例集（describe） | 同一业务的有先后顺序的功能 |
| 用例（it） | 单个被测功能 |
| 用例集间无耦合 | 不同业务的功能可并行执行 |

### 1.4 生成的代码结构

```javascript
describe('串行测试集：测试 RAT=5G，area=江苏省', () => {
  it('基础数据查询测试', () => { ... })
  it('表-图联动测试', () => { ... })
})
describe('并行测试', () => { ... })
```

## 二、输入数据与副作用配置

开发人员的**最大工作量**：配置一头一尾两笔数据。

### 2.1 前置条件（输入数据）配置

选定组件 → 在"值"框填写预期数据 → 完成。

**关键特点**：
- **看不到任何技术细节**（无 Selector、无测试框架 API 调用）
- 这些技术细节正是传统 UI 测试用例所有问题的根源
- 低代码平台自动知道组件的 Selector（使用 ID 选择器，平台确保唯一）

生成的代码示例：

```javascript
it('基础数据查询测试', () => {
  cy.get('#jigsawInput11').type('小明');
  cy.get('#jigsawSelect12').select('江苏');
})
```

### 2.2 验证数据（副作用/预期数据）配置

展示所有受波及的组件（通过装饰器 + AST 分析找到的） → 为每个组件配置预期数据。

生成的代码示例：

```javascript
it('基础数据查询测试', () => {
  const expectData = {
    header: [ "...", "...", "...", "..." ],
    field: [ "...", "...", "...", "..." ],
    data: [[ "...", "...", "...", "..." ], [ "...", "...", "...", "..." ]]
  }
  checkData(this.jigsawTable1.data, expectData, 'contains');
})
```

`checkData` 内部调用 `assertJsonEquality` 函数（上一讲末尾给出）。

## 三、HTTP 拦截器

### 3.1 问题

几乎每个功能都涉及 HTTP 请求 → 每个功能都要配置 → 大量重复。

### 3.2 两个配置点

| 配置点 | 时机 | 作用 |
|--------|------|------|
| 页面初始化数据等待 | `beforeEach` 钩子 | 页面打开后等待初始化服务返回再执行操作 |
| 监听请求 | 用例内部 | 等待特定 HTTP 请求完成后校验数据 |

两者配置方式相似，差异仅在触发时机。若 URL 规则相同，后者可省略。

## 四、一键测试与反馈

### 4.1 平台已支持预览的情况

应用执行环境已就绪 → 集成测试驱动框架（Cypress）和浏览器驱动 → 一键执行。

### 4.2 平台未支持预览的情况

在导出应用时，连同测试用例代码一起导出一个**一键部署和启动测试的脚本** → 应用开发人员执行脚本即可。

---

## 五、完整流程总结

```
被测功能定义（归纳法）
  → 输入数据 → 触发功能 → （中间不关心）→ 产生副作用

自动发现被测功能
  → 抓住交互事件 → 跟踪事件链/树
  → AST 分析代码块 + 装饰器标记结构化配置

副作用检测
  → 找到受波及组件
  → 关键假设：组件不会出错 → 只需比对数据，无需比对 DOM

配置即测试
  → 开发人员只需配置：功能顺序、输入数据、预期数据、HTTP 规则
  → 平台自动生成完整测试用例代码
```

**核心理念**：把简单留给别人，把复杂留给自己。
