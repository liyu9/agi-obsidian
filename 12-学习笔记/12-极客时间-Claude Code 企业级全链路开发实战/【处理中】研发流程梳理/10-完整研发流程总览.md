### 阶段1：需求分析

| 属性 | 内容 |
|------|------|
| **阶段说明** | 在动手之前，先用咨询模式让 Agent 帮你梳理需求全景 |
| **Agent协作模式** | 咨询模式 |
| **核心产出物** | 功能全景清单 |
| **课程来源** | 文章02、03（三问裁剪法） |

**Agent 操作**：
```
"帮我梳理一个 AI Agent 开发平台（如 Dify）的核心功能模块，
从用户视角列出主要功能点，不需要实现细节"
```

**方法论：三问裁剪法**

| 问题 | 目的 | 示例 |
|------|------|------|
| **第一问：做了有什么价值？** | 评估功能ROI | "RAG知识库能做什么？价值有多大？" |
| **第二问：不做的代价是什么？** | 评估放弃成本 | "没有RAG，用户能接受吗？" |
| **第三问：做到什么程度？** | 确定功能边界 | "做TXT还是PDF？全文检索还是语义检索？" |

**产出示例**：
```markdown
## Hify 功能全景
1. 模型提供商管理（OpenAI/Claude/Ollama）
2. Agent 创建与配置
3. 对话引擎（流式响应、多轮对话）
4. 知识库 + RAG（一期TXT、固定分块）
5. 工作流编排（JSON配置）
6. MCP 工具接入
7. 管理控制台
```

### 阶段2：边界定义

| 属性 | 内容 |
|------|------|
| **阶段说明** | 明确"做什么"和"不做什么"，这是后续所有决策的基础 |
| **Agent协作模式** | 人类主导 |
| **核心产出物** | 产品边界文档 |
| **课程来源** | 文章03 |

**关键原则**：边界定义错误会导致后续所有决策偏离目标

**反面案例**（课程踩的坑）：
- 直接让 Agent 设计架构，没有定义边界
- Agent 给出过度方案：服务注册中心、分布式配置、链路追踪
- 结果：做了一个"百万用户生产系统"，而不是"几十人内部平台"

**产品边界示例**：
```markdown
## 项目概述
Hify 是一个简版的 AI Agent 开发平台，面向团队内部小规模使用（20-50人）。

### 做什么
- 多模型提供商管理（OpenAI、Claude、Gemini、Ollama）
- Agent 创建与配置
- 对话引擎（流式响应、多轮对话）
- 知识库 + RAG（一期只支持TXT文档）
- 简版工作流（JSON配置）

### 不做什么
- 不做可视化工作流拖拽编排
- 不做多租户/权限体系
- 不做插件市场、计费系统
```

| **课程来源** | 文章05 |

**数据库规范要点**：
```markdown
### 通用字段
- 主键 id BIGINT 自增，禁止 UUID
- 时间字段 created_at / updated_at，DATETIME(3)
- 逻辑删除 deleted TINYINT(1)
- 禁止 NULL，空值用空字符串或 0

### 索引规则
- 命名 idx_{表名}_{字段名}
- 逻辑删除字段必须加进组合索引

### 分页规则
- 默认用游标分页（WHERE id < lastId ORDER BY id DESC LIMIT N）
```

| 7 | Controller | 接口层 | curl全部返回200 |

### 阶段7：编码执行

| 属性 | 内容 |
|------|------|
| **阶段说明** | 实际编写代码，是工作量最大的阶段 |
| **Agent协作模式** | 执行模式 |
| **核心产出物** | 业务代码、接口、前端页面 |
| **课程来源** | 文章13-19 |
| **关键原则** | 必须使用三步检查法验收每一行代码 |

**三步检查法**：

| 步骤 | 检查什么 | 优先级 |
|------|----------|--------|
| **第一步：查意图** | 它做的是不是你让它做的？有没有擅自添加功能？ | 最高 |
| **第二步：查质量** | 风格、规范、一致性（命名、返回格式等） | 中 |
| **第三步：查边界** | 错误处理、异常、潜在风险（如并发问题） | 中 |

**精确指令公式**：
```
[规范引用] + [技术选型] + [功能范围] + [边界条件] + [排除项]
```

**典型问题发现**：

| 问题类型 | 发现环节 | 解决方式 |
|----------|----------|----------|
| 软删除机制（未要求） | 第一步 | 确认是否需要或删除 |
| 方法命名不一致 | 第二步 | 统一命名规范 |
| 并发场景未处理 | 第三步 | 补充并发控制 |
| ID不存在抛500 | 第三步 | 改为抛404 |

### 阶段11：MCP集成

| 属性 | 内容 |
|------|------|
| **阶段说明** | 扩展 AI 能力，连接外部系统 |
| **Agent协作模式** | 执行模式 |
| **核心产出物** | MCP Server、MCP Client |
| **课程来源** | 文章24、25 |

**MCP 核心概念**：

| 概念 | 说明 |
|------|------|
| **MCP Server** | 提供工具的服务端 |
| **MCP Client** | 调用工具的客户端 |
| **Tools** | 可被 AI 调用的工具集合 |

**MCP Server 实现步骤**：

1. **定义工具**：编写工具描述（名称、参数、返回值）
2. **实现工具**：编写工具执行逻辑
3. **注册服务**：将工具注册到 MCP Server
4. **配置 Client**：在 Agent 中配置 MCP Server 连接

**MCP 工具示例**：
```json
{
  "name": "search_knowledge",
  "description": "搜索知识库",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string"}
    }
  }
}
```

**Dockerfile 模板**：
```dockerfile
# 多阶段构建
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests

FROM eclipse-temurin:21-jre-alpine
RUN addgroup -g 1000 appgroup && adduser -u 1000 -G appgroup -s /bin/sh -D appuser
WORKDIR /app
COPY --from=builder /build/target/*.jar app.jar
USER appuser
EXPOSE 8080
HEALTHCHECK --interval=30s CMD wget -qO- http://localhost:8080/health
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**日志规范要点**：

| 规范 | 内容 | 示例 |
|------|------|------|
| **格式** | JSON结构化日志 | `{"time":"...","level":"INFO","traceId":"..."}` |

## 四、两种协作模式速查

| 协作模式 | 使用场景 | 人类动作 | Agent动作 |
|----------|----------|----------|-----------|
| **执行模式** | 想清楚了让它执行 | 拆解任务→验收结果 | 执行任务→输出结果 |
| **咨询模式** | 还没想清楚 | 提问→判断取舍 | 提供方案→对比分析 |

**切换时机**：
- 需求不清楚 → 咨询模式
- 方案不确认 → 咨询模式
- 任务已明确 → 执行模式
