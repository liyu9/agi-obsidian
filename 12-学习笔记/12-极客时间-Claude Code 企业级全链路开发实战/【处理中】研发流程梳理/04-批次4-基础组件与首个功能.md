## 一、前端UI设计

### 流程环节说明
课程展示了如何用AI做UI设计，让没有设计背景的后端工程师也能做出有品牌感的界面。

### 课程原文内容

#### 1.1 让AI当设计师

设计指令结构示例：
```
Hify 是一个 AI Agent 开发平台，面向技术团队内部使用，用户是开发者。
管理后台为主——大量表格、表单、配置页，加一个对话页。
风格：浅底 + 科技感点缀。主色蓝紫系，辅色青色，
侧边栏深色底，按钮和关键元素用亮色。
参考 Linear、Supabase 的视觉风格——干净但不无聊。
帮我设计一套 CSS 变量设计系统：主色/背景色阶/文字色阶/圆角/阴影/过渡动效。
```

课程中强调：
> "你不需要懂设计理论，只需要能描述你想要什么。'浅底科技感、侧边栏深色、蓝紫主色、参考 Linear'，这些描述任何一个后端工程师都能给出来，Claude Code 会把它翻译成具体的 CSS。"

#### 1.2 UI打磨来回调

课程中展示的UI打磨句式：
```
[位置/组件] + [哪里不对] + [应该怎样]

# 示例
表格和顶部标题区之间间距太大，改成 16px
状态列的禁用标签用灰色，不要用红色（禁用是正常状态，不是错误）
弹窗提交按钮在 loading 时要有转圈动画
```

课程总结：
> "你不需要知道 CSS 属性名，不需要知道 Element Plus 的组件 API，只需要描述'在哪里、什么问题、我想要什么效果'，Claude Code 负责把你的描述翻译成代码。"

## 二、前端基础组件封装

### 流程环节说明
前端基础组件封装可以一条指令搞定，后端工程师不需要在前端实现细节上花太多时间。

### 课程原文内容

#### 2.1 一条指令生成五个组件

Claude Code的指令：
```
在 hify-web 中创建以下前端公共组件（src/components/）：
1. HifyTable.vue：通用列表表格，props 接收 columns 配置和 api 方法，
   内部管理 loading 和分页，暴露 refresh() 方法。
2. HifyFormDialog.vue：通用表单弹窗，v-model 控制显示，
   open(data?) 方法区分新增/编辑模式，提交触发 submit 事件。
3. useConfirm.ts：删除确认 composable，接收确认文案和 API 方法，
   一行代码完成确认→调接口→成功提示。
4. useRequest.ts：请求状态管理，返回 { data, loading, error, execute }。
5. notify.ts：统一通知封装，notifySuccess/notifyError/notifyWarning。
所有组件 Vue 3 Composition API + TypeScript，泛型支持不同数据类型。
```

#### 2.2 组件的核心价值

课程中总结：
> "HifyTable 已经处理了分页、loading、空状态，useRequest 已经处理了 loading/error 三态，useConfirm 已经处理了确认弹窗 + 调接口 + 成功提示。业务页面只需要关心'调哪个 API、显示哪些字段'，不需要重复处理交互逻辑。"

## 三、工程搭建全流程实操

### 流程环节说明
课程以实操方式展示了工程搭建的完整过程，包括任务拆解、报错处理、验证方法。

### 课程原文内容

#### 3.1 任务拆解标准

课程中提出的判断标准：

> "**标准一：生成量是否超出一次能 review 的范围。** 十几行代码，肉眼扫一遍就行，不用拆。几十个文件、几百行配置，一次看不过来，必须拆。"

> "**标准二：步骤间是否有依赖关系。** 如果第二步依赖第一步的结果，那就应该先完成第一步、验证正确，再做第二步。"

> "**以'一次能验证'为单位。** 什么叫一次能验证？就是每个子任务做完，你能跑一个命令或者访问一个接口，确认这个子任务是对的。"

#### 3.2 报错处理方法

课程中展示的高效处理方式：

差的提问：
```
报错了，帮我修复
```

好的提问：
```
mvn clean install 报错了，完整错误如下：
[ERROR] ...（完整错误日志）
项目结构是 Maven 多模块，hify-common 被 hify-app 依赖，相关 pom 如下：
...（相关 pom 内容）
帮我分析根本原因并修复。
```

课程中强调：
> "完整上下文 + 相关代码 + 明确问一个'根本原因'，Claude Code 的修复准确率会高很多。如果两三轮还没解决，停下来自己看一眼错误信息，往往问题比你想象的简单。"

#### 3.3 工程搭建四步流程

**第一步：认知对齐先于执行**
```
查看当前 CLAUDE.md，确认项目结构和模块划分部分是否清晰
如果有遗漏或不清晰的地方告诉我。
```

**第二步：生成父pom和子模块结构**
```
按照 CLAUDE.md 中定义的项目结构，创建 Hify 的 Maven 多模块工程骨架。
父 pom 声明所有子模块，dependencyManagement 统一管理版本。
只创建 pom 文件和目录结构，不需要任何 Java 代码。
```

**第三步：验收**
```
mvn compile
```

**第四步：SDD闭环**
> "展示 Claude Code 第一版在兜底 catch 里硬编码了 `code: 500, message: "系统繁忙"` 的问题。让它改成 `Result.fail(ErrorCode.INTERNAL_ERROR)`。同步在 CLAUDE.md 补一条：'异常处理必须使用 ErrorCode 枚举，禁止硬编码错误码'。这就是规范迭代的实际过程，不是一次性写完的。"

## 四、首个完整功能交付

### 流程环节说明
模型提供商管理是第一个完整的业务模块，展示了标准交付流程。

### 课程原文内容

#### 4.1 咨询模式想清楚

**问题一：支持哪些供应商？**

Claude Code的指令：
```
Hify 要支持 LLM 模型提供商管理。帮我分析：主流的 LLM 供应商有哪些？
它们的 API 有什么共性和差异？哪些是一期必须支持的？
```

Claude Code的发现：
> "按接口兼容性分：OpenAI 兼容是一个巨大的阵营。DeepSeek、Moonshot、Azure OpenAI 这些，接口格式和 OpenAI 一模一样，只需要改 baseUrl 和 API Key 就能接入，不需要写一行适配代码。"

**问题二：有没有现成的依赖库？**

Claude Code的指令：
```
Java 生态里有没有封装了多 LLM 供应商调用的库？
Spring AI、LangChain4j 等，分析成熟度和优缺点。
```

决策：
> "一期不引入这些框架，基于 10 讲封装的 LlmHttpClient 自己做。大部分供应商兼容 OpenAI 格式，自己封装工作量不大。引入大框架只为用模型调用部分，性价比不高。"

**问题三：数据模型设计**

Claude Code的指令：
```
基于上面的分析，设计 Provider 模块的数据模型。需要考虑：
多种供应商鉴权方式的差异怎么统一存储、
一个供应商下有多个模型怎么管理、
供应商健康状态怎么表示。
```

#### 4.2 数据模型关键决策

**鉴权信息存储**
```
// 不同供应商用JSON存储差异结构
// OPENAI / OPENAI_COMPATIBLE
{ "apiKey": "sk-xxx" }
// ANTHROPIC
{ "apiKey": "sk-ant-xxx", "anthropicVersion": "2023-06-01" }
// OLLAMA
{}
```

课程中追问：
> "Claude Code 一开始建议单独建 auth 表，我追问'一对一关系建表有什么收益'，它承认没有实际收益。这种细节层面的追问就是架构师的价值。"

**健康状态独立成表**
> "健康状态写频繁——定时探测每分钟更新一次，每次 LLM 调用也可能更新状态。如果放在 provider 表里，高频写操作会和业务读竞争锁。分离之后，provider 表写少读多，可以放心加 @Cacheable 缓存；provider_health 表不缓存，直接读库。"

#### 4.3 按层拆解执行

课程中展示的8个后端任务：
```
1. Entity + Mapper（继承BaseEntity，用JSON TypeHandler）
2. DTO（CreateRequest/UpdateRequest/QueryRequest/DetailResponse）
3. Service — CRUD（加@Cacheable/@CacheEvict）
4. Service — 连通性测试（根据type分发）
5. Service — 模型同步
6. Service — 健康检查定时任务（用asyncExecutor）
7. Controller（RESTful路径，返回Result）
8. 前端API文件
```

验收流程：
```bash
# 创建
curl -X POST http://localhost:8080/api/v1/providers \
  -H "Content-Type: application/json" \
  -d '{"name":"OpenAI","type":"OPENAI",...}'
# 连通性测试
curl -X POST http://localhost:8080/api/v1/providers/1/test-connection
# 分页列表
curl "http://localhost:8080/api/v1/providers?page=1&pageSize=10"
```

#### 4.4 前端对接

Claude Code的指令：
```
把 ProviderList.vue 的 mock 数据换成真实 API 调用。
在 src/api/provider.ts 中创建 API 方法：getProviderList、createProvider、updateProvider、deleteProvider、testConnection
HifyTable 的 api prop 从 mock 函数换成 getProviderList
HifyFormDialog 的 submit 事件处理从 console.log 换成 createProvider/updateProvider
删除按钮的 useConfirm 从 mock 换成 deleteProvider
```

课程中总结：
> "API 文件是新增的，ProviderList.vue 基本只是把数据源从 mock 函数换成了 API 函数，组件结构不变。这就是 11 讲封装前端基础组件的回报。"

#### 4.5 完整验收

课程中的完整验收流程：
```
1. 点"模型管理"，看到空列表（还没有数据）
2. 点"新增提供商"，弹出表单，填入 OpenAI 的信息，提交
3. 列表刷新，出现一条记录，健康状态显示灰色 "UNKNOWN"
4. 点"连通性测试"，几秒后返回结果
5. 健康状态变成绿色 "UP"，延迟列显示具体毫秒数
6. 点模型数展开，看到从 OpenAI 拉取的模型列表
7. 等一分钟，检查健康状态是否被定时任务自动更新
8. 再添加 Ollama 和 DeepSeek，验证"OpenAI 兼容"类型开箱即用
```

## 五、Skill机制

### 流程环节说明
Skill是让Claude Code自动按流程走的核心机制，把经验沉淀成可复用的操作手册。

### 课程原文内容

#### 5.1 Skill vs CLAUDE.md

| 对比项 | CLAUDE.md | Skill |
|--------|-----------|-------|
| 性质 | 全局规范 | 具体任务的操作手册 |
| 内容 | "什么规矩要遵守" | "这类任务怎么做" |
| 生效 | 每次对话自动加载 | 引用时才生效 |
| 例子 | "Controller 只做参数校验" | "新模块交付的6步流程" |

#### 5.2 领域快速理解四问

课程中提出的快速理解陌生领域的方法：

```
第一问：它是什么，解决什么问题？建立认知框架。
第二问：用在哪里，什么场景？理解优先级。
第三问：由什么组成，哪些是必要的？支撑功能取舍。
第四问：技术架构是怎样的？支撑架构决策。
```

课程总结：
> "四个问题从外到内，一两个小时建立 70% 的领域认知，剩下 30% 靠亲手用一下产品、翻一下文档来补。这套方法不只适用于 Dify。你要做订单系统、监控平台、数据管道，都是同样的路径。"

#### 5.3 模块交付Skill

课程中展示的Skill结构：
```
# Skill: 业务模块全流程交付
触发方式：当用户说"开发 XX 模块"时，按此流程推进。

## Step 1 — 咨询与设计（不写代码）
目标：对齐需求边界和数据模型
产出物：候选方案对比表、数据模型草稿、接口清单
> ⚠️ 等待用户确认：数据模型和接口设计确认后再进入 Step 2

## Step 2 — 更新 schema.sql
## Step 3 — Entity + Mapper
## Step 4 — DTO
## Step 5 — Service
## Step 6 — Controller（curl验证）
> ⚠️ 等待用户确认：所有 curl 返回预期结果后再进入前端对接

## Step 7 — 前端 API 文件
## Step 8 — 前端页面对接

## 常见坑速查
| 现象 | 原因 | 修复 |
```

#### 5.4 供应商适配Skill

课程中展示的重构：
```
# Skill: 新增 Provider Adapter
触发方式：当用户说"接入新供应商"时按此流程推进。

## Step 1 — 分析目标供应商 API
| 问题 | 说明 |
|------|------|
| 认证方式 | Bearer Token / API Key Header / 双 Header / 无认证？ |
| 列模型接口 | URL 路径？返回结构？ |
| 必填 authConfig 字段 | ... |
> ⚠️ 等待用户确认：API 特征分析结果确认后再写代码

## Step 2 — 实现 Adapter
## Step 3 — 注册到 Factory（加@Component即可）
## Step 4 — 更新 ProviderType 枚举（如需要）
## Step 5 — 验证（curl + 浏览器）
```

课程中强调：
> "Skill 和 CLAUDE.md 一样是活文档。每做一个模块，Skill 就更完善一点。做到第四五个模块的时候，你的 Skill 已经覆盖了绝大多数场景，Claude Code 几乎不需要额外指导就能按你的标准交付。"
