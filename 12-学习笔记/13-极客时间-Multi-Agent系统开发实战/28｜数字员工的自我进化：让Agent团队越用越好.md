最佳实践与反模式
反模式
日志只记录结果，不记录过程
复盘时无法定位根因，分析变成猜测，自我复盘只能
得出"某类任务做得不好"，找不到具体改进点。
样本不足时强行复盘
提案质量极低（"基于2个样本"的推断容易偏差）—
—应该设定最小样本量阈值，不满足则跳过当日复盘
Agent 自动落地改进，不经审批
跳过人类审批直接修改 soul/SOP——系统自我改变
方向不受控，可能向错误方向漂移
最佳实践
改进提案必须附 Evidence
人类审批时可以直接查看原始记录，而不是盲目信
任 Agent 的分析——这是建立人类信任的关键
改进分级处理
小改（Tool 调用参数调整、SOP 新增一个步骤）
低摩擦快速审批；大改（soul 重写、角色定义调
整、引入新 Agent）要求更高审批门槛
记录改进版本历史
每次改进落地后，为 soul/SOP/Skill 文件记录版本
号（或 git commit），方便在改进效果不好时精准
回滚，而不是整体回退
