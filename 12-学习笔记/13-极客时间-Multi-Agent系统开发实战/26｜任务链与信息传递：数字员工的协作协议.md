26｜任务链与信息传递
数字员工的协作协议


角色有了，但协作没有


人类项目协作的两种机制


共享工作区解决"状态在哪里"，邮箱解决"谁让我做什么"


共享工作区：结构化、有权限、Manager定规则


邮箱设计：有结构的消息系统


代码实战：邮箱实现：公共 Skill + 文件锁


同步通知 + 后台唤醒：两种机制互斥互补


Manager → PM → Manager 三步任务链


最佳实践与反模式
反模式
多 Agent 并发写同一文件，没有文件锁
消息丢失是静默的——LLM 不会报错，Agent 
不知道消息没到，整个任务链在某一步卡死
工作区没有 owner
MAST 分类法研究表明，所有 Agent 失败模式 
37%的根因是资源所有权不唯一
最佳实践
文件的 rename 安全写入
防止并发协作时冲突，写文件后 rename
Agent协作通过文件 + 轻量级触达
大幅度节省 token 成本
对邮件消息处理的三态状态机
初始->已读->已处理，可靠性设计保证每个消息都正
确处理，不会一直 hang 住


课程总结
下节提示：人和数字团队应该如何协作
共享工作区和邮箱两种 agent 协作方式
共享工作区需要 manage r创建并定义好权限分工
邮箱需要结构化，通过同步通知和主动唤醒来完成协作
