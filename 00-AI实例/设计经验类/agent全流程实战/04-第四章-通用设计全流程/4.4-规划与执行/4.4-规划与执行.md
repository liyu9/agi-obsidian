# 4.4 规划与执行：让 AI 学会自己拆解任务、按计划做、从错误中学习

> **核心结论**：规划 + 执行 + 反思 = AI 的"行动闭环"——决定 AI 能不能完成复杂任务。
> **判断铁律**：单步能解决的不规划（Prompt），多步能解决的不反思（Workflow），多步+工具+反思才上 Agent。
> **底线思维**：没有规划能力的 AI 只能当"工具"用，不能当"助手"用。

## 一、规划能力：让 AI 学会自己拆解任务

### 1.1 为什么需要规划能力

简单任务 AI 可以"一步出答案"（如"翻译这段话"）。复杂任务必须先拆解：

**反例（无规划）**：
> 用户："帮我研究竞争对手并出一份报告"
> AI：直接生成一份粗糙的报告，遗漏关键信息

**正例（有规划）**：
> 用户："帮我研究竞争对手并出一份报告"
> AI 思考：
> 1. 识别要研究的竞争对手（3 家）
> 2. 收集每家的公开信息（财报、新闻、产品）
> 3. 对比分析（业务模式、营收、优势劣势）
> 4. 撰写报告（2000 字，含图表）
> 5. 自检（关键数据是否齐全）

### 1.2 规划的 3 个层次

| 层次 | 含义 | 适用场景 |
|------|------|---------|
| **任务级** | 拆解到子任务 | "研究 → 收集 → 分析 → 撰写" |
| **步骤级** | 子任务拆到可执行步骤 | "收集 → 搜财报 → 搜新闻 → 搜产品页" |
| **操作级** | 步骤拆到具体工具调用 | "调搜索 API → 调网页抓取 → 调文本摘要" |

PM 设计时，根据任务复杂度选择层次。**研究类任务**需要任务级 + 步骤级，**操作类任务**需要操作级。

## 二、执行能力：让 AI 按计划做

### 2.1 执行的核心要求

- **顺序执行**：按规划顺序执行，不能跳步
- **失败重试**：单步失败时重试 3 次，再失败则降级
- **进度回传**：每步完成时回传状态，让用户看到进度
- **异常中断**：用户取消时立即中断，不继续

### 2.2 执行的 3 种模式

| 模式 | 特点 | 适用 |
|------|------|------|
| **顺序执行** | 一步一步走 | 标准流程 |
| **并行执行** | 多个独立任务同时跑 | 信息收集 |
| **条件执行** | 根据上一步结果决定下一步 | 决策类任务 |

反面案例：某 AI 助手"研究 3 个竞品"用了顺序执行，耗时 15 分钟。改为并行执行后只需 5 分钟，体验大幅提升。

## 三、反思能力：让 AI 从错误中学习

### 3.1 反思的 3 个层次

| 层次 | 含义 | 例子 |
|------|------|------|
| **结果自检** | 检查输出是否满足要求 | "这份报告包含 3 个竞品吗？" |
| **过程回溯** | 复盘执行过程哪里出问题 | "为什么这一步失败了？" |
| **策略调整** | 改换策略重新尝试 | "这条路不通，换一条" |

### 3.2 反思的实现方式

**反例（无反思）**：
> AI 生成报告 → 输出

**正例（有反思）**：
> AI 生成报告 → 自检（3 个竞品齐全？数据准确？字数达标？）→ 不通过则改 → 输出

反面案例：某 AI 报告生成后没自检，输出"3 个竞品"实际只写了 2 个。引入自检后，报告完整度从 70% 提升到 95%。

## 四、ReAct 模式：推理 + 行动循环

ReAct 是 Single Agent 的核心范式，循环 3 步：

```
Thought（推理）→ Action（行动）→ Observation（观察）→ Thought...
```

| 步骤 | 含义 | 示例 |
|------|------|------|
| **Thought** | 决定下一步做什么 | "我需要先查询天气" |
| **Action** | 调用工具 | 调用天气 API |
| **Observation** | 评估结果 | "天气是雨天，建议带伞" |

适用场景：开放任务、步骤不确定、需要多轮工具调用。

## 五、Plan-and-Execute 模式：先规划后执行

不同于 ReAct 的"边想边做"，Plan-and-Execute 是"先想清楚，再做"：

```
Plan（完整规划）→ Execute（执行每步）→ Re-plan（如需要）
```

| 模式 | 特点 | 适用 |
|------|------|------|
| **ReAct** | 边想边做，灵活但不稳定 | 探索类任务 |
| **Plan-and-Execute** | 先规划再执行，稳定但僵硬 | 流程化任务 |

**选择建议**：
- 任务路径多变 → ReAct
- 任务路径相对稳定 → Plan-and-Execute
- 关键决策任务 → Plan-and-Execute + 人审

反面案例：某 AI 报销审批用 ReAct，每次执行路径都不同，3 个月后无法审计。改为 Plan-and-Execute 后路径稳定，可审计。

## 六、规划与执行的 3 个反模式

| 反模式 | 表现 | 应对 |
|-------|------|------|
| **过度规划** | 简单任务也用 3 层规划 | 单步任务用 Prompt，不上规划 |
| **无反思** | AI 输出后不检查 | 关键任务必加自检 |
| **ReAct 滥用** | 流程化任务也用 ReAct | 流程稳定用 Plan-and-Execute |

## 七、PM 行动清单

看完本节后：

1. **简单任务用 Prompt，复杂任务用 Agent**：避免"小问题大做"
2. **规划层次按任务复杂度选**：任务级 / 步骤级 / 操作级
3. **并行执行用于独立子任务**：节省时间
4. **关键任务必加自检**：避免输出错误
5. **稳定流程用 Plan-and-Execute，开放任务用 ReAct**
