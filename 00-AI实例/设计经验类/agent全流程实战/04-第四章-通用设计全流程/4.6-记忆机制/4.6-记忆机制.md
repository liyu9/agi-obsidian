# 4.6 记忆机制：让 AI 拥有"短期 / 长期 / 工作 / 知识库"四类记忆

> **核心结论**：AI 记忆 = 4 类（短期/长期/工作/知识库）——每类各司其职，不能混用。
> **判断铁律**：能放知识库的不放长期记忆，能放短期对话的不放工作记忆。
> **底线思维**：无记忆的 AI 是"金鱼"（7 秒记忆），有混乱记忆的 AI 是"疯子"（张冠李戴）。

## 一、为什么 AI 需要"记忆"

LLM 本身是无状态的——每次推理从零开始，**不记得任何事**。这带来 3 个核心问题：

1. 用户问"我刚才说的订单号呢" → AI 不记得
2. 用户第二天再来 → AI 不认识他
3. AI 完成多步任务时 → 不记得上一步的结果

反面案例：某 AI 助手"完成任务 1 后接着做任务 2"，但忘了任务 1 的输出，重新再做一遍。3 倍 Token 消耗 + 3 倍时间。

## 二、AI 记忆的 4 类组成

| 记忆类型 | 作用 | 生命周期 | 存储位置 |
|---------|------|---------|---------|
| **短期记忆** | 记住当前会话的对话 | 单次会话 | 模型上下文 |
| **工作记忆** | 任务执行中的中间状态 | 单次任务 | 任务状态库 |
| **长期记忆** | 跨会话的用户偏好 | 永久 | 用户档案库 |
| **知识库记忆** | 业务知识 / 文档 | 半永久 | 向量库 |

### 2.1 短期记忆（Session Memory）

**作用**：在单次会话中记住用户和 AI 的所有对话。

**典型实现**：
- 把对话历史拼接到模型上下文
- 长度受模型窗口限制（8K-128K tokens）
- 超出窗口时用滑动窗口 / 摘要压缩

**反例**（无短期记忆）：
> 用户："我昨天咨询过一个报销问题"
> AI："我没有你的历史记录"

### 2.2 工作记忆（Working Memory）

**作用**：任务执行过程中，临时存储中间结果。

**典型场景**：多步骤任务（"先查订单 → 再分析 → 最后回复"）
- 步骤 1：查询订单 → 工作记忆：{order_id, status}
- 步骤 2：分析订单 → 读工作记忆
- 步骤 3：回复 → 读工作记忆

**反例**（无工作记忆）：
> AI 步骤 1 查了订单 → 步骤 2 重新查一次 → 3 倍 Token

### 2.3 长期记忆（Long-term Memory）

**作用**：跨会话记住用户偏好、历史行为。

**典型实现**：
- 用户档案（用户 ID → 偏好）
- 行为历史（用户最近 10 次任务）
- 偏好设置（用户语言、风格偏好）

**反例**（无长期记忆）：
> 用户第 2 天再来，AI 问"您贵姓？"——完全不认识

### 2.4 知识库记忆（Knowledge Memory）

**作用**：存储业务知识、文档、规章制度。

**典型实现**：
- RAG（Retrieval-Augmented Generation）：用户问题 → 检索相关文档 → 把文档拼到 Prompt → 模型回答
- 向量库（Milvus / Qdrant / Weaviate）

**反例**（无知识库）：
> 用户问"公司年假政策"，AI 编一个看似合理但完全错误的政策

## 三、4 类记忆的典型场景对比

| 场景 | 该用哪种记忆 | 示例 |
|------|-------------|------|
| 用户问"刚才我说了什么" | 短期记忆 | 读会话历史 |
| AI 多步任务中间结果 | 工作记忆 | 任务状态库 |
| 用户偏好（语言 / 风格） | 长期记忆 | 用户档案 |
| 业务知识 / 文档 | 知识库 | RAG + 向量库 |

## 四、记忆管理的 3 个关键问题

### 4.1 记忆的写入

| 类型 | 写入时机 |
|------|---------|
| 短期记忆 | 每轮对话自动写入 |
| 工作记忆 | 任务步骤完成时写入 |
| 长期记忆 | 用户明确行为（如设置偏好）+ AI 自动抽取关键信息 |
| 知识库记忆 | 业务知识更新时（如政策变化） |

### 4.2 记忆的读取

| 类型 | 读取时机 |
|------|---------|
| 短期记忆 | 每轮对话自动读取 |
| 工作记忆 | 当前任务步骤需要时 |
| 长期记忆 | 涉及用户偏好时 |
| 知识库记忆 | 用户问题涉及业务知识时 |

### 4.3 记忆的清理

| 类型 | 清理时机 |
|------|---------|
| 短期记忆 | 会话结束 / 窗口溢出 |
| 工作记忆 | 任务完成 / 任务失败 |
| 长期记忆 | 用户主动清除 / 隐私合规要求 |
| 知识库记忆 | 知识过期 / 数据治理要求 |

反面案例：某 AI 助手长期记忆里存了用户 3 年前的医疗记录，被监管处罚。根因是"无清理机制"。

## 五、记忆机制的 4 个反模式

| 反模式 | 表现 | 应对 |
|-------|------|------|
| **无短期记忆** | AI 不记得对话历史 | 用 Session Memory |
| **无工作记忆** | 多步任务重复计算 | 用 Working Memory |
| **无长期记忆** | 用户每次都重新介绍自己 | 用 Long-term Memory |
| **无知识库** | AI 凭空编造业务知识 | 用 RAG + 向量库 |

## 六、PM 行动清单

看完本节后：

1. **每个 AI 功能必问"需要哪种记忆"**：4 类记忆按需选择
2. **多步任务必用工作记忆**：避免重复计算
3. **用户偏好必写长期记忆**：跨会话保持一致
4. **业务知识必用知识库**：避免 AI 编造
5. **记忆必设清理机制**：满足隐私合规
