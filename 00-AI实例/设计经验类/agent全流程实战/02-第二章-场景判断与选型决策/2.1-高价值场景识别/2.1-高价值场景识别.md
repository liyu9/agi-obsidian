# 2.1 高价值场景识别：按部门梳理企业内部值得做 Agent 的场景

> **核心结论**：场景识别是 Agent 项目的"生死线"——选错场景，再好的技术也救不回来。
> **判断铁律**：用 25 分制评估表给每个候选场景打分，≥ 18 分立项、12-18 分慎评、< 12 分放弃 Agent 化。
> **底线思维**：先识别"真实频次高、流程可拆解、错误代价可承受"的工作，再谈 AI 介入。

## 一、为什么场景识别是 Agent 项目的"生死线"

行业级数据反复印证这个判断：MIT NANDA Initiative 2025 年研究显示 95% 的企业 GenAI 试点未能产生可测量的业务影响；Gartner 2025 报告 50% 的 GenAI 项目失败；BCG 2024 调研 74% 的企业无法从 AI 中获取和扩展价值；RAND 2024 报告 80% 以上的 AI 项目无法实现有意义的生产部署。这些数字来自 IBM、沃尔玛、摩根大通这样有资源、有技术的大企业。问题根因不是模型不够准、不是工程不成熟，而是**场景选错了**。

反面案例几乎都是"过度 Agent 化"的典型：

| 反面案例 | 教训 |
|---------|------|
| Klarna 用 AI 替代 700 名客服 | 场景错选比技术错选代价更大（忽略情感劳动，55% 企业后悔） |
| 多家公司做"对话式数据分析"，前提条件不满足就上 AI | 数据前提不满足时，再先进架构也救不回来 |
| 某团队 prompt caching miss 收到 38,000 美元 AWS Bedrock 账单 | 价值/代价比不达标的项目，不应启动 |

共同特征不是"技术不够好"，而是"必要性没判断好"。PM 启动 Agent 项目时做的第一张表，不应该画系统架构图，而应该画**场景审查表**。

## 二、场景识别方法论：业务痛点 → 场景假设 → MVP 验证

### 2.1 主动扫描，而非被动等待

业务方不知道 AI 能做什么，他们提的需求往往是幻想，而不是真实场景。PM 在企业里会碰到两种极端——要么"帮我用 AI 做一个 ChatGPT"，要么"这件事好像 AI 能做？"——两个都没法直接转化成有价值的落地方案。

正确做法是**主动扫描**。L34 给出三种方法，覆盖 ToB 和 ToC 的主要场景。

**方法一：工作流审计法（ToB 核心方法）**

工作流审计的核心原则是**不要看系统文档，去看人实际在做什么**。系统文档写的是"应该怎么做"，人实际做的是"真正发生了什么"，两者之间的缝隙，就是最有价值的 AI 机会。

扫描时找重复性痕迹：桌面上摆着大量 Excel 模板、每周五有"必须发的汇报邮件"、操作手册里写着"第 3 步：把 A 系统的数据复制到 B 系统"、会议记录里出现"老规矩""跟上次一样处理"。这些痕迹的共同特征是**人在做机器能做、但没人做自动化的事**。找到之后问三个问题：这件事每周做几次？有没有现成的模板？做错了怎么处理？答案往往就能告诉你 AI 介入的价值和风险。

**方法二：摩擦点溯源法（ToC 核心方法）**

ToC 产品的场景扫描，数据是最好的向导。找两类信号：**断点信号**（用户在哪个步骤的放弃率最高？漏斗的哪一层最薄？）和**求助信号**（客服日志里频率最高的 Top 20 条问题是什么？用户在帮助中心搜了什么关键词？用户愿意为哪些事情花钱找人代劳？）。"求助行为"背后，藏着真正的摩擦点。摩擦点的背面，往往就是 AI 的机会点。

**方法三：竞品-同行扫描法**

从同行已落地的方案里"反推场景"。边界是：不要直接照抄场景，要先看对方解决的具体问题，再判断自己的业务是否有同构问题。

### 2.2 从痛点出发，而不是从工具出发

04 课中给出一个反常识判断：**发现需求时，应该在了解"锤子"的基础上找"钉子"，而不是拿着锤子找钉子**。

传统 PM 的反模式是：看到 AI 火 → 找企业里能"用上 AI"的场景 → 立项目。结果是大量"伪需求"——技术上能跑通 Demo，但用户根本不用。

正确做法的反例：04 课讲述的电子说明书升级到智能说明书案例——年出货 40 万台、消费群体 6-18 岁的电子消费品公司，超过 80% 用户问题是产品使用的基本问题，AI 解决方案价格昂贵且效果不好，客服成本高（10 名全职客服、培训成本高），长尾诉求分析耗时太长。从这个真实痛点出发，"智能说明书"才是有 ROI 的方向。

PM 的启示是：从痛点出发，先识别**真实频次高、目前由人低水平重复完成、且容忍度可以允许 AI 介入的工作**，再去匹配工具，而不是看到一个新技术就到处找落地场景。

### 2.3 "一招致胜"框架：知识类 vs 执行类

06 课给出"企业 AI 场景框架"——把企业 AI 可落地场景分为**知识类场景**和**执行类场景**，分别用于提升企业大脑的"认知力"和企业机器的"执行力"。

**知识类场景**按认知的步骤依次是：知识获取 → 知识理解 → 知识生产。知识获取包括信息搜索、知识问答、资讯推送、培训考试；知识理解包括文档摘要、合同审查、舆情分析；知识生产包括营销文案、报告生成、方案撰写。

**执行类场景**按执行方式分为：流程自动化、工具调用、决策辅助。流程自动化如工单流转、报销审批；工具调用如数据库查询、邮件发送；决策辅助如风控判断、信用评估。

PM 在做场景扫描时，可以快速判断一个候选场景属于哪一类，从而确定它的能力需求、风险特征、ROI 计算方式。

## 三、按部门场景表：8 大部门的高价值 Agent 场景

企业内部高 ROI 场景按部门拆分，8 大部门场景矩阵如下（具体案例细节请回原文阅读）：

| 部门 | 典型高价值场景 | 价值来源 |
|------|---------------|----------|
| 研发 | 代码评审、单元测试、Bug 定位、文档生成 | 研发人员时间稀缺、错误代价高 |
| 客服 | 工单分类、知识库问答、情绪检测 | 工单量大、知识可标准化 |
| 数据分析 | 报表生成、归因分析、指标解读 | 数据沉淀成本高、解释成本高 |
| 运维 | 告警分类、故障定位、值班辅助 | 7×24 不可中断、经验依赖 |
| 销售 | 客户画像、商机跟进、邮件草拟 | 销售周期长、需个性化沟通 |
| HR | 简历筛选、面试问题生成、员工 FAQ | HR 事务性工作量大 |
| 财务 | 票据识别、报销审核、月度结账 | 规则明确、错误代价高 |
| 法务 | 合同审查、条款比对、风险标注 | 文档量大、专业门槛高 |

**部门适配判断标准**：
1. 业务频次是否足够高（每周至少发生一次才有自动化价值）
2. 流程是否可拆解（无法拆解成步骤的复杂判断不适合 AI）
3. 错误代价是否可承受（错误代价高于人工成本时不适合 AI）

三个标准都满足的部门，才进入候选池。

## 四、高 ROI 场景识别清单（25 分制评估表）

L34 给出的"AI 适用性评估表"是 25 分制、五个维度、10 分钟可填完的实操工具。定位是"一张表，五个维度，可以对业务方说清楚的立项结论"。

**五个维度**（每维 1-5 分，合计 25 分）：

| 维度 | 含义 | 评分要点 |
|------|------|---------|
| 业务频次 | 候选场景在企业内的发生频率 | 频次越高分越高 |
| 流程可拆解性 | 候选场景能否被拆成清晰的步骤 | 可拆解才适合 Workflow / Agent |
| 错误代价 | 场景出错后的代价 | 代价高的场景必须有人审环节 |
| 数据可获得性 | AI 所需的数据是否存在、质量如何 | 数据前提不满足则该维 0 分 |
| 价值/代价比 | 综合 ROI 判断 | Token 成本 > 人工工资直接穿透底线 |

**立项阈值**：
- 总分 ≥ 18 分 → 建议立项（用 Agent 或 Multi-Agent）
- 总分 12-18 分 → 慎重评估（用 Prompt / Workflow 解决）
- 总分 < 12 分 → **不要上 Agent**（用更简单方案）

**特别提醒**：边界分数场景（如 17、18 分）必须配套"人审环节"——AI 给出结果，人做最后核验，避免 38,000 美元账单式的事故。

## 五、场景识别的 5 个反模式

| 反模式 | 表现 | 应对 |
|-------|------|------|
| **等业务方提需求** | 业务方提什么做什么，PM 不主动扫描 | 主动用工作流审计 / 摩擦点溯源 / 竞品反推 |
| **拿着 AI 找场景** | "Multi-Agent 是趋势"作为立项依据 | 严格判断情感劳动、复杂案例处理、合规要求 |
| **部门一刀切** | 8 大部门全做 Agent | 按业务频次 / 流程可拆解 / 错误代价三标准筛 |
| **Demo 通过 = 立项** | 凭 Demo 觉得可行就立项 | 立项前必过 25 分制评估表 |
| **数据默认存在** | 不验证数据是否存在 / 质量如何 | 立项前先确认数据前提 |

## 六、PM 行动清单

看完本节后：

1. **建立"场景审查优先于系统设计"的意识**：第一张表是场景评估表，不是架构图
2. **主动用三种方法做场景扫描**：工作流审计（ToB）/ 摩擦点溯源（ToC）/ 竞品反推
3. **对每个候选场景套用 25 分制评估表**：5 维度、10 分钟、给业务方说清楚的立项结论
4. **拒绝"拿着 AI 找场景"**：先识别真实痛点，再匹配工具
5. **得分 < 12 分的场景直接放弃 Agent 化**：用 Prompt / Workflow 解决，不浪费工程投入
