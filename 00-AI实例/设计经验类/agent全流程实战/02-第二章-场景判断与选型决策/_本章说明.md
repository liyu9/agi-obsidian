# 第二章 场景判断与选型决策

## 一、章节定位

**解决 PM 启动 Agent 项目前的"该不该做 + 选什么"两个核心决策。**

第二章是 PM 从"了解 Agent 是什么"（第一章）走向"开始动手做 Agent"之间的关键决策阶段。专注于回答两个前置问题：

1. **该不该做**——这个业务场景真的需要 Agent 吗？
2. **选什么**——如果要做，应该用哪种 Agent 形态？

跳过这两个问题直接进入"动手搭建"环节，PM 几乎必然掉进两个常见坑：**Over Design**（低熵业务用了复杂架构，浪费工程投入）或 **Under Design**（高熵业务用了简单架构，方案跑不通）。

## 二、章节在方法论总纲中的对应

本章对应原 PM 设计 Agent 全流程方法论总纲中的：

- **Part 1.第二"企业 Agent 落地场景地图"**——本章节 2.1（高价值场景识别）覆盖该部分
- **Part 1.第三"Agent 分类与选型"**——本章节 2.2（业务熵值评估）、2.3（Agent 形态选型）、2.4（必要性判断）覆盖该部分

## 四、四节内容速览

### 2.1 高价值场景识别

**核心问题**：企业内部哪些部门、哪些场景值得做 Agent？

**核心方法**：
- 主动扫描（工作流审计、摩擦点溯源、竞品反推）
- 从痛点出发（锤子找钉子 vs 钉子找锤子的反模式）
- 知识类 vs 执行类框架（覆盖企业 AI 场景全景）
- 25 分制 AI 适用性评估表（5 维度 10 分钟可填完）
- 8 大部门场景表（研发/客服/数据分析/运维/销售/HR/财务/法务）

**主素材**：L34 + 04 + 06

### 2.2 业务熵值评估

**核心问题**：这个业务的不确定性格局是什么？

**核心方法**：
- 阿什比定律（只有多样性才能对抗多样性）
- 业务熵三维度（输入熵 / 过程熵 / 结果熵）
- 熵-架构匹配矩阵（Order / Sweet Spot / Over Design / Under Design）
- C.U.P. 三维评估模型（U 是核心，P 拥有一票否决权）

**主素材**：L01 + L04 + L02

### 2.3 Agent 形态选型

**核心问题**：如果要做，应该用哪种 Agent 形态？

**核心方法**：
- 自主性三档分级（Copilot / Assist / Automated）
- 形态四分类（对话 / 工作流 / 自主 / Multi-Agent）
- 能力三分类（检索 / 执行 / 决策）
- 场景-形态选型矩阵（5 个业务场景对应 4 种形态的推荐组合）

**主素材**：L01 + L02 + L04 + 10

### 2.4 必要性判断

**核心问题**：这个场景真的需要 Agent 吗？

**核心方法**：
- Agent 必要性三条件（多步骤 + 工具调用 + 价值 > 代价）
- 简单优先原则（能用单 Prompt / Workflow 解决，就不 Agent 化）
- 快速场景扫描方法（5 步 1 小时完成多个候选场景评估）
- 必要性判断的 5 个反模式（技术火就立项、AI 替代人就立项、创意性当万能理由、试用当立项、数据基础当默认前提）

**主素材**：L04 + 06

## 五、四节内容之间的逻辑关系

四节之间不是平行罗列，而是有严格的递进逻辑：

```
2.1 场景识别（先有候选池）
   ↓
2.2 熵值评估（看清每个候选场景的不确定性格局）
   ↓
2.3 形态选型（把熵分布映射到正确的 Agent 形态）
   ↓
2.4 必要性判断（在动手前最后确认是否真的需要 Agent）
```

PM 启动一个 Agent 项目时，应该按这个顺序依次走完四节的方法论。**任一环节跳过，都会导致后续方案跑偏。**

## 六、使用建议

### 6.1 适合什么人读

- **AI 转型的传统产品经理**：第一次接触 Agent 选型，需要建立决策框架
- **企业内部 AI 项目负责人**：要做立项评审，需要可量化的判断工具
- **企业架构师 / 技术 Leader**：要拍板技术方案，需要和 PM 共享同一套语言
- **AI 产品创业者**：要做 B 端场景扫描，需要快速识别高 ROI 机会

### 6.2 怎么读

1. **第一遍**：按 2.1 → 2.2 → 2.3 → 2.4 的顺序通读，建立完整的决策框架
2. **第二遍**：针对一个具体的候选场景，对照四节内容依次走一遍
3. **第三遍**：把四节内容作为"工具书"，在每次立项评审时按需查阅

### 6.3 与其他章节的衔接

- **第一章** 提供 Agent 的"是什么"和"基本形态"——是本章的认知基础
- **本章** 提供 Agent 的"该不该做"和"选什么"——是第三章（动手搭建）的前置决策
- **第三章及以后** 假定 PM 已经完成了本章的四个判断，可以直接进入"怎么搭"
