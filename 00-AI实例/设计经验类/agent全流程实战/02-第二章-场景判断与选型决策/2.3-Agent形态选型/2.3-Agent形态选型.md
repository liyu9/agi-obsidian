# 2.3 Agent 形态选型：把业务熵映射到正确的架构形态

> **核心结论**：形态选型是 PM 的核心决策——先画业务熵分布图，再匹配形态能力。
> **判断铁律**：用"自主性三档 + 形态四分类 + 能力三分类"三把尺同时约束，匹配到正确形态。
> **底线思维**：能 Workflow 解决就不上 Agent，能 Prompt 解决就不上 Workflow——简单优先。

## 一、形态选型是 PM 的核心决策

在 AI 圈"概念满天飞、极度混乱"的今天，同一个词在不同人嘴里意思可能完全不一样：有人认为只有具备自主决策能力的才叫 Agent，有人却把只要多调了几次大模型的工作流也叫 Agent。PM 面对一个候选场景时，需要在 10 分钟内回答"这个场景应该用哪种形态"。

解药是用"自主性"和"复杂度"两条轴，把所有 AI 应用形态统一收纳。

## 二、自主性三档分级（Copilot / Assist / Automated）

自主性三档分级作为"连续光谱"描述 AI 与人的协作关系，是后续选型的关键基础设施。

**Copilot（副驾驶）**：AI 在人旁边提供建议、起草内容，但最终动作必须由人触发。典型场景：写代码时的 Tab 补全、起草邮件时的智能补全。

**Assist（辅助）**：AI 主动完成部分步骤，但仍需要人在关键节点确认。典型场景：智能客服在用户问题超出知识库时主动转人工。

**Automated（自动化）**：AI 自主完成全流程，人只在异常或审计节点介入。典型场景：定时批量处理、智能体自主完成跨境数据迁移。

PM 选型时，第一步要判断这个业务场景在"自主性光谱"上落在哪一档。判断信号：
- 业务方要求"AI 永远不能直接给用户答案，必须有人审核" → **Copilot 档**
- 业务方说"AI 可以直接发邮件，但每周需要人复盘一次" → **Automated 档**

## 三、形态四分类（对话 / 工作流 / 自主 / Multi-Agent）

PM 用这套范式描述所有候选场景。四种范式按"自主性"和"复杂度"由低到高排列：

### 3.1 范式一：对话型（Prompt Engineering）

**核心理念**：一切交给模型。所有处理逻辑在一个大模型（LLM）的黑盒里一次性完成。开发者核心工作是构建并优化给到模型的那一长串 Message List。

**输入构成**：静态文本（手动粘贴的竞品数据）+ 思维链 CoT（生成报告的步骤指导）+ 任务预期（目标、风格样例）。

**局限性**：
1. 容易超出上下文限制——文本量超过 3-5 万字后，模型指令遵循能力和逻辑提取能力会大幅下降
2. 对模型要求极高，效果不稳定——把压力都给了模型的大脑，模型一换或稍有波动，提示词可能就要推翻重调

### 3.2 范式二：工作流型（Workflow / Chain）

**核心理念**：预先编排，稳定执行。本质是 Code-Driven（程序员决定下一步）。

**典型链路**：爬虫抓取网页（代码节点）→ Python 清洗 HTML（代码节点）→ LLM 提取观点和信息（分析节点）→ LLM 生成报告（总结节点）→ LLM 检查报告并改进（审核节点）→ 写入 PDF（代码节点）。

**优势**：极其稳定。边界清晰时能解决 80%-90% 的工程落地问题。
**局限**：遇到步骤不确定、异常分支极多的复杂场景（如排查未知线上 Bug），工作流的枚举成本会变得不可接受。

### 3.3 范式三：自主型（Single Agent）

**核心理念**：模型决定下一步（Model-Driven）。模型成为真正的"大脑"。给任务目标、工具箱（Tools）和记忆（Memory），基于反馈回路自主进行规划（Planning）。

**L02 的 ReAct 范式**：Single Agent 的核心是 ReAct——Reasoning + Acting 循环。模型每一步先推理（决定下一步做什么），再行动（调用工具），再观察（评估结果），循环到目标完成。这种范式是处理高过程熵业务的关键设计。

**痛点**：单体 Agent 执行复杂长链路任务时，每一次搜索和调用结果都会堆积在上下文中，导致上下文迅速膨胀，最终引发模型幻觉或执行崩溃。

### 3.4 范式四：Multi-Agent（组织的力量）

**核心理念**：用组织的力量给模型"减负"。

**关键避坑**：在一条工作流里用了三个不同的 Prompt 节点，不叫 Multi-Agent。真正的 Multi-Agent 系统，其每一个节点都必须是一个具备自主决策能力的 Single Agent。

**两大核心目的**：
1. **上下文隔离与动态交互（Context Isolation & Interaction）**：原本单体 Agent 会把所有搜索和分析历史塞满脑子；MAS 中 Role A（研究员）只负责搜索数据并传递，Role B（分析师）拿到精简后的数据进行分析，Role C（审核员）负责质检，不合格则回退/拒绝。子任务隔离大幅缩短单个 Agent 的上下文长度
2. **工具的专注度**：研究员拥有搜索工具，分析师拥有数据分析工具。像企业里不同岗位员工各司其职，避免模型在海量工具库中选错工具的风险

## 四、能力三分类（检索 / 执行 / 决策）

10 课（提升可靠性：选择合适的 Agent 的设计模式）对 Agent 的能力做了更细的拆分——记忆、工具使用、规划、反思能力是 Agent 的四大能力。其中"工具使用"对应"执行能力"、"规划 + 反思"对应"决策能力"、"记忆"为前两者提供支撑。

把 L01 的形态四分类和 L10 的能力四维度结合，PM 关心能力三分类：

1. **检索能力**：AI 能从企业知识库、外部数据源中"找到"信息。基础能力，几乎所有形态都需要
2. **执行能力**：AI 能调用工具、写入系统、操作外部世界。Workflow → Single Agent 的分水岭
3. **决策能力**：AI 能在多个备选路径中做选择。Single Agent → Multi-Agent 的分水岭

L10 特别强调：Agent 的"规划能力"是把上述三大能力组织成"目标→分解→执行→反思"闭环的关键。没有规划能力的 Agent 只是工具的简单堆叠；有了规划能力，工具和检索才能被合理调度。

## 五、场景 → 形态选型矩阵

把"业务熵分布"（2.2 节）、"自主性档位"、"能力需求"放在一起，得到 PM 可直接使用的选型决策表：

| 业务场景示例 | 业务熵分布 | 自主性档位 | 能力需求 | 推荐形态 | 选型理由 |
|------------|-----------|-----------|---------|---------|----------|
| 标准合同信息抽取 | 三维低 | Copilot | 检索 | Prompt Engineering | 输入确定、过程确定、输出标准，模型一次性输出即可 |
| 月度财务月报生成 | 输入中、过程低、结果中 | Assist | 检索 + 执行 | Workflow | 流程固定但需调用多个数据源，编排稳定 |
| 客服工单分类与转人工 | 输入高、过程中、结果低 | Assist | 检索 + 决策 | Single Agent | 用户输入开放，需要模型判断走哪条处理路径 |
| 跨境数据迁移任务 | 三维高 | Automated | 检索 + 执行 + 决策 | Multi-Agent | 任务可拆分为多个子任务，需并行处理 + 上下文隔离 |
| 未知 Bug 排查 | 过程极高、结果模糊 | Automated | 检索 + 执行 + 决策 | Multi-Agent | 执行路径完全未知，需要多角色协作（信息收集、根因分析、修复方案、验证） |

L04 一句话总结选型原则：**"不要靠直觉去猜，要去精准度量（Don't Guess, Measure）"**。PM 做形态选型时，应先画出业务的熵分布图，再去对应形态能力，而不是看哪个形态火就用哪个。

## 六、形态选型的 4 个常见误区

**误区一：追求"最先进"**。Multi-Agent 不是"更高级"的 Workflow，是为不同业务设计的不同形态。比喻：**面对一个工程需求，究竟是用一把精美的美工刀去建大楼，还是雇佣一支专业的施工队去修一扇小窗户？** 选型错位的代价远高于选型保守。

**误区二：用 Prompt 解决 Multi-Agent 的问题**。典型表现：试图用一个超长 Prompt 让模型完成"搜索 + 分析 + 审核 + 写报告"全流程。3-5 万字以上的输入，模型指令遵循能力会大幅下降。

**误区三：用 Workflow 应对高过程熵业务**。典型表现：试图为"未知 Bug 排查"枚举出所有可能的执行路径。枚举成本会变得不可接受。

**误区四：把"用了三个 Prompt 节点"当 Multi-Agent**。在一条工作流里用了三个不同的 Prompt 节点，不叫 Multi-Agent。每个节点必须是具备自主决策能力的 Single Agent。

## 七、PM 行动清单

看完本节后：

1. **用三把尺同时约束**：自主性档位 + 形态四分类 + 能力三分类
2. **先画熵分布图，再选形态**：业务熵决定形态，不是技术热度决定形态
3. **优先选择简单形态**：能 Prompt 就不 Workflow，能 Workflow 就不 Agent，能 Single Agent 就不 Multi-Agent
4. **避开 4 个常见误区**：追求"最先进" / Prompt 解决 Multi-Agent 问题 / Workflow 应对高过程熵 / 误把 Prompt 节点当 Multi-Agent
5. **每场景必过选型决策表**：把"熵分布 + 自主性 + 能力需求"对齐到选型矩阵，结论落到表上
