# 第五章 Multi-Agent 与团队化

## 一、章节定位

**回答 PM 在 Multi-Agent 落地时遇到的"该不该上、怎么分工、怎么管"三个问题。**

第二、三、四章奠定了"单 Agent 怎么做"的方法论基础。第五章把视角从"单 Agent 内部"扩展到"多 Agent 之间的协作与组织化"——这是企业级 Agent 走向规模化、走向"数字员工"形态必经的一步。

PM 启动一个复杂 Agent 项目时，几乎注定会遇到这三个问题：

1. **该不该上 Multi-Agent**——单 Agent 已经不够用了？还是为了"技术先进"而拆？
2. **怎么分工**——多 Agent 之间的角色、协作模式、决策权怎么分配？
3. **怎么管**——多个 Agent 组成"数字员工团队"后，PM 的管理方式如何变化？

跳过这三个问题直接堆 Agent，结果往往是"用 10 倍的 Token 成本换 5% 的效果提升"。

## 二、章节在方法论总纲中的对应

本章对应原 PM 设计 Agent 全流程方法论总纲中的：

- **Part 2.第四"Multi-Agent 与组织进化"**——本章节 5.1（何时用多 Agent）覆盖该部分
- **Part 2.第五"Agent 团队化与企业级落地"**——本章节 5.2（协作模式）、5.3（数字员工团队）、5.4（单 vs 多决策）覆盖该部分

## 四、四节内容速览

### 5.1 何时用多 Agent

**核心问题**：什么样的业务场景才真正需要 Multi-Agent？

**核心方法**：
- 单 Agent 的能力边界（上下文膨胀 / 工具过载 / 任务过载）
- 3 问判断法（可拆解 / 隔离 / 角色差异）
- 4 步升级路径（Prompt → Workflow → Single Agent → Multi-Agent）
- 5 类伪 Multi-Agent 场景（避坑）

**主素材**：L11 + L12 + L13

### 5.2 协作模式

**核心问题**：多 Agent 之间怎么协作？

**核心方法**：
- 集中式 vs 分布式（决策权归属）
- 串行 vs 并行 vs 层级（执行结构）
- 3 种基础协作模式（Supervisor / Pipeline / Peer-to-Peer）
- 通信与状态管理（消息总线 / 共享记忆 / 锁机制）
- 死锁与一致性陷阱

**主素材**：L11 + L12 + L15

### 5.3 数字员工团队

**核心问题**：Agent 团队化后，PM 怎么把它当作"数字员工"来管理？

**核心方法**：
- 数字员工的 4 个属性（角色 / 职责 / KPI / 协作接口）
- 团队规模与边界（5-8 人小团队原则）
- 人机协同的 3 种模式（HITL / HOTL / Autonomy）
- 数字员工的入职 / 培训 / 考核 / 淘汰闭环

**主素材**：L13 + L15 + L16

### 5.4 单 vs 多决策

**核心问题**：面对一个具体场景，应该选 Single Agent 还是 Multi-Agent？

**核心方法**：
- 决策必要性（5.1 的延伸）
- 3 问判断法（可拆解 / 隔离 / 角色差异）
- 4 步升级路径（Prompt → Workflow → Single → Multi）
- 3 笔账（复杂度 / Token / 延迟）
- 7 项检查清单（决策前必过）
- 5 个真实场景决策表

**主素材**：L11 + L12 + L13 + L15

## 五、四节内容之间的逻辑关系

四节之间是严格的递进关系，从"决策必要性"到"具体怎么搭"：

```
5.1 何时用多 Agent（先确认是否真的需要）
   ↓
5.2 协作模式（如果需要，多 Agent 之间怎么配合）
   ↓
5.3 数字员工团队（把多 Agent 当作"数字员工团队"来管理）
   ↓
5.4 单 vs 多决策（面对具体场景的回溯式决策方法）
```

**关键逻辑**：
- 5.1 是"门控"——挡住不必要的 Multi-Agent 立项
- 5.2 是"骨架"——多 Agent 系统的结构范式
- 5.3 是"治理"——团队化后的 PM 管理方法
- 5.4 是"落地"——把前三节凝练为可操作的决策流程

PM 启动一个 Multi-Agent 项目时，应该按这个顺序走完四节。**任一环节跳过，都会导致项目跑偏。**

## 六、使用建议

### 6.1 适合什么人读

- **正在做复杂 Agent 项目的 PM**：遇到"单 Agent 跑不动"的真实困境
- **企业 AI 平台架构师**：要设计多 Agent 平台，需要可参考的协作模式
- **AI 产品创业者**：要做企业级数字员工产品，需要团队化设计思路
- **AI 转型的组织管理者**：要把 Agent 当作"数字员工"来管理，需要 HITL 协同框架

### 6.2 怎么读

1. **第一遍**：按 5.1 → 5.2 → 5.3 → 5.4 的顺序通读，建立 Multi-Agent 的完整决策框架
2. **第二遍**：针对一个具体场景，对照 5.4 的 7 项检查清单做一次决策
3. **第三遍**：把 5.2 的协作模式作为"工具书"，在每次多 Agent 架构设计时按需查阅

### 6.3 与其他章节的衔接

- **第二章** 提供"该不该做 Agent"的判断——是 5.1 的认知基础
- **第三章** 提供"企业级设计原则"——是 5.3 团队化设计的合规/安全前提
- **第四章** 提供"通用设计全流程"——5.x 在第四章基础上扩展到多 Agent 场景
- **本章** 提供"Multi-Agent 必要性 + 协作 + 团队化 + 决策"——是第六章（组织进化）的前置
