# 5.4 单 vs 多决策：什么时候用 Single Agent，什么时候用 Multi-Agent

> **核心结论**：Single 优先，Multi 是手段不是目的——先 Single 撑不住再上 Multi。
> **判断铁律**：3 个问题答"是"才上 Multi——可拆解 / 需隔离 / 角色差异。
> **底线思维**：上 Multi 前必算 3 笔账——复杂度、Token、延迟。

## 一、为什么 PM 必须会做"单 vs 多"决策

错误的架构选型代价巨大：

- **Single 错选 Multi** → 复杂度爆炸，Token 翻 3 倍，延迟 8 秒，项目最终回退
- **Multi 错选 Single** → 上下文爆炸，任务失败，3 个月后重做

PM 必须在立项时做出正确决策，否则项目从开始就跑偏。

## 二、3 问判断法

PM 在选 Single / Multi 时必答 3 个问题：

### 问题 1：这个任务能否拆成多个独立子任务？
- **能** → 倾向 Multi
- **不能** → 倾向 Single

### 问题 2：子任务之间是否需要上下文隔离？
- **需要** → 倾向 Multi
- **不需要** → 倾向 Single

### 问题 3：子任务是否需要专业不同的大脑？
- **需要** → 倾向 Multi
- **不需要** → 倾向 Single

**3 个问题答"是"的总数**：
- 0-1 个 → **Single Agent**（能用 Single 解决）
- 2 个 → **Single 为主 + Workflow 辅助**（不需要完整 Multi）
- 3 个 → **Multi-Agent**（真需要 Multi）

反面案例：某项目 3 问都答"是"才上 Multi，结果团队没准备好"通信协议、状态管理、错误处理"，3 个月后才发现"上 Multi 是个错误"。

## 三、4 步升级路径

PM 启动 AI 项目时，按以下路径**从简单到复杂**升级：

```
Step 1：Prompt Engineering（对话型）
   ↓ 不够用
Step 2：Workflow / Chain（工作流型）
   ↓ 不够用
Step 3：Single Agent（自主型）
   ↓ 不够用
Step 4：Multi-Agent（多 Agent 协作）
```

**关键原则**：每一步都先确认"撑不住"再升级。**跳级 = 浪费**。

反面案例：某项目从 Prompt 直接跳到 Multi，结果 80% 成本浪费在"为了 Multi 而 Multi"的架构上。

## 四、上 Multi 前必算 3 笔账

| 账目 | 公式 | 警示线 |
|------|------|--------|
| **复杂度账** | 通信协议 + 状态管理 + 错误处理 = 3-5x Single | 复杂度 > 团队能力时不上 |
| **Token 账** | Multi Token ≈ 1.5-2x Single | 客户付费 < 成本时不上 |
| **延迟账** | Multi 延迟 ≈ 1.5-3x Single | SLA 要求 < 2 秒时不上 |

3 笔账中**任一"算不过来"就不上 Multi**。

## 五、上 Multi 前的 7 项检查清单

| # | 检查项 | 不通过时 |
|---|--------|---------|
| 1 | 3 问判断全答"是" | 回到 Single |
| 2 | 4 步路径都走完 | 回到上一步 |
| 3 | 通信协议已设计 | 不上 |
| 4 | 错误隔离方案已设计 | 不上 |
| 5 | Token 成本 ROI 算过 | 不上 |
| 6 | 延迟 SLA 可满足 | 不上 |
| 7 | 团队有 Multi-Agent 经验 | 不上 |

## 六、5 个真实场景的决策

| 场景 | 3 问判断 | 推荐 |
|------|---------|------|
| 智能客服（FAQ 回答） | 0 个是 | Prompt / Workflow |
| 工单分类 + 自动转人工 | 1 个是 | Single Agent |
| 研究 → 写作 → 审校 | 3 个是 | Multi-Agent |
| 跨境数据迁移 | 3 个是 | Multi-Agent |
| 月报自动生成 | 0 个是 | Workflow |
| 未知 Bug 排查 | 3 个是 | Multi-Agent |
| 财务票据审核 | 0 个是 | Workflow |
| 跨业务领域咨询 | 3 个是 | Multi-Agent |

## 七、PM 行动清单

看完本节后：

1. **每个项目立项必过 3 问判断**：可拆解 / 隔离 / 角色差异
2. **必走 4 步升级路径**：从 Prompt 开始，逐级升级
3. **上 Multi 前必算 3 笔账**：复杂度 / Token / 延迟
4. **上 Multi 前必过 7 项检查清单**：7 项不通过不上
5. **真需要 Multi 时也优先监督式**：减少实现难度
