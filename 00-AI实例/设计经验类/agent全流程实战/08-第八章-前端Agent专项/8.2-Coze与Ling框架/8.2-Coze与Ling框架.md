# 8.2 Coze 与 Ling 框架：前端智能体工作流的两条路径

> **核心结论**：Coze 适合"业务早期快速验证"，Ling 适合"产品成熟后要私有化、要代码可控"——两条路径互补。
> **判断铁律**：选型看 3 个维度——团队构成 / 私有化需求 / 定制深度。
> **底线思维**：Coze 的代价是"平台绑定"，Ling 的代价是"学习曲线"——没有银弹。

## 一、为什么需要工作流框架

8.1 解决了"前端如何把 LLM API 跑起来"，但 8.1 的视角仍是"单次调用"。真实的前端智能体——给 6 岁孩子讲睡前故事、给"十万个为什么"做科普、给面试官当陪练——都需要**多步骤、多模型、可能并行的复杂工作流**。

**智能体（Agent）vs 单纯 API 调用的关键差异**：

| 维度 | 单纯 API 调用 | 智能体 |
|------|--------------|--------|
| 决策权 | 写死的代码路径 | 模型运行时自主决策 |
| 工具使用 | 不会 | 主动调用 |
| 流程 | 单一调用 | 多步、可能并行、可能分支 |
| 输入 | 用户 prompt | 用户 prompt + 环境状态 + 工具结果 |
| 输出 | 模型回复 | 行动（可能含工具调用结果） |

**智能体工作流** = 智能体中构成主要功能的流程，由多个节点（LLM 节点、工具节点、条件节点）按一定顺序或并行方式连接。

## 二、Coze 平台路径

### 2.1 Coze 的工作流编排模型

字节跳动 Coze（扣子）平台是典型的"低代码工作流编排器"，前端工程师使用 Coze 的核心心智模型：

- **节点**：大模型节点、插件节点、代码节点、条件节点、开始/结束节点
- **连线**：节点之间的输入/输出变量绑定
- **变量**：开始节点的输入是工作流入口参数；中间节点的输出变量可被下游消费
- **发布**：工作流可发布为"智能体"或"API"

**"睡前故事"工作流编排**（教科书级案例）：

```
开始节点 → input: { topic, age }
   ↓
意图分析节点（豆包 1.5 Pro）→ output: { query }
   ↓
搜索节点（搜索插件）→ output: { articles }
   ↓
内容整理节点（大模型）→ output: { draft }
   ↓
润色节点（大模型，6-8 岁风格）→ output: { finalText }
   ↓
TTS 节点（语音合成插件）→ output: { audioUrl }
   ↓
结束节点 → output: { text, audio }
```

### 2.2 Coze 的前端消费方式

Coze 工作流发布后，前端有 3 种消费方式：

1. **Coze SDK 直接调用**：用 `@coze/chat-sdk` 或 API 客户端
2. **API 模式**：把工作流发布为 HTTP API，前端 fetch 调用
3. **iframe 嵌入**：把 Coze 智能体作为 iframe 嵌入到自有页面

**Coze 的代价**：业务逻辑被平台绑定，后续要做私有化、定制 UI、深度集成会比较痛——这正是 Ling 框架存在的意义。

## 三、Ling 框架路径

### 3.1 Ling 是什么

Ling 是一个**基于流式 JSON 数据的异步工作流框架**（`@bearbobo/ling`）。它解决 Coze 解决不了的问题：**把工作流编排权完全交给前端工程师（用代码），同时保留"边推边渲"的流式体验**。

Ling 的核心心智模型：

- **Ling 实例**：工作流的根容器
- **Bot**：对大模型节点的抽象（ChatBot / EmbeddingBot / CustomBot）
- **Bot 之间的连线**：通过"上一节点的某个 JSON 字段 → 下一节点的 prompt 变量"来配置
- **String-Response 事件**：当某节点某个 JSON 字段推理完成时，立即 emit 事件，触发下游
- **Tube**：流式对象的封装 + 前后端通讯协议（SSE 格式）+ 事件管理

### 3.2 Ling 的"边推边渲"

"AI 十万个为什么"案例展示了一个两级节点的工作流：

```
外层 LLM（BotOutline）: 生成文章大纲（title + outline[]）
  ├─ string-response: "/title"     → emit "title" 事件
  └─ string-response: "/outline/N" → 触发对应 BotSection
                ↓
内层 LLM（BotSection × N）: 展开每个章节的内容
  └─ string-response: "/sections/N/content" → emit 事件
                ↓
Tube 推 SSE 到浏览器 → Vue 响应式更新
```

**关键技巧**：外层 LLM 一边写大纲，内层 LLM 就一边展开。用户看到的是标题先出现，然后章节标题依次出现，然后每章节内容实时填充——**等待时间被压缩到极致**。

### 3.3 Ling 与 Coze 的对比

| 维度 | Coze | Ling |
|------|------|------|
| 编排方式 | 图形化 | 代码 |
| 学习曲线 | 低（产品/运营可上手） | 中（需要懂 TS + JSON 协议） |
| 私有化 | 需要 Coze 企业版/自研 | 直接 fork 代码 |
| 调试 | 平台日志 | VS Code / 终端 |
| 适合场景 | 业务早期、MVP、跨职能协作 | 产品成熟、需要深度定制 |

## 四、Ling 框架的底层实现

### 4.1 四个子系统

| 子系统 | 职责 |
|--------|------|
| **adapter** | 大模型 API 底层适配器（OpenAI 协议 + Coze 协议） |
| **bot** | 对大模型节点的抽象，管理和控制单一节点 |
| **parser** | JSONParser（可独立使用，09 讲用过） |
| **tube** | 流式对象封装 + 前后端通讯（SSE）+ 事件管理 |

**调用链路**：Ling 管理 bot → bot 内部调用 adapter → adapter 通过 parser 解析大模型输出 → 处理好的数据通过 tube 发送 → tube 转发到前端。

### 4.2 Adapter 模块

设计要点：
- **统一接口**：`getChatCompletions(config, messages, options)`，所有底层 API 都收敛到这一个方法
- **协议抽象**：OpenAI 协议（Deepseek / Moonshot / 通义 / Ollama）和 Coze 协议各一个实现类
- **流式内部化**：adapter 内部处理 ReadableStream，向上层只暴露 string-response 事件

### 4.3 Bot 与 Tube 模块

- **Bot** 是工作流节点主体，核心能力：`run(input)` 启动推理，内部状态机 `INIT → WORKING → INFERENCE_DONE → FINISHED/ERROR`，通过 `nunjucks` 模板引擎渲染 prompt
- **Tube** 是数据流的"管道"，关键能力：增量 JSON 编码成 SSE 格式、管理前后端事件命名空间、处理背压（防止浏览器处理慢时内存爆炸）

## 五、项目实战

### 5.1 Ling 重构"拍摄记单词"

06 讲里的"拍摄记单词"是非流式实现——用户拍完照必须等 3-5 秒才能看到单词释义。用 Ling 重构后，**流式体验让等待感几乎消失**：

- 单词信息分阶段到达：先看到单词 → 释义 → 例句 → 配图
- 用户能"提前看"——单词一出现就扫一眼，释义到达时已经准备好读下一项
- 失败回退：某一项流式失败时，自动降级到完整结果，不让 UI 卡死

### 5.2 AI 版"十万个为什么"

Ling 框架的"集大成"案例，覆盖 8.2 节所有要点：

- **多节点工作流**：大纲 Bot + 多个章节 Bot + 插图 Bot + 听书 Bot
- **流式体验**：标题 → 章节 → 内容 → 配图 → 语音 全部边推边渲
- **JSON 协议贯穿**：所有节点输出都是结构化 JSON
- **前后端协作**：BFF 用 Ling 编排，前端用 Vue 订阅 SSE 渲染

该项目同时也是 8.3 节 RAG、8.4 节 Vibe Coding 的"母项目"。

## 六、选型决策树

```
需求是"快速验证一个 AI 智能体业务"
   ├─ 团队有运营/产品介入 → Coze
   └─ 纯前端工程师主导 → Ling

需求是"私有化部署 / 深度定制"
   └─ Ling（或基于 Ling 自研）

需求是"做平台，让运营自助配置"
   └─ Dify（8.4 节私有化方案）
```

## 七、与方法论总纲的对应

| 总纲方法论 | 本节前端特殊化 |
|------------|---------------|
| Workflow（预定义路径） | Ling / Coze 编排 |
| Agent（运行时自主） | Ling 中可以"工作流 + Agent 节点"混合 |
| Tool Use | Coze 插件 / Ling 自定义 Bot |
| 流式输出 | Ling 全部节点默认流式 |
| 私有化 | Ling 代码可控；Coze 需企业版 |
