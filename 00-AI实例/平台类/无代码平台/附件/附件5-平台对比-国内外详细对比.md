## 5.1 国内三大代表：明道云 HAP vs 飞书多维表格 vs 简道云

| 维度 | 明道云 HAP | 飞书多维表格 | 简道云 |
|------|------------|--------------|--------|
| **核心定位** | 企业级无代码中后台 + AI 增强 | 协同表格 + AI 字段 + 智能搭建 | 表单流程 + 行业方案 + AI 接入 |
| **AI 能力成熟度** | 高（向量知识库 + MCP + Agent + 对话机器人 + Mingo） | 高（AI 字段捷径 + 智能搭建 + AI 问数 + DeepSeek R1） | 中（AI 字段 + AI 助手） |
| **AI 能力特点** | 重在"业务编排 + Agent + 知识" | 重在"自然语言搭建 + 智能字段" | 重在"开箱即用 + 行业模板" |
| **目标用户** | 千人以上企业的中后台业务 | 全员协作场景（HR、运营、销售） | 中小企业 + 业务部门 |
| **部署方式** | 公有云 + 私有化 | 公有云（绑定飞书生态） | 公有云 + 私有化 |
| **典型场景** | 销售管理、项目管理、合同审批、跨系统集成 | 客户管理、活动运营、内容归档、轻审批 | 巡检、报修、问卷、行政 HR |

**关键判断**：
- **明道云 HAP**：AI 能力最深、最适合"中后台业务系统 + Agent 编排"重场景，适合 IT 主导的体系化建设。
- **飞书多维表格**：AI 接入门槛最低、最适合"全员轻协作 + 快速验证"场景，适合业务部门自驱。
- **简道云**：行业方案最丰富、最适合"中小企业 + 标准化场景"，AI 能力相对滞后但在快速追赶。

## 5.2 国外对标：Retool / Airtable / Notion / Glide

| 平台 | 核心定位 | AI 时代的关键动作 |
|------|---------|------------------|
| **Retool** | 面向专业团队的内部工具 | 2024 发布 AI Workflows，强化 AI 流程编排 |
| **Airtable** | 协作型数据库 | 2024 发布 Cobuilder，主打自然语言建应用 |
| **Notion** | 知识管理 + 协作 | 2023-2025 持续迭代 AI 写作、AI 问答、AI 搜索 |
| **Glide** | 无代码 App 搭建 | 2025 发布 AI Actions，强调"无代码 + AI 自动化" |
| **Cursor / v0 / Bolt** | AI 原生开发 | 不属于传统无代码，但侵蚀"前端 + 中小应用"市场 |

**关键观察**：
- 国外市场更细分，Retool 服务"专业团队 + 内部工具"，Airtable/Glide 服务"业务用户"，Cursor/v0 服务"开发者"。
- 国内市场由于生态成熟度差异，明道云 HAP / 飞书多维表格 / 简道云三家覆盖了从"企业级"到"中小企业"到"全员协作"的完整光谱，竞争更激烈。

## 5.3 平台选择的"AI 时代新维度"

AI 时代选择无代码平台，需要增加四个新评估维度：

| 维度 | 评估问题 | 评分（参考） |
|------|---------|------------|
| **AI 能力深度** | 是否支持 AI 字段、AI 节点、AI Agent、知识库、智能搭建？ | 满分 5 分，明道云 / 飞书均 4-5 分 |
| **数据主权** | 数据是否在企业自己的租户？是否能私有化？是否支持 BYOK（自带密钥）？ | 私有化能力决定合规底线 |
| **生态连接性** | 是否支持 MCP、API、Webhook、第三方模型接入？ | MCP Server 是 2025 年的关键加分项 |
| **治理能力** | 是否支持 AI 操作的权限隔离、操作审计、人工确认？ | 直接决定能否在生产环境用 |

> **特别提示**：不要被厂商的"AI 能力数量"迷惑，要重点考察 **"AI 能力是否能落地到生产环境"**。评估方法：要求厂商演示一个完整的"业务场景 → AI 增强 → 治理闭环"案例，而不是单独的功能点。
