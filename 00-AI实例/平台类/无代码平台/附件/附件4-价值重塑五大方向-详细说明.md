# 附件 4 - 价值重塑五大方向：详细说明

> **来源**：[无代码产品在AI时代的生态位与价值重塑.md](file:///d:/360MoveData/Users/admin/Desktop/AgI-obsidian/00-AI实例/平台类/无代码平台/AI相关内容/无代码产品在AI时代的生态位与价值重塑.md)  |  **对应章节**：四、价值重塑的五大方向

## 4.1 方向一：从"信息化"到"智能化"

**核心变化**：无代码平台产出的不再是"信息系统"，而是"智能业务系统"。

**关键能力对比**：

| 维度 | 信息化阶段（传统无代码） | 智能化阶段（AI 增强无代码） |
|------|-----------------------|-----------------------|
| 数据录入 | 人工填字段 | AI 抽取 + 自动填字段 |
| 数据处理 | 公式 + 规则 | LLM 理解 + 规则 + Agent |
| 数据洞察 | 固定报表 | 自然语言问数 + 自动洞察 |
| 用户交互 | 点按钮 | 对话 + 命令 |
| 决策方式 | 流程分支判断 | AI 判断 + 人工确认 |

**产品形态示例**：
- **飞书多维表格的 AI 字段捷径**：用自然语言定义字段逻辑，例如"自动从客户沟通记录中提取客户姓名、需求、跟进状态"（资料来源：飞书帮助中心 464880997049）。
- **飞书多维表格的 AI 问数**：用自然语言查询业务数据，例如"Q2 各销售组的回款金额排名"（资料来源：飞书帮助中心 多维表格 AI 功能）。
- **明道云 HAP 的 AI 动作配置**：在流程节点中调用大模型做信息抽取、文本分类、内容生成（资料来源：明道云 AI 动作配置与使用指南）。

**对企业的价值**：从"信息化覆盖率"转向"智能化渗透率"，这是 AI 时代企业数字化的新衡量标尺。

## 4.2 方向二：从"流程驱动"到"Agent 驱动"

**核心变化**：业务系统的执行主体从"预设流程"转向"智能体"。

**传统流程模式**：
```
[触发] → [节点1: 数据校验] → [节点2: 条件判断] → [节点3: 通知] → [结束]
```
- 每条路径都是预先设计的
- 遇到"流程没覆盖"的情况，只能"走异常分支 + 人工兜底"

**Agent 驱动模式**：
```
[触发] → [Agent 节点: 自主分析 + 调用工具] → [结束/人工确认]
```
- Agent 自主判断要做什么
- 调用工具（查表、查 API、发通知）完成任务
- 关键决策点回退人工确认

**产品形态示例**：
- **明道云 HAP 的 AI Agent 节点**：在流程中嵌入 Agent，自动分析客户投诉内容、识别严重程度、判断责任人、分发到不同处理路径（资料来源：明道云 Agent 最佳实践）。
- **飞书多维表格的 AI Agent 工作流节点**：在自动化流程中调用 AI Agent 完成多步骤任务（资料来源：飞书帮助中心 多维表格 AI 工作流节点）。

**关键设计原则**：
1. **人工确认兜底**：新增/更新类操作必须让用户确认，避免 Agent 误操作。
2. **按权限隔离**：Agent 只能访问"对话人有权限"的数据。
3. **结构化输出**：用 JSON Schema 约束 Agent 输出，便于下游节点引用。
4. **分级使用模型**：简单任务用 mini/nano 级别模型（性价比高），复杂任务用旗舰模型。

**对企业的价值**：让流程具备"应对未覆盖场景"的能力，从"穷举式设计"解放为"目标式驱动"。

## 4.3 方向三：从"工具交付"到"能力供给"

**核心变化**：无代码平台不再是"一次性交付的应用"，而是"持续供给的能力"。

**传统模式**：
- 业务方提需求 → IT/无代码开发者搭建 → 上线 → 运维
- 价值在"上线那一刻"，之后是"维护成本"

**新模式**：
- 平台沉淀通用 AI 能力（OCR、文本抽取、问数、智能分类、Agent 模板）
- 业务方按需"订阅"能力，自己组合出应用
- 价值在"持续运营"，新能力上线即可被复用

**产品形态示例**：
- **明道云 HAP 的"AI 能力超市"**：把向量知识库、AI 动作、MCP Server、Agent 节点作为标准能力供给，业务应用按需组合。
- **飞书多维表格的"AI 字段捷径库"**：把常用 AI 字段（情感分析、文本摘要、实体抽取、多语言翻译）做成可一键启用的"字段捷径"（资料来源：飞书帮助中心 字段捷径）。

**对企业的价值**：AI 时代的能力建设不是"项目制"，而是"平台制"——把通用能力做成可复用资产，让业务创新"站在 AI 平台上"。

## 4.4 方向四：从"业务自助"到"业务自治"

**核心变化**：业务用户的角色从"搭建者"升级为"业务系统的运营者"。

**业务自助（Self-Service）**：
- 业务用户能搭建应用
- 但仍需要 IT/平台方解决技术问题

**业务自治（Business Autonomy）**：
- 业务用户能独立完成"搭建 + 运营 + 优化"全周期
- AI 辅助决策"什么时候该改、改哪里"
- IT 的角色从"交付者"变为"治理者"

**产品形态示例**：
- **飞书多维表格的"智能搭建业务系统"**：用自然语言描述需求，AI 自动生成数据表 + 视图 + 自动化 + 仪表盘，业务用户零代码搭建完整系统（资料来源：飞书帮助中心 智能搭建）。
- **明道云 HAP 的"对话机器人"**：业务用户通过对话完成"查客户、补录线索、更新跟进"等操作，无需进入应用界面（资料来源：明道云 help.mingdao.com/ai/best-practices-for-agent）。

**对企业的价值**：让业务部门真正成为"业务系统的 Owner"，而不是"需求提报者"。

## 4.5 方向五：从"数据存储"到"知识沉淀"

**核心变化**：无代码平台的数据底座从"结构化数据"扩展到"结构化数据 + 非结构化知识"。

**传统数据资产**：
- 业务数据（订单、客户、合同、报销）
- 字典与配置（部门、产品线、流程规则）

**AI 时代的知识资产**：
- 业务数据（同上）
- 文档知识（产品手册、制度规范、FAQ、最佳实践）
- 历史经验（过去处理过的相似案例、典型异常解决方案）
- 专家经验（业务专家的判断逻辑、决策偏好）

**产品形态示例**：
- **明道云 HAP 的向量知识库**：把企业文档、规章制度、产品手册转化为可被 AI 检索的知识资产（资料来源：明道云 向量知识库文档）。
- **飞书的"知识库 + AI 问答"**：把多维表格、文档、聊天记录整合为可被 AI 引用的统一知识源。
- **明道云 Mingo AI 随行助手**：基于知识库 + 业务数据，提供"随用随取"的智能问答（资料来源：明道云 Mingo AI 随行助手文档）。

**对企业的价值**：让企业的"数据资产"和"知识资产"在同一平台上沉淀，AI 才能真正"懂企业"。
