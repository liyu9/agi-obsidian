## 1.1 三个被广泛讨论的"取代论"

过去 24 个月，行业内出现了三类典型的"取代论"声音，构成了对无代码平台最直接的认知冲击：

| 论断 | 典型表述 | 依据 |
|------|---------|------|
| **自然语言取代拖拽** | "以后直接跟 AI 说一句话就能做应用，拖拽就是多余的" | Cursor、v0、Bolt.new、Lovable 等工具快速崛起 |
| **AI Agent 取代低代码** | "Agent 能直接调用工具完成任务，业务系统会被 Agent 取代" | Anthropic MCP、OpenAI Function Calling、AutoGen 等框架成熟 |
| **大模型取代 SaaS** | "每个企业都会有自己的 AI 操作系统，传统软件形态会被压缩" | Salesforce Einstein Copilot、Microsoft 365 Copilot 的快速渗透 |

这些论断的共同底层假设是：**无代码平台只是"过渡形态"，其价值会被更高级的 AI 形态覆盖**。

## 1.2 论据 vs 现实：为什么这些论断不成立

把视角拉回到企业实际落地，会发现三个反证：

**反证一：企业 70% 的"长尾需求"根本不是"代码"问题**。
某千人互联网公司 2025 年的内部需求盘点显示：年需求 1840 条，其中真正需要复杂代码开发的不超过 18%（约 330 条），其余 82% 都是"数据收集 + 流程审批 + 报表统计"类需求。这类需求的核心是**业务规则沉淀、数据治理、权限管控**，不是"代码生成"。Cursor/v0 在这类需求上不仅没有效率优势，反而会带来"代码没人敢维护"的新问题。

**反证二：Agent 离不开"业务底座"**。
Agent 强大在"理解 + 推理 + 行动"，但 Agent 要行动就必须有"可操作的对象"——工作表、业务规则、权限范围、数据字典。这些恰好是无代码平台长期沉淀的能力。明道云 HAP 2025 年发布的 AI Agent 最佳实践显示：让 Agent 真正"干活"的关键不是模型本身，而是**Agent 与工作表、权限、PBP 流程的深度耦合**（资料来源：明道云 help.mingdao.com/ai/best-practices-for-agent）。

**反证三：企业需要"可控"而不是"全自动"**。
Gartner 2025 年对企业 CIO 的调研显示，**72% 的受访者认为"可控性"是 GenAI 落地的首要约束**，高于"准确性"（54%）、"成本"（48%）和"易用性"（41%）（资料来源：Gartner「2025 CIO GenAI Survey」）。无代码平台长期构建的"权限体系、审批流、审计日志、字段级数据管控"，正是 GenAI 落地最稀缺的"可控性"基础设施。

> **关键判断**：AI 不是无代码的"替代者"，而是"放大器"。没有无代码平台沉淀的业务底座，AI Agent 就是"空中楼阁"；没有 AI 增强的无代码平台，将沦为"传统信息化工具"。

## 1.3 真正在发生的事：边界在移动，而不是消失

更准确的描述是：**AI 时代，无代码的"应用边界"和"价值重心"都在移动**。

- **应用边界在扩大**：从"业务表单 + 流程"延伸到"对话界面 + 智能体 + 知识库 + 业务编排"。
- **价值重心在转移**：从"开发效率"（做一个应用多快）转向"业务智能化"（让数据/流程本身具备思考能力）。

这就要求产品经理用新的框架重新审视无代码——不是"AI 来了要不要换工具"，而是"我的无代码平台是否在朝新生态位进化"。
