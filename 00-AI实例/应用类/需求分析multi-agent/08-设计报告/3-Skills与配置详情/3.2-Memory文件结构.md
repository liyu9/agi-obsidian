# 3.2 Memory 文件结构（7 个 Agent 目录树）

> **本文档职责**：v3 架构下 7 个 Agent 的 Memory 目录树与每个文件的字段定义
> **源文档**：[`02-架构沉淀/终态方案/MRD转PRD-Multi-Agent架构设计方案.md`](../../02-架构沉淀/终态方案/MRD转PRD-Multi-Agent架构设计方案.md) §3.1-§3.7 Memory 段落
> **配套文档**：[`3.0-Skills总览.md`](3.0-Skills总览.md) / [`3.1-Skills字典.md`](3.1-Skills字典.md)
> **版本**：v3.1（基于 v3 + 7.x 校验完善方案）

---

## 文档说明

Memory 是 Agent 的"长期记忆"，是 Skills 调用时加载的上下文数据源。v3 架构的 Memory 全部沉淀在 `workspace/{agent}/` 目录下，每个文件由对应 Agent 持有写权限，其他 Agent 只能读（Owner 唯一原则，v3 关键决策 5）。

文档按 7 个 Agent 展开目录树。每个文件给出 4 段信息：作用（文件解决什么问题）、字段（YAML/Markdown 内的核心字段）、v3.1 增强（基于 7.x 校验的完善方向）、引用（L 课 + M 编号）。所有文件目录树合计 ≥ 5 个文件 / Agent，满足 v3.1 校验下界。

Memory 与 Skills 的关系：每个 Skill 调用前会按"启动索引"预加载若干 Memory 文件作为上下文。Manager 的启动索引是 `sop_prd_team.md` + `team_roster.md` + `decision_patterns.md` 三个文件（参见 7.1 §3 G2），其他 Agent 的启动索引由各 Agent 自己的 §4 提示词骨架定义。

## 一、Manager（5 个文件）

Manager 的 Memory 围绕"团队调度 + 决策沉淀 + 异常熔断"展开。5 个文件全部达 v3.1 下界。

### workspace/manager/

#### sop_prd_team.md
- **作用**：团队 SOP（阶段 0-4 流转规则），是 Manager 调度的"宪法"
- **字段**：阶段编号 / 前置条件 / 动作 / 产物路径 / 后续阶段 / 异常处理分支
- **v3.1 增强**：YAML 化（每阶段一个 YAML block，便于 LLM 结构化解析），来源 7.x §3 G1 完善方案
- **引用**：L23 Orchestrator 范式 + L26 端到端流程 + M12

#### team_roster.md
- **作用**：5 个子 Agent 名册与职责，作为 Manager 派任务的"通讯录"
- **字段**：Agent ID / 角色名 / Soul / 上下限 / 主要 Skills / 写权限范围 / 启动 prompt 模板
- **v3.1 增强**：增加"工具白名单 + 写权限范围"列（来自 7.0 §4 共性 6）
- **引用**：L25 三维隔离 + M18 + 7.1 §1

#### decision_patterns.md
- **作用**：修复决策模式库（"qa_report 命中 X → 自动派修订 Y"）
- **字段（v3.1 增强）**：pattern_id / timestamp / agent / 失败原因 / 修复策略 / 触发条件 / 命中次数（YAML 化 + 至少 30 条）
- **v3.1 增强**：向量索引（v3.1 新增，按 7.x §3 G1 接入 RAG，Manager 决策时按相似度检索 top-3 模式）
- **引用**：L21 搜索驱动记忆 + L28 自我进化 + M02/M19 + 7.1 §3 G1（P0）

#### gt_index.md
- **作用**：GT 样本索引，标注 4 类分库（产品 30 / 流程 20 / 数据 20 / 页面 50）的位置与匹配关键词
- **字段**：GT ID / 类别 / 关键词标签 / 匹配度历史 / 沉淀日期 / 来源 PRD ID
- **v3.1 增强**：增加"匹配度历史"列（基于 gt_matcher 历史调用结果），便于 Manager 优化匹配策略
- **引用**：L21 + M09 + 7.0 §4 共性 1

#### escalation_log.md
- **作用**：历史熔断记录，用于团队复盘与决策模式沉淀
- **字段**：session_id / trace_id / 触发阶段 / 失败原因 / 修复结果 / 是否 Human 介入 / 复盘结论
- **v3.1 增强**：与 `decision_patterns.md` 双向链接（每次熔断必沉淀为 1 条决策模式）
- **引用**：L31 3 级降级 + L27 Human as 甲方 + M14/M17

## Memory 演化规则

依据 7.0 §4 共性 5（自我进化机制）和 v3 §11 飞轮，所有 Memory 文件的演化遵循 3 条规则：

1. **写入触发条件**：每次任务完成后，Agent 必须评估"本次是否产出了可沉淀的新 pattern"——如果是，写入对应 Memory 文件。
2. **索引升级路径**：v3.0 关键词索引 → v3.1 向量索引 → v3.2 图谱索引（按 7.x §3 G1 完善方向）。
3. **淘汰机制**：超过 6 个月未命中的 Memory 条目进入"待淘汰"列表，人工抽检后决定保留或删除（来自 7.0 §4 共性 8 负反馈循环反制）。
