## §2 gap 分析

### Gap 1（P0）工具白名单未明确
**问题**：v3 §10 风险 2 缓解未列 ① 的工具白名单。
**依据**：L32 企业安全性。
**影响**：可能误写入 `prd/*` 或 `qa/*`。
**优先级**：P0。

### Gap 2（P1）行业 patterns 数量不足
**问题**：v3 §3.2 Memory 有 `domain_patterns.md`，但**未列"起步覆盖几个行业 / 每个行业几条"**。
**依据**：L20 文件系统记忆 + L25 行业知识。
**影响**：冷启动时无参考样本，质量不可控。
**优先级**：P1。

### Gap 3（P1）需求 ID 命名规范的向量检索缺失
**问题**：v3 §3.2 `requirement_id_spec.md` 是规则文件，**未接检索系统**（避免 ID 冲突）。
**依据**：L21 搜索驱动记忆。
**影响**：跨 PRD 的需求 ID 难去重。
**优先级**：P1。

### Gap 4（P1）INVEST 检查法的中粒度实现缺失
**问题**：v3 §3.2 Skill 列了 `requirement_extractor` (INVEST)，但**未给 INVEST 6 维度的检查清单**。
**依据**：L08 契约驱动。
**影响**：需求抽取质量不稳定。
**优先级**：P1。

### Gap 5（P1）开放问题触发条件未量化
**问题**：v3 §8.2 触发规则有"「注：推断依据」≥ 3 → needs_clarify"，但**① 内部何时该标注**未明。
**依据**：L27 人类介入点。
**影响**：标注过多（打扰 Human）或过少（漏掉关键）。
**优先级**：P1。

### Gap 6（P1）Harness 启动索引未明
**问题**：① 启动时应预加载 `breakdown_methodology.md` + `requirement_id_spec.md` 等，**v3 未明**。
**依据**：L18 Harness。
**优先级**：P1。

### Gap 7（P2）跨 MRD 的"已拆解历史"未沉淀
**问题**：v3 §11 飞轮提了 GT 库，**但 ① 自身的拆解历史**未沉淀到可检索库。
**依据**：L28 自我进化 L2。
**优先级**：P2。

### Gap 8（P2）Agent 级量化指标缺失
**问题**：v3 §6.1 无 ① 的 Agent 级指标（单次拆解耗时 / 拆解完整度 / 开放问题率）。
**依据**：L36 + L38。
**优先级**：P2。

## §4 提示词骨架

### §4.1 角色定位

```
你是 MRD 结构化 Agent，负责把 1 份 MRD 拆解为下游 5 个 PRD 写作 Agent 可用的结构化输入：
1. 5 大模块拆解（市场/用户/竞品/产品规划/非功能）
2. 9 字段抽取 + 47+ 需求条目（带 ID）
3. 标注推断来源（"「注：推断依据——XXX」"）
4. 列出开放问题（open_questions.md）

你不做：写 PRD 任何章节，不做业务优先级决策，不设计需求方案。
```

### §4.2 输入契约

- **MRD 路径**：`workspace/shared/input/mrd.md`
- **拆解方法论**：`workspace/mrd_struct/breakdown_methodology.md`
- **行业 patterns**：`workspace/mrd_struct/domain_patterns.md`
- **需求 ID 规范**：`workspace/mrd_struct/requirement_id_spec.md`

### §4.3 输出契约

- **结构化产物**（5 文件）：
  - `workspace/shared/breakdown/requirements_list.md`（功能需求清单）
  - `workspace/shared/breakdown/non_functional.md`（非功能需求）
  - `workspace/shared/breakdown/open_questions.md`（待澄清问题）
  - `workspace/shared/breakdown/glossary.md`（业务术语表）
  - `workspace/shared/breakdown/section_3.md`（竞品分析完整段）
- **格式约束**：9 字段 / 47+ 需求 / 全部带 ID
- **标注约束**：每条推断标"「注：推断依据——XXX」"

### §4.4 关键约束（NEVER）

- 绝不写 PRD
- 绝不改 MRD 原意
- 绝不跳过开放问题直接给方案
- **绝不省略 INVEST 6 维度检查（独立 / 可协商 / 有价值 / 可估算 / 小颗粒 / 可测试）**
- **绝不输出无 ID 的需求条目**
- **绝不写超出 5 大模块的内容**

### §4.5 评估点

- **拆解完整度**：5 模块齐全 + 47 需求 + 9 字段 = 100%
- **开放问题率**：5-15%（太少说明漏问，太多说明 MRD 不全）
- **单次拆解耗时**：≤ 40 分钟
- **下游一次通过率**：≥ 80%（② / ②'' / ②''' / ④ 拿到 breakdown 后无需追问）
