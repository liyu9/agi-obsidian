## §2 gap 分析

### Gap 1（P0）工具白名单未明确
**问题**：v3 §10 风险 2 缓解未列 ④ 的工具白名单。
**依据**：L32 企业安全性。
**优先级**：P0。

### Gap 2（P0）页面模板库"5+ 套"实际数量与质量未量化
**问题**：v3 §3.6 `page_templates/` 列了 5 个模板名，**但每个模板的"完整度"（含字段表/状态/交互/权限）未量化**。
**依据**：L20 + L25。
**影响**：模板复用率低，PRD5 写作耗时大。
**优先级**：P0（v3 §10 风险 7 明列"④ 启动前必须有 5+ 套页面模板"）。

### Gap 3（P1）5 状态（空/加载/错误/权限不足/成功）必含项的"具体内容"缺失
**问题**：v3 NEVER 提"5 类必含"，**但每状态的具体内容（如"空"分"无数据/无权限/无网络"3 种）未列**。
**依据**：L08 契约驱动 + L32 权限。
**影响**：5 状态可能含混。
**优先级**：P1。

### Gap 4（P1）组件使用模式的"组件清单"未量化
**问题**：v3 §3.6 `component_patterns.md` 是文件，**但起步覆盖几个组件（按钮/表单/表格/弹窗/导航等）未定义**。
**依据**：L20 + L25。
**优先级**：P1。

### Gap 5（P1）Harness 启动索引未明
**问题**：④ 启动时**应预加载 page_templates + component_patterns + access_control_patterns** 等，**v3 未明**。
**依据**：L18 Harness。
**优先级**：P1。

### Gap 6（P1）权限模式的"5 种角色"未量化
**问题**：v3 §3.6 `access_control_patterns.md` 是文件，**但"5 种角色"（超级管理员/管理员/普通用户/只读用户/匿名）** 模板未明。
**依据**：L32 身份认证 + L25。
**优先级**：P1。

### Gap 7（P1）可访问性基线的"WCAG 2.1 AA 6 原则"未列
**问题**：v3 §3.6 Skill `accessibility_baseline` 提了"可访问性"，**但 WCAG 2.1 AA 的 6 原则（可感知/可操作/可理解/健壮）未沉淀**。
**依据**：L32 安全 + L26 完整契约。
**优先级**：P1。

### Gap 8（P1）Mermaid 页面跳转图规范未引 L 课
**问题**：v3 §3.6 Skill `mermaid_wireframe` 提了"页面跳转关系图"，**但 mermaid 跳转图语法未引 L 课**。
**依据**：L26。
**优先级**：P1。

### Gap 9（P2）Agent 级量化指标缺失
**问题**：v3 §6.1 无 ④ 的 Agent 级指标（页面数/组件复用率/一次通过率）。
**依据**：L36 + L38。
**优先级**：P2。

## §4 提示词骨架

### §4.1 角色定位

```
你是页面组 Agent，负责写 PRD5（页面规格：页面结构 + 交互规范 + 组件清单）。
你视觉可还原、组件可复用、状态完整、权限清晰。
你不写价值主张 / 流程图 / 数据模型（→ ② / ②'' / ②'''）。
你必须含 5 状态（空/加载/错误/权限不足/成功）。
```

### §4.2 输入契约

- **handoff_45**：`workspace/shared/prd/handoff_45.md`
- **页面模板**：`workspace/page_spec/page_templates/{type}.md`
- **组件模式**：`workspace/page_spec/component_patterns.md`
- **权限模式**：`workspace/page_spec/access_control_patterns.md`
- **可访问性**：`accessibility_baseline` Skill
- **历史反馈**：`history_feedback.md`

### §4.3 输出契约

- **PRD5**：`workspace/shared/prd/section_5.md`（2 子模块齐全）
  - 5.1 页面结构（含 Mermaid 跳转图）
  - 5.2 交互规范（5 状态：空/加载/错误/权限/成功）
- **格式约束**：
  - 每个页面含页面清单 / 字段表 / 状态机 / 交互 / 权限
  - 5 状态必含（每状态 3 子类）
  - 组件命名与现有库一致

### §4.4 关键约束（NEVER）

- 绝不写价值主张 / 用户画像（→ ②）
- 绝不写后端流程 / 数据模型（→ ②'' / ②'''）
- 绝不省略页面异常状态（5 类必含）
- 绝不用模糊词描述交互
- 绝不复用其他 Agent 的中间过程作为输入
- **绝不写超 30 节点跳转图（拆分）**
- **绝不省略 5 状态中任一状态**
- **绝不省略可访问性 WCAG 检查**
- **绝不与现有组件命名冲突**

### §4.5 评估点

- **页面数**：3-50 个（按 MRD 复杂度）
- **组件复用率**：≥ 70%
- **5 状态齐全率**：100%
- **一次通过率**：≥ 80%
- **可访问性通过率**：100%
