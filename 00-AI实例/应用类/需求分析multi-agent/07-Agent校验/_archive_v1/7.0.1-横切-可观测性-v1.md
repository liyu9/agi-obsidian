## 1. 为什么需要 Langfuse

v3 §6.3 可观测性当前仅"邮箱日志 + completion.json"，存在 3 个系统性问题：

1. **无 trace 关联**：7 个 Agent 之间的调用链无统一标识，调试时无法串联
2. **无评分回写**：③ 质检的 100 分制评分**未回写**到生产追踪系统
3. **无监控面板**：4 类指标（可用性 / 质量 / 效率 / 业务）无统一可视化

**课程 L30 解决路径**：
> "可观测性 = Hook 骨架 + Langfuse 全链路追踪。关键节点埋 Hook，把 trace_id 串联起来，再用 Langfuse 的 score API 把质检评分回写。"

**v3.1 目标**：所有 7 个 Agent 的 LLM 调用统一接入 Langfuse，实现"端到端 trace + 评分回写 + 监控面板"。

## 2. trace_id 标识规范

### 2.1 全局 trace_id 格式

```
{prefix}-{session_id}-{agent_name}-{step_index}

示例：mgr-2026-06-26-001-mrd-2
```

| 字段 | 说明 | 示例 |
|------|------|------|
| **prefix** | Agent 缩写（见下表） | `mgr` |
| **session_id** | 本次 MRD→PRD 任务的会话 ID（日期 + 序号） | `2026-06-26-001` |
| **agent_name** | Agent 名称（与 prefix 一致） | `mrd` |
| **step_index** | 该 Agent 在本任务中的执行步骤序号 | `2` |

### 2.2 7 个 Agent 的 trace_id 前缀表

| Agent | trace_id 前缀 | 角色 | 课程 L 课 |
|-------|--------------|------|----------|
| **Manager** | `mgr-` | 主调度 | L23 + L25 + L27 |
| **① MRD 结构化** | `mrd-` | 拆解 MRD | L07 + L08 + L25 |
| **② 产品组** | `prd-` | 价值主张 + 功能规格 | L07 + L08 + L25 |
| **②'' 流程组** | `flow-` | 流程图 + 旅程 | L03 + L09 + L25 |
| **②''' 数据组** | `data-` | 数据模型 + ER 图 | L07 + L25 + L32 |
| **④ 页面组** | `page-` | 页面规格 + 交互 | L07 + L25 + L30 |
| **③ 质检** | `qa-` | 100 分制 + 3 视角 | L23 BP-1 + L36 |

**v3.1 实施要求**：
- 每个 Agent 的 system prompt 启动索引中**必须**包含 `trace_id = "{prefix}-{session_id}-{agent_name}-{step}"`
- 子 Agent 启动时**必须**把 `trace_id` 作为参数注入
- Manager 在派任务时**必须**把当前 `session_id` 传给子 Agent

## 3. 评分回调机制

### 3.1 评分流程图

```
┌────────────────────────────────────────────────────────────────┐
│  Langfuse 评分回调（基于 L30 + L36）                              │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  ① 子 Agent 完成写作                                             │
│     ↓ (trace_id: prd-2026-06-26-001-prd-3)                     │
│  ② Manager 派任务给 ③ 质检（带 trace_id）                         │
│     ↓                                                          │
│  ③ ③ 质检完成 5 维度评分                                          │
│     ↓ 输出 qa_report.json (含 score + trace_id)                 │
│  ④ Langfuse score API 回调                                       │
│     - score_value: 总分（0-100）                                 │
│     - score_name: "qa_total"                                    │
│     - trace_id: prd-2026-06-26-001-prd-3                        │
│     - comment: 5 维度明细 + 缺陷位置                              │
│     ↓                                                          │
│  ⑤ Langfuse 监控面板汇总                                          │
│     - Agent 级一次通过率                                          │
│     - PRD 级 5 维度趋势                                          │
│     - 异常自动告警                                                │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 3.2 5 维度评分映射（v3 §7.1 + L36）

| 维度 | 满分 | Langfuse score_name | 度量方式 |
|------|------|---------------------|---------|
| **完整性** | 20 | `qa_completeness` | 必填字段覆盖率 |
| **一致性** | 20 | `qa_consistency` | 跨章节一致 + 与 MRD 一致 |
| **可执行性** | 20 | `qa_executability` | 开发 / 测试 / 运营可读 |
| **风险标注** | 20 | `qa_risk_marking` | [TBD] / 风险点覆盖 |
| **风格统一** | 20 | `qa_style_consistency` | 模板遵从度 |
| **总分** | 100 | `qa_total` | 5 维度之和 |

**Langfuse score API 调用规范**：

```python
# 伪代码（v3.1 实施时填充）
from langfuse import Langfuse

langfuse = Langfuse(
    public_key="...",
    secret_key="...",
    host="https://cloud.langfuse.com"
)

# ③ 质检完成评分后回调
langfuse.score(
    trace_id="prd-2026-06-26-001-prd-3",
    name="qa_total",
    value=85,  # 5 维度之和
    comment={
        "completeness": 18,
        "consistency": 17,
        "executability": 16,
        "risk_marking": 17,
        "style_consistency": 17,
        "issues": ["3.2 缺权限边界", "5.4 数据脱敏规则 [TBD]"]
    }
)
```

## 4. v3.1 实施步骤

### 4.1 第 1 步：注册与配置（1 周）
- 注册 Langfuse Cloud 账号（自托管或 SaaS）
- 创建 v3-mrd-prd 项目
- 获取 `public_key` / `secret_key` / `host`
- 配置 7 个 Agent 各自的 `langfuse_secret` 环境变量

### 4.2 第 2 步：trace_id 注入（1 周）
- 修改 Manager 的 system prompt：每次派任务时**生成** `session_id`（YYYY-MM-DD-NNN）
- 修改每个子 Agent 的启动 hook：接收 `session_id` + 自动生成 `trace_id = {prefix}-{session_id}-{agent_name}-{step}`
- 修改 ③ 质检的回调 hook：评分完成后调用 Langfuse score API

### 4.3 第 3 步：灰度接入（2 周）
- 先在 1 个 Agent（如 ① MRD 结构化）上灰度
- 验证 trace_id 串联正确性 + 评分回写正确性
- 修复 bug 后扩展到 ②/②''/②'''/④
- 最后接入 Manager + ③ 质检

### 4.4 第 4 步：监控面板（1 周）
- Langfuse 自带面板：按 trace_id 查看 7 个 Agent 调用链
- 自建面板（可选）：4 类指标（可用性 / 质量 / 效率 / 业务）汇总
- 告警规则：单次评分 < 60 自动告警 + 重试
