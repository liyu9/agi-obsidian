## 1. 项目概览

### 1.1 一句话使命与边界
为企业员工提供 7×24 小时、覆盖 IT/HR/行政等高频场景的 AI 自助服务平台，把内部职能部门从重复咨询中解放出来。[原]

- **使命**：让员工"问一次、解决一次"，让 IT/HR/行政从客服转为知识与流程治理者。
- **边界（做）**：意图识别、知识问答、情绪分级、答案审核重试、转人工、运维 MCP 执行、工单自动流转。
- **边界（不做）**：对外 C 端客服（独立项目）；非企业内部场景的通用 ChatBot；替代人事/审计判断的高风险决策。

### 1.2 当前阶段与规模

| 维度 | 当前值 | 数据来源 |
|---|---|---|
| 阶段 | MVP→PMF 验证中（已上线主流程，CSAT 出现下降趋势需迭代）| [原] |
| 服务对象 | 企业全员（IT/HR/行政/财务为主） | [原] |
| 核心入口 | 企业 IM、Web 工单门户、邮箱、自助终端 | [原] |
| 知识库覆盖率 | 95% | [原] |
| 意图识别准确率 | 综合 80%，垂直场景 90% | [原] |
| 人工客服成本下降 | 45% | [原] |
| CSAT | 60%+（呈下降趋势，触发优化项）| [原] |

### 1.3 关键成果数据速览
- 量化：人工成本 -45%、知识库覆盖率 95%、意图识别准确率 80%（垂直 90%）。[原]
- 质性：沉淀可复用的客服工作流模板、混合检索 + 循环节点审核重试组合最佳实践。[原]
- 风险：CSAT 60%+ 出现下降趋势，要求短期内通过语义缓存 + 长记忆 + 多 Agent 协作扭转。[原]

### 1.4 项目所属与上下游
- **上游**：知识库治理团队（IT/HR/行政 SOP 文档源头）、企业 IM 平台、ITSM 工单系统。
- **下游**：转人工坐席（IT 二线、HR BP、行政接待）、数据分析平台（落库 6 字段供 BI）、运维 MCP 执行通道。
- **协作方**：法务（合规审核）、安全（数据脱敏）、知识小组（FAQ 维护）。

### 1.5 与对外客服的边界差异（强提醒）
| 维度 | AI 企业客服（本项目） | 游戏客服（兄弟项目） |
|---|---|---|
| 用户身份 | 已认证员工，身份可信 | 匿名/账号玩家，需风控 |
| 入口 | 企业 IM、工单门户 | 游戏内、官网、APP、短信 |
| 高频问题 | 密码重置、报销、考勤、设备 | 充值、封号、卡顿、活动、举报 |
| 关键 KPI | 人工成本下降、首解率、知识覆盖 | CSAT、转人工率、合规拦截率 |
| 合规约束 | 内部数据隔离、SOX/ISO27001 | 未成年人保护、网络游戏管理办法、防沉迷 |
| SLA 基线 | CSAT≥80%、FCR≥70%、知识时效≤8h | CSAT≥75%、FCR≥65%、知识时效≤1h |
| 灰度上限 | 50% 员工 | 10% 玩家 |
| 风险事件 | 误指示导致流程错误 | 公关风险、监管处罚、玩家集体投诉 |

## 2. 背景与多角色痛点

### 2.1 企业层痛点
- IT/HR/行政重复咨询占 40%-60% 一线工时，规模化扩张时人均产能瓶颈。[训]
- 跨系统知识割裂：IT 知识在 Confluence、HR 在 e-HR、行政在 OA，员工"问哪个找哪个"成本高。[原]
- 合规要求逐年提升（数据安全法、个保法、SOX、ISO27001），人工服务留痕成本高。[训]

### 2.2 业务层（IT/HR/行政一线）痛点
- 80% 工单是高频低价值（密码重置、报销询问、考勤异常），消耗一线工时。[原]
- 知识库陈旧、回答不一致：新员工不会写、老员工不会更新。[原]
- 节假日/夜间无值班，员工只能等到上班时间。[训]

### 2.3 终端用户层（员工）痛点
- 跨部门求助"打电话→转工单→等回复"链路长，平均 4 小时以上。[训]
- 表述不规范导致被反复"请提供工号/截图"，体验差。[原]
- 不知道找谁问，跨部门员工尤其严重。[原]

### 2.4 技术层痛点
- 早期"大模型 JSON 解析做意图"耗时高、稳定性差。[原]
- 单一语义检索召回不稳，专有名词、内部术语命中率低。[原]
- 缺少答案审核机制，幻觉直接抛给员工，影响信任。[原]

### 2.5 管理层痛点
- 服务过程不可观测：无统一数据看板，无法 quantify 改进。[原]
- ROI 不清晰：投了多少做 IT 助手、HR 助手等"小工具"，未沉淀平台化能力。[训]
- 满意度治理：CSAT 出现下降时缺乏归因抓手。[原]

### 2.6 行业数据交叉验证
- Gartner 2025 预测：到 2027 年 50% 企业内部 IT/HR 服务台将引入 GenAI 自助助理。[网]
- IDC 2025《企业内部服务自动化白皮书》：成熟落地企业平均节约 30%-45% 一线人工。[网]
- ServiceNow Now Assist 案例：客户报告平均工单解决时间下降 22%-30%。[网]
- Microsoft Copilot for Service：在 IT 服务台场景平均首解率提升 19%。[网]

| 痛点 | 员工 | IT 一线 | HR/行政 | 管理层 | 技术 |
|---|---|---|---|---|---|
| 高频重复 | ★ | ★★★ | ★★★ | ★★ | ★ |
| 等待时间长 | ★★★ | ★ | ★ | ★★ | - |

## 3. 需求验证（三步法）

### 3.1 步骤 1：目标用户群体确认
- **P0**：员工（咨询者）、IT/HR/行政一线坐席（被解放者）、知识小组（FAQ 维护者）。
- **P1**：管理层（看板使用者）、安全/法务（合规守门人）。
- **P2**：BI 团队（消费落库数据）。

### 3.2 步骤 2：痛点假设
- H1：员工 80% 高频问题可由 AI 自助闭环（密码、报销、考勤、设备）。
- H2：知识库混合检索 + Rerank 比单一语义检索召回提升 ≥30%。
- H3：情绪两级分级可减少 ≥20% 不必要转人工。
- H4：循环节点 2 次审核重试可压制幻觉触达率到 ≤5%。

### 3.3 步骤 3：假设验证方式与结论

| 假设 | 验证方式 | 结论 |
|---|---|---|
| H1 | 8 周灰度 + 工单回流分类 | ✅ 自助率达到 65%+，覆盖率 95% [原] |
| H2 | A/B 对比纯语义 vs 混合 | ✅ 召回率 +35% [原] |
| H3 | 情绪两级 vs 一刀切转人工 | ✅ 减少 30% 不必要转人工 [原] |
| H4 | 2 次循环 + Fallback | ✅ 幻觉触达 ≤4% [原]，但 CSAT 仍下降，触发新一轮迭代 |

### 3.4 验证沉淀
- 真问题：高频低价值咨询、知识不一致、夜间无人响应。
- 伪问题：员工要"全能 AI 助手"——实测员工只在 IT/HR/行政等垂直场景信任 AI，跨域问题更倾向人工。

### 4.3 P0 角色画像

**P0-A：员工咨询者「小李」**
- 画像：销售岗，常出差，凌晨打不开 VPN、报销卡单。
- 痛点：找谁问？等多久？答案权威吗？
- 关键需求：一句话定位问题；给到可执行的步骤或自助链路；解决不了能秒级转人工。

**P0-B：IT 一线坐席「老王」**
- 画像：5 年经验，每天处理 80 单以上，疲于应付密码/网络/打印。
- 痛点：高频重复、夜间值班疲劳、知识库不及时。
- 关键需求：AI 拦截 70% 高频；剩余 30% 提供上下文摘要；运维 MCP 直接执行重置/解锁。

**P0-C：HR BP「小韩」**
- 画像：负责 5 个 BU、每月入离调转 50+。
- 痛点：政策口径不一致、新员工 onboarding 重复回答 100 次。
- 关键需求：政策版本化、变更可灰度、可观测各 BU 命中差异。

**P0-D：知识维护者「小赵」**
- 画像：兼职做 FAQ 维护，工具不顺手就放弃。
- 痛点：写完没人看、不知道哪条答案被命中、改了不知道生效没。
- 关键需求：所写即所用、命中率反馈、改动可灰度。

### 4.4 用户问题说明（"作为…我想做…从而…"）
- 作为出差销售，我想凌晨自助解锁 VPN，从而不耽误次日早会。
- 作为 IT 一线，我想让 AI 拦截高频问，从而把精力放到疑难单。

- 作为知识维护者，我想看到"哪条 FAQ 被命中、被点踩"，从而精准迭代。
- 作为管理层，我想看到 CSAT 与人工成本曲线，从而决定下一步投入。

- 静态：部门、职级、工作地、入职时长、设备、权限组。
- 动态：近 30 日工单频次、最近一次 CSAT、是否触发情绪分级、是否复诊问题。

## 5. 底层需求洞察

### 5.1 表面需求 vs 底层需求

| 表面 | 底层 |
|---|---|
| "我要 7×24 答复" | 不被等待、被尊重、问题可控 |
| "AI 要更聪明" | 答得对、有据可查、不胡说 |
| "全部转人工" | 信任不足，需要兜底 |
| "知识库要全" | 知识可治理、变更可控 |
| "看板再多一点" | 异常可干预、ROI 可解释 |

### 5.2 一句话统一所有 P0
> "让员工的每一次咨询，都被快、准、稳地解决，让一线和知识维护者从重复劳动中解放出来。"

### 5.3 心理学维度
- 安全感：合规留痕、答案有出处。
- 控制感：随时可转人工、随时可挽留。
- 公平感：政策一致、口径一致。
- 效能感：员工自助成功、坐席效率提升。

### 5.4 跨角色冲突点
- 员工要"快"，合规要"准"——以两级情绪 + 审核重试解。
- 一线要"少打扰"，管理要"全留痕"——以全链路落库 + 看板解。
- 知识维护要"灵活"，安全要"权限严"——以分级权限 + 灰度发布解。

## 6. 产品定义与方案

### 6.1 使命宣言
做一套"可治理、可观测、可灰度"的企业内部 AI 客服平台，把 IT/HR/行政从重复咨询中彻底解放。

### 6.2 产品原则
1. 先抓自助率，再抓 CSAT。
2. 不可解释的答案不上线，能审核才能输出。
3. 任何阶段都允许"两次找人工 + 挽留"，不强行拦截。
4. 数据先落库再优化，没有数据不做决策。
5. 平台化优先：避免做一堆烟囱式"小助手"。

### 6.3 用例三要素
- 谁：员工/一线坐席/知识维护者。
- 何时何地：工作日 + 节假日 + 夜间，IM/工单门户/邮箱/自助终端。
- 期望结果：自助闭环 or 转人工带上下文 or MCP 直接执行。

### 6.4 MVP 两阶段
- **0→0.5（验证价值）**：意图识别原生节点 + 知识库混合检索 + 答案审核重试 + 转人工挽留 + 6 字段落库。
- **0.5→1（真实可用）**：情绪两级分级 + 运维 MCP（IT 高频执行类）+ 知识灰度 + 看板 + CSAT 归因。

### 6.5 一定不优先（≥3 条）
1. 不做对外 C 端客服功能，避免与游戏客服混线。
2. 不做"全能 AI"，不接非 IT/HR/行政场景。
3. 不做无审核的开放生成，所有输出走审核-重试-Fallback 链路。
4. 不做闭门数据，所有对话强制落库 6 字段。

### 6.6 PRD 五要素映射
| 要素 | 落点 |
|---|---|
| 用户 | 员工/一线/知识维护者/管理层 |
| 问题 | 高频重复、知识割裂、夜间无人 |
| 方案 | 5 层架构 + 混合检索 + 循环审核 + 运维 MCP |
| 价值 | 人工 -45%、覆盖 95%、夜间可用 |
| 度量 | CSAT、自助率、首解率、知识时效、幻觉触达 |

## 7. 核心功能与架构

### 7.1 五层架构总览（沿用原资料）

| 层 | 职责 | 关键节点 |
|---|---|---|
| 入口层 | 多渠道接入、缓存匹配、找人工两次触发 + 挽留 | IM/Web/邮件适配器、缓存规则 |
| 意图层 | 意图识别 + 情绪检测 + 分支路由 | 原生意图节点、情绪两级 |
| 知识层 | 混合检索 + Rerank + 命中判断 | 语义+全文，防无限引导 |
| 生成层 | 答案生成 + 审核 + 重试 | 循环节点 2 次 + Fallback |
| 输出层 | 转接原因生成、引导、对话记录、回复输出 | 6 字段落库 |

### 7.2 主 Agent 与多 Agent 协作（演进规划）
- 当前：单主 Agent + 工具调用（知识检索、运维 MCP、工单创建）。
- 下阶段：拆分为 IT-Agent / HR-Agent / 行政-Agent，主 Agent 做调度，提升垂直场景准确率。
- 长期：引入长期记忆 Agent，记录员工偏好（VPN 客户端、报销习惯）。

### 7.3 六大亮点对应模块
1. 情绪分级处理 → 意图层（两级、降低 30% 不必要转人工）。
2. 循环节点审核重试 → 生成层（2 次循环 + Fallback）。
3. 混合检索策略 → 知识层（召回 +35%）。
4. 全链路数据落库 → 输出层（6 字段）。
5. 意图识别原生节点 → 意图层（速度更快、配置更简单）。
6. 运维 MCP → 工具层（从问答升级为执行：密码重置、解锁、配额、报销代查）。

### 7.4 关键流程时序
1. 入口接收 → 缓存匹配（命中直接回）。
2. 未命中 → 意图识别 + 情绪检测。
3. 高频意图（如密码重置）→ MCP 直接执行 + 反馈。
4. 通用问答 → 混合检索 + Rerank → 命中判断。
5. 命中 → 生成 → 审核（不通过则重试 1 次，再不通过 Fallback）。
6. 输出 + 落库 + CSAT 反馈。
7. 二次找人工 + 挽留失败 → 转人工 + 上下文摘要。

### 7.5 知识与模板治理
- 来源：IT 知识库、HR 政策库、行政 SOP、历史工单。
- 治理：版本化、灰度发布、命中率/点踩反馈、过期自动告警。
- 输出：FAQ + 操作手册 + 自助链路 + MCP 动作。

### 7.6 业务驱动模型分析
- 高频低价值 → MCP 自动执行（成本最低）。
- 高频高价值 → 知识问答 + 审核（重点优化）。
- 低频高复杂 → 转人工 + 上下文摘要（不强求 AI）。
- 低频低价值 → 缓存兜底，不投入精力。

### 7.7 多渠道接入抽象
- 适配器统一抽象 input/event/context；下游链路一套。
- 支持 IM、Web 工单门户、邮箱、自助终端、工位电话（语音转文）。

## 8. 行业对标与竞品分析

## 9. 指标体系

### 9.1 正向指标（4 步法）

**Step 1：最高目标**
- 在不增加合规风险的前提下，把内部高频咨询自助率拉到 70%+，CSAT 拉到 80%+。

**Step 2：子指标**
- 自助率（覆盖率 × 命中率）
- 首解率 FCR
- CSAT
- 知识库时效（≤8h）
- 幻觉触达率
- 转人工率
- 运维 MCP 自动执行成功率
- 知识命中点踩比

**Step 3：功能关联**
| 指标 | 关键功能 |
|---|---|
| 自助率 | 知识混合检索 + MCP 执行 |
| FCR | 意图识别 + 上下文 |
| CSAT | 情绪两级 + 审核重试 + 挽留 |
| 知识时效 | 知识治理 + 灰度 |
| 幻觉触达率 | 审核重试 + Fallback |
| 转人工率 | 两次触发 + 挽留 |
| MCP 成功率 | 工具层稳定性 |

**Step 4：量化阈值（SLA 基线）**
| 指标 | 当前 | 目标 | 红线 |
|---|---|---|---|
| 自助率 | 65% | 70% | 50% |
| FCR | 70% | 75% | 60% |
| CSAT | 60%+（下降）| 80% | 70% |
| 知识时效 | 8h | 4h | 24h |
| 幻觉触达率 | 4% | ≤2% | 5% |
| 转人工率 | 30% | 20% | 35% |
| MCP 成功率 | 95% | 99% | 90% |

### 9.2 反指标（量化阈值 + 安全红线 + 降级策略）
- **反指标 1**：误指示导致流程错误率（红线 ≤0.5%，超阈降级到只读建议）。
- **反指标 2**：合规拦截误杀率（红线 ≤1%，超阈关闭强拦截改提示）。
- **反指标 3**：MCP 误执行率（红线 ≤0.1%，超阈下线该动作并人工兜底）。
- **反指标 4**：员工"再问一次"率（红线 ≤15%，超阈触发 FAQ 评审）。
- **降级策略**：模型超时 → 切到缓存或工单；审核失败 → 转人工带上下文摘要；MCP 失败 → 自动建工单。

### 9.3 指标权衡机制
- 安全 > 质量 > 体验 > 成本。
- 当 CSAT 与自助率冲突时，优先保 CSAT，先把自助率下调到 60% 也要先把 CSAT 拉回 75%。
- 任何新功能上线必须不让反指标越红线。

### 9.4 侵蚀效应评估
- 自助率拉太高 → 一线坐席技能退化（保留每周轮岗）。
- MCP 太激进 → 误执行风险（必须双人复核高危动作）。
- 缓存太宽 → 知识更新滞后被掩盖（缓存 TTL 与命中率监控）。

### 9.5 PMF 判断标准（5 条门槛）
1. 自助率持续 ≥65%（连续 4 周）。
2. CSAT 持续 ≥75%（连续 4 周）。
3. 一线工时下降 ≥40%（与上线前同期对比）。
4. 幻觉触达率 ≤3%。
5. 至少 3 个垂直场景（IT/HR/行政）独立达标。

### 10.2 一定不优先（≥3 条）
1. 不做对外 C 端客服。
2. 不做"通用助手"，不接非内部职能场景。
3. 不做无审核的开放生成。
4. 不做没有数据落库的功能。

### 10.3 权衡取舍四步法
1. 必须事项（安全/合规/留痕）必做。
2. 高 ROI 事项（高频低价值场景的 MCP 自动化）优先。
3. 中 ROI 事项（多 Agent、长期记忆）排在 PMF 后。
4. 低 ROI 事项（数字人皮、跨语言）放 P2。

### 10.4 中长期规划路线
- 0-1 季度：CSAT 拉回 75%（语义缓存 + 知识治理 + 多 Agent 试点）。
- 1-2 季度：多 Agent 全量、长期记忆全量。
- 2-4 季度：语音入口、数字人皮、跨语言、海外子公司试点。

### 10.5 增长代价评估
- 多 Agent 拆分：开发成本 +20%、运维复杂度上升，但准确率提升明确。
- 长期记忆：合规成本 + 数据脱敏成本上升，需联合安全/法务设计。
- 语义缓存：可能掩盖知识更新滞后，需要 TTL + 命中率监控配合。

## 12. 落地实践与迭代经验

### 12.1 已踩过的坑与教训
1. 早期用大模型 JSON 解析做意图：稳定性差、时延高 → 切原生意图节点。
2. 单一语义检索：内部术语命中差 → 切混合检索 + Rerank。
3. 一刀切转人工：情绪一负面就转，转人工率飙升 → 情绪两级。
4. 无审核直出：偶发幻觉直接抛给员工 → 循环 2 次审核 + Fallback。
5. 落库字段不全：缺转接原因导致归因难 → 6 字段标准。
6. MCP 运维过激：曾误重置一次密码 → 高危动作必须双人复核 + 二次确认。
7. 知识更新滞后：员工反复"答得不对" → 知识灰度 + 时效告警。
8. 缓存 TTL 过长：政策变更后旧答案仍命中 → TTL 分场景配置 + 命中率监控。
9. CSAT 归因薄弱：知道在掉但不知道为什么 → CSAT 看板 + 标签反查。
10. 入口分散：多个渠道各做一套 → 适配器统一抽象。

### 12.2 关键决策的对错复盘
| 决策 | 结果 | 复盘 |
|---|---|---|
| 用 Coze 循环节点做审核重试 | 对 | 兼顾质量与体验，可复用 |
| 早期不做语义缓存 | 半对 | 时延偏高，应在 v0.7 就开始 |
| 早期不做多 Agent | 对 | 单 Agent 跑通 PMF 再拆，避免过度设计 |
| 知识库治理放后期 | 错 | 应在 v0.5 就启动版本化 |
| 直接接入运维 MCP | 半对 | 价值大，但高危动作复核机制应同步上 |

### 12.3 大厂实践对项目的具体启示
1. ServiceNow → 工单闭环 + 数据落库（已落）。
2. Microsoft → IM 优先入口（已落）。
3. Atlassian → 知识源头治理（部分落）。
4. Moveworks → 垂直场景胜过通用（已落）。
5. 飞书/钉钉 → 组织通讯录数据底座（已落）。

### 12.4 推进过程中的协作经验
- IT/HR/行政三方知识小组每月对账，命中率/点踩榜单决定优先迭代项。
- 法务/安全/合规嵌入审核与 MCP 高危动作评审。
- 灰度先在 IT 1 个 BU 试点，再扩 HR/行政。

### 12.5 给同类项目的建议
- 不要追求"全能 AI"，垂直场景胜出。
- 数据落库永远第一优先级，没有数据就没有改进。
- 转人工不是失败，而是体验保险阀。
- 把"知识治理"当产品做，而不是当后台运营做。
