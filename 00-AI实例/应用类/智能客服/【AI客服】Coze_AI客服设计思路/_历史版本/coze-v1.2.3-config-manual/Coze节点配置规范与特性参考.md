# Coze 节点配置规范与特性参考

> **用途**：AI Agent 编写 Coze 工作流配置文档时的参考规范。阅读本文档后，应能生成符合 Coze 平台限制、可在 Coze 中落地的配置方案。
>
> **适用平台**：Coze 扣子（对话流 Chatflow / 工作流 Workflow）
>
> **数据来源**：[Coze 官方文档](https://www.coze.cn/api/open/docs/guides/workflow) + 实操经验

---

## 一、节点类型总览

| 节点类型 | Coze 名称 | 本项目数量 | 核心能力 |
|---------|----------|-----------|---------|
| 开始节点 | 开始 | 1 | 定义输入参数（对话流自动含 `USER_INPUT`） |
| 结束节点 | 结束 | 1 | 返回最终结果（返回文本 / 返回变量） |
| 大模型节点 | 大模型 | 9 | LLM 推理生成，支持 Prompt、技能、会话历史 |
| 代码节点 | 代码 | 5 | 自定义代码逻辑（Python / JS），结构化处理 |
| 选择器节点 | 选择器 | 4 | if-else 分支路由，支持多条件、优先级排序 |
| 数据库节点 | 数据库 | 2 | 读写 Coze 数据库（查询 / 写入） |
| 变量赋值节点 | 变量赋值 | 2 | 为会话变量赋值（读取变量无需专门节点） |
| 输出节点 | 输出 | 2 | 中间过程输出（Loading / 安抚语 / 阶段性结果） |
| 知识库节点 | 知识库检索 | 1 | 检索知识库文档，支持语义 / 全文 / 混合检索 |

## 二、各节点配置规范

### 2.1 大模型节点

**官方文档**：https://www.coze.cn/api/open/docs/guides/llm_node

#### 配置文档格式

每个大模型节点按以下结构编写：

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名（分支名） | → 下游节点名

**1. 输入**
- `参数名` / 类型 / `{{上游节点.变量名}}`（或固定值）

**2. 模型配置**
- 模型：豆包 Lite 7B / 豆包 Pro 32B+
- 温度：0.0 ~ 1.0（分类 ≤ 0.2，生成 0.4~0.7，创意 ≥ 0.8）
- 最大输出长度：XXX tokens
- 输出格式：文本 / Markdown / JSON
- 会话历史：开启 / 关闭（对话流可开启，工作流不可用）
- 会话历史写入：写入 / 不写入（仅对话流）

**3. 系统提示词（System Prompt）**
```
角色定义 + 任务说明 + 规则约束 + 输出要求
```

**4. 用户提示词（User Prompt）**
```
{{变量引用}} + 补充说明
```

**5. 输出**

- **文本 / Markdown**：仅 1 个输出参数，值为模型回复文本
- **JSON**：多个输出参数，每个需指定名称、类型、描述

| 变量名 | 类型 | 描述 |
|-------|------|------|
| `field1` | String | 字段说明 |

> JSON 样例（仅 JSON 输出时需要）：
> ```json
> { "field1": "value1", "field2": 0.9 }
> ```

**6. 异常处理**
- 整体执行超时：默认 180s，可调 0.1s ~ 600s
- 首次响应超时：最大 100s（需 ≤ 整体超时）
- 重试次数：0（默认）/ 1（可设备选模型）
- 异常处理方式：中断流程 / 返回设定内容 / 执行异常流程

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| 输出变量名必须有意义 | 参数名和描述影响模型输出质量，`new_query` 比 `output1` 更好 |
| 异常设定内容格式 | 必须与输出格式一致：Text → 纯文本，JSON → JSON |
| 异常时自动增加输出 | 设定"返回设定内容"或"执行异常流程"时，自动增加 `isSuccess`、`errorBody` |
| 流式输出 | 仅 Text/Markdown 且单参数时支持；JSON 不支持 |
| 续写功能 | 仅支持续写的模型可开启，增加响应时间和 Token 消耗 |
| 会话历史 | 对话流可开启（自动传入最近多轮对话）；工作流不可用 |
| 技能扩展 | 可添加插件/工作流/知识库，模型自动判断调用时机 |
| 超时默认 3 分钟 | 可调至 10 分钟；开启流式后一旦开始输出，异常无法重试 |

#### 编写规则

- 输出格式为 JSON 时，**必须**提供 JSON 样例和每个字段的描述
- 异常处理"设定内容"的格式**必须**与输出格式一致
- 模型选择：分类/引导用 Lite 7B（低成本），答案生成用 Pro 32B+（高质量）
- 会话历史写入：Loading/安抚语/引导语 → **不写入**；业务回复 → **写入**
- 对话流中，大模型节点可读取会话历史，无需手动传入

### 2.2 代码节点

**官方文档**：https://www.coze.cn/api/open/docs/guides/code_node

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名

**1. 输入**
- `参数名` / 类型 / `{{上游节点.变量名}}`（或固定值）

**2. 代码**
- 语言：Python / JavaScript
- 代码：

```python
async def main(args: Args) -> Output:
    params = args.params
    # 逻辑说明
    ret: Output = {
        "输出变量名": 值
    }
    return ret
```

**3. 输出**
- `变量名` / 类型 / 描述

**4. 异常处理**
- 整体执行超时：默认 60s，可调 0.1s ~ 60s
- 重试次数：0（默认）/ 1
- 异常处理方式：中断流程 / 返回设定内容（JSON）/ 执行异常流程

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| **必须以对象形式返回** | 即使只有一个输出值，也必须 `return {"key": value}`，不能 `return value` |
| 输出参数名必须与 return 一致 | 输出定义的参数名、类型必须与 return 对象的 key 完全一致 |
| 不支持多个函数 | 只能定义一个 `main` 函数 |
| 超时 60s | 硬限制，不可超过 |
| 不支持外部依赖 | Python 仅内置 `requests_async`、`numpy`；JS 仅内置 `dayjs`、`lodash` |
| Python 版本 | 3.11.3 标准库，不支持 `multiprocessing` / `threading` / `sockets` |
| JS 版本 | V8 11.3.244.8（Node.js 20.3.1），支持 ES2022 |
| 输入参数引用 | 通过 `args.params['param_name']` 或 `params.get('param_name')` 取值 |
| 每个工作流最多 50 个代码节点 | 全局限制 |
| sleep 应使用 asyncio.sleep | `time.sleep` 会阻塞工作流执行，导致限流 |

#### 编写规则

- 输出**必须**以对象形式返回，即使只有一个字段
- 输出参数定义**必须**与 return 对象的 key 名和类型完全一致
- **不要**使用 `time.sleep()`，使用 `asyncio.sleep()`
- **不要**引入除 `requests_async`/`numpy`（Python）或 `dayjs`/`lodash`（JS）之外的第三方库
- 会话变量全部为 String 类型，比较前**必须** `int()` 转换，输出时**必须** `str()` 转换
- 代码节点入参上限 2MB，超出会报错或截断
- 异常处理"返回设定内容"**必须**是 JSON 格式（即使输出是 Text 格式）

### 2.3 选择器节点

**官方文档**：https://www.coze.cn/api/open/docs/guides/condition_node

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名（多个分支）

**1. 输入**
- 无需额外输入参数（通过引用上游节点输出变量进行条件判断）

**2. 分支配置（按优先级从上到下）**

| 分支 | 名称 | 条件 | 目标节点 |
|------|------|------|---------|
| 分支 1 | 分支名称 | `{{上游节点.变量}}` 运算符 值 | 节点 X |
| 分支 2 | 分支名称 | `{{上游节点.变量}}` 运算符 值 | 节点 Y |
| 否则 | 兜底 | 默认 | 节点 Z |

> **分支优先级说明**：按从上到下顺序逐个判断，首个匹配的分支执行，后续分支跳过

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| **无输出参数** | 选择器节点通过分支路由到下游，本身不产生输出 |
| 优先级可拖拽调整 | 分支顺序决定判断优先级，首个匹配的分支执行 |
| 支持多条件组合 | 每个分支支持添加多个条件，支持"且"/"或"逻辑 |
| 条件运算符 | 等于、不等于、包含、不包含、大于、小于、为空、不为空等 |
| 否则分支必须有 | 所有条件均不满足时执行，建议配置兜底逻辑 |

#### 编写规则

- 选择器节点**没有**输出参数，**不要**写"3. 输出"段落
- 分支优先级非常重要，**必须**按业务重要性从高到低排列
- 每个分支**必须**说明连接的目标节点
- 否则分支**必须**配置兜底逻辑，不能留空

### 2.4 数据库节点

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名

**1. 输入**
- 无需额外输入参数（在写入字段中直接引用上游变量）

**2. 配置内容**

查询模式：
- 数据表：表名
- 查询条件：字段 / 运算符 / 值
- 查询上限：N（默认 10）
- 排序：按 field_name 升序/降序

写入模式：
- 数据表：表名
- 写入模式：追加 / 更新

| 字段名 | 值来源 | 说明 |
|-------|-------|------|
| `field1` | `{{上游节点.变量}}` | 来源说明 |
| `field2` | 固定值 | 来源说明 |

**3. 输出**
- `outputList` / Array / 查询结果列表（仅查询模式）
- 无输出参数（写入模式）

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| **不支持自动生成时间戳** | 需要上游代码节点生成 `datetime.now()` 后传入 |
| **不支持表达式** | 写入字段的值只能是固定值或变量引用，不能写 `{{a + b}}` |
| 查询上限默认 10 | 可调大 |
| QPS 限制 | 数据库节点 400 QPS（主账号+子账号共享） |
| 超时 1 分钟 | 数据库节点默认超时 60s |
| 不支持事务 | 多次写入不在同一事务中 |

#### 编写规则

- 数据库写入节点**不支持**表达式，需要计算的字段**必须**通过上游代码节点处理
- 时间戳字段**必须**由上游代码节点生成，不能直接写"当前时间"
- 写入字段的值来源**必须**明确标注（变量引用或固定值）

### 2.5 变量赋值节点

**官方文档**：https://www.coze.cn/api/open/docs/guides/add_variables_in_app

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名

**1. 配置内容**
- 节点类型：变量赋值
- 变量赋值列表：

| 目标变量 | 赋值来源 |
|---------|---------|
| 会话变量 `var_name` | `{{上游节点.变量名}}` 或固定值 |

> **注意**：Coze 变量赋值节点不需要声明输入参数，直接在配置面板中选择会话变量并设置赋值来源。无输出参数，直接写入会话变量。

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| **不需要输入参数** | 直接在配置面板中选择目标会话变量和赋值来源 |
| **不支持表达式** | 赋值来源只能是固定值或变量引用，不能写 `{{a + 1}}` |
| **无输出参数** | 直接写入会话变量，下游通过 `{{会话变量名}}` 读取 |
| 变量节点已停用 | 旧版"变量节点"已停用，新配置使用"变量赋值节点" |
| 读取变量无需专门节点 | 除开始节点、输入节点、知识库写入节点外，所有节点都能读取会话变量 |
| 变量名最长 20 字符 | 会话变量名有长度限制 |
| 变量值最长约 6 万字符 | 不建议存储过长内容 |
| **不支持手动输入固定值** | 变量值只能从下拉菜单中选择上游节点输出，无法直接输入固定值。如需赋固定值，需上游代码节点输出该值后引用 |

#### 编写规则

- **不要**写"1. 输入"段落，变量赋值节点没有输入参数配置项
- **不要**写"3. 输出"段落，变量赋值节点没有输出参数
- **不支持**表达式！需要计算时**必须**用上游代码节点处理
- 赋值来源写清楚是固定值还是变量引用

### 2.6 输出节点

**官方文档**：https://www.coze.cn/api/open/docs/guides/message_node

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名

**1. 输入**
- `参数名` / 类型 / `{{上游节点.变量名}}`（或固定值）

**2. 配置内容**
- 节点类型：输出
- 输出内容：模板文本，可引用 `{{变量名}}`
- 流式输出：开启 / 关闭（仅在大模型节点之后可开启）
- 会话历史写入：写入 / 不写入

**3. 输出**
- 文本内容直接输出给用户（**不产生可引用的输出变量**）

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| **不产生可引用的输出变量** | 输出节点直接向用户展示内容，下游节点无法引用其输出 |
| 流式输出限制 | 仅在大模型节点之后才能开启流式；绑定卡片时即使开启流式也是非流式 |
| 会话历史写入 | Loading/安抚语建议"不写入"，避免污染上下文 |
| 支持绑定卡片 | 可绑定消息卡片展示富交互效果 |

#### 编写规则

- 输出节点**不产生**输出变量，下游节点**不能**引用输出节点的内容
- Loading/安抚语/引导语 → 会话历史写入设为"**不写入**"
- 业务回复 → 会话历史写入设为"**写入**"
- 流式输出仅在大模型节点之后可开启
- 如果下游需要引用输出内容，应使用大模型节点而非输出节点

### 2.7 知识库节点

#### 配置文档格式

**节点作用**：一句话描述业务目的

**数据流向**：← 上游节点名 | → 下游节点名

**1. 输入**
- Query / String / `{{变量引用}}`

**2. 配置内容**
- 节点类型：知识库检索
- 选择知识库：知识库名称（可多选）
- 搜索策略：语义 / 全文 / 混合
- 最大召回数量：N（默认 1，建议 5~10）
- 最小匹配度：0.X（默认 0.5）
- 高级设置：
  - 查询改写：开启 / 关闭
  - 结果重排：开启 / 关闭
  - 会话历史辅助检索：开启 / 关闭

**3. 输出**
- `outputList` / Array / 检索结果列表
  - 每条结果包含 `content`（文档内容）和 `score`（相似度分数）
  - 无匹配结果时为空数组 `[]`

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| 内置查询改写 | 开启后自动结合对话上下文改写 Query（指代消解、模糊问题明确化） |
| 内置结果重排 | RRF（倒数排名融合）算法，综合多路检索结果排序 |
| Query 只能配置一个表达式 | 不能根据路径动态切换 Query 来源 |
| outputList 为空数组 | 无匹配结果时返回 `[]`，不会报错 |
| 多知识库同时检索 | 可同时勾选多个知识库，结果合并返回 |

#### 编写规则

- 如果需要 boost_query 增强，在 Query 中拼接：`{{USER_INPUT}} {{上游节点.boost_query}}`
- 建议开启查询改写和结果重排
- 最小匹配度建议 0.5，最大召回数量建议 5~10
- outputList 为空时不会报错，下游代码节点需做空数组判断
- Query 只能配置一个表达式，多条路径汇合时需要上游统一处理

### 2.8 开始节点

#### 配置文档格式

**节点作用**：定义对话流的输入参数

**数据流向**：→ 下游节点名

**1. 预置参数**
- `USER_INPUT` / String / 用户消息（必填，对话流自动生成，不可删除）
- `CONVERSATION_NAME` / String / 会话标识（必填，对话流自动生成，不可删除）

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| 对话流自动含 USER_INPUT | 不可删除 |
| 对话流自动含 CONVERSATION_NAME | 不可删除 |
| 支持导入 JSON 批量建参 | 可从 JSON 结构快速生成参数列表 |
| 参数可设为必填/可选 | 必填参数缺失时工作流报错 |

---

### 2.9 结束节点

#### 配置文档格式

**节点作用**：返回最终结果，结束工作流

**数据流向**：← 上游节点名

**1. 返回模式**
- 返回文本：直接输出文本内容（可引用变量 `{{变量名}}`）
- 返回变量：输出 JSON 结构（需定义输出参数）

#### 平台限制

| 限制项 | 说明 |
|-------|------|
| 两种返回模式 | 返回文本（简单）/ 返回变量（结构化，适合子工作流/API） |
| 输出节点的内容不经过结束节点 | 输出节点直接向用户展示，结束节点是最终结果 |
| 未执行节点的变量引用返回空字符串 | 不会报错 |

## 三、跨节点通用规则

### 3.1 变量引用

| 规则 | 说明 |
|------|------|
| 引用上游输出 | `{{上游节点名.输出变量名}}` |
| 引用会话变量 | `{{会话变量名}}`（直接写变量名，不需要节点前缀） |
| 嵌套引用 | `{{变量名.子字段名}}` 或 `{{变量名[数组索引]}}` |
| 未执行节点 | 返回空字符串，不会报错，下游需做空值判断 |
| 变量名最长 | 20 字符（会话变量限制） |
| 变量值最长 | 约 6 万字符，不建议存储过长内容 |

### 3.2 数据流向标注规范

格式：`**数据流向**：← 上游节点名（分支名） | → 下游节点名`

- 上游是分支节点时，**必须**标明具体分支名（如"缓存判断（分支3）"）
- 多个上游用"或"连接，多个下游列出所有（如"→ 节点X / 节点Y"）
- 使用具体节点名称，不使用模糊描述

### 3.3 超时限制

| 节点类型 | 默认 | 最大 |
|---------|------|------|
| 大模型节点 | 3 分钟 | 10 分钟 |
| 代码节点 | 1 分钟 | 1 分钟（硬限制） |

## 四、编写检查清单

生成或审核 Coze 配置文档时，逐项检查：

### 大模型节点
- [ ] 输出格式（Text/JSON）与异常处理设定内容格式一致
- [ ] JSON 输出时有 JSON 样例和字段描述
- [ ] 温度设置合理（分类 ≤ 0.2，生成 0.4~0.7）
- [ ] 会话历史写入设置正确（Loading 不写入，业务回复写入）
- [ ] 输出变量名有意义（不是 output1/text 等）

### 代码节点
- [ ] return 是对象形式（即使只有一个字段）
- [ ] 输出参数名/类型与 return 对象一致
- [ ] 没有使用 time.sleep()（用 asyncio.sleep）
- [ ] 没有引入不支持的第三方库
- [ ] 会话变量比较前有 int() 转换，输出前有 str() 转换

### 选择器节点
- [ ] 没有写"3. 输出"段落
- [ ] 分支优先级按业务重要性排列
- [ ] 否则分支有兜底逻辑

### 数据库节点
- [ ] 写入字段值来源明确（变量引用或固定值）
- [ ] 没有使用表达式（需要计算时用上游代码节点）
- [ ] 时间戳字段有上游代码节点生成

### 变量赋值节点
- [ ] 没有写"1. 输入"和"3. 输出"段落
- [ ] 没有使用表达式（需要计算时用上游代码节点）
- [ ] 赋值来源明确（固定值或变量引用）

### 输出节点
- [ ] 没有声明输出变量名（输出节点不产生可引用变量）
- [ ] 会话历史写入设置正确
- [ ] 流式输出仅在大模型节点之后开启

### 通用
- [ ] 数据流向标注格式统一（节点名 + 分支名）
- [ ] 变量引用格式正确（`{{节点名.变量名}}`）
- [ ] 未执行节点的变量引用已考虑空值情况
