# 企业AI Agent客服应用 - Coze v1.3 配置手册

> **版本**：v1.3 | **平台**：Coze 扣子（对话流 Chatflow）
> **目标**：按本手册逐步操作，可在 Coze 中完整搭建 AI 客服系统
> **基于**：v1.2 配置手册，优化意图识别与意图澄清流程体验

---

## v1.3 迭代内容

> 相比 v1.2 的改动，共 2 项（体验优化）：

| 序号 | 迭代项 | v1.2 问题 | v1.3 方案 | 涉及节点 |
|-----|-------|----------|----------|---------|
| 1 | non_service 通用回复 | 闲聊/非业务问题直接转人工，浪费人工资源 | 新增「通用回复」大模型节点，友好回应+引导回归服务范围，不转人工 | 通用回复（新增）、分支路由 |
| 2 | 低置信度智能追问 | 意图澄清为固定文案输出节点，无针对性 | 改为大模型节点，根据意图识别结果动态生成针对性追问 | 意图澄清（改造） |

---

## v1.2 迭代内容（历史）

> 相比 v1.1 的改动，共 8 项：

| 序号 | 迭代项 | v1.1 问题 | v1.2 方案 | 涉及节点 |
|-----|-------|----------|----------|---------|
| 1 | 意图分类恢复为4类 | 仅 product_inquiry + non_service 2类，知识库检索方向性差 | 恢复 product_info / order_logistics / after_sale / non_service 4类，按意图定向检索 | 意图识别、分支路由 |
| 2 | 缓存改为 boost_query | 缓存硬编码答案与知识库内容可能不一致（如运费偏远地区3个vs5个） | 缓存只输出 boost_query 快速通道关键词，命中后走知识库检索返回最新内容 | 高频缓存匹配、缓存判断 |
| 3 | 重试判断去掉自引用 | 重试判断节点引用自身输出 is_retry，Coze 可能循环依赖报错 | 改用会话变量 retry_count 计数，无自引用 | 重试判断 |
| 4 | 情绪检测嵌入意图识别 | 负面情绪用户得不到安抚 | 意图识别 prompt 增加情绪字段，选择器新增负面情绪分支 | 意图识别、分支路由 |
| 5 | 短输入检测 | 用户输入"那个呢""价格"等极短文本，意图识别容易误判 | 缓存匹配节点增加 is_short_input 检测，引导用户使用示例格式提问 | 高频缓存匹配、缓存判断 |
| 6 | 答案生成 prompt 增加 intent 信息 | prompt 中的意图信息未被有效利用 | 将细分意图（product_info/order_logistics/after_sale）传入答案生成，指导回答侧重方向 | 答案生成 |
| 7 | 审核维度细化 | 审核只检查通过/不通过，不给出具体修改建议 | 审核不通过时输出 revision_hint 修改建议，供重试时答案生成参考 | 答案审核、答案生成 |
| 8 | 联系方式引导文案动态化 | 固定文案，转接原因和情绪感知弱 | 联系方式引导读取转接原因变量，结合情绪状态输出差异化安抚文案 | 联系方式引导 |

**v1.1 遗留问题修复说明**：

- **缓存与知识库不一致**：v1.1 中缓存硬编码"偏远地区（新疆/西藏/内蒙古）"，但知识库中为"新疆/西藏/内蒙古/青海/甘肃"。v1.2 缓存不再硬编码答案，改为 boost_query 走知识库，彻底消除不一致风险
- **重试判断自引用**：v1.1 重试判断节点 `is_retry` 引用自身输出，Coze 不支持节点引用自己的输出作为输入。v1.2 改用会话变量 `retry_count`，由代码节点读写，无自引用
- **意图分类过粗**：v1.1 将订单物流、售后、产品咨询全部归入 product_inquiry，导致知识库检索时无法按意图方向过滤。v1.2 恢复4类，后续可按意图选择不同知识库

## 第一步：创建对话流

### 1.1 进入 Coze 平台

1. 打开 [coze.cn](https://www.coze.cn)，登录账号
2. 进入**工作空间**（左侧边栏选择你的团队/个人空间）

### 1.2 创建智能体

1. 点击左侧**「智能体」**菜单
2. 点击**「创建智能体」**按钮
3. 填写基本信息：
   - **名称**：`AI客服助手`（可自定义）
   - **描述**：`企业智能客服，自动回答产品咨询、订单物流、售后政策等常见问题`
4. 点击**「创建」**

### 1.3 创建对话流

1. 进入刚创建的智能体 → 点击**「对话流」**标签页
2. 点击**「创建对话流」**
3. 输入名称：`AI客服主流程`
4. 点击**「确认」**，进入对话流编辑器

> 进入编辑器后，画布中央会自动出现一个**「开始」**节点和一个**「结束」**节点。

---

## 第二步：创建知识库

> 在配置节点之前，先创建好知识库，后续知识库检索节点需要绑定。

### 2.1 创建产品知识库

1. 点击左侧**「知识库」**菜单（或进入「资源库」→「知识库」）
2. 点击**「创建知识库」**
3. 填写信息：
   - **名称**：`产品知识库`
   - **描述**：`商品信息、功能介绍、规格参数、使用方法等`
4. 点击**「创建」**
5. 进入知识库 → 点击**「添加文件」** → 上传产品相关文档（Markdown/TXT/Word）
6. 等待文件解析完成

### 2.2 创建 FAQ 知识库

1. 重复上述步骤，创建第二个知识库：
   - **名称**：`FAQ知识库`
   - **描述**：`常见问题与标准答案`
2. 上传 FAQ 问答文档

### 2.3 知识库内容格式要求

上传的文档建议使用以下格式（一问一答结构）：

```
Q: 这个产品支持什么支付方式？
A: 我们目前支持微信支付、支付宝、银行卡支付、花呗/京东白条分期。

Q: 退货流程是什么？
A: 退货流程：1. 进入「我的订单」→ 找到对应订单 2. 点击「申请退货」→ 选择退货原因 3. 等待审核通过 → 寄回商品 4. 确认收货后退款到原支付账户。
```

> **提示**：每个 Q&A 之间用空行分隔，便于 Coze 自动分段。

## 第三步：创建会话变量

> **v1.2 新增**：需要创建一个会话变量 `retry_count`，用于记录答案审核重试次数，替代 v1.1 中重试判断节点的自引用方案。

### 3.1 创建 retry_count 会话变量

1. 在对话流编辑器中，点击左侧或顶部**「变量」**面板
2. 切换到**「会话变量」**标签
3. 点击**「添加变量」**
4. 配置：
   - **变量名**：`retry_count`
   - **类型**：Number
   - **默认值**：`0`
5. 点击**「保存」**

> **说明**：会话变量在整个会话期间持久存在，不同轮次共享。`retry_count` 记录当前问题已重试生成答案的次数，流程开始时重置为0。

### 节点 2：高频缓存匹配（代码节点）

> **v1.2 变更**：不再硬编码答案，改为输出 `boost_query`（增强查询词）和 `is_short_input`（短输入标记）。命中缓存时走知识库快速通道，确保答案与知识库一致。

**创建方式**：点击画布空白处 → 选择**「代码」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：双击节点标题，改为 `高频缓存匹配`

2. **选择语言**：在节点配置面板中，语言选择 **Python**

3. **添加输入参数**：
   - 点击**「添加输入参数」**
   - 参数名：`question`，类型：String
   - 变量引用：点击右侧 `{{}}` 按钮 → 选择 `USER_INPUT`

4. **粘贴代码**（在代码编辑区域）：

> Coze Python 代码节点格式要求：
> - 入口函数必须为 `async def main(args: Args) -> Output:`
> - 通过 `args.params` 获取输入参数
> - 输出变量必须命名为 `ret`，类型注解为 `Output`
> - `args` 由平台自动注入，不要 import 或重新定义

```python
async def main(args: Args) -> Output:
    params = args.params
    question = (params.get('question', '') or '').lower().strip()

    # 高频问题库（关键词 → boost_query 增强查询词）
    # v1.2 变更：不再硬编码答案，改用 boost_query 走知识库快速通道
    # 避免缓存答案与知识库内容不一致的问题
    # 请根据实际业务替换以下关键词和 boost_query
    cache_rules = [
        {
            "keywords": ["退货", "退换货", "怎么退", "退货流程", "退款流程"],
            "boost_query": "退货流程 退款 7天无理由退货"
        },
        {
            "keywords": ["支付方式", "怎么付款", "付款方式", "支持什么支付"],
            "boost_query": "支付方式 付款 微信支付 支付宝 银行卡"
        },
        {
            "keywords": ["发货时间", "什么时候发货", "多久发货", "发货快吗"],
            "boost_query": "发货时间 物流 发货政策 配送"
        },
        {
            "keywords": ["运费", "包邮", "邮费", "运费多少", "免邮"],
            "boost_query": "运费 包邮 邮费 偏远地区运费"
        },
        {
            "keywords": ["发票", "开票", "增值税发票", "电子发票"],
            "boost_query": "发票 电子发票 增值税发票 开票"
        },
        {
            "keywords": ["保修", "质保", "维修", "保修期"],
            "boost_query": "保修 质保 售后维修 保修期"
        },
        {
            "keywords": ["尺码", "尺寸", "码数", "多大", "尺码表"],
            "boost_query": "尺码 尺寸对照表 码数选择"
        },
        {
            "keywords": ["优惠", "折扣", "活动", "满减", "优惠券"],
            "boost_query": "优惠活动 折扣 满减 优惠券 促销"
        }
    ]

    # 短输入检测：极短文本（<=3字符且不含标点/空格）标记为短输入
    # v1.2 新增：避免"那个呢""价格"等模糊输入被意图识别误判
    is_short = len(question) <= 3 and question.isalpha()

    # 匹配逻辑
    for rule in cache_rules:
        for kw in rule["keywords"]:
            if kw in question:
                ret: Output = {
                    "is_cached": True,
                    "boost_query": rule["boost_query"],
                    "cached_answer": "",
                    "is_short_input": is_short
                }
                return ret

    # 未命中缓存
    ret: Output = {
        "is_cached": False,
        "boost_query": "",
        "cached_answer": "",
        "is_short_input": is_short
    }
    return ret
```

5. **确认输出参数**（代码运行后会自动识别）：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| `is_cached` | Boolean | 是否命中缓存 |
| `boost_query` | String | 增强查询词，用于知识库检索 |
| `cached_answer` | String | 保留字段（v1.2 始终为空，兼容回复输出节点） |
| `is_short_input` | Boolean | 是否为极短输入 |

---

### 节点 3：缓存判断（选择器节点）

> **v1.2 变更**：新增短输入分支。缓存判断现在有 3 个出口：缓存命中（走知识库快速通道）、短输入（引导补充）、正常（走意图识别）。

**创建方式**：点击画布空白处 → 选择**「选择器」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `缓存判断`

2. **配置分支条件**（按顺序创建，顺序即优先级）：

   **分支 1**（缓存命中 → 知识库快速通道）：
   - 左值：`{{高频缓存匹配.is_cached}}`
   - 运算符：**等于（==）**
   - 右值：`true`

   **分支 2**（短输入 → 引导补充）：
   - 左值：`{{高频缓存匹配.is_short_input}}`
   - 运算符：**等于（==）**
   - 右值：`true`

   **否则分支**（正常 → 意图识别）：
   - 默认已存在，无需配置

---

### 节点 3.5：短输入引导（输出节点）

> **v1.2 新增**：当用户输入极短文本（如"价格"、"那个呢"）时，引导用户使用更明确的表述。

**创建方式**：点击画布空白处 → 选择**「输出」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `短输入引导`

2. **配置输出内容**：
   ```
   您好，能否详细描述一下您想了解的内容呢？例如：
   - "这款羽绒服的价格是多少"
   - "我的订单什么时候发货"
   - "退货流程是什么"
   - "保修期是多长时间"
   ```

3. **流式输出**：设为**关闭**

4. **会话历史写入**：设为**写入**

   > 必须写入历史，这样用户补充描述后，意图识别可以看到本轮追问的上下文。

---

### 节点 4：意图识别（大模型节点）

> **v1.2 变更**：意图分类从2类恢复为4类；新增情绪检测字段 emotion。

**创建方式**：点击画布空白处 → 选择**「大模型」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `意图识别`

2. **选择模型**：
   - 模型：选择 **豆包 Lite**（或任意 7B 级别小模型）

3. **模型参数设置**：
   - **温度（Temperature）**：设为 **0.1**（确保分类稳定）
   - **最大输出长度**：500 tokens

4. **输出格式**：
   - 选择 **JSON**

5. **JSON 样例配置**：

   添加以下 4 个字段：

| 字段名 | 类型 | 说明 |
|-------|------|------|
| `intent` | String | 意图分类 |
| `confidence` | Number | 置信度 |
| `key_info` | Array | 关键信息 |
| `emotion` | String | 情绪状态 |

   粘贴 JSON 样例：
   ```json
   {
     "intent": "product_info",
     "confidence": 0.92,
     "key_info": ["iPhone 16 Pro", "颜色"],
     "emotion": "neutral"
   }
   ```

6. **添加输入参数**：
   - 参数名：`question`，类型：String
   - 变量引用：`{{USER_INPUT}}`

7. **系统提示词**（System Prompt）：

```
你是电商客服意图识别专家。你的任务是分析用户的问题，判断其意图分类，提取关键信息，并检测用户情绪。

## 意图分类体系（4类）

1. product_info - 产品咨询（商品信息、价格、规格参数、功能介绍、使用方法、尺码、材质等）
2. order_logistics - 订单物流（订单查询、发货时间、物流状态、配送范围、到货时间等）
3. after_sale - 售后服务（退货、退款、换货、维修、保修、发票、投诉、售后政策等）
4. non_service - 非客服问题（闲聊、无关话题、明确不是客服能回答的问题）

## 情绪检测

根据用户语气判断情绪状态：
- neutral: 正常咨询，无情绪倾向
- frustrated: 感到困扰或不满（如多次追问同一问题、表达"怎么还没解决"）
- angry: 明确表达愤怒或抱怨（如含"垃圾"、"骗子"、"投诉"等）
- anxious: 焦虑着急（如含"急"、"赶紧"、"什么时候"多次出现）

## 输出要求

请以 JSON 格式输出，包含以下字段：
- intent: 意图分类（使用上述英文标识）
- confidence: 置信度分数（0-1之间的小数）
- key_info: 提取的关键信息数组（如商品名称、订单号、问题类型等）
- emotion: 情绪状态（neutral/frustrated/angry/anxious）

## 注意事项

- 如果用户消息包含指代词（如"那个"、"这个"），请结合对话历史理解其含义
- 置信度仅作为参考，不要因为置信度低就改变意图分类结果
- 即使不确定，也要给出最可能的意图分类
- key_info 中提取的信息应尽量具体，便于后续知识库检索
- 情绪判断要基于用词和语气，不要过度解读
```

8. **用户提示词**（User Prompt）：

```
请分析以下用户问题：

用户问题：{{question}}

请输出 JSON 格式的意图识别结果（含意图分类、置信度、关键信息、情绪状态）。
```

9. **会话历史**：
   - 找到**「会话历史」**或**「智能体会话历史」**开关 → **开启**

10. **异常处理**：
    - 找到**「异常处理」**配置
    - 选择**「返回设定内容」**
    - 设定内容：
    ```json
    {
      "intent": "non_service",
      "confidence": 0,
      "key_info": [],
      "emotion": "neutral"
    }
    ```

### 节点 6：转接原因生成（代码节点）

> **v1.2 变更**：增加情绪状态和细分意图的转接原因描述。

**创建方式**：点击画布空白处 → 选择**「代码」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `转接原因生成`

2. **选择语言**：Python

3. **添加输入参数**（共 4 个）：

| 参数名 | 类型 | 变量引用 |
|-------|------|---------|
| `n4_intent` | String | `{{意图识别.intent}}` |
| `n4_confidence` | Number | `{{意图识别.confidence}}` |
| `n4_emotion` | String | `{{意图识别.emotion}}` |
| `n_audit_reason` | String | `{{答案审核.reason}}` |

   > **注意**：`n_audit_reason` 引用了「答案审核」节点的输出。首次配置时答案审核节点可能尚未创建，变量引用可能显示为红色，创建后会自动关联。

4. **粘贴代码**：

```python
async def main(args: Args) -> Output:
    params = args.params
    n4_intent = params.get('n4_intent', '')
    n4_confidence = params.get('n4_confidence', 0)
    n4_emotion = params.get('n4_emotion', 'neutral')
    n_audit_reason = params.get('n_audit_reason', '')

    # 意图中文映射
    intent_map = {
        'product_info': '产品咨询',
        'order_logistics': '订单物流',
        'after_sale': '售后服务',
        'non_service': '非客服问题'
    }

    # 如果答案审核已执行（有审核原因），使用审核原因
    if n_audit_reason:
        reason = '答案审核不通过（' + n_audit_reason + '），已重试仍不通过，需人工处理'
    elif n4_emotion in ('angry', 'frustrated'):
        emotion_map = {'angry': '愤怒', 'frustrated': '不满'}
        reason = '用户情绪' + emotion_map.get(n4_emotion, n4_emotion) + '，需人工安抚'
    elif n4_intent == 'non_service':
        reason = '非客服问题，无法自动处理'
    else:
        intent_cn = intent_map.get(n4_intent, n4_intent)
        reason = intent_cn + '问题，置信度过低（' + str(n4_confidence) + '），需人工处理'

    ret: Output = {
        "transfer_reason": reason
    }
    return ret
```

5. **确认输出参数**：
   - `transfer_reason`（String）

### 节点 12：重试判断（代码节点）

> **v1.2 变更**：去掉自引用，改用会话变量 retry_count 计数。流程开始时重置计数，每次审核不通过 +1，超过阈值不再重试。

**创建方式**：点击画布空白处 → 选择**「代码」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `重试判断`

2. **选择语言**：Python

3. **添加输入参数**（共 2 个）：

| 参数名 | 类型 | 变量引用 | 说明 |
|-------|------|---------|------|
| `approved` | Boolean | `{{答案审核.approved}}` | 审核是否通过 |
| `retry_count` | Number | 会话变量 `retry_count` | 当前重试次数 |

   > **v1.2 重要变更**：不再引用自身输出 `is_retry`，改为读取会话变量 `retry_count`。会话变量在第三步已创建。

4. **粘贴代码**：

```python
async def main(args: Args) -> Output:
    params = args.params
    approved = params.get('approved', False)
    retry_count = params.get('retry_count', 0)

    # 最大重试次数
    MAX_RETRY = 1

    # 审核通过，不需要重试，重置计数
    if approved:
        ret: Output = {
            "need_retry": False,
            "retry_count_out": 0
        }
        return ret

    # 审核不通过，判断是否还有重试次数
    if retry_count < MAX_RETRY:
        ret: Output = {
            "need_retry": True,
            "retry_count_out": retry_count + 1
        }
        return ret

    # 已达最大重试次数，不再重试
    ret: Output = {
        "need_retry": False,
        "retry_count_out": retry_count
    }
    return ret
```

5. **确认输出参数**：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| `need_retry` | Boolean | 是否需要重新生成答案 |
| `retry_count_out` | Number | 更新后的重试次数（需写回会话变量） |

6. **写回会话变量**：
   - 在节点配置面板中，找到**「变量赋值」**或**「会话变量写入」**配置

     - 目标变量：会话变量 `retry_count`
     - 赋值来源：`{{重试判断.retry_count_out}}`

   > **说明**：如果 Coze 代码节点不支持直接写回会话变量，可去掉代码中的 retry_count_out，改为在「满意度判断」选择器的重试分支中，用「变量赋值」节点将 retry_count + 1 后写回。

### 节点 13：满意度判断（选择器节点）

> **v1.2 变更**：分支条件适配新的重试判断输出（need_retry 不再依赖自引用的 is_retry）。

**创建方式**：点击画布空白处 → 选择**「选择器」**节点 → 拖入画布

**步骤**：

1. **重命名节点**：改为 `满意度判断`

2. **配置分支条件**：

   **分支 1**（审核通过 + 有知识库支撑 → 直接回复）：
   - 条件组合模式：**AND**
   - 条件 A：
     - 左值：`{{答案审核.approved}}`
     - 运算符：**等于（==）**
     - 右值：`true`
   - 条件 B：
     - 左值：`{{命中判断.has_knowledge_hit}}`
     - 运算符：**等于（==）**
     - 右值：`true`

   **分支 2**（审核不通过 + 需要重试 → 重新生成答案）：
   - 条件组合模式：**AND**
   - 条件 A：
     - 左值：`{{重试判断.need_retry}}`
     - 运算符：**等于（==）**
     - 右值：`true`
   - 条件 B：
     - 左值：`{{答案审核.approved}}`
     - 运算符：**等于（==）**
     - 右值：`false`

   **分支 3**（审核不通过 + 无需重试 → 引导人工）：
   - 条件：
     - 左值：`{{重试判断.need_retry}}`
     - 运算符：**等于（==）**
     - 右值：`false`

   **否则分支**（兜底 → 引导人工）：
   - 默认已存在

> **重试机制说明**：
> 1. 审核不通过 → 重试判断检查 retry_count
> 2. retry_count < 1 → need_retry = true → 回到答案生成（此时 revision_hint 有值，指导修订）
> 3. 答案生成 → 答案审核 → 命中判断 → 重试判断（retry_count 已 +1）
> 4. retry_count >= 1 → need_retry = false → 走转人工路径
> 5. **最多重试 1 次，防止无限循环**

## 常见问题解答

### Q1：为什么 v1.2 缓存不再直接返回答案？

v1.1 中缓存硬编码答案，容易与知识库内容不一致。例如运费政策：
- 缓存写"偏远地区（新疆/西藏/内蒙古）运费15元"
- 知识库更新后写"偏远地区（新疆/西藏/内蒙古/青海/甘肃）运费15元"

v1.2 改为 `boost_query` 方式：缓存只提供增强查询词，命中后走知识库检索，返回的知识库内容始终是最新且一致的。代价是多走一次知识库检索（约增加200ms延迟），但保证了准确性。

---

### Q2：会话变量 retry_count 在哪里创建？

在对话流编辑器中：
1. 点击左侧或顶部的**「变量」**面板
2. 切换到**「会话变量」**标签
3. 点击**「添加变量」**，创建 `retry_count`（Number，默认值 0）

---

### Q3：Coze 代码节点如何写回会话变量？

有两种方式：

**方式 A（推荐）**：代码节点输出变量 + 节点配置面板的变量赋值
1. 代码节点输出 `retry_count_out`
2. 在节点配置面板找到「变量赋值」区域
3. 添加规则：会话变量 `retry_count` ← `{{重试判断.retry_count_out}}`

**方式 B**：在选择器分支后插入「变量赋值」节点
1. 在满意度判断的重试分支后，插入一个变量赋值节点
2. 赋值：`retry_count` ← `retry_count + 1`

如果方式 A 不可用，使用方式 B。

---

### Q4：意图分类为什么从2类恢复为4类？

v1.1 将所有客服问题统一为 `product_inquiry`，导致：
- 用户问物流问题和退货问题走同一个知识库检索，检索方向性差
- 后续扩展困难（如想对物流和售后用不同知识库或不同回答策略）

v1.2 恢复为 product_info / order_logistics / after_sale / non_service 4类：
- 知识库检索时，key_info 提取的词更有针对性
- 后续可以按意图选择不同知识库
- 分支路由可以做差异化处理

---

### Q5：负面情绪分支为什么要放在意图分支之前？

因为负面情绪需要优先处理。即使用户问的是产品问题（intent=product_info），但如果情绪为 angry，应该先安抚再转人工，而不是按正常流程自动回答。

顺序逻辑：
1. 先排除非客服问题（non_service）
2. 再检查负面情绪（angry/frustrated）→ 安抚 + 转人工
3. 再检查低置信度 → 追问
4. 最后按细分意图走正常流程

---

### Q6：短输入检测的阈值为什么是3个字符？

经验值。3个字符以下的中文输入（如"价格"、"退货"、"发货"）通常意图不够明确：
- "价格" → 不知道问哪个商品
- "退货" → 不知道什么商品、什么原因
- "那个呢" → 指代不明

但"怎么退货"（4字符）已经足够明确，应正常进入意图识别。

如果发现 3 字符阈值过于严格或宽松，可在代码中调整 `len(question) <= 3` 的数值。

---

### Q7：答案审核的 revision_hint 如何传递给重试的答案生成？

数据流路径：
1. 答案审核输出 `revision_hint`（如"回答中提到的退货天数与知识库不一致"）
2. 审核不通过 → 满意度判断分支2 → 回到答案生成
3. 答案生成的输入参数 `revision_hint` 引用 `{{答案审核.revision_hint}}`
4. 答案生成的系统提示词中包含 `{{revision_hint}}` 变量
5. 模型看到修改建议，针对性地修订回答

> **关键**：Coze 对话流中，重试回到答案生成时，答案审核的上一次输出变量仍然可用（同一轮次内变量保持），所以 revision_hint 可以正确传递。

## 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 知识库检索无结果 | 知识库未绑定或内容为空 | 检查知识库检索节点，确认已勾选知识库并上传了文档 |
| 意图识别结果不准确 | 模型选择错误或温度过高 | 确认使用豆包 Lite 7B，温度设为 0.1 |
| 回复内容编造信息 | 知识库内容不足 | 补充知识库文档，检查答案生成 Prompt 中的约束 |
| 变量引用显示红色 | 引用的节点尚未创建 | 先完成所有节点创建，变量会自动关联 |
| 缓存命中但答案不对 | boost_query 与知识库不匹配 | 检查 boost_query 关键词是否覆盖知识库中的核心词 |
| 短输入引导不触发 | 阈值设错或 isalpha 判断问题 | 检查短输入检测代码，确认输入不含空格/标点时才触发 |
| 重试计数不重置 | 会话变量未正确写回 | 检查重置重试计数节点的变量赋值配置 |
| 重试无限循环 | retry_count 未递增或阈值过大 | 检查重试判断代码，确认 MAX_RETRY = 1 |
| 情绪分支不触发 | emotion 字段未正确输出 | 检查意图识别 prompt，确认 emotion 在 JSON 样例中 |
| 选择器分支未触发 | 条件值类型不匹配 | 确认条件值的类型（String/Boolean/Number）与变量类型一致 |
| 流式输出不生效 | 结束节点配置错误 | 确认结束节点为"返回文本"模式，流式输出已开启 |
| 进度反馈出现在对话历史中 | 会话历史写入未关闭 | 确认进度反馈和联系方式引导节点的"会话历史写入"设为"不写入" |
| 联系方式引导中变量为空 | 转接原因生成未执行 | 检查连线，确认转接原因生成在联系方式引导之前 |
