# Coze 扣子 AI 客服（通用电商场景）详细设计方案

## 摘要

基于 Coze 扣子平台对话流（Chatflow）能力，设计一套通用电商 AI 客服系统的完整方案。输出为 Markdown 文档，包含 Mermaid 流程图、10 个核心节点的详细配置（输入/输出/工具/知识库/Prompt/代码片段）、知识库分类方案，以及各节点配置校验清单。

## 实施计划

### 步骤 1：创建 Markdown 文档框架

**文件**：`/workspace/coze_ai_customer_service_detail.md`

创建文档骨架，包含以下章节：
1. 项目概述（背景、目标、技术选型）
2. 整体流程设计（Mermaid 流程图 + 流程说明）
3. 知识库分类与设计
4. 各节点详细配置（N1-N10，每个节点独立章节）
5. 节点配置校验清单
6. 进阶优化策略

### 步骤 2：编写 Mermaid 流程图

在文档中嵌入 Mermaid 流程图，展示：
- 主流程（用户输入 → 意图识别 → 分支路由 → 知识库检索 → 答案生成 → 审核 → 输出）
- 分支路径（转人工、直接回复、免容回复）
- 节点间的数据流向

使用 `flowchart TD` 语法，包含条件判断菱形节点和不同颜色的路径标注。

### 步骤 3：设计知识库分类方案

针对通用电商场景，设计知识库分类体系：
- **产品知识库**：商品信息、功能介绍、规格参数
- **FAQ 知识库**：常见问题与标准答案
- **订单/物流知识库**：查询、退换货、配送政策
- **售后政策知识库**：保修、投诉、赔偿规则
- **营销活动知识库**：优惠活动、优惠券、促销规则

说明每个知识库的内容规范、更新策略、以及在 Coze 中的配置方式（搜索策略、召回数量、最小匹配度等）。

### 步骤 4：编写各节点详细配置（N1-N10）

每个节点包含以下配置项：

#### N1 开始节点
- Coze 节点类型：开始节点（对话流模式）
- 预置参数：`USER_INPUT`（String，必选）、`CONVERSATION_NAME`（String，必选）
- 自定义参数：`channel`（String，可选）、`attachment`（File，可选）
- 校验点：确认对话流模式下预置参数不可删除

#### N2 会话上下文加载
- Coze 节点类型：查询会话历史节点
- 输入：`conversationName`（引用 CONVERSATION_NAME）、`rounds`（固定值 5）
- 输出：`messageList`（Array，含 role 和 content）
- 校验点：rounds 不超过 30 轮限制

#### N3 意图识别
- Coze 节点类型：大模型节点（LLM）
- 配置：开启会话历史、输出格式 JSON
- Prompt：意图分类体系（产品咨询/订单查询/物流查询/售后退换/投诉建议/营销活动/非客服）
- 输出：intent、confidence、key_info
- 校验点：JSON 输出格式需导入样例、模型需支持 Function Call

#### N4 分支路由
- Coze 节点类型：选择器节点
- 条件分支：基于 intent 和 confidence 的多条件组合（AND/OR）
- 6 条分支路径对应不同业务场景 + 1 条兜底转人工
- 校验点：分支优先级拖拽排序、否则分支兜底

#### N5 知识库检索
- Coze 节点类型：知识库检索节点
- 输入：Query（引用 USER_INPUT + key_info 组合）
- 知识库配置：搜索策略（语义/混合）、最大召回 5 条、最小匹配度 0.5、开启查询改写
- 开启会话历史辅助检索
- 输出：`outputList`（Array，含 output 和 documentId）
- 校验点：火山知识库和扣子知识库不可混用

#### N6 答案生成
- Coze 节点类型：大模型节点（LLM）
- 输入：question、retrieval_results、intent、conversation_history
- Prompt：严格基于知识库回答、友好语气、300字限制
- 输出格式：文本
- 校验点：系统提示词 + 用户提示词分离配置

#### N7 答案审核
- Coze 节点类型：大模型节点（LLM）
- 输入：question、answer、retrieval_results
- Prompt：四维度审核（准确性/安全性/规范性/完整性）
- 输出格式：JSON（approved、reason）
- 校验点：审核不通过时异常处理配置

#### N8 满意度判断
- Coze 节点类型：选择器节点
- 条件：approved + confidence_source 组合判断
- 校验点：确保所有路径都有下游节点

#### N9 人工转接
- Coze 节点类型：插件节点（HTTP Request）或代码节点
- 输入：user_id、question、intent、conversation_history、transfer_reason
- 功能：推送工单 + 发送兜底消息
- 校验点：超时配置、重试策略、异常处理

#### N10 回复输出
- Coze 节点类型：结束节点（返回文本模式）
- 配置：开启流式输出
- 输入：final_answer（引用 N6 或 N9 输出）
- 校验点：流式输出仅在大模型节点后生效

### 步骤 5：编写节点配置校验清单

- 性能优化：并行执行、缓存策略
- 知识库运营：内容规范、更新流程、Bad Case 分析
- 扩展能力：多语言、工单系统、数据统计、子流程模块化
- 效果评估指标体系

## 假设与决策

1. **技术选型**：使用对话流（Chatflow）而非工作流（Workflow），因为需要会话历史和多渠道发布
2. **模型选择**：默认使用豆包大模型（7B+），中文理解效果好
3. **知识库类型**：使用扣子知识库（非火山知识库），配置更灵活
4. **转人工方式**：使用 HTTP 插件调用企业工单系统 Webhook
5. **流程图语法**：使用 Mermaid flowchart TD，确保主流 Markdown 渲染器兼容

3. 验证变量引用语法（`{{}}` 格式）在所有节点间传递是否正确
4. 确认知识库分类方案覆盖电商客服主要场景
