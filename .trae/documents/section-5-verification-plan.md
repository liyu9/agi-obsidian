### 2. 生成校验主清单

**文件**：`c:\Users\admin\.trae-cn\work\6a44a581dba843d71f7d8eb0\云端Agent记忆系统_表格校验清单.md`

**改什么**：逐格记录 312 条校验结果，按表分节。

**为什么**：用户明确要求「每个表的结果都需要校验」；逐格记录保证覆盖率、可追溯，并支持后续差异分析。

**怎么做**：

- 三层判定：
  - **L1 方向一致性**：`PASS_DIR` / `FAIL_DIR` / `INSUFFICIENT_DATA`。
  - **L2 摘要事实相符**：`PASS_SUM` / `PARTIAL_SUM` / `INSUFFICIENT_DATA`。

- 证据要求（关键）：

  - 每条 `PARTIAL_SUM` 至少 1 条 P0/P1 + 1 条其他等级来源，且明确指出差异点。

- 记录字段：`table / row_id / product / cell_symbol / cell_summary / evidence_refs(≥1) / L1 / L2 / L3 / issue_note / next_step`。
- 呈现：每张表一张 Markdown 对照表，列头 `行 | 产品 | 原符号 | 原摘要 | 一手证据 | L1 | L2 | (L3) | 备注`。
- `INSUFFICIENT_DATA` 模板：

```
[INSUFFICIENT DATA]
- 缺失项：<产品>·<能力名>·<原摘要>
- 已尝试的检索：<关键词1 / 关键词2 / 站点检索 site:xxx>

  1) 尝试 GitHub Issues / Discussions 搜索该能力关键词
  2) 联系产品社区（Discord / Slack）确认
```

**验证**：条目数 = 312；FAIL / PARTIAL 引用 ≥ 2 条独立 P0/P1；INSUFFICIENT_DATA 字段齐备。

## Assumptions & Decisions

1. **一手来源优先，禁止用同一二手来源多次「交叉」**。P0 优先于 P1，P1 优先于 P2；不使用未署名自媒体。
2. **粒度差异不算冲突**。§6 与 §5.0 表 A 存在父子关系；只有父 ❌ 与子 ✅（或反之）才算 `FAIL_CROSS`。
3. **`✅✅` 视为「✅ 且业界最强 / 独占」**，L1 等价 ✅。
4. **同一工具 + 同一参数不重复调用**（研究守则）。若首次检索失败，须改关键词、换检索通道，而不是重试。
5. **一份总清单 + 按产品分节**，不为 4 款产品各出独立清单。
6. **只标注问题、不给修订文案**。修订留待用户后续授权。
7. **产物存放于工作目录**，不进入用户工作区；若用户后续要归档，再复制到 `.trae/documents/`。
8. **搜索深度分层**：先 broad sweep（关键词 + site:官方），再 refine（版本号 + 具体能力），再 adjacent（GitHub Issues + Discord + 论文）。
9. **Cognee 的证据密度可能低于其他 3 款**，属正常；INSUFFICIENT_DATA 占比偏高不视为校验失败，但需在下一步中给出确切的检索路径。
