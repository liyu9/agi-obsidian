1. **读**：单文件 Read，限 ≤ 250 行/次（如超 250 行分两次读）。

5. **写回**：原子写入（先写 `*.md.tmp`，再 rename）。

## 九、上下文管理策略

### 9.1 单次 LLM 调用输入预算

| 输入项 | 字节预算 | 说明 |
|--------|---------|------|
| 风格锚点（2.4） | 9.4K | 必带，固定 |
| 重写规范（rewrite_spec） | 2-3K | 必带，固定 |
| 当前待改文件 | 5-15K | 单次仅加载 1 个 |
| 跨章术语表（glossary） | 1-2K | 必带 |
| 章节上下文（仅本章说明时） | 5-30K | 改 `_本章说明.md` 时才带 |
| 改写指令 prompt 本身 | 1-2K | 必带 |
| **合计（典型）** | **~20-25K 字节** | **约 8-10K tokens** |

**总输入预算 ≤ 25K 字节（约 10K tokens）**，留出充足输出空间。

### 9.2 分片读取策略

| 场景 | 策略 |
|------|------|
| 单文件 ≤ 250 行 | 一次性 Read |
| 单文件 250-500 行 | Read 两次（先 1-250，再 251-500） |
| 单文件 500-800 行 | Read 三次，分块改写后合并（仅 8.3 适用） |
| 章节说明文件 | Read 一次，但需要附带"本章节 4 个正文文件的路径"作为 LLM 输出参考 |

### 9.3 防上下文丢失的 3 道防线

**防线 1：每文件独立上下文**
- 不一次性把整章加载到 LLM
- 改 A 文件时，LLM 上下文里只有 A 文件 + 锚点 + 规范，不看 B/C/D

**防线 2：风格锚点必带**
- 2.4 样章在每个文件改写时**必带**（避免风格漂移）
- 不在 LLM 上下文中压缩/省略

**防线 3：每章完成 50% 时做对齐回扫**
- 已完成文件加入"本章节已确认样本"清单
- 后续文件改写时同时加载 1-2 个已完成样本做风格对齐

### 9.4 输出限制

- 单文件输出目标 5-10K 字节（约 2-4K tokens 输出）
- 8.3 例外：可到 12-15K 字节
- 超出 → 触发"内容溢出" 校验，强制拆分

## 十二、资源冲突处理

### 12.1 写入冲突

- **现状**：6 个章节位于不同子目录，无写入路径重叠
- **对策**：
  - 并行 Worker 按章节分目录写入
  - 同一 Worker 内串行处理（避免同一文件被并发改写）
  - 写入前检查文件 mtime，确认未被外部修改

### 12.2 LLM 上下文冲突

- **对策**：
  - 并行 Worker 使用独立 LLM 会话（或独立上下文）
  - 不共享 prompt history
  - 阶段 5 跨章校验时，才把所有 36 文件加载到统一上下文

### 12.3 备份目录冲突

- **对策**：
  - `.bak` 与原文件同目录
  - 命名格式 `*.md.bak.{chapter}.{seq}`（如 `2.1-高价值场景识别.md.bak.ch2.001`）
  - 阶段 5 结束后统一归档到 `99-原始资源索引/_backup_2026-06-24/`

### 12.4 阶段衔接冲突

- **第二章试点**结果如未通过 → 暂停后续阶段，回到阶段 0 调整 `rewrite_spec.md`
- **第三章失败** → 第四章继续推进（独立章节，不阻塞）
- **第八章失败** → 独立回滚，不影响前 5 章
