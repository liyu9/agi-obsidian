### 2.3 §5 需解决的 4 个具体缺陷

**D1 · §5.x 与 §3 5 道题未打通**
- §3 5 条问题（多 Agent 共享 / 四层分级 / 三级隔离 / 企业治理 / 可观测）在 §5.x 里没有明确"该产品对这 5 条的作答"，读者需要自行从表格提取
- 结果：无法快速判断"哪个产品能覆盖哪几个业务问题"

**D2 · §5.x.3 能力映射与 §5.0 完全同构**
- §5.1.3 / §5.2.3 / §5.3.3 / §5.4.3 都是把 §5.0 表格里那一列文字化再念一遍
- 没有增值信息（如版本、场景边界、二手补充材料的旁证）
- 应改成「§5.0 已经给了结论，§5.x.3 给证据 + 差异化细节 + 版本时间」

**D3 · 一手来源与主档 fact 之间没有行内 anchor**
- 主档写「Mem0 有 SOC 2 Type 1 + HIPAA」但没标注哪条 URL；读者只能从附录 A 里翻
- 应在关键 fact 后加短 `[^ov5]` 或 `[docs.mem0.ai](url)` 直链

**D4 · 缺 INSUFFICIENT_DATA 明示**
- 一些字段（如 Letta 是否公开 P95 / Cognee ACL 迭代频度）我在上一轮已发现"官方未公开"，但主档里表现为普通结论
- 应显式标 `INSUFFICIENT_DATA / 未公开`，避免读者当作已知事实

### 2.4 主档缺少 §5.5「调研执行方法与限制」

- 现状没有一节说明"调研以什么口径、什么来源等级、什么截止日期完成"
- 结果：后续复核时无法判断"上次调研做了什么、没做什么"
- 应新增 §5.5，记录：来源分级、覆盖清单、检索时间、未覆盖项、复核建议

    - 多 Agent 共享：✅ HTTP + Python/Go SDK；`agent/user/team/resource` 分级目录天然可共享 [\[Concepts 11 Multi-tenant\]](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/11-multi-tenant.md)
    - 四层分级：✅ L0/L1/L2 + 目录分层可承载短期/工作/长期/归档四层 [\[Concepts 03 Context Layers\]](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/03-context-layers.md)
    - 三级隔离：⚠️ 目录级承载三级，但企业 ACL 需自建 [\[Concepts 11\]]()
    - 企业治理：⚠️ 加密 + KMS + 租户密钥，但无 SOC 2/HIPAA 公开认证 `INSUFFICIENT_DATA`

  - `.5` 差异化：唯一提供"文件系统式抽象 + 多语言 SDK + 官方 Prometheus 指标"的开源候选；短板是 ACL 与合规资质需自建

**保留**：§5.0 总览 4 张表不动（已经在上一轮"落地"里校验过）。

### 3.3 主档新增 §5.5「调研执行方法与限制」

- **What**：在 §5.4 之后、§6 之前，新增 §5.5，包含 5 个子项：
  1. **来源分级方法**：P0 官方仓库/文档 / P1 官方博客/论文 / P2 二手权威（如企业级评测） / P3 社区

  3. **一手引用位置**：主档 §5.x.4 5 道题的证据直链、附录 A 全量 URL
  4. **未覆盖项 / 已知局限**：
     - 未做压测；性能数据依赖官方公开值
     - 未在真实 2000 人环境部署，无真实 P95 数据
     - 4 款开源候选版本号截止 2026-07-01；后续版本可能补齐 SOC 2 等
  5. **复核建议**：新主版本发布后 30 天内复核 §5 对应章节
- **Why**：满足"文档质量保障"需求 —— 让后续读者能判断报告的可信边界与更新时机
