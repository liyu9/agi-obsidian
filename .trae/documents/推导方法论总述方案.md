- 因此本次任务**只输出对话内容**，不写任何 `.md` 文件（除本 plan 文件外）

- 用户确认"还要覆盖 multi-agent 上下文、上下游边界、交付物门检"
- 3 块均为新增内容，原 3-推导过程.md 未涉及

### 决策 3：长度采用"中等版（500-800 字，5-7 张表）"

- 用户已选"中等版"
- 实际规划为 ~630 字 + 6 张表（接近上界但不溢出）

### 决策 4：multi-agent 上下文默认 4 Agent 划分

- 假设常见划分：市场研究 Agent / 产品规划 Agent / 功能详述 Agent / 文档质检 Agent
- 此划分与"multi-agent"目录命名契合，且覆盖了 4 步法每个步骤的主执行者
- 如用户所属团队的 Agent 划分不同，可后续调整

### 决策 5：上下游边界默认 5 阶段链

- 假设完整链路：BRD → MRD → PRD → Spec → TestCase
- 推导起点 = MRD（可上溯到 BRD），推导终点 = PRD（可下推到 Spec）
- 明确"PRD 不是 Spec"、"TestCase 由 QA 负责，本方法论不涉及"

### 决策 6：交付物门检采用 5 维评估

- 5 维：完整度 / 可追溯 / 无歧义 / 可验证 / 粒度匹配
- 每维设"通过条件 + 不通过处理"2 项
- 不通过 → 回到对应 4 步法步骤重做
