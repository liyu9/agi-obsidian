### 每节内容来源与写法

#### 导语（300 字）
- **来源**：§1.1 + §1.2
- **写法**：用 MRD→PRD 转换的实际痛点开场（6 万字 PRD / 20 子模块 / 单 Agent token 临界），点明"为什么需要多智能体"，引出报告定位

#### 1. 架构演化路径
- **来源**：§1.2（3 轮迭代表）
- **写法**：每轮用"问题→证据→解法"三段式叙事，不用表格，突出演化逻辑
  - v0→v1：通用 Agent 3 崩溃（Soul 漂移 + token 临界）→ 拆 1+3
  - v1→v2：② PRD 撰写过载（5 章节 6 万 token）→ 拆产品组+工程组
  - v2→v3：PRD5 占 54% + Soul 漂移 + 服务对象不同 → PRD5 独立

#### 2. 核心设计原则
- **来源**：§1.3（6 大原则）
- **写法**：每条原则用 2-3 句解释"为什么这条原则重要" + 1 句"v3 怎么体现"
  - Orchestrator 范式 / 三维隔离 / 上下文 < 30K / GT 驱动 / 独立验收 / 单一人类接口

#### 3. 关键架构决策
- **来源**：§9（12 条精选 8 条）
- **写法**：每条用"决策 → 备选 → 否决理由"结构
  - 选：1+5 拓扑 / ③ 独立 / Manager 无写工具 / < 30K 上下文 / Owner 唯一 / 三态邮箱 / PRD5 独立 / 章节级并发

#### 4. 角色体系
- **来源**：§2.2（7 角色表）+ §3（四层框架）
- **写法**：用拓扑图 + 每个角色 3 行职责描述（Charter 核心职责 + Soul 一句话 + 上下文约束），不逐一抄录四层框架全字段
- **重点**：三维隔离判断法在角色拆分中的应用

#### 5. 协作机制
- **来源**：§4（共享工作区 + 邮箱 + handoff）
- **写法**：用数据流图讲清楚"文件怎么流转"，三态邮箱用状态转换图

#### 6. 端到端流程
- **来源**：§5（9 阶段 SOP + 甘特图）
- **写法**：简化为流程图 + 阶段 5 并发设计的重点说明（为什么能并发 + outline 锁）

#### 7. 质量与可靠性
