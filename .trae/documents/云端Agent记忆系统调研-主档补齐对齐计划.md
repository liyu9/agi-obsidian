## 3. Proposed Changes（提议的修改）

> 全部修改**仅限主档 `云端Agent记忆系统调研报告.md`**。附录、一期方案、集成报告不动。

### 3.1 §1 业务背景 — 补真实语境

- **What**：改写 §1 内容，明确以下 5 个要素：
  - 互联网公司 **2000 人规模**
  - 云端部署 Claude Code + OpenClaw + Hermes（**多 Agent 共存**，未来还会扩展）
  - 记忆需求：**短期上下文 + 长期偏好/知识**
  - **部门粒度隔离**（每部门独立 Agent）+ **个人粒度隔离**（每人独立 Agent）+ **数据不跨越**
  - 参考 OpenViking 的向量存储 + 分级记录设计模式
- **Why**：主档 §1 需要与用户历史对话确认的产品背景严丝合缝，否则后续所有选型逻辑失去锚点
- **How**：3 段式改写（当前痛点 → 目标形态 → 参考模式）

### 3.2 §2 典型用户 — 改成"云 Agent 平台的使用与运营方"两侧

- **What**：把当前 3 类角色（研发/产品/管理者）改成 2 侧视角：
  - **A 侧：Agent 使用者**（2000 名员工，通过 Claude Code / OpenClaw / Hermes 消费记忆系统）
  - **B 侧：云 Agent 平台运营方**（负责记忆库部署、隔离、合规、可观测的团队）
- **Why**：用户提到"云 agent 平台，部署各类 agent"——运营方是隐藏的关键用户，需要在文档里明确
- **How**：保留原有的员工使用场景描述，增加"平台运营方"一段

### 3.3 §3 要解决的问题 — 5 条对齐 2000 人 + 多 Agent + 隔离

- **What**：在现有 5 条问题基础上，把用词与 §1 新语境对齐：
  1. **多 Agent 之间的偏好 / 知识 / 项目上下文共享**（Claude Code 写、OpenClaw 读）
  2. **短期 / 工作 / 长期 / 归档 四层分级**（对齐 §4.1 组成层次）
  3. **部门级 / 个人级 / 会话级 三级隔离**（把原 "四级" 明确说清楚）
  4. **企业级治理**：ACL / 审计 / 加密 / 数据驻留 / 删除权
  5. **可观测**：命中率 / 污染率 / 延迟 / 成本
- **Why**：主档 §3 需要与后续 §4.4 8 项能力形成"问题 → 能力"一一对应
- **How**：修改现有 5 条，语义对齐，不改条数
