# 产品设计方法论驱动项目文档化

基于产品设计知识框架，用结构化10步流程追问项目信息，产出完整、逻辑自洽的项目分析文档。

## 核心原则

不是套模板填空，而是用框架的每个问题去"逼问"项目的真实逻辑。框架问"问什么"，项目答"是什么"，SOP确保每个问题都被问到、每个答案都有数据支撑、不同角色的答案之间不矛盾。

## 输入输出规格

### 输入（3要素）

| 输入 | 说明 | 示例 |
|------|------|------|
| 方法论文档 | 指导项目设计的知识框架（可选，默认使用内置方法论） | 产品设计核心知识总结.md |
| 项目原始资料 | 未经结构化整理的项目信息 | 问题列表、方案描述、指标、经验教训等 |
| 互联网行业信息 | 搜索补充竞品/行业数据 | 网易七鱼、行业报告数据 |

### 输出

结构化项目分析文档，包含10个章节：
1. 多角色痛点梳理
2. 需求验证（三步法）
3. 用户问题说明
4. 先拓展再专注
5. 用户画像
6. 底层需求洞察
7. 产品定义（使命宣言+原则+MVP）
8. 成功指标+反指标（含量化阈值）
9. 优先级与"一定不优先"
10. 行业对标与数据验证

## 执行流程（5阶段）

### 阶段1：前置准备 — 收集项目原始信息

整理项目的"硬事实"作为后续分析锚点：
- 项目名称、企业规模、核心描述
- 关键技术方案、核心成果数据

> 只整理事实，不做分析。成果数据先列出来，后面分析时会逐个追问它对应什么方法论。

### 阶段2：10步分析

按 `references/sop.md` 执行10步分析流程。每步包含"做什么+关键追问+产出格式"，方法论细节查阅对应参考文件：

| 步骤 | 主题 | 方法论参考 |
|------|------|-----------|
| 1 | 多角色痛点梳理 | `01-用户需求与痛点验证.md`、`05-功能优化步骤.md` |
| 2 | 需求验证（三步法） | `01-用户需求与痛点验证.md` |
| 3 | 用户问题说明 | `02-目标客户与用户画像.md` |
| 4 | 先拓展再专注 | `02-目标客户与用户画像.md` |
| 5 | 用户画像 | `02-目标客户与用户画像.md` |
| 6 | 底层需求洞察 | `01-用户需求与痛点验证.md`、`02-目标客户与用户画像.md` |
| 7 | 产品定义 | `04-用例与最小化可行产品MVP.md`、`06-项目成果与验证.md` |
| 8 | 成功指标+反指标 | `03-产品成功指标与反指标.md`、`06-项目成果与验证.md` |
| 9 | 优先级与"一定不优先" | `05-功能优化步骤.md` |
| 10 | 行业对标与数据验证 | `06-项目成果与验证.md` |

核心检查：每步产出是否能回溯到方法论？

### 阶段3：互联网搜索补充

阶段2识别出缺失环节时，搜索补充：
- 竞品产品能力与数据（如"网易七鱼智能客服解决率"）
- 行业基准数据（如"AI客服FCR行业均值"）
- 大厂实践与踩坑（如"腾讯赛马机制治理"）

搜索策略：关键词 = 场景 + 竞品名/行业名 + 核心指标名

### 阶段4：自检清单

分析完成后逐项检查（详见 `references/sop.md`）：

- [ ] 痛点是否覆盖企业/业务/技术/管理至少3个层面？
- [ ] 每个痛点是否有行业数据交叉验证？
- [ ] 用户画像是否包含"非典型用户"（如后端工程师、IT管理者）？
- [ ] 底层需求是否用一句话统一了所有P0角色的诉求？
- [ ] MVP是否同时满足了所有P0角色的核心需求？
- [ ] 反指标是否有明确的量化阈值和触发动作？
- [ ] 优先级表是否覆盖了所有P0角色必需的功能？
- [ ] "一定不优先"板块是否列出了3条以上明确不做的事项？
- [ ] 行业数据能否佐证至少一半以上的痛点假设？
- [ ] 大厂实践的每个启示是否对应到项目的一个具体决策？

### 阶段5：文档输出

按方法论框架组织完整项目分析文档，必须包含以下章节：

1. 需求验证（三步法）
2. 方案设计/产品定义（含MVP两阶段）
3. 指标体系（4步法+反指标含量化阈值+PMF判断标准）
4. 行业对标与差距分析
5. 迭代经验与教训
6. 后续规划（P0/P1/P2+"一定不优先"）

## 实战共性经验

项目原始资料一定缺这些——主动补充：

| 缺失项 | 说明 | 补充动作 |
|--------|------|---------|
| 反指标 | 项目方很少主动提反指标 | 补充量化安全阈值+降级策略 |
| 行业对标 | 项目方只关注自身 | 搜索竞品数据和差距分析 |
| "一定不优先" | 项目方倾向于什么都做 | 明确划定不做的事 |
| 迭代经验 | 原始资料往往只有"做对了什么" | 追问"做错了什么、为什么" |
| 非典型用户画像 | 容易遗漏关键角色 | 多角色痛点扫描时主动寻找"必须先过"的角色 |
| 指标权衡机制 | 只列指标不列优先级 | 明确 安全>质量>增长 的权衡顺序 |
| PMF判断标准 | 只说"效果不错"没有量化 | 补充PMF量化临界点 |
