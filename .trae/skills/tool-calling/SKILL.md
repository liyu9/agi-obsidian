# 智能工具调用与协同

## 核心能力

本 Skill 赋予 Agent 类似豆包 APP 的"工具调用"能力，支持：
- **智能工具选择**：根据任务类型自动选择最优工具
- **工具编排**：组合多个工具完成复杂任务
- **参数优化**：自动构造最优的工具调用参数
- **结果聚合**：整合多工具输出为统一结果

## 工具分类体系

```
┌─────────────────────────────────────────────────────────────────┐
│  工具层级架构（类似豆包的工具生态）                              │
├─────────────────────────────────────────────────────────────────┤
│  L1 基础工具 │ 文件读写、代码搜索、命令执行        │ 毫秒级响应 │
│  L2 专业工具 │ 代码生成、调试、测试执行            │ 标准响应   │
│  L3 复合工具 │ 项目构建、部署、跨工具协同          │ 多轮执行   │
│  L4 Agent级  │ 复杂任务编排、自主决策、深度研究    │ 迭代优化   │
└─────────────────────────────────────────────────────────────────┘
```

### 工具编排示例

**场景：代码重构任务**

```
用户：帮我重构这个项目的用户认证模块

工具调用序列：
───────────────────────────────────────────────────────────────

Step 1: 代码分析
  工具: glob
  参数: pattern="**/*auth*.{ts,js}"
  结果: 找到 5 个相关文件
  
Step 2: 读取代码
  工具: read
  参数: file_path="src/auth/login.ts"
  结果: 获取文件内容

Step 3: 依赖分析
  工具: grep
  参数: pattern="import.*from.*auth"
  结果: 找到 12 处依赖

Step 4: 代码重构
  工具: write/edit
  参数: {file, old_code, new_code}
  结果: 完成代码修改

Step 5: 验证测试
  工具: RunCommand
  参数: command="npm test -- --grep auth"
  结果: 全部测试通过
```

## 多工具协同策略

### 并行调用

当工具之间无依赖时，可并行执行：

```
┌─────────────────────────────────────────────────────────────┐
│  并行调用场景                                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  任务：同时获取多个文件的信息                                 │
│                                                             │
│  工具A: read(file="config.json")    ─┐                     │
│  工具B: read(file="package.json")   ─┼─→ 结果聚合 → 输出    │
│  工具C: read(file="tsconfig.json")  ─┘                     │
│                                                             │
│  优势：减少总执行时间                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 串行调用

当工具之间有依赖时，必须串行执行：

```
┌─────────────────────────────────────────────────────────────┐
│  串行调用场景                                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  任务：基于搜索结果进行深入分析                               │
│                                                             │
│  工具A: SearchCodebase(query="用户认证") → 获取文件列表      │
│       ↓                                                     │
│  工具B: read(file=工具A.结果[0])       → 读取第一个文件       │
│       ↓                                                     │
│  工具C: read(file=工具A.结果[1])       → 读取第二个文件       │
│       ↓                                                     │
│  工具D: 分析整合所有文件              → 生成分析报告          │
│                                                             │
│  优势：确保数据依赖正确                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 条件调用

根据中间结果决定后续工具：

```
┌─────────────────────────────────────────────────────────────┐
│  条件调用逻辑                                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  工具A: SearchCodebase → 获取搜索结果                        │
│       ↓                                                     │
│  判断: 结果数量 > 0 ?                                        │
│       ├─ YES → 继续分析                                     │
│       └─ NO  → 尝试其他搜索策略                             │
│       ↓                                                     │
│  工具B: 深入分析（如果条件满足）                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 工具调用最佳实践

### 1. 最小化调用原则

```
✅ GOOD: 一次性读取整个目录
  工具: glob + 循环read
  次数: 1 + N次

❌ BAD: 逐个文件搜索
  工具: grep × 100次
  次数: 100次
```

### 2. 参数优化原则

```
✅ GOOD: 精确指定搜索范围
  工具: grep
  参数: {path: "src", pattern: "auth", type: "ts"}

❌ BAD: 全局搜索
  工具: grep
  参数: {pattern: "auth"}  // 范围太大
```

### 3. 错误处理原则

```
每调用工具时，必须处理：
1. 正常结果 → 继续执行
2. 空结果   → 尝试备选方案
3. 错误结果 → 记录日志 + 降级处理
```

## 配置参数

```yaml
tool_config:
  max_parallel: 3          # 最大并行调用数
  max_retries: 2          # 失败重试次数
  timeout_ms: 30000        # 单次调用超时
  show_log: true          # 是否展示调用日志
  error_handling: "retry"  # 错误处理策略
```
