# PM Skill Builder

基于本地三本PM书籍方法论和社区调研，按4步流程创建产品经理能力skill。

## 触发条件

用户提到以下意图时激活：
- "创建一个XX的skill"（XX与产品经理能力相关）
- "把XX方法论做成skill"
- "设计产品经理XX能力的skill"

## 执行流程

**目标**：找到同类型skill/框架/方法论作为参考。

|------|---------|---------|
| GitHub | `"{topic} skill/prompt/framework"` 搜索仓库和代码 | skill结构、框架模板、最佳实践 |

### Step 3: 设计创建方案并校验

**目标**：结合社区调研和本地方法论，设计skill方案，用skill-creator规则校验。

**3.1 设计方案**

方案必须包含：

```
1. skill名称与description（<200字符，含功能+触发条件）
2. 触发条件（3-5个用户意图示例）
3. 执行流程（Step分步，每步含输入/操作/输出）
4. 方法论引用策略：
   - 通用型skill → 按需Read外部文件（绝对路径）
   - 垂直型skill → 内嵌原文引用（标注来源章节）
5. 输出模板
6. 验证检查项
7. 使用示例（2-3个）
```

**3.2 校验清单**（依据skill-creator规范）

- [ ] frontmatter: name和description字段完整？
- [ ] description: 含功能说明+触发条件，<200字符？
- [ ] 结构: 有触发条件→执行流程→输出模板→验证检查项？
- [ ] 层次: 渐进式披露（骨架→详情→引用），非一坨文本？
- [ ] 示例: 至少2个使用示例？
- [ ] 引用: 本地文件路径为绝对路径？
- [ ] 行数: SKILL.md < 500行？

校验不通过则修正方案，直到全部通过。

### Step 4: 创建SKILL.md

**操作**：
1. 创建目录 `.trae/skills/<skill-name>/`
2. 写入 `SKILL.md`
3. 读取文件确认内容正确

**创建后验证**：
- [ ] 文件路径正确
- [ ] frontmatter格式无误
- [ ] 内容与方案一致
- [ ] 所有绝对路径可访问
