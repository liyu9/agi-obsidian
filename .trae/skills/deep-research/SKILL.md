# 深度研究与信息收集

## 核心能力

本 Skill 赋予 Agent 类似豆包 APP 的"边想边搜"能力，支持：
- **多轮迭代研究**：先思考再搜索，持续优化查询
- **多源信息整合**：聚合不同来源的信息
- **交叉验证**：多角度验证信息准确性
- **结构化输出**：生成可操作的研究报告

## 核心创新：边想边搜模式

```
┌─────────────────────────────────────────────────────────────────┐
│  传统模式 vs 豆包"边想边搜"模式                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  传统模式：                                                     │
│  用户输入 → 搜索网页 → 整理内容 → 输出答案                        │
│             ↓                                                   │
│        单轮搜索，信息碎片化                                      │
│                                                                 │
│  豆包"边想边搜"：                                               │
│  用户输入 → 思考推理 → 搜索验证 → 再思考 → 再搜索 → 输出答案       │
│             ↓           ↓          ↓                           │
│          多轮循环   动态优化    深度整合                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 研究流程（6步）

### Step 1: 问题理解

分析研究问题，明确：
- 核心研究目标
- 关键信息需求
- 预期输出形式

```
研究目标分析：
┌─────────────────────────────────────────────────────────────┐
│  原始问题：比较 React 和 Vue 的优劣势                         │
├─────────────────────────────────────────────────────────────┤
│  核心问题：技术选型决策支持                                    │
│  拆解子问题：                                                 │
│    1. 核心特性对比                                           │
│    2. 生态系统对比                                            │
│    3. 学习曲线对比                                            │
│    4. 适用场景分析                                           │
│    5. 社区活跃度对比                                         │
│  预期输出：技术选型建议报告                                    │
└─────────────────────────────────────────────────────────────┘
```

### Step 2: 制定研究策略

确定信息来源和搜索策略：

| 信息类型 | 来源 | 搜索策略 |
|---------|------|---------|
| 官方文档 | 官网、Docs | 精准关键词 |
| 技术博客 | Medium、掘金、CSDN | 权威作者+主题 |
| 社区讨论 | GitHub、Stack Overflow | 问题导向 |
| 最新动态 | 新闻、推特 | 时间范围筛选 |
| 数据统计 | NPM Trends、State of JS | 直接获取 |

### Step 3: 第一轮搜索

基于初始理解执行搜索：

```
第一轮搜索：
├── 搜索1: "React vs Vue 2025 comparison"
├── 搜索2: "React advantages disadvantages"
└── 搜索3: "Vue advantages disadvantages"
```

### Step 4: 分析与反思

分析搜索结果，识别信息缺口：

```
反思清单：
□ 获取了足够的技术特性信息吗？
□ 是否需要补充最新数据？
□ 是否有矛盾的观点需要验证？
□ 哪个方面还需要深入了解？

识别到的信息缺口：
❌ 缺少 2025 年的最新对比数据
❌ 缺少性能基准测试数据
❌ 需要补充团队规模适用性分析
```

### Step 5: 第二轮搜索（迭代优化）

基于反思结果执行补充搜索：

```
第二轮搜索：
├── 搜索1: "React Vue performance benchmark 2025"
├── 搜索2: "React Vue team size recommendation"
└── 搜索3: "React Vue developer experience survey 2024"
```

### Step 6: 整合与输出

整合所有信息，生成结构化报告：

```markdown
# 技术选型研究报告：React vs Vue

## 1. 研究背景
## 2. 核心对比
   - 2.1 架构设计
   - 2.2 性能表现
   - 2.3 开发体验
## 3. 生态对比
   - 3.1 库与工具链
   - 3.2 社区支持
## 4. 适用场景分析
## 5. 风险评估
## 6. 选型建议
## 7. 参考资料
```

## 多轮迭代机制

### 迭代终止条件

满足以下任一条件时终止迭代：

```
┌─────────────────────────────────────────────────────────────┐
│  迭代终止条件                                                │
├─────────────────────────────────────────────────────────────┤
│  ✅ 达到最大迭代次数（默认3轮）                              │
│  ✅ 信息饱和度 > 90%（新增信息重复率高）                      │
│  ✅ 核心问题已充分解答                                        │
│  ✅ 用户明确表示满意                                          │
└─────────────────────────────────────────────────────────────┘
```

### 迭代质量评估

每轮迭代后评估：

| 指标 | 计算方式 | 阈值 |
|------|---------|------|
| 信息增量 | 新发现/总信息量 | > 15% |
| 覆盖度 | 已解答问题/总问题 | > 80% |
| 一致性 | 观点冲突数/总观点 | < 10% |

```
┌─────────────────────────────────────────────────────────────┐
│  信息源可信度排序                                            │
├─────────────────────────────────────────────────────────────┤
│  1️⃣ 官方文档（官方、权威、可追溯）                           │

│  3️⃣ 行业报告（知名机构发布）                                │

└─────────────────────────────────────────────────────────────┘
```

## 交叉验证机制

### 三源验证原则

关键信息必须从至少3个独立来源验证：

```
验证示例：
───────────────────────────────────────────────────────────────
信息："React 的虚拟 DOM 性能优于 Vue"

来源1: 官方文档 → React 声称虚拟 DOM 优化
来源2: 技术博客 → 多个开发者实测验证
来源3: 学术论文 → JMeter 基准测试数据

验证结论：✅ 可信（3/3 源支持）
───────────────────────────────────────────────────────────────

验证示例：
───────────────────────────────────────────────────────────────
信息："Vue 3 比 React 更容易学习"

来源1: 官方文档 → Vue 文档更清晰（Vue观点）
来源2: 技术博客 → 有人认为 React 更简单（争议）
来源3: 社区讨论 → 反馈不一

验证结论：⚠️ 可信度中等（存在争议，需补充）
───────────────────────────────────────────────────────────────
```

### 矛盾信息处理

```
当多个来源信息矛盾时：
1. 识别矛盾点
2. 分析矛盾原因（立场、时间、场景不同）
3. 标注矛盾，供用户判断
4. 提供建议而非断言

示例输出：
⚠️ 信息矛盾说明：
- 来源A认为 X 优于 Y
- 来源B认为 Y 优于 X
- 原因分析：两者测试场景不同
- 建议：根据您的实际场景选择
```

## 搜索优化技巧

### 关键词策略

| 目标 | 关键词模式 | 示例 |
|------|-----------|------|
| 获取概述 | "XX vs YY comparison" | "React vs Vue comparison" |
| 获取数据 | "XX benchmark statistics" | "React Vue benchmark 2025" |
| 获取教程 | "XX tutorial getting started" | "Vue tutorial for React developers" |
| 获取问题 | "XX common problems issues" | "React common problems enterprise" |
| 获取趋势 | "XX trend 2025 future" | "Frontend framework trend 2025" |

### 时间范围筛选

| 研究目的 | 推荐时间范围 |
|---------|-------------|
| 技术对比 | 近2年 |
| 框架选型 | 近1年 |
| 工具使用 | 近6个月 |
| 最新特性 | 近3个月 |

## 豆包"边想边搜"核心差异

| 维度 | 传统研究 | 豆包"边想边搜" |
|------|---------|---------------|
| 搜索时机 | 先搜后想 | 先想后搜再想 |
| 搜索轮数 | 1轮 | 2-3轮 |
| 信息整合 | 碎片化 | 动态迭代优化 |
| 用户体验 | 需手动优化查询 | 自动优化 |
| 结果质量 | 一般 | 深度、全面 |
