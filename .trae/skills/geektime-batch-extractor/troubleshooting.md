# 异常处理与修复策略

> 本文件为 geektime-batch-extractor 的参考文档，由 SKILL.md 按需加载。

## 异常处理表

| 异常 | 检测方式 | 处理 |
|------|---------|------|
| Chrome 端口不可用 | `findPort()` 返回 null | 暂停任务，提示用户启动 Chrome |
| 无课程目录页 | init-course.js 找不到目录页 | 自动降级为扫描标签页模式 |
| 无文章标签页 | 扫描标签页返回空列表 | 报错退出，提示用户打开文章 |
| 文章标签页未打开 | extract-single.js 返回 `{ok:false, error:'Page not found'}` | 记录到失败列表，继续处理其他 |
| 付费墙 | 浏览器内检测到「仅可试看」 | 返回 `{error:'paywall'}`，提示用户登录/订阅 |
| 图片下载超时 | 30秒超时机制 | 重试1次，仍失败保留远程链接 |
| 图片下载失败 | HTTPS 错误 | 保留远程链接，不阻塞流程 |
| 校验失败 | validate-lib.js 返回 `pass:false` | 加入修复队列 |
| regen 也失败 | regen 后校验仍不通过 | 标记为需重新提取（需浏览器） |
| sub_agent 超时 | 主 Agent 等待超过 120s | 重试1次，仍超时则标记失败继续 |
| sub_agent 崩溃 | Task tool 返回错误 | 记录失败，继续下一轮 |

## 修复策略

```
校验失败文章
    ↓
regen.js（不需要浏览器，从 raw-data 缓存重新生成）
    ↓
regen 成功？
├─ Yes → 校验通过？→ 完成
│         └─ 仍失败 → 标记为「需重新提取」
└─ No  → 缓存损坏？→ 标记为「需重新提取」

需重新提取的文章
    ↓
extract-single.js（需要浏览器，重新获取数据）
    ↓
成功？
├─ Yes → 校验 → 完成
└─ No  → 标记为「人工处理」，继续其他文章

全部修复完成后
    ↓
batch-validate.js 全局校验
    ↓
仍有失败？
├─ Yes → 输出失败清单给用户，询问是否继续
└─ No  → 进入清理阶段
```

## 常见问题

### Q: 批量提取中部分文章失败，是否影响其他文章？
不影响。每篇文章由独立 sub_agent 处理，单篇失败不影响其他文章的提取和校验。

### Q: regen 和重新提取的区别？
- **regen**：从本地缓存（raw-data/）重新生成 MD，不需要浏览器，速度快
- **重新提取**：重新连接浏览器获取内容，需要对应标签页打开

### Q: 原始数据缓存什么时候可以删除？
阶段3 用户确认所有文章正确后，可以删除 raw-data/ 目录。删除前确保所有校验通过。

### Q: sub_agent 超时时间为什么不同？
- 提取（120s）：需要浏览器交互+图片下载，耗时较长
- 校验（30s）：纯文件操作，速度很快
- 修复/regen（30s）：纯文件操作，不涉及网络
