# B端产品方案设计

基于《决胜B端》第04/05章方法论，完成从整体方案设计到细节方案设计的全链路产品设计工作。

## 触发条件

用户提到以下意图时激活：
- "设计产品方案"
- "写PRD"
- "做产品架构"
- "画功能模块图"
- "设计数据模型"
- "做权限设计"
- "从0到1设计一个产品"
- "整体方案怎么设计"
- "细节方案怎么设计"

## 执行流程

### Phase 0: 双钻模型顶层设计（补充）

**目标**：在开始具体设计前，先明确真正要解决的问题。

**方法**（社区设计思维框架）：

双钻模型四阶段：

**阶段一：发现（Discover）** — 发散
- 用户访谈、观察、问卷
- 收集尽可能多的问题和需求
- 不要急于下结论

**阶段二：定义（Define）** — 收敛
- 整理发现的问题
- 找到核心问题（用"5 Why分析法"挖到底层原因）
- 明确本次要解决的关键问题

**阶段三：开发（Develop）** — 发散
- 产生多种解决方案
- 不评判，快速头脑风暴
- 画出草图、流程图、原型

**阶段四：交付（Deliver）** — 收敛
- 评估和选择最优方案
- 细化设计
- 准备PRD和开发

**适用场景**：
- 从0到1的新产品设计
- 需求模糊、不确定要解决什么问题
- 多人协作、需要共识的场景

**输出**：问题定义声明 + 解决方案方向

---

### Phase A: 整体方案设计

**目标**：从宏观层面勾勒产品轮廓，明确产品定位和规划蓝图。

#### Step 1: 商业模式设计（精益画布）

**目标**：明确产品商业模式和价值主张。

**方法**（第04章）：

精益画布九要素（从中心到两侧）：
1. 核心价值主张（产品解决什么问题）
2. 目标客户（谁有这个痛点）
3. 痛点问题（TOP3）
4. 解决方案（如何解决）
5. 渠道（如何触达客户）
6. 关键指标（如何衡量成功）
7. 独特卖点（竞争优势）
8. 收入模式（如何赚钱）
9. 成本结构（钱花在哪里）

**输出**：精益画布（九宫格格式）

#### Step 2: 核心业务流程

**目标**：梳理核心业务流程，定义产品边界。

**方法**：

1. 绘制核心业务流程图（跨部门、跨系统）
2. 确定产品覆盖的业务边界（哪些在线上，哪些在线下）
3. 确定与现有系统的集成关系

**关键问题**：
- 产品负责哪部分业务场景？
- 与现有系统的边界在哪？
- 哪些模块复用，哪些新建？

**输出**：核心业务流程图 + 产品边界定义

#### Step 3: 产品定位

**目标**：从宏观和执行两个层面明确产品定位。

**方法**（第04章）：

**宏观层面**（一句话）：
> 产品的**目标客户**是谁？解决了他的**什么问题**？提供了**什么价值**？

**执行层面**（子系统划分）：
- 确定需要设计几套子系统
- 每套子系统的目标用户是谁
- 每套子系统解决什么问题
- 终端形态（PC/H5/App）

| 子系统 | 目标用户 | 核心功能 | 终端形态 |
|--------|---------|---------|---------|
|        |         |         |          |

**输出**：产品定位一句话 + 子系统划分表

#### Step 4: 应用架构

**目标**：明确新产品与现有系统架构的融合关系。

**方法**：

1. 盘点现有系统模块（哪些可以复用）
2. 确定复用方案（直接用/改造后用/新建）
3. 画出应用架构图（新建系统+改造系统+现有系统）

**常见复用考量**：
- 账号体系（是否需要子母账号）
- 权限管理（是否复用Auth服务）
- 消息通知（是否复用消息中心）
- 订单中心（是否复用现有订单服务）
- 支付平台（是否复用现有支付）

**输出**：应用架构图 + 复用方案说明

#### Step 5: 功能模块设计

**目标**：为每个子系统设计功能模块，绘制模块图。

**方法**（第04章）：

三种模块抽象思路（按需选择）：

**思路一：基于业务领域**（最常见）
- 按业务部门/业务单元划分
- 体现内部聚合性和松耦合

**思路二：基于业务场景**
- 按业务场景划分菜单
- 适合流程属性重的系统（如WMS）

**思路三：基于业务对象**
- 按关键数据对象划分模块
- 适合CRM等系统

**输出**：每个子系统的功能模块图（体现一级/二级菜单结构）

#### Step 6: 演进蓝图（Roadmap）

**目标**：规划产品分阶段实现路径。

**方法**：

**一期（MVP）**：聚焦核心业务闭环
- 凡是可以手动处理的问题，暂时不做系统支持
- 验证业务模式是否成立

**二期**：补充运营管理诉求
- 报表统计
- 风控管理

**三期**：强化运营与扩展能力
- 风控强化
- 高级功能

**产出**：演进蓝图表格

| 阶段 | 周期 | 核心功能 | 预期价值 |
|------|------|---------|---------|
| 一期 |      |         |          |
| 二期 |      |         |          |
| 三期 |      |         |          |

### Phase B: 细节方案设计

**目标**：对整体方案中的关键场景进行深入细化设计。

#### Step 7: 业务数据建模

**目标**：提炼业务本质，构建数据底层。

**方法**（第05章核心方法论）：

**三步法**：
1. **找实体**：梳理核心流程 → 提取所有名词 → 找到关键表单 → 提炼人/事/物
2. **理关系**：判断实体间关系（一对一/一对多/多对多）
3. **定属性**：标记关键字段

**重要原则**：
- 宁可设计成多对多，也不要轻易设计成一對一（保留扩展性）
- 数据建模决定数据库表结构，是系统灵活性的根基

**输出**：ER图（实体-关系图）

#### Step 8: 流程与角色设计

**目标**：明确系统中涉及的角色和操作流程。

**方法**：

1. 识别系统角色（与业务流程中的岗位对应）
2. 绘制业务流程图（跨子系统/跨角色）
3. 明确各角色的职责边界（避免职责交叉）

**角色清单**：
| 角色 | 所属方 | 职责 | 关联子系统 |
|------|--------|------|-----------|
|      |        |      |           |

**输出**：角色清单 + 业务流程图

#### Step 9: 页面流转设计

**目标**：明确用户完成某项操作需要访问的页面及跳转顺序。

**方法**：

1. 确定关键使用场景
2. 绘制页面流转图（针对单一角色单一场景）
3. 识别可复用的页面
4. 汇总所有页面清单

**关键问题**：
- 是否需要新建页面，还是复用已有？
- 不同角色是否共用同一页面（靠权限区分）？

**输出**：页面流转图 + 页面清单

#### Step 10: 界面设计

**目标**：设计关键页面的交互方案。

**方法**（第05章）：

**常见页面类型**：
- 列表页（检索条件 + 结果列表 + 分页器）
- 详情页（信息呈现 + 编辑表单）
- 首页/工作台（待办 + 仪表盘 + 快捷入口）

**设计原则**：
- 借鉴成熟软件（AntDesign/Salesforce/Lightning）
- 采用标准控件（不发明轮子）
- B端产品不需要花哨UI，聚焦功能效率

**输出**：关键页面线框图（可用文字描述或手绘示意图）

#### Step 11: 权限设计

**目标**：设计功能权限和数据权限。

**方法**（第05章）：

**功能权限设计**（RBAC模型）：
- 用户 → 角色 → 权限
- 用户组 → 角色 → 权限
- 权限表（页面/按钮 × 角色）

| 页面 | 按钮/功能 | 角色A | 角色B |
|------|----------|-------|-------|
|      |          |       |       |

**数据权限设计**（两种方案）：
- **方案一：组织机构树**（最灵活）：根据账号在机构树中的位置确定数据范围
- **方案二：地区/客户维度**（简单）：根据账号所属区域确定数据范围

**输出**：权限表 + 数据权限设计方案

#### Step 12: PRD撰写（优化版）

**目标**：输出完整的产品需求文档。

**方法**（第05章 + 社区PRD七步法）：

**PRD七步法结构**：

**Step 12.1 目标和背景**
- 产品目标：本次要达成什么业务目标？
- 项目背景：为什么做这个需求？
- 成功标准：如何衡量成功？（量化指标）

**Step 12.2 确定范围**
- 功能范围：本次做什么
- **非功能范围（重要）**：明确本次不做什么
- 边界定义：与关联系统的边界在哪？

**Step 12.3 用户和角色**
- 用户画像：谁会使用这个功能？
- 角色定义：有哪些角色参与？
- 使用场景：用户在不同场景下的诉求

**Step 12.4 功能需求**
- 功能清单：列出所有功能点
- 功能优先级：按MoSCoW排列（Must/Should/Could/Won't）
- 用户故事：INVEST原则编写（Independent/Negotiable/Valuable/Estimable/Small/Testable）

**Step 12.5 业务流程**
- 核心流程图：跨角色、跨系统的完整流程
- 异常流程：异常情况如何处理？
- 状态流转：涉及哪些状态变更？

**Step 12.6 界面和交互**
- 页面清单：有哪些页面？
- 页面原型：关键页面线框图
- 交互说明：特殊交互、校验规则

**Step 12.7 验收标准**
- 功能验收：功能如何验收？通过标准是什么？
- 非功能验收：性能、安全、兼容性要求
- 埋点需求：需要埋哪些点？

**两种PRD视角**（可按需选择）：

| 视角 | 特点 | 适用场景 |
|------|------|---------|
| 场景视角 | 聚焦业务场景和痛点，业务属性强 | 从1到N迭代、定制化项目 |
| 功能视角 | 聚焦模块和功能点，技术属性强 | 从0到1设计、产品化产品 |

**输出**：PRD文档

## 验证检查项

- [ ] 精益画布九要素是否完整？
- [ ] 核心业务流程是否定义了产品边界？
- [ ] 产品定位是否一句话说清楚（含客户+问题+价值）？
- [ ] 应用架构是否明确了复用方案？
- [ ] 功能模块图是否体现了一二级菜单结构？
- [ ] 演进蓝图是否按MVP优先原则分阶段？
- [ ] ER图是否正确标注了实体关系（一对一/一对多/多对多）？
- [ ] 角色是否与业务流程岗位对应，且无交叉？
- [ ] 权限设计是否包含功能权限和数据权限两部分？
- [ ] PRD七步法是否完整？（目标/范围/用户/功能/流程/界面/验收）
- [ ] 非功能范围是否明确？（本次不做什么）
- [ ] MoSCoW优先级是否标注？

## 使用示例

**示例1: 从0到1设计一个新系统**
> 用户: "我要设计一个供应商管理系统"
> → Step1: 精益画布（目标客户是谁？解决什么问题？）
> → Step2: 核心业务流程（供应商从哪里来？怎么管理？怎么淘汰？）
> → Step3: 产品定位（可能分供应商管理后台+采购员前端）
> → Step5: 功能模块（供应商档案/评估/合同/绩效）
> → Step6: Roadmap（一期先做档案和合同）

**示例2: 设计一个数据模型**
> 用户: "帮我设计一个CRM的客户数据模型"
> → Step7: 三步法找实体（客户/联系人/商机/订单）
> → 梳理关系（一个客户可以有多个联系人/多个商机/多个订单）
> → 输出ER图

**示例3: 设计权限方案**
> 用户: "总部和区域销售能看到的数据不一样，怎么做权限"
> → Step11: 组织机构树方案
> → 总部账号：能看到所有数据
> → 大区账号：能看到本大区及下属小区域数据
> → 输出权限表
