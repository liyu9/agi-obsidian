# 需求评估方法




> 来源：三节课AI知识库课程内容整理

## 需求分析三大维度




> 来自课程7（人工智能产品经理进阶提升）

```
项目是否适合做AI？
    ├── 数据维度
    ├── 问题维度
    └── 商业维度
```

### 一、数据维度




| 评估维度 | 关键问题 | 说明 |
|----------|----------|------|
| **数据可获取性** | 数据是否方便获得？ | 医疗等特殊行业数据获取难度大 |
| **数据质量** | 数据是否全面、有代表性？ | 需要覆盖所有特征维度 |
| **数据存量** | 当前有多少数据可用？ | 数据越多越好（保证质量的前提下） |
| **数据闭环** | 能否持续获取反馈数据？ | 让机器持续学习 |

**数据全面性案例**：
- 湘雅医院皮肤病PASI评分项目
- 需要近照、远照、侧照、皮肤镜下照片等多角度数据
- 数据不全导致项目困难，后续补了大量数据

**数据代表性案例**：
- 微博用户数据**不能**代表全民偏好（有数据偏差）
- 快手、抖音、B站用户画像各不同

**AI的核心法则**：

> **AI的上限由数据的上限决定**
> 有什么样的数据，就能做出什么样水平的模型

### 二、问题维度




| 评估维度 | 说明 | 案例 |
|----------|------|------|
| **可解释性** | 是否需要解释决策原因 | 诊断需要；推荐不需要 |
| **错误容忍度** | 能容忍多少错误 | 语音翻译容忍度高；人脸识别容忍度低 |
| **问题复杂度** | 特征数量和规则数量 | 特征多+确定性弱→适合AI |
| **鲁棒性** | 模型泛化能力 | 同一模型在不同场景是否可用 |
| **实时性** | 对响应速度的要求 | 刷脸需要秒级响应；诊断可等几分钟 |

**三原则**：
1. 越需要**因果关系**解释的 → 偏向传统机器学习，而非深度学习
2. 错误**容忍度低** → 谨慎使用深度学习，人机协同是方向
3. **商业价值与性价比** → 衡量投入产出比

**确定性强弱与特征多少的决策矩阵**：

| 特征数量 | 确定性强 | 确定性弱 |
|----------|----------|----------|
| **特征多** | 可用规则 | ✅ **最适合AI** |
| **特征少** | 可用规则 | 需要人工解决 |

**案例：游戏外挂检测**
- 简单游戏（俄罗斯方块）：特征少+确定性强 → 规则即可
- 复杂游戏（吃鸡）：特征多+确定性弱 → **适合AI检测**

### 三、商业维度




| 评估维度 | 说明 |
|----------|------|
| **业务价值** | AI对业务价值的贡献有多大 |
| **痛点** | 这个痛点是否真实、够痛 |
| **AI辅助人工** | 是否能有效辅助人工 |
| **商业化可行性** | 投入产出比是否合理 |

### 四、李开复5秒钟法则




> 如果人类能在**5秒钟**内对某个任务进行反馈/判断，那么这个任务适合用AI解决

**吴恩达的观点**更激进：**小于1秒钟**就可以做AI

### 五、场景大于逻辑




> 来自课程7

**场景大于逻辑**——用户使用产品的环境和条件比产品本身的逻辑流程更重要

**案例：微信的返回逻辑**
- 从任意联系人进入聊天页面
- 点击返回 → 直接回到主聊天列表（而非逐层返回）
- 这就是基于"场景"（用户在单聊场景）而非"逻辑"（逐层返回）的设计

### 六、识别业务与AI结合点的两种方法




> 来自课程3（工作流重塑与能力跃迁）

#### 方法一：从AI新特性上长出新玩法




| 新特性 | 说明 | 案例 |
|--------|------|------|
| **降低成本** | 部署成本：大模型根据实时数据调整资源消耗降低固定成本；获客成本：新型应用市场带来插件生态无界营销 | 大模型自动优化配置 |
| **交互范式改变** | GUI→LUI，计算机理解并生成自然语言，一个指令串联多个应用功能 | 微软Copilot自然语言唤起功能 |
| **实时内容生成** | 从文本代码到视频声音图像，根据用户行为实时生成 | 教育内容根据学习进度实时调整 |
| **多模态感知** | AI同时感知文本图像文档，输入变得更丰富 | 智能驾驶通过视觉听觉做分析判断 |

#### 方法二：从三位一体结构出发




> 2023年陆奇博士在奇绩论坛提出

| 维度 | 说明 | 作用 |
|------|------|------|
| **信息维度** | 专注于信息的优化获取和供给 | 提升业务效率 |
| **模型维度** | 通过高效的数据筛选分析和预测 | 增强决策能力 |
| **行动维度** | 通过用户交互的优化和自动化流程 | 获得更好的效果 |

**理解**：
- **信息是媒介**，连接不同系统的原子
- **模型是在信息的基础上做了一层思考跟表达**
- **行动是思考之后跟环境交互的体现**

**从三个维度识别结合点**：

**信息维度思考点**：
- 我的业务应用，信息获取跟供给方式还可以再优化吗？
- 大模型能通过自然语言生成跟对话能力降低用户对复杂信息的理解负担
- 我是否可以扩充信息内容的广度跟深度？

**模型维度思考点**：
- 通过不断更新跟扩展知识库，引入多元内容实现特定领域响应能力
- 基于用户反馈不断优化信息质量

**行动维度思考点**：
- 通过用户交互优化和自动化流程获得更好效果
- 比如跨境电商结合大模型图像识别和NLP能力提供多视角商品展示
