# 需求分析能力




需求分析是AI产品经理的核心能力之一。

## 1. AI产品经理的需求分析视角




> 来源：课程3 — 工作流重塑与能力跃迁

AI产品经理的需求分析不只看业务场景和用户需求，还要看**业务如何结合AI能力**，以及**怎么评估结合成效**。需要深入了解业务场景跟需求，然后去倒推并且抽象出需要模型具备的能力。

与传统产品经理的区别：

| 维度 | 传统产品经理 | AI产品经理 |
|------|-------------|-----------|
| 关注重点 | 业务场景 + 用户需求 | 业务场景 + 用户需求 + AI能力结合 |
| 分析方向 | 从需求到功能 | 从需求倒推模型能力 |
| 评估方式 | 功能完成度 | AI结合成效评估 |

## 2. 识别业务与AI结合点




### 方法一：从AI新特性上长出新玩法




| AI特性 | 具体表现 |
|--------|---------|
| 降低成本 | 部署成本 + 获客成本 |
| 交互范式改变 | GUI → LUI |
| 实时内容生成 | AIGC动态生成 |
| 多模态感知 | 文本/图像/语音/视频融合理解 |

### 方法二：从三位一体结构出发




```
┌─────────────────────────────────────────┐
│            三位一体结构                    │
├─────────────┬─────────────┬─────────────┤
│  信息维度    │  模型维度    │  行动维度    │
├─────────────┼─────────────┼─────────────┤
│ 信息优化获取 │ 数据筛选分析 │ 用户交互优化 │
│ 信息优化供给 │ 预测能力    │ 自动化流程   │
└─────────────┴─────────────┴─────────────┘
```

- **信息维度**：信息优化获取和供给
- **模型维度**：数据筛选分析和预测
- **行动维度**：用户交互优化和自动化流程

## 3. 需求分析三大维度




> 来源：课程7 — 进阶提升

### 数据维度




| 指标 | 说明 |
|------|------|
| 可获取性 | 数据是否能获取到 |
| 质量 | 数据的准确性和一致性 |
| 存量 | 现有数据量是否足够训练 |
| 闭环 | 数据能否形成持续优化闭环 |

### 问题维度




| 指标 | 说明 |
|------|------|
| 可解释性 | 模型输出是否需要向用户解释 |
| 错误容忍 | 业务对错误的容忍程度 |
| 复杂度 | 问题本身的复杂程度 |
| 鲁棒性 | 模型对异常输入的抗干扰能力 |
| 实时性 | 是否需要实时响应 |

### 商业维度




| 指标 | 说明 |
|------|------|
| 业务价值 | 解决问题带来的业务收益 |
| 痛点程度 | 用户痛点的强烈程度 |
| AI辅助人工 | AI能在多大程度上辅助人工 |
| ROI | 投入产出比 |

## 4. 场景大于逻辑原则




> 用户使用产品的**环境和条件**比产品本身的逻辑流程更重要。

在做需求分析时，不能只关注产品功能逻辑，更要深入理解用户的使用场景、环境约束和实际条件，这些场景因素往往决定了产品设计的方向。

## 5. AI适合性的判断标准




### 李开复5秒钟法则




> 如果一个人能在**5秒钟**内对一件事做出判断，那么这件事大概率可以用AI来解决。

### 吴恩达观点




> 判断时间可以更短——**小于1秒**就可以，适合AI处理。

### 确定性与特征的决策矩阵




|  | 特征少 | 特征多 |
|---|--------|--------|
| **确定性强** | 规则引擎即可 | 传统ML/统计模型 |
| **确定性弱** | 需要人工辅助 | ⭐ **最适合AI** |

> **特征多 + 确定性弱 = 最适合AI解决的场景**
