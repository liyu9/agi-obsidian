# RAG与知识库




## 什么是RAG




> 来源：课程5

RAG（Retrieval-Augmented Generation）是**搜索 + 生成**结合的AI架构。

```
用户提问
   ↓
┌──────────┐     ┌──────────┐     ┌──────────┐
│  检索阶段  │ ──→ │  生成阶段  │ ──→ │  输出回答  │
│ 搜索文档   │     │ 大模型生成 │     │          │
│ 查询数据库 │     │ 结合检索结果│     │          │
└──────────┘     └──────────┘     └──────────┘
```

**核心思路**：模型先搜文档、查数据库，再基于检索到的内容生成回答。

**适用场景**：

| 场景 | 说明 |
|------|------|
| 企业内部问答 | 基于公司文档回答员工问题 |
| 知识库机器人 | 产品FAQ、政策咨询等 |
| 合规问答 | 法规、制度相关精准回答 |

## 外围工程中的知识库建设




> 来源：课程3

知识库系统经常通过**RAG方式**做检索生成。

| 角色 | 职责 |
|------|------|
| 研发 & 算法团队 | 主导基建开发（向量数据库、检索引擎、Pipeline搭建） |
| 产品经理 | 负责知识库场景定义、内容策略、结构和召回规则的设计 |

## 产品经理在知识库建设上的职责




### 1. 明确知识库应用场景




界定哪些问题靠知识库回答，哪些靠大模型直接生成。

```
用户提问
   ↓
问题分类
   ├── 知识库覆盖的标准问题 → RAG检索回答
   └── 开放性问题 → 大模型直接生成
```

### 2. 制定知识来源标准




| 标准维度 | 说明 |
|----------|------|
| 来源渠道 | 官方文档、内部Wiki、业务系统数据等 |
| 准确性 | 内容必须经过验证，确保事实正确 |
| 时效性 | 明确知识有效期，过期内容需更新或下架 |
| 权限 | 不同角色可访问的知识范围不同 |
| 安全性 | 敏感信息的存储和访问控制策略 |

### 3. 设计知识库组织架构




| 类型 | 结构形式 | 适用场景 |
|------|----------|----------|
| 实体型 | 知识图谱、结构化数据 | 实体关系明确的知识（产品参数、组织架构） |
| 文档型 | 非结构化文档分块存储 | 长文档、手册、报告 |
| FAQ型 | Q&A问答对 | 高频标准问题的快速匹配 |

### 4. 制定知识更新机制




| 维度 | 需明确的内容 |
|------|-------------|
| 知识分类 | 哪些是静态知识（不常变），哪些是动态知识（需频繁更新） |
| 维护责任 | 谁负责更新，是否需要人工审核 |
| 更新频率 | 每日、每周、每月的更新节奏 |

### 5. 设定知识召回策略




定义模型调用知识库的**时机**和**优先级**：

- 何时触发知识库检索（关键词匹配 / 意图识别 / 全量检索）
- 知识库结果与模型生成的优先级排序
- 多个知识片段冲突时的处理策略

## 知识库搭建实操




> 来源：课程5第十二章

```
原始数据
   ↓
┌──────────┐
│ 数据清洗   │  去噪、去重、格式统一
└──────────┘
   ↓
┌──────────┐
│ Chunk分块  │  按语义段落切分文档
└──────────┘
   ↓
┌──────────┐
│ 向量化     │  Embedding生成向量表示
└──────────┘
   ↓
┌──────────┐
│ 向量库存储  │  存入向量数据库供检索
└──────────┘
```

| 步骤 | 说明 |
|------|------|
| 数据清洗 | 去除噪声、重复内容，统一格式 |
| Chunk分块 | 将长文档按语义段落切分为合适大小的片段 |
| 向量库设计 | 选择合适的向量数据库，设计索引和检索策略 |

## Embedding概念




> 来源：课程5

**Embedding = 把文字转成向量**

AI只理解数字。Embedding是将文本映射到**高维向量空间**的过程。

```
"今天很开心" → [0.23, -0.15, 0.87, ...]  ← 多维数字数组（语义坐标）
"我心情很好" → [0.21, -0.13, 0.85, ...]  ← 语义空间中距离很近
```

| 概念 | 说明 |
|------|------|
| 向量 | 多维数字数组，代表文本的语义坐标 |
| 语义相似性 | 语义相近的文本在向量空间中距离很近 |
| 应用 | 文本检索、相似度计算、聚类分析 |

> "今天很开心"和"我心情很好"经过embedding后在语义空间里很近——这就是RAG能找到相关知识的原理。
