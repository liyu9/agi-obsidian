# 交付与部署




## 交付能力




> 来源：课程2

AI产品经理需要懂的交付相关能力：

| 能力 | 说明 |
|------|------|
| GPU算力 | 了解不同GPU型号的算力差异，评估训练和推理所需的算力资源 |
| 云厂商选型 | 对比主流云厂商（AWS、阿里云、腾讯云等）的AI服务能力和性价比 |
| 数据库选型 | 根据数据类型选择合适的数据库（关系型、向量数据库、图数据库等） |
| 私有化部署 | 评估私有化部署的需求、成本和技术可行性 |

## API调用能力




> 来源：课程2、课程5

AI产品通常不会自己训练模型，而是**远程调用大模型服务**。

### 调用流程




```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ 用户输入  │ ──→ │ 系统转成  │ ──→ │ 模型生成  │ ──→ │ 传回前端  │
│          │     │ Token    │     │ 结果     │     │ 显示     │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
```

| 步骤 | 说明 |
|------|------|
| 1. 发送用户输入 | 前端将用户请求发送给后端 |
| 2. 系统转成Token | 将文本转换为模型可处理的Token序列 |
| 3. 模型生成结果 | 大模型在线推理生成回答 |
| 4. 传回前端显示 | 将生成结果返回给用户界面展示 |

## 推理服务




> 来源：课程5

模型被部署后，每次请求**在线思考一次**的过程就是推理过程。

| 概念 | 说明 |
|------|------|
| 推理（Inference） | 模型接收输入，经过前向计算，输出预测结果 |
| 推理服务 | 将模型部署为在线API服务，支持实时请求响应 |
| 推理成本 | 每次推理消耗的算力资源，与模型参数量和请求量正相关 |

## 模型压缩与优化




> 来源：课程2

| 优化技术 | 说明 |
|----------|------|
| 网络剪枝 | 去除冗余神经元和连接，减小模型体积 |
| 分层结构 + 局部注意力 | 优化注意力机制的计算范围，降低计算量 |
| 参数共享 + 跨层连接 | 不同层共享参数，减少总参数量 |
| 低精度计算 | 16bit / 32bit混合精度，降低计算和存储开销 |

```
模型压缩优化路径：

原始模型（FP32）
   ↓  低精度量化
混合精度模型（FP16 + FP32）
   ↓  网络剪枝
精简模型
   ↓  参数共享
压缩部署模型
```

## 自建vs外包决策




> 来源：课程7

| 项目类型 | 建议 | 原因 |
|----------|------|------|
| 机器学习项目 | 可自建可外包 | 技术相对成熟，调参空间有限 |
| 深度学习项目 | 尽量自建 | 参数调节多，需大量迭代沟通，外包效率低 |
| 核心竞争壁垒项目 | 必须自建 | 核心能力不能依赖外部，否则失去竞争优势 |

## 算法备案




> 来源：课程2

算法备案是**新增的合规要求**，AI产品上线前需按规定完成算法备案。

| 维度 | 说明 |
|------|------|
| 备案主体 | 提供算法推荐服务的企业 |
| 备案内容 | 算法基本原理、数据来源、安全评估等 |
| 合规要求 | 符合国家相关法规，保障用户权益 |

### Ollama本地大模型部署
来自06课程第3讲。Ollama支持一键本地部署开源大模型，不需要云端API。产品经理需了解本地部署的适用场景：数据安全要求高、离线环境、成本敏感的B端场景。
