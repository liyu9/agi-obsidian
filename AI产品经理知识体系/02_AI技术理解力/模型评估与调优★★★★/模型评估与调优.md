# 模型评估与调优




## 模型评估指标场景化适配




> 来源：课程2

不同任务类型应选用不同的评估指标：

| 任务类型 | 推荐指标 | 说明 |
|----------|----------|------|
| 分类任务 | AUC | 衡量分类器区分正负样本的能力 |
| 文本生成 | ROUGE + 人工评分 | ROUGE衡量生成文本与参考文本的重叠度，辅以人工评估质量 |
| 机器翻译 | BLEU + 语义一致性 | BLEU衡量翻译精确度，语义一致性评估含义是否保持 |

## 模型期望类型




> 来源：课程7

| 场景 | 侧重指标 | 策略 | 原因 |
|------|----------|------|------|
| 科研工作 | 精确率（Precision） | 宁缺毋滥 | 错误结论代价极高 |
| 医学筛查 | 召回率（Recall） | 宁错勿漏 | 漏诊后果严重 |

```
精确率 = TP / (TP + FP)   → 预测为正的中，有多少是真的正
召回率 = TP / (TP + FN)   → 真正的中，有多少被找出来了
```

## 策略设计——基座能力训练（微调）




> 来源：课程3

### 预训练 vs 微调




| 概念 | 类比 | 说明 |
|------|------|------|
| 预训练 | 模型在大型图书馆自学成才 | 在海量无标注数据上学习通用能力 |
| 微调 | 当模型的老师，帮它定义标准答案 | 在特定领域标注数据上学习专业能力 |

### 产品经理在微调中的职责




| 职责 | 具体内容 |
|------|----------|
| 明确微调目标 | 定义微调要解决的核心问题 |
| 设计微调数据 | 标注标准、标签体系、数据格式 |
| 定义微调策略和边界 | 调用逻辑、模型选择、微调类型、路由逻辑、跨场景边界控制 |
| 定义优化方向 | 准确性、一致性、用户满意度、推理成本 |

### 微调判断原则




> **只有当外围工程做无可做之后，才考虑引入微调，因为微调成本较高。**

```
优化路径（由低成本到高成本）：

Prompt优化 → RAG检索增强 → 外围工程调优 → 微调 → 训练新模型
  （低成本）                                          （高成本）
```

### 案例：物流客服机器人




| 阶段 | 问题 | 解决方案 |
|------|------|----------|
| 初始方案 | 直接用泛化模型回答 | 回答太泛，不够专业 |
| 优化方案 | 针对快递物流问题微调专用模型 | 在物流领域数据上微调，提升专业度 |

## Fine-Tuning能力




> 来源：课程2

| 技术 | 说明 |
|------|------|
| 全量微调 | 更新模型全部参数，效果最好但成本最高 |
| LoRA | 低秩适配，只更新少量参数，成本低、效果好 |

## 可用性原则




> 来源：课程7

```
准确率提升的边际成本：

50% → 90%  ：约需 3 天
90% → 99%  ：约需 1 年
99% → 99.5%：可能一辈子也完不成
```

| 原则 | 说明 |
|------|------|
| AI项目不是科研项目 | 达到可用阈值即可发布，不必追求极致 |
| 快速上线迭代 | 先让用户用起来，通过真实反馈持续优化 |
| 边际收益递减 | 越往高精度走，投入产出比越低 |

## 补充：AI大模型项目落地实战（极客时间课程）

### AI智能体开发三层次
来自06课程第4讲。由浅入深：
1. 应用开发层：通过API调用现有大模型，用Prompt控制行为，核心参数Temperature（控制创造力vs确定性的平衡）
2. 微调开发层：以行业数据微调大模型，使模型在某类问题上完全具备特定能力
3. 专有模型开发层：从0或基于开源模型训练行业专用模型

判断原则模型示意：
```
提示工程能解决 → 应用开发
提示工程不能解决 → 微调开发
微调仍不能解决 → 专有模型开发
```

### 微调实战案例：电商客服模型
来自06课程第14-17讲。
- 微调数据量：每个细化场景需1000-10000条训练数据
- 数据格式：提示词+预期输出结对训练
- 效果评估：对比微调前后准确率，需关注JSON等数据协议的识别能力

### 奖励模型——评估专家模型
来自06课程第19-21讲。核心思路：让AI评估AI的输出，实现评估过程完全无人化。
- 参考ChatGPT RLHF中的Reward Modeling机制
- 基于人类专家小样本标注数据训练评估模型
- Llama Guard 3案例：基于Llama 3.1 8B小模型微调实现安全评估
- 关键洞察：数据质量判断简化为"采用-丢弃"二值化评估
