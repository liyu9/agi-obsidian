# Agent系统设计




## 什么是Agent




> 来源：课程5

AI Agent是把大模型赋能到一个能够**思考**、**拆解任务**、**自己动手完成操作**的智能体。

```
Agent ≠ 大模型生成的结果

Agent = 大模型 + 工作链路设计 + 用户意图管理 + 反馈机制
```

| 概念 | 说明 |
|------|------|
| 大模型生成的结果 | 单次问答，输入→输出 |
| AI Agent | 利用大模型 + Memory + Action + 目标管理，构成的AI执行系统 |

### Agent用到的组件




```
┌─────────────────────────────────────┐
│              AI Agent                │
├─────────────────────────────────────┤
│  大模型（LLM）  ← 核心推理引擎       │
│  Prompt        ← 任务指令设计        │
│  RAG           ← 知识检索增强        │
│  Memory        ← 记忆与上下文管理    │
│  工具接口       ← 调用外部API/系统    │
└─────────────────────────────────────┘
```

## 三种技术应用模式




> 来源：课程3

| 模式 | 自主化程度 | 核心特征 | 适用场景 |
|------|-----------|----------|----------|
| 嵌入模式 | 低 | AI作为工具嵌入现有流程 | 人工决策要求高的场景 |
| Copilot模式 | 中 | AI与人类共同参与任务执行 | 需要实时调整的复杂任务 |
| 智能体模式 | 高 | AI独立完成任务 | 规则明确、可自动化的场景 |

### 嵌入模式（低自主化）




```
用户 → 操作流程 → 调用AI工具 → 获取结果 → 人工决策
                     ↑
              AI作为工具嵌入其中
```

- **优势**：实施难度低
- **局限**：AI作用有限

### Copilot模式（中自主化）




```
用户 ←→ AI协作
  ↕          ↕
任务拆解 ←→ 实时调整
```

- AI跟人类共同参与任务执行
- 适用需要实时调整的复杂任务

### 智能体模式（高自主化）




```
用户：设定目标 + 监督
  ↓
AI Agent：独立完成任务
  ↓
结果反馈 → 用户确认
```

- AI独立完成任务，人类角色从**执行者**变成**设定者和监督者**
- **优势**：最大程度发挥AI能力
- **挑战**：执行准确性谁来兜底

## 构建Agent的思路




> 来源：课程5

构建Agent要做的不是"答一句话"，而是：

| 能力 | 说明 |
|------|------|
| 自动处理流程 | 根据目标自动编排执行步骤 |
| 多步执行任务 | 将复杂任务拆解为多步骤串行/并行执行 |
| 持续记忆 | 在执行过程中保持上下文和历史信息 |
| 反馈学习 | 根据执行结果和用户反馈进行自我调整 |

## 八、补充：Multi-Agent系统开发实战（极客时间课程）

### ReAct范式 — Agent的核心运行机制

来自13课程第2讲。Agent本质是一个"思考→行动→观察"循环机器。

核心Prompt模板结构：
```
Thought（模型输出下一步想法）
  → Action（选择工具名称）
    → Action Input（提取调用参数）
      → Observation（工具返回结果）
        → 再次Thought...循环
          → Final Answer（最终答案）
```

产品经理需理解：Agent的参数抽取精度和工具调用成功率可以直接影响产品体验。

### Multi-Agent协作 — Agent × Task × Process

来自13课程第3讲。单Agent的崩溃场景：
- 上下文长度爆炸：一个Agent处理所有任务导致上下文超限
- 上下文内容污染：不同任务的信息混杂导致决策混乱
- 多指令挑战：同时执行多个指令时优先级冲突

解决方案：构建"数字化职能部门"
- Agent（角色）：研究员、写手、审查员，每个Agent有角色、目标、背景故事、可用工具
- Task（任务）：子任务明确分工，每个Task绑定特定Agent
- Process（流程）：定义顺序执行还是Hierarchical层级执行

### AI应用四种架构范式

来自13课程第1讲。

| 范式 | 特点 | 适用场景 | 自主性 |
|------|------|---------|--------|
| Prompt Engineering | 一切交给模型，单次调用 | 简单问答/翻译/摘要 | 最低 |
| Workflow/Chain | 代码驱动的流水线，预先编排 | 多步骤标准化流程 | 低 |
| Single Agent | 模型决定下一步，ReAct驱动 | 研究/搜索/复杂任务 | 中 |
| Multi-Agent | 组织的力量，分工协作 | 企业级复杂系统 | 高 |

关键原则——阿什比定律：业务的不确定性决定系统需要的不确定能力。简单确定的任务用Prompt/Workflow，复杂不确定的任务用Agent/Multi-Agent。

### Orchestrator范式 — 任务层的主Agent+子Agent

来自13课程第23讲。Orchestrator只负责调度和决策，不亲自执行任务。优势：职责分明、便于扩展、容错性强。

### 数字团队体系

来自13课程第25/26/27讲。
- 角色分工：每个Agent有明确的角色描述和职责边界
- 行为规范：通过System Prompt定义行为准则
- 任务链与信息传递：任务间通过标准化JSON格式传递信息
- 人类介入点设计：Human as 甲方，关键决策点设置人工确认环节

### 记忆管理系统

来自13课程第18-22讲。三种记忆模式：
- 短期记忆：上下文对话，会话内有效
- 文件系统记忆：让Agent自己写记忆文件、自己学技能
- 搜索驱动记忆：企业级海量记忆管理方案（RAG+语义搜索）

### 可观测性与安全

来自13课程第30/32讲。
- Hook骨架+Langfuse全链路追踪：Agent的每一步决策和执行都可见
- 沙箱隔离：Agent的工具调用在受限环境执行
- 权限网关与身份认证：企业级权限控制
