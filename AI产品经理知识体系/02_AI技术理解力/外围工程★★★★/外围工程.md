# 外围工程




> 来源：三节课AI知识库课程内容整理

## 一、什么是外围工程




> 来自课程3（工作流重塑与能力跃迁）

在**不改变大模型本身参数跟训练语料的前提**下，通过外围能力来增强模型的实用性跟可靠性，从而更好地服务于垂直业务的需要。

外围工程能够真正把大模型**从能力转化为生产力**，这样一套完整的工程化体系就是外围工程。

## 二、外围工程类型




| 类型 | 说明 |
|------|------|
| **提示工程（Prompt Engineering）** | 通过设计和编写提示文本来引导模型生成符合特定要求的内容 |
| **外部知识库** | 通过RAG方式做检索跟生成，外挂企业文档、FAQ数据库等 |
| **模型联网** | 让模型通过索引网站或搜索引擎内容来总结引用后输出 |
| **插件系统/工具调用** | 配置特定功能插件（搜索、计算、调用API等），让应用具备观察、决策、行动的能力 |
| **上下文管理** | 管理对话上下文 |
| **多模型路由** | 选择合适的模型 |
| **策略控制** | 控制策略执行 |

## 三、外围工程与基座能力的关系




### 策略设计两大组成部分




```
策略设计
├── 基座能力训练（微调）── 算法工程团队为主
│   ├── 预训练：模型在大型图书馆里自学成才
│   └── 微调：当模型老师，帮模型定义标准答案
│
└── 外围工程优化 ── 产品经理深度参与
    ├── 提示工程
    ├── 外部知识库（RAG）
    ├── 模型联网
    ├── 插件系统/工具调用
    ├── 上下文管理
    ├── 多模型路由
    └── 策略控制
```

### 核心转变




**传统策略**：输入主要靠写规则、配权重
**AI策略**：从设计提示词的结构、配置知识库、判断模型是否微调，逐层来做分析

## 四、外围工程优化流程：提示词工程




> 来自课程3

### 1. 定义能力任务树




从整个场景里提炼出它对应到底有哪些任务要去处理。

**任务定义**：输入、处理逻辑和输出分别是什么。

**客服案例**：

| 能力类型 | 说明 |
|---------|------|
| 通用能力 | 对话的生成、情绪的识别、用户意图的理解 |
| 场景特定能力 | 粉丝的拉新转化、推荐活动、分析粉丝行为 |

### 2. 定义评估标准




**常见评估标准**：
- 回复的正确率
- 响应的及时率
- 服务的友好度

### 3. 执行评估




**常见评估方式**：
- 定义评测的题库（常见问题、边界问题）
- 评测方式：自动评测还是人为评测
- 打分的标准

### 4. 提示词优化




- 分析提示词的结构跟问题
- 根据模型本身的表现来调整提示的长度、语义和逻辑

## 五、判断原则：先做外围工程，再考虑微调




> 来自课程3

**只有当外围工程做无可做之后，才会考虑引入微调，因为微调所付出的成本还是比较高的。**

**判断流程**：

```
1. 先尝试通过提示工程优化
2. 再尝试通过知识库（RAG）增强
3. 再尝试通过模型路由和策略控制
4. 以上都做无可做之后 → 考虑微调
```

## 六、外围工程中的分工




| 角色 | 职责 |
|------|------|
| **研发跟算法团队** | 主导外围工程的基建开发工作 |
| **产品经理** | 负责场景定义、内容策略、结构和召回规则的设计 |

### 产品经理在外围工程中的具体职责




1. **明确应用场景**：哪些问题靠知识库，哪些靠大模型生成
2. **制定内容标准**：准确性、更新时效性、权限控制、安全性
3. **设计组织架构**：实体型/文档型/FAQ型
4. **制定更新机制**：静态知识vs动态知识、维护责任、审核流程、更新频率
5. **设定召回策略**：模型调用知识库的时机和优先级

## 补充：MCP协议与工具生态（极客时间课程）

来自13课程第14-16讲。

### MCP协议
Model Context Protocol — AI应用与外部工具/服务的标准通信协议。
- 统一工具接口：不同工具通过统一的MCP接口接入AI
- 与REST API的区别：MCP专为AI Agent设计，支持上下文感知和流式交互
- 工具设计哲学：组合优于耦合，单功能工具可组合成复杂Pipeline

### Skills生态
让Agent接入大量工具的方法论。将专业知识封装为可复用的技能模块，Agent按需加载。

### 自定义工具封装
- 工具输入格式标准化（JSON Schema定义）
- 工具输出需要同时返回人类可读描述和AI可解析结构化数据
