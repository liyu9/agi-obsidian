# 交付与迭代




## 产品阶段拆解




> 来自课程5

```
原型期 → MVP期 → 小范围测试 → 正式交付
```

| 阶段 | 目标 | 关键动作 |
|------|------|---------|
| 原型期 | 概念验证：快速验证AI做这件事能不能靠谱 | 最小可行验证 |
| MVP期 | 团队内部交付：从能用到能跑 | 明确输入输出、建立基础知识库、Prompt模块化、最小可控流程链路 |
| 小范围测试 | 暴露问题 | 加入异常处理、权限控制、监控 |
| 正式交付 | 产品上线 | 加入用户权限、数据加密、操作日志审计 |

---

## 复盘和迭代机制




> 来自课程5

> AI不是一次性交付的作品，是需要持续调教、反馈、优化的**可成长型产品**。

**关键词**：可监控、可定位、可调整、可复用

### 反馈机制组件




| 组件 | 说明 |
|------|------|
| 用户评分模型 | 收集用户对AI输出的评价 |
| 异常情况标签和自动记录 | 自动标记异常输出 |
| 失败的Prompt收集 | 积累Prompt优化素材 |

### 三张活表




| 活表 | 用途 |
|------|------|
| Prompt模块表 | 管理和迭代Prompt模块 |
| 任务链结构图 | 可视化任务执行链路 |
| Prompt DSL语法库 | 积累Prompt设计模式 |

## 问题定位思考路径




> 来自课程5

```
AI反馈错误
  ├── 是Prompt设计问题？→ 调整Prompt结构
  ├── 还是输入信息不足？→ 加入多轮追问
  ├── 还是任务链顺序错了？→ 重排执行流程
  └── 还是知识库命中不准？→ 重新做Embedding
```

## 产品迭代三重驱动力




> 来自课程6

| 驱动力 | 说明 | 示例 |
|-------|------|------|
| 场景扩展 | 原来不能做的现在可以做 | 新增支持多语言 |
| 模型能力提升 | 功能不变但模型有提升（如引入RAG或微调） | 问答准确率提升 |
| 数据积累 | 积累更多优质数据推动模型优化 | 智能驾驶里程越多能力越好 |

### 可观测性：Hook骨架+Langfuse全链路追踪
来自13课程第30讲。核心：Agent的每一步决策和执行都必须可见。实现方式：Hook骨架在关键节点嵌入追踪代码 + Langfuse提供可视化面板。

### 沙箱安全
来自13课程第32讲。AI Agent的执行环境必须隔离：工具调用在沙箱中执行、权限最小化原则、对敏感操作设置人工确认。
