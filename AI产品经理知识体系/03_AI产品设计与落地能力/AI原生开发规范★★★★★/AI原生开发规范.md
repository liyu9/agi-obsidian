# AI原生开发规范

> 来源：极客时间《AI原生开发工作流实战》课程内容整理

## 一、AI-开发者集成成熟度模型

> 来自04课程第1讲

| Level | 协作模式 | 典型代表 | 核心特征 |
|-------|---------|---------|---------|
| **L1** | AI作为外部知识库 | 网页版ChatGPT/Gemini | AI隔离在开发环境之外，需"搬运"上下文，极高摩擦力 |
| **L2** | AI作为嵌入式副驾驶 | Cursor/Copilot Chat | AI嵌入IDE，被动响应，文件级视野，无主动能力 |
| **L3** | AI作为自治Agent | Claude Code/Cline | AI自主执行任务、规划多步骤、有项目级视野、可调用工具 |
| **L4** | AI原生协同 | 规范驱动开发 | AI与开发者"双屏探戈"，AI主动感知项目状态、上下文自动加载 |

**产品经理启示**：L3→L4的演进本质是"规则内化"——从每次手动告诉AI规则，到AI自动加载并遵循规则。

## 二、规范驱动开发三文件体系

> 来自04课程第6/7讲

### CLAUDE.md — 项目私有规范
- 会话开始时自动加载的高优先级背景知识
- 如《团队开发规范手册》，AI"入职第一天就读过并内化"
- 将高频指令从"动态提示"沉淀为"静态配置"

### AGENTS.md — 跨Agent行业标准
- 由OpenAI、Google等共同倡议的开放标准
- 写给AI Agent看的专属README.md
- 打破"巴别塔困境"——不同Agent工具读取同一份规范
- 包含：开发环境、测试指令、代码风格、PR流程、协作规范

### constitution.md — 项目架构铁律
- 定义不可违背的核心原则
- 每次改动前后验证是否符合架构要求
- 如：Go项目的错误处理规范、API响应体格式统一

**产品经理视角**：将产品规范文档化为AI可读取的标准格式，实现AI与产品需求的对齐。

## 三、Slash Commands — 自定义指令集

> 来自04课程第8讲

### 核心概念
将高频复杂提示封装为可复用的斜杠指令，完成从"AI使用者"到"指令设计师"的角色转变。

### 指令分类体系

| 类别 | 典型指令 | 功能 |
|------|---------|------|
| 会话与上下文管理 | `/clear`, `/context`, `/compact` | 管理AI的短期工作记忆 |
| 环境与配置 | `/config`, `/model`, `/output-style` | 实时调整AI行为参数 |
| 项目与协作 | `/review`, `/init`, `/add-dir` | 将AI融入工程实践 |
| 元信息与帮助 | `/help`, `/cost`, `/memory` | 查看工具状态 |

### 工作流封装案例
```
/commit → 自动git diff → 生成Conventional Commits格式提交信息
/review → 代码审查 → 重点关注错误处理和constitution.md一致性
```

## 四、Hooks事件驱动机制

> 来自04课程第11讲

在AI会话的关键节点自动触发，实现被动响应到主动感知的转变。

```
PreToolUse（工具调用前） → 如：拦截危险文件操作
PostToolUse（工具调用后） → 如：自动格式化生成的代码
Notification（通知事件） → 如：任务完成时发送通知
UserPromptSubmit（用户提问前） → 如：自动注入上下文
SessionStart（会话开始时） → 如：加载最新项目状态
```

**产品经理应用场景**：在AI产品中设计自动化触发点，减少人工干预。

## 五、spec → plan → tasks 需求编译链

> 来自04课程第17/18/19/20/21讲

### 全流程

```
模糊想法 → spec.md（需求规范）
              ↓
         plan.md（计划文档）
              ↓
         tasks.md（任务拆解）
              ↓
         编码实现（AI驱动TDD）
              ↓
         代码审查（/review 标准化审查）
              ↓
         构建与交付（自动化CI/CD）
```

### AI原生开发角色转变

| 传统角色 | AI原生角色 | 变化 |
|---------|-----------|------|
| 需求分析者 | **需求编译器** | 结构化的Prompt将模糊想法编译为spec.md |
| 架构设计者 | **框架搭建者** | 搭建CLAUDE.md+constitution.md开发驾驶舱 |
| 开发者 | **AI协作者** | TDD由AI驱动，人类负责审查 |
| 测试工程师 | **质量把关者** | AI生成测试，人类定义预期行为 |

## 六、核心原则：规范驱动，而非工具驱动

- 学习通用方法论，而非特定工具的"奇技淫巧"
- 规范是入口，交付是出口
- 前后一致的可重复流程，AI原生开发的圣杯
