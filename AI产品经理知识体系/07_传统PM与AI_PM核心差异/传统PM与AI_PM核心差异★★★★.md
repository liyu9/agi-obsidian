# 传统PM与AI PM核心差异




> 来源：三节课AI知识库课程内容整理

## 一、工作流对比




> 来自课程3（工作流重塑与能力跃迁）

### 传统产品经理工作流




```
需求分析 → 交互视觉设计 → 研发功能实现 → 测试走查产品上线 → 用户反馈跟优化
```

**核心关注点**：
- 用户的需求
- 业务流程跟功能的设计
- 试图通过需求场景分析、交互设计和产品运营来实现产品价值

### AI产品经理工作流




```
需求分析（结合业务与AI能力）→ 算法工程/产品策略设计 → 系统集成/用户交互优化
→ 研发功能实现 → 测试走查产品上线 → 用户反馈跟优化
```

**关键差异**：AI产品经理在传统产品经理工作流基础上，补充了**算法工程/产品策略设计**和**系统集成**环节

---

## 二、工作要求对比




| 对比维度 | 传统产品经理 | AI产品经理 |
|---------|-------------|-----------|
| **交付目标** | 相对明确，有明确目标的功能型产品 | 不太明确，概率型产品 |
| **工作重心** | 识别业务机会点，实现产品价值 | 模型表现+用户体验 |
| **交互范式** | GUI为主 | LUI+GUI混合模式 |
| **迭代周期** | 功能开发周期为主，稳步推进 | 模型训练测试周期，不可控，频繁AB测试 |
| **资源协调** | 前后端研发资源 | 数据、算法、研发、策略等多团队 |

### AI产品经理工作重点补充说明




对于AI产品经理来说，他会更看重技术上下游，尤其是引入了算法工程团队、引入了数据团队之间的协作。

你需要重点考虑怎么将技术能力（AI模型和算法）融入到产品设计里，然后通过策略的制定去实现产品价值的最大化。

### 策略制定内容包括




- 提示工程
- 模型微调的策略
- 知识库的搭建
- 模型能力上面的集成

## 三、能力要求对比




> 来自课程3

| 能力维度 | 传统产品经理 | AI产品经理 |
|---------|-------------|-----------|
| **需求分析** | 围绕用户群体和产品商业变现投入 | 一方面需了解业务，一方面要了解AI能力，才能知道二者怎么结合，有不同情况下的场景化设计 |
| **交互设计** | 更看重用户体验跟视觉的呈现 | 更注重引导化设计：连续对话的引导、对话的推荐等 |
| **技术理解** | 基本了解推动功能实现 | 要求更高：需理解AI算法工作原理，结合具体场景定义模型目标（优化推荐、生成内容、实现对话策略、通过提示工程影响输出效果） |
| **数据分析** | 更多关注用户行为数据跟转化率，策略偏功能规则设计 | 跟策略设计息息相关，需要数据驱动，设计策略并获取高质量数据指导算法优化，对数据和策略的理解要求高很多 |
| **策略设计** | 功能规则设计 | 提示工程、知识库、微调等 |
| **团队协作** | 前后端研发 | 数据+算法+研发+策略多团队 |

**小结**：
- 传统产品经理：更偏重业务跟产品的设计
- AI产品经理：更看重AI技术理解、业务抽象和产品的实现能力

## 四、AI产品经理稀缺的原因




> 来自课程3（工作流重塑与能力跃迁）

### 1. 知识体系比较新



AI领域发展速度非常快，体系都没有很稳定的情况下，对于产品经理来说，学习能力要求非常高。

### 2. 技术门槛相对较高



AI底层技术的认知曲线比较陡峭，涉及模型原理（训练、微调）、算法机制、数据策略、提示工程等，这些外围工程能较大限度地影响模型效果和应用产出。

### 3. 复合型要求比较高



传统算法工程师懂AI但不懂产品，传统产品经理懂产品但不懂AI，需要给他时间。

### 4. 组织能力的缺口



很多公司算法跟产品是两张皮，产品落地比较难。算法有比较多前沿技术探索，但未必适用于当前产品形态。

### 5. 思维转型的问题



传统产品是确定性的产品，可以通过AB test等方式明确成效。但AI产品是概率型的产品，不确定所做的事情在用户侧有多大的效果提升。每个人用的时候得到的反馈也不一致。AI产品经理要接受这种概率型产品的思维。

## 五、AI产品经理核心定位




> 来自课程3

### 论断一：AI能力本质是手段不是目的




不管是AI 1.0还是AI 2.0，都要有自己本身产品能力的基本盘。在这个基本盘之上，如何通过AI能力的赋能帮助产品做更好的提效跟增收。AI能力跟产品之间怎么去结合，这是要实现的手段，不是目的。

以后长远来看：
- 招电商的产品经理，默认就应该学会用AI做智能推荐
- 招客服平台的产品经理，默认应该会用AI做智能客服
- 招SaaS平台的产品经理，默认需要懂得用AI做智能分析

### 论断二：每一个产品经理都要懂AI




三个必备要素：
1. **懂算法原理**：不是算法工程师，但要知道为什么工程师用这种方式微调
2. **懂数据策略**：更底层的东西，有些策略需要产品经理来定义
3. **懂模型评估**：做AI产品经理最大的难点。在AI产品中构建高质量数据飞轮是产品经理的重要工作

### 案例：Midjourney的数据飞轮




Midjourney通过让用户在四个选项中选一个，实现**百分之百的数据反馈率**，从而构建自己的高质量数据飞轮。

## 六、AI产品经理分类




> 来自课程2（AI 3.0）和课程3（工作流重塑）

### 产业链层级对应




```
基础设施层 ──→ AI平台产品经理（理解算法原理、数据策略、平台能力封装）
    ↓
模型层 ────→ 策略型产品经理（模型性能优化、预训练/微调策略）
    ↓
应用层 ────→ C端/B端/策略产品经理（面向用户/企业、对话效果设计）
```

### AI应用产品经理四象限




```
            C端
    AI原生应用      产品内嵌AI
            B端
```

### C端AI产品经理类型




| 类型 | 说明 |
|------|------|
| 端侧产品经理 | 做偏终端型的产品经理 |
| 多模态产品经理 | 懂图文、懂音乐、懂语音等 |
| 策略产品经理 | 偏把终端能力跟背后服务层能力嫁接 |
| AI开放平台产品经理 | 把AI能力封装成服务接口对外暴露 |
| 基于业务的AI产品经理 | 偏业务内嵌AI的产品经理 |

### B端AI产品经理类型




| 类型 | 说明 |
|------|------|
| 智能体开发平台产品经理 | 需要偏智能体开发平台的产品经理 |
| AI开放平台产品经理 | 把AI能力封装成服务接口 |
| 基于业务的AI产品经理 | 有足够的业务经验，结合AI能力 |

### AI产品经理五大类型（来自课程2）




| 类型 | 特点 | 适合人群 |
|------|------|---------|
| AI产品经理（软件型） | 场景需求挖掘、技术选型、产品开发 | 软件背景从业者 |
| AI产品经理（软硬件协同型） | 额外需要BOM规划、硬件外观设计、开模 | 有硬件兴趣者 |
| 行业型AI产品经理 | AI+行业融合 | 行业专家转型 |
| 消费型AI产品经理 | 零售型AI产品开发 | 消费品背景 |
| 纯AI产品经理（基站型） | 底层算法、数据、算力 | 技术背景深厚者 |

## 七、AI 1.0与AI 2.0产品经理差异




> 来自课程3

| 对比维度 | AI 1.0 | AI 2.0 |
|---------|--------|--------|
| 时间阶段 | 2010年-2022年 | 2022年至今 |
| 核心技术 | NLP、CV推荐算法、语音图像识别 | 大模型、提示工程、外挂知识库 |
| 产品形态 | AI作为功能插件 | AI作为产品主体 |
| 能力特点 | 单点、能力较弱 | 泛化能力强、内容理解生成强 |
| 交互方式 | 图形用户界面 | 自然语言交互 |
| 适用场景 | 垂直领域碎片化应用 | 智能体应用、生成式应用 |

### AI原生开发中的角色转变（极客时间补充）
来自04课程第1讲。AI-开发者集成成熟度模型：L1外部知识库→L2嵌入式副驾驶→L3自治Agent→L4 AI原生协同。核心转变：开发者从"编码者"变为"规范设计者"和"AI协作指挥者"。产品经理从"功能设计者"变为"需求编译器"——提供清晰的需求意图和验收标准即可。
