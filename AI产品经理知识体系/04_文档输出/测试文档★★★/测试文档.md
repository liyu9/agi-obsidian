> 来源：三节课AI知识库课程内容整理

## 一、AI产品测试与传统产品测试的差异




> 来自课程7（人工智能产品经理进阶提升）

| 维度 | 传统产品测试 | AI产品测试 |
|------|-------------|-----------|
| 验收标准 | 功能完整 | 模型精度达标 + 功能完整 |
| 测试对象 | 功能和流程 | 模型效果 + 功能和流程 |
| 测试结果 | 确定性（通过/不通过） | 概率性（精度指标） |

## 二、模型评估指标




### 场景化适配




> 来自课程2（AI 3.0 引领未来的实战AI产品）

| 业务场景 | 核心评估指标 | 适配原因与案例 |
|---------|-------------|--------------|
| **分类任务（风险识别）** | AUC | 衡量模型区分正负样本的能力，如信用卡欺诈检测 |
| **文本生成（内容创作）** | ROUGE + 人工评分 | ROUGE衡量与参考文本相似度，人工评分补充可读性和风格匹配度 |
| **机器翻译（跨语言沟通）** | BLEU + 语义一致性 | BLEU评估翻译准确性，语义一致性确保不偏离原文核心 |
| **图像生成（创意设计）** | FID + 人工评估 | FID衡量生成质量，人工评估创意和审美 |

### 模型期望类型选择




> 来自课程7

| 场景 | 优先指标 | 原因 |
|------|----------|------|
| **科研工作** | 精确率（Precision） | 追求准确，宁缺毋滥 |
| **医学筛查** | 召回率（Recall） | 宁错勿漏，如癌症筛查宁可误报不可漏报 |

## 四、评测执行方法




> 来自课程3（工作流重塑与能力跃迁）

### 1. 定义能力任务树




从整个场景里提炼出到底有哪些任务要去处理。

### 2. 定义评估标准




- 实际能解决的问题是什么
- 需求可以实际能解决的问题和需求是什么
- 能给出确保可执行的评估标准

**常见评估标准**：
- 回复的正确率
- 响应的及时率
- 服务的友好度

### 3. 执行评估




**常见评估方式**：
- 定义评测的题库（常见问题、边界问题）
- 评测方式：自动评测还是人为评测
- 打分的标准

## 五、微调后的验收标准




> 来自课程3

产品经理需要从业务视角定义微调后的验收标准：

| 指标 | 说明 |
|------|------|
| **准确性** | 有没有提升 |
| **一致性** | 同类问题回答的一致性有没有提升 |
| **用户满意度** | 用户是否满意 |
| **推理成本** | 成本是否可控 |

**设计对应的评估机制跟上线验收的标准**

## 六、可用性原则




> 来自课程7

```
50% → 90%：可能只需要3天
90% → 99%：可能需要1年
99% → 99.5%：可能一辈子也完不成
```

- AI项目不是科研项目，不需要追求极致精度
- 达到可用阈值即可发布上线
- 避免过度优化

## 七、复盘与问题定位




> 来自课程5（产品经理AI技术入门实战）

### 问题定位思考路径




AI反馈错误时，需要结构化思考：

```
1. 是Prompt的设计问题？
2. 还是输入的信息不足？
3. 还是任务链的顺序错了？
4. 还是知识库的命中不准？
```

**然后**：
- 调整Prompt的结构
- 加入多轮的追问去重排执行流程
- 重新去做Embedding

### 三张活表




1. **Prompt的模块表**
2. **任务链的结构图**
3. **Prompt DSL的语法库**（需要注释版本号和影响范围）

> AI最害怕的并不是答错，而是答错了你还不知道
