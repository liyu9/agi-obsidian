# 技术预研文档




> 来源：三节课AI知识库课程内容整理

## 一、技术预研是AI产品经理的核心能力




> 来自课程7（人工智能产品经理进阶提升）

> **业务技术化**：将业务需求转化为技术方案

技术预研是AI产品区别于传统互联网产品的关键环节，是AI产品经理的核心能力体现。

## 二、AI产品经理 vs 算法工程师的技术预研差异




| 角色 | 关注点 |
|------|--------|
| **算法工程师** | 纯技术方案——用什么算法，用什么框架 |
| **AI产品经理** | 业务技术化——用什么技术手段解决业务问题 |

## 三、技术预研案例：专利语义检索




> 来自课程7

```
业务需求：判断一篇新专利是否侵权/与已有专利重复
                    ↓
技术问题转化：这是一个语义检索任务
                    ↓
业务分析：专利内容可能上百页，不适合全文检索
                    ↓
聚焦范围：标题 + 摘要 + 权利要求（Claim）
                    ↓
技术细分：中文分词 → 语义相似度计算 → PageRank评分
```

## 四、技术预研文档内容




| 模块 | 内容 |
|------|------|
| 业务需求描述 | 清晰描述要解决的业务问题 |
| 技术问题转化 | 将业务问题转化为技术命题 |
| 算法选型分析 | 可选方案对比，推荐方案及理由 |
| 数据可行性 | 数据是否可获取、质量如何 |
| 技术边界评估 | 当前技术能力能否解决，成熟度如何 |
| 成本评估 | 算力、人力、时间成本估算 |

## 五、新增环节：技术展望




> 来自课程6（AI大模型在数字产品中的落地实践）

在产品规划过程中，除了围绕业务、产品、规划协同的工作之外，还需要：

- 做**技术的展望和预言**
- 知道落地过程中**有哪些能力可用**
- **哪些能力成熟度不够**，可以关注但暂时用不上

### AI大模型对各研发阶段的影响




| 研发阶段 | 传统模式 | AI时代新要求 |
|---------|---------|-------------|
| 规划 | 业务视角+产品视角 | 增加技术视角——做技术前瞻和展望 |
| 需求分析 | 洞察需求、分析场景 | 框架不变，但角色可能被解构甚至消失 |
| 产品设计 | 流程+功能+交互 | 增加AI能力融合，引入大模型能力 |
| 研发 | 功能/流程/界面研发 | 协同模型研发，协调两种不同研发模式 |
| 交付运营 | 让客户会用能用 | 设计匹配AI特性的交付流程、运营指标和策略 |

## 六、技术预研的关键判断




> 来自课程7

### 自建 vs 外包的决策




| 类型 | 适合方式 | 原因 |
|------|---------|------|
| **机器学习项目** | 可自建、可外包 | 灵活度较高 |
| **深度学习项目** | 尽量自建 | 参数调节多，需大量迭代沟通 |
| **核心竞争壁垒项目** | 必须自建 | 核心能力不能外包 |

### 不懂技术可能遇到的问题




- 与算法工程师沟通专业度不足
- 无法评价AI技术实现难度
- 不了解需要什么样的团队人员
- 不懂算力容易被卡脖子
- 不知道应该购买多少GPU
- 开发功能与投入产出不匹配
- 无法撰写AI产品规划文档和PRD
