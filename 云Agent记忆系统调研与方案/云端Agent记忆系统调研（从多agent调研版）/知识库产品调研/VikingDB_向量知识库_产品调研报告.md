# Viking 向量知识库 产品调研报告

> **调研对象**：火山引擎 Viking 向量知识库（Viking Knowledge Base）
> **调研时间**：2026-07-06
> **数据来源**：火山引擎官方文档中心、产品更新公告、墨天轮百科、官方最佳实践

---

## 摘要

Viking 向量知识库是火山引擎基于 VikingDB 向量库构建的端到端 RAG（检索增强生成）服务产品，提供「文档管理 - 语义检索 - 智能对话」一体化能力。本报告系统梳理其产品定位、核心功能、控制台核心页面与功能介绍，为企业搭建 RAG 应用提供完整的选型与实施参考。

---

## 1. 产品解决的问题

### 1.1 核心痛点

企业在落地大模型问答场景时普遍面临三类痛点：

| 痛点 | 描述 |
|---|---|
| **知识局限** | 大模型缺乏企业内部专属知识，无法回答专业问题 |
| **幻觉问题** | 大模型可能编造信息，权威性不足 |
| **检索不准** | 传统关键词检索难以匹配语义相近的提问方式 |

Viking 向量知识库通过「文档智能解析 + 向量语义检索 + 大模型推理」三段式链路解决上述问题，使企业能够基于私有文档构建准确、专业的问答系统。

### 1.2 产品定位

> **Viking 向量知识库**是火山引擎提供的检索增强生成（RAG）服务，能够智能解析分段结构化和非结构化文档，通过向量检索实现精准的语义匹配，结合大模型推理能力，为企业客户提供更准确、专业的问答效果。

- **底层依赖**：基于 VikingDB 向量库（百亿级存储 + 毫秒级检索）
- **服务形态**：SaaS 化云服务，控制台 + API + SDK
- **数据支持**：结构化 + 非结构化 + 多模态

### 1.3 应用场景

| 场景 | 典型描述 |
|---|---|
| **客服应用** | 基于企业 FAQ 与工单文档构建智能客服 |
| **个人知识库** | 个人学习资料、笔记的统一管理与问答 |
| **车机助手** | 车型手册、维修指南的智能问答 |
| **论文伴读** | 学术论文的解析与问答 |
| **法律文档问答** | 法规、判例的检索式问答 |
| **企业文档管理** | 内部规章、制度、流程的集中问答 |

## 2. 核心功能与功能作用

### 2.1 三大核心能力

| 能力 | 功能作用 |
|---|---|
| **文档管理** | 智能解析结构化和非结构化文档，自动分段、向量化、构建索引 |
| **语义检索** | 基于向量相似度匹配用户问题，召回最相关的文档片段 |
| **智能对话** | 结合大模型推理能力，根据召回内容生成专业、可控的回复 |

### 2.2 文档管理

#### 2.2.1 支持的文档类型与规格

**非结构化文档**：

| 文档类型 | 规格 |
|---|---|
| pdf | 350 MB，5000 页 |
| doc/docx | 350 MB |
| ppt/pptx | 200 MB |
| markdown | 5 MB |
| txt | 5 MB |
| faq.xlsx | 50 sheet，文件行数总和 30000 行 |
| 图片（JPEG/PNG/WEBP/BMP/TIFF 等） | 单文件不超过 8 MB，宽高比 [1/100, 100]，边长 [10, 6000] 像素 |
| mp4 | 本地 350 MB；URL/TOS 1 GB |

**结构化文档**：

| 文档类型 | 规格 |
|---|---|
| jsonl | 30000 行，单行不超过 65535 个字符 |
| csv | 50 sheet，文件行数总和 30000 行 |
| xlsx | 50 sheet，文件行数总和 30000 行 |

#### 2.2.2 文档上传方式

| 上传方式 | 适用场景 |
|---|---|
| **前端本地上传** | 单次最多 100 个文档，适合小批量 |
| **TOS 桶批量导入** | 适合大规模历史文档迁移（推荐方案） |
| **URL 导入** | 适合导入在线可访问的文档 |
| **API/SDK 导入** | 适合集成到自动化流程（支持 TOS/URL 方式） |

#### 2.2.3 切片（Chunking）管理

知识库自动将文档拆分为「切片」，每个切片最大 **8000 tokens**，单个文档支持最大 **10 万个切片**。

| 切片操作 | 功能说明 |
|---|---|
| **查阅切片** | 在知识库详情页点击「切片详情」可查阅切片内容 |
| **编辑切片** | 支持手动调整切片内容，修正分段质量 |
| **删除切片** | 支持删除指定切片 |
| **元数据（meta）** | 可在导入时为文档配置 `doc_id` 等元数据，便于后续按 ID 精准召回 |

### 2.3 向量化与索引

#### 2.3.1 支持的向量化模型

| 模型 | 特点 |
|---|---|
| **Doubao-embedding+多功能版** | 多语言 + 长文本，可同时进行稀疏和稠密索引 |
| **Doubao-embedding** | 字节自研，中英双语，高精度纯语义检索，4k Token 输入窗口 |
| **Doubao-embedding-large** | Doubao-embedding 增强版 |
| **短文本高精度+多功能版** | 短文本高精度 |
| **短文本高精度版** | 短文本高精度 |
| **Doubao-embedding-vision-text** | 图文场景下的文本向量服务 |
| **Doubao-embedding-vision-image** | 图文场景下的图片向量服务 |

#### 2.3.2 向量维度与索引

- **向量维度**：最高 4096 维
- **索引能力**：基于 VikingDB 向量库，支持稠密、稀疏、稠密+稀疏混合索引
- **重排序**：内置 Rerank 模型对召回结果进行二次精排

### 2.4 检索能力

| 检索能力 | 说明 |
|---|---|
| **语义检索** | 基于向量相似度的语义匹配 |
| **关键词检索** | 稀疏向量检索，适合专有名词、术语 |
| **混合检索** | 稠密 + 稀疏向量混合检索（推荐方案） |
| **标量过滤** | 按元数据（如 doc_id、文档类型）过滤 |
| **召回数量** | 单次最多召回 200 个文本片段 |
| **标签检索** | 单个知识库最多 180 个标签，单次检索单一标签可指定 1024 个值 |

### 2.5 智能对话

| 配置项 | 说明 |
|---|---|
| **大模型选择** | 接入方舟大模型平台，按 input/output tokens 分别计费 |
| **Prompt 配置** | 支持自定义 system prompt 与业务提示语 |
| **重排模型** | 可选配 Rerank 模型对召回结果精排 |
| **MCP Server 集成** | 支持通过 MCP Server 将知识库能力暴露给外部 Agent |

### 2.6 高级能力

| 能力 | 说明 |
|---|---|
| **标签管理** | 单个知识库支持最大 180 个标签 |
| **结构化表字段** | 单个知识库最多支持 380 个结构化表字段 |
| **Rerank 限流** | 默认 15 万 tokens/秒，可申请提高 |
| **分账管理** | 支持按团队/项目分账（知识库分账管理） |

### 2.7 SDK 与集成

| SDK | 用途 |
|---|---|
| **Python SDK** | volcengine.viking_knowledgebase 模块 |
| **TOS SDK** | 对象存储集成，用于批量上传 |
| **方舟大模型 SDK** | 大模型推理调用 |
| **MCP Server** | 模型上下文协议接入，标准化 Agent 调用 |

## 5. 总结与判断

Viking 向量知识库本质上是把「VikingDB 向量检索能力 + 方舟大模型推理能力」封装为标准化的 RAG 服务，让企业无需自建检索-生成链路即可拥有专业问答能力。

从功能设计角度看，Viking 向量知识库有三大差异化优势：
- **检索精度高**：支持稠密+稀疏混合检索 + Rerank 重排，召回效果优于纯向量方案；
- **多模态原生**：从向量模型到文档解析全链路支持图文多模态；
- **生态集成完整**：内置 TOS 对象存储、方舟大模型、MCP Server、实时对话式 AI（RTC） 等火山引擎全栈能力，可一键打通企业级 AI 应用。

对企业用户而言，Viking 向量知识库的关键选型决策点是**「旗舰版 vs 标准版」**：旗舰版按 CU 独占计费，适合生产环境高并发检索（QPS 上限 1 万）；标准版按知识库数量共享计费，适合测试与个人开发（QPS 上限仅 1）。

### 5.1 基于实际控制台的洞察

通过分析控制台截图，可以提炼出以下用户视角的关键洞察：

**洞察 1：四步引导教程降低接入门槛**

知识库首页直接展示「创建知识库 → 上传文档 → 检索问答 → API 调用」四个步骤，每个步骤附简短说明和示意图。这种设计明显降低了 RAG 产品的接入门槛，让非技术用户也能在 5 分钟内理解全流程。

**洞察 2：版本对比透明化定价策略**

选择版本弹窗用并排卡片对比两版功能差异（知识库类型、上传额度、QPS 上限、计费方式），用户无需跳转其他页面就能完成版本决策。这种"所见即所得"的对比设计大幅降低了企业用户的选型成本。

**洞察 3：三级 Tab 组织管理任务**

知识库详情页用「原始文档 → 切片详情 → 知识检索 → 知识问答」四个 Tab 组织管理任务，覆盖了文档生命周期管理（上传/查看/删除）、切片质量验证、检索效果调试、问答测试四个核心场景。这种结构让用户在一个页面内即可完成日常运营工作。

**洞察 4：检索参数面板化降低调优难度**

知识检索 Tab 把 Top-k、重排模型、Dense Weight、阈值过滤、行业库扩展检索等专业参数全部可视化，用户无需阅读 API 文档即可调试检索效果。重排模型选择还附带详细的指令编辑、计费单价、输入上限信息，体现"既给能力又给指引"的产品设计哲学。

**洞察 5：免费试用 + 到期提醒引导转化**

顶部横幅显示"30 天免费已到期，30 天后将自动删除，如需继续使用，可续为标准版计费知识库"，通过明确的免费期限制 + 一键续费路径，引导免费用户向付费用户转化，是典型的 SaaS 增长策略。
