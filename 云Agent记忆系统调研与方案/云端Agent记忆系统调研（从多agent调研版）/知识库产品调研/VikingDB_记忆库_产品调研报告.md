# Viking 记忆库（长期记忆）产品调研报告

> **调研对象**：火山引擎 Viking 记忆库（Viking Long-term Memory）
> **调研时间**：2026-07-06
> **数据来源**：火山引擎官方文档中心、官方产品介绍、私网连接文档、快速开始与创建记忆库文档、官方最佳实践

---

## 摘要

Viking 记忆库（长期记忆）是火山引擎推出的标准化长期记忆产品，旨在为 AI 应用提供持久记忆能力。它通过"自动记忆抽取 + 结构化画像生成 + 向量检索"三段式链路，从对话与业务数据中持续沉淀关键事件与用户画像，并结合 VikingDB 向量数据库实现百亿级规模存储与毫秒级检索。本报告围绕该产品从产品定位、核心功能、核心页面、控制台页面结构四个维度展开系统梳理，为企业级 AI 应用引入长期记忆能力提供完整选型与实施参考。

---

## 1. 产品解决的问题

### 1.1 核心痛点

AI 应用在长期交互场景中普遍面临"金鱼记忆"问题：

| 痛点 | 描述 | 业务影响 |
|---|---|---|
| **上下文丢失** | 跨会话对话历史无法保留 | 用户每次开聊都要重新介绍自己 |
| **个性化不足** | AI 无法记住用户偏好 | 推荐、陪伴体验单调 |
| **信息提取困难** | 长对话中的关键事件难以沉淀 | 用户重要数据散落在历史中 |
| **多角色混乱** | 用户、助手、群组记忆无法隔离 | 数据串台，体验混乱 |

Viking 记忆库通过"事件抽取 + 画像生成 + 多层级隔离 + 向量化检索"机制，让 AI 真正拥有跨会话的持久记忆。

### 1.2 产品定位

> **Viking 长期记忆**是火山引擎推出的标准化长期记忆产品，旨在为 AI 应用提供持久记忆能力。该产品能够从对话和业务数据中自动抽取关键事件与用户画像，并以结构化形式保存，结合 VikingDB 向量数据库实现百亿级规模存储与毫秒级检索。记忆库支持自定义事件与画像模板，并具备用户、助手、群组等多层级记忆隔离能力。

- **底层依赖**：基于 VikingDB 向量数据库，支持百亿级存储 + 毫秒级检索
- **服务形态**：SaaS 化云服务，控制台 + OpenAPI/SDK
- **核心机制**：事件抽取 + 画像生成 + 向量检索 + 多层级隔离
- **索引策略**：向量检索 + 张量重排，确保召回精准

### 1.3 应用场景

| 场景 | 典型描述 |
|---|---|
| **社交陪伴 AI** | 记住用户的性格、兴趣、表达习惯，提供个性化陪伴 |
| **教育陪练** | 追踪学员知识点掌握情况，动态调整学习路径 |
| **智能硬件助手** | 记住家庭成员习惯，提供主动服务 |
| **AI 客服** | 记住用户历史订单与偏好，提供连贯服务 |
| **客户服务与营销** | 基于用户画像沉淀，实现个性化沟通与精准推荐 |
| **多轮对话 AI 应用** | 跨会话维持上下文与个性化体验 |

## 2. 核心功能与功能作用

### 2.1 三大核心能力

| 核心能力 | 功能作用 |
|---|---|
| **自动记忆抽取** | 平台根据模板规则自动从会话中抽取事件与画像，无需业务侧二次开发 |
| **结构化画像生成** | 将抽取结果沉淀为结构化画像，并支持按模板持续演化 |
| **向量检索与重排** | 基于 VikingDB 向量数据库实现毫秒级语义检索 + 张量重排提升精度 |

### 2.2 数据写入

| 写入方式 | 接口 | 触发时序 | 典型用途 |
|---|---|---|---|
| **批式写入** | `AddSession` | 调用即触发批式抽取 | 一批会话数据同步入库 |
| **实时流式写入** | `StreamingWrite` | 按 `trigger` 自动判断 | 对话进行中的实时记忆抽取 |

> 关键提示：`AddSession` 接口在使用相同 `session_id` 时会覆盖该会话产生的画像与事件，官方建议使用 UUID 动态生成 `session_id`，确保每次会话独立。

### 2.3 事件记忆管理

事件记忆用于捕捉"发生过什么"。通过 `事件记忆规则` 配置，控制台支持三类字段：

| 字段 | 说明 |
|---|---|
| **事件规则名称** | 用于唯一标识该事件规则 |
| **事件抽取方法** | 描述如何抽取、抽取哪些要素（人物、时间、动作等） |
| **事件字段定义** | 自定义抽取出的字段名、类型与描述（如 `summary`、`event_time`） |
| **事件权重** | 固定权重（默认 0.5）或按字段表达式动态计算，影响最终得分 |

### 2.4 画像记忆管理

画像记忆用于沉淀"用户是什么样的"。控制台支持以下维度：

| 字段 | 说明 |
|---|---|
| **画像规则名称** | 用于唯一标识画像规则 |
| **画像抽取方法** | 描述画像构成（如基础信息、兴趣偏好、地理位置等） |
| **按 assistant 隔离** | 开启后，同一用户在不同 assistant 下的画像相互独立、分别演化 |
| **记忆更新时机** | 实时 / 每日 00:00 / 每周一 00:00 / 手动调用接口更新 |
| **记忆更新方式** | 覆盖更新（持续演化） / 新增并保存历史 |
| **画像字段定义** | 自定义字段名、类型与描述（如 `basic_info`、`interests`） |
| **高级配置** | 关联事件：用事件数据补全画像中的数值类信息 |

### 2.5 记忆检索与调用

| 接口 | 检索维度 | 检索时机 |
|---|---|---|
| `GetContext` | 短期 + 长期记忆（按 `conversation_id`） | 与实时写入配套使用，直接拼接到对话模型 prompt |
| `SearchEventMemory` | 事件记忆（按 `user_id` 或 `assistant_id`） | 建议每轮对话都进行检索 |
| `SearchProfileMemory` | 画像记忆（按 `user_id` 或 `assistant_id`） | 通常在会话开始时进行一次检索即可 |

> 索引构建约需 **3–5 分钟**；索引创建完成后，新增会话到可检索的延迟约 **15 秒**。

### 2.6 多层级隔离与记忆有效期

| 隔离维度 | 说明 |
|---|---|
| **用户级** | 每个 `user_id` 拥有独立的画像与事件空间 |
| **助手级** | 同一用户在不同 `assistant_id` 下画像互不干扰 |
| **群组级** | 在群聊 / 多人协作场景下按 `group_id` 记忆隔离 |

**记忆有效期**：默认为整个记忆库设置统一的 TTL 策略，可选**永久保留**或**自动过期**（指定时长），用于成本控制。

### 2.7 SDK 与集成

| 集成方式 | 入口 | 说明 |
|---|---|---|
| **OpenAPI** | 火山引擎 API 网关 | 适配签名生成脚本直接调用 |
| **SDK** | 多语言 SDK（兼容初始化域名） | 初始化脚本中将公网域名替换为终端节点域名即可私网访问 |
| **私网连接 PrivateLink** | 创建接口终端节点 | 服务名 `com.volces.privatelink.cn-beijing.vikingdb-knowledge` |
| **MCP Server** | 第三方客户端（如 Claude/Cursor） | 用于将记忆库工具暴露给 LLM 客户端 |

## 5. 总结与判断

### 5.1 基于官方手册的洞察

1. **标准化能力**：把"长期记忆"从过去需要业务自建抽取 + 向量库 + 隔离机制的链路，封装为 SaaS 化服务，降低了 AI 应用接入持久记忆的工程成本；
2. **模板化抽取**：事件 / 画像规则作为一等公民，平台同时支持内置模板与自定义字段，意味着业务可以在不动 API 的前提下调整记忆语义；
3. **多级隔离**：user / assistant / group 三级隔离让产品可以同时支持 ToC、ToB、群聊等不同业务粒度的隐私要求；
4. **持久化策略**：内置 TTL 与"实时 / 每日 / 每周 / 手动"四档更新时机，体现了对成本与召回新鲜度的平衡。
