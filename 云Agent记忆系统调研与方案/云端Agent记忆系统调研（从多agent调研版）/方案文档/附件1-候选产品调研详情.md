## 1. OpenViking（详尽）

### 1.1 产品定位
OpenViking 是**火山引擎开源**的记忆中间件，主打**文件系统式抽象**：以 `agent/user/team/resource` 分级目录承载不同层次的记忆，任何 Agent 可通过 HTTP/SDK 访问同一份目录树。

### 1.2 核心设计
- **L0/L1/L2 三层信息模型**：L0 abstract（~100 tokens，用于向量检索）+ L1 overview（~1k tokens，用于 rerank 与直接注入）+ L2 detail（原始文件，按需加载）
- **flat_hybrid 索引**：dense + sparse 混合，cosine 距离 + int8 量化
- **两阶段检索**：向量召回 + doubao-seed-rerank
- **多租户模型**：account / user / peer 三级 ID + ROOT/ADMIN/USER 三种角色
- **静态加密**：KMS + 租户密钥；账号密钥物理隔离
- **可观测**：Prometheus 指标族（rerank_used_total、检索延迟直方图等）
- **许可**：AGPL-3.0

### 1.3 能力映射（§4.4 × §4.5）

**A. §4.4 Agent 记忆系统核心能力**
- **作用域与隔离**：⚠️ 目录级天然分层（agent/user/resource/team）；企业级 ACL 需自建 [Concepts 11 Multi-tenant](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/11-multi-tenant.md)
- **记忆写入**：✅ 文件式写入 + L0/L1/L2 摘要 + 原文；官方 Parser + SessionCompressorV2 抽取管线 [Concepts 06 Extraction](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/06-extraction.md)
- **记忆类型**：✅ 事实/偏好/文档；实体-关系型弱
- **记忆召回**：✅ 向量 + 关键词 + 元数据过滤；两阶段 vector recall + doubao-seed-rerank [Concepts 07 Retrieval](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/07-retrieval.md)
- **生命周期**：⚠️ 读写完备 + 事务锁；去重/合并/版本化需自建
- **跨 Agent 共享**：✅ HTTP API + Python/Go SDK；TypeScript/Java 需走 HTTP
- **治理与安全**：⚠️ AGPL-3.0 自托管 + 静态加密 + KMS + 租户密钥；ROOT/ADMIN/USER 三角色 [Concepts 10 Encryption](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/10-encryption.md)；SOC 2 / HIPAA 合规证书 `INSUFFICIENT_DATA`
- **可观测性**：✅ Prometheus 指标族 + rerank_used_total + 检索延迟直方图 [Concepts 12 Metrics](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/12-metrics.md)

**B. §4.5 RAG / 向量底座**
- **数据处理（§4.5.1）**：⚠️ 文件式承载；Parser 支持 Markdown/PDF/HTML/Image/Video/Audio；L2 层挂原文 + VLM 描述
- **数据存储（§4.5.2）**：✅ 内置 dense + sparse；flat_hybrid（cosine + int8 量化）；LOCOMO 端到端千万级案例 [Concepts 05 Storage](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/05-storage.md)
- **数据获取（§4.5.3）**：✅ 向量 + 关键词 + 元数据；内置 doubao-seed-rerank；阈值需上层实现

### 1.4 与本场景的契合度（回答 §3 5 道业务题）

- **多 Agent 共享**：✅ HTTP + Python/Go SDK；`agent/user/team/resource` 分级目录天然可被多 Agent 共享读写 [Multi-tenant](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/11-multi-tenant.md)
- **四层分级**：✅ L0/L1/L2 三层信息模型 + 目录分层承载 短期/工作/长期/归档 [Context Layers](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/03-context-layers.md)
- **三级隔离**：⚠️ 目录级承载"部门/个人/会话"（`team/{dept}/` + `user/{uid}/` + `agent/{aid}/session/`），但**部门级 ACL 需自建** [Multi-tenant](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/11-multi-tenant.md)
- **企业治理**：⚠️ 加密 + KMS + 租户密钥 + audit log；SOC 2 / HIPAA 官方认证 `INSUFFICIENT_DATA` [Encryption](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/10-encryption.md)
- **可观测**：✅ Prometheus 指标族原生暴露，可直接接 Grafana [Metrics](https://raw.githubusercontent.com/volcengine/OpenViking/main/docs/en/concepts/12-metrics.md)

### 1.5 差异化亮点与限制

- **独特优势**：4 款中**唯一**提供"文件系统式抽象 + 内置 doubao-seed-rerank + 原生 Prometheus 指标族 + 火山生态亲和"的开源候选；分级目录直接映射公司/部门/个人四级
- **独特短板**：**部门级 ACL / 企业合规资质**需自建；SDK 只覆盖 Python/Go，TypeScript/Java 走 HTTP；实体-关系记忆弱

## 2. Mem0（重点）

### 2.1 产品定位
Mem0 是**开源的个人化记忆中间件**，主打**从对话中被动抽取事实/偏好**，通过 4 级 ID（user/agent/run/app）原生隔离；商业版有 SOC 2 + HIPAA。

### 2.2 核心设计
- **add API + LLM 自动抽取**：对话结束时自动从消息序列抽取事实、偏好、关系
- **V3 ADD-only 抽取**：仅添加新事实，冲突由 update API 处理
- **20+ 向量后端**：Qdrant / Pinecone / Weaviate / pgvector / Milvus 等
- **v2 search API**：内置 rerank + BM25 + entity 融合 + threshold 默认 0.3
- **合规**：SOC 2 Type 1 + HIPAA + BYOK + Air-gapped（企业版）
- **Mem0 Platform**：命中率 / 延迟 / 成本看板

### 2.3 能力映射（§4.4 × §4.5）

**A. §4.4 Agent 记忆系统核心能力**
- **作用域与隔离**：✅ user_id / agent_id / run_id / app_id 四级 ID 原生 [Add Memories API](https://docs.mem0.ai/api-reference/memory/add-memories)
- **记忆写入**：✅ add API + LLM 自动抽取事实/偏好；V3 ADD-only 抽取
- **记忆类型**：✅ 事实/偏好为主 [Memory Types](https://docs.mem0.ai/core-concepts/memory-types)；文档/实体-关系弱
- **记忆召回**：✅ 向量 + 元数据过滤；semantic + BM25 + entity 并行融合 [v2 Search API](https://docs.mem0.ai/api-reference/memory/v2-search-memories)
- **生命周期**：✅ add/update/delete + 内置去重合并
- **跨 Agent 共享**：✅ Python + TypeScript SDK + HTTP API；跨语言 SDK 生态完整
- **治理与安全**：✅ SOC 2 Type 1 + HIPAA + BYOK + Air-gapped（企业版） [Mem0 官网](https://mem0.ai/)
- **可观测性**：✅ Mem0 Platform 面板（企业版）；每次读写审计；开源版指标 `INSUFFICIENT_DATA`

**B. §4.5 RAG / 向量底座**
- **数据处理（§4.5.1）**：⚠️ 主要吃对话文本；图像 ≤20MB（JPEG/PNG/WebP/GIF） [Multimodal Support](https://docs.mem0.ai/open-source/features/multimodal-support)；无内置文档解析
- **数据存储（§4.5.2）**：✅ 20+ 后端可选（Qdrant/Pinecone/Weaviate/pgvector/Milvus 等） [Vector Stores Overview](https://docs.mem0.ai/components/vectordbs/overview)；元数据可查询；条目级容量 `INSUFFICIENT_DATA`
- **数据获取（§4.5.3）**：✅ v2 search 内置 rerank 参数 + threshold 默认 0.3 [v2 Search API](https://docs.mem0.ai/api-reference/memory/v2-search-memories)；user_id/agent_id/元数据过滤

### 2.4 与本场景的契合度（回答 §3 5 道业务题）

- **多 Agent 共享**：✅ user_id 命名空间 + Python/TypeScript SDK + HTTP，跨 Agent 通过共享 user_id 复用 [Add Memories API](https://docs.mem0.ai/api-reference/memory/add-memories)
- **四层分级**：⚠️ run_id 承载短期、user_id 承载长期；工作/归档层需应用层拼装 [Memory Types](https://docs.mem0.ai/core-concepts/memory-types)
- **三级隔离**：✅ 四级 ID（user/agent/run/app）原生映射个人/Agent/会话；**部门级需在应用层加 dept_id 元数据过滤**
- **企业治理**：✅ SOC 2 Type 1 + HIPAA + BYOK + Air-gapped（企业版）；开源版依部署侧 [Mem0 官网](https://mem0.ai/)
- **可观测**：✅ Platform 版命中/延迟/成本看板 + 每次读写审计；开源版指标 `INSUFFICIENT_DATA`

### 2.5 差异化亮点与限制

- **独特优势**：4 款中**唯一**同时公开 **SOC 2 Type 1 + HIPAA + BYOK + Air-gapped** 的产品；4 级 ID 原生隔离；LLM 论文级抽取（arXiv:2504.19413）
- **独特短板**：**文档 / 实体-关系记忆弱**；开源版无内置可观测面板；部门级隔离要靠元数据过滤，非目录级

## 3. Letta（原 MemGPT）（重点）

### 3.1 产品定位
Letta（前身 MemGPT）是**分层记忆 Agent 框架**，主打 **Core / External / Archival / Conversation** 四类记忆分层，是唯一原生支持"多 Agent 共享 memory blocks"的框架。

### 3.2 核心设计
- **四层记忆**：Core（<50k chars）+ External（工具调用）+ Archival（长期向量）+ Conversation（历史）
- **显式工具调用**：memory_replace / memory_insert / memory_rethink 由 LLM 主动决策
- **hybrid + RRF**：向量 + FTS 融合；无独立神经 Rerank
- **多 Agent 原生共享**：多个 Agent 可读同一份 memory blocks，支持 read-only 权限
- **sleep-time 后台整合**：agent 空闲时自动做 recursive summary
- **可观测**：OTel Trace + ClickHouse / Signoz / Datadog / Grafana

### 3.3 能力映射（§4.4 × §4.5）

**A. §4.4 Agent 记忆系统核心能力**
- **作用域与隔离**：⚠️ 框架层 user/agent 隔离；企业级 ACL 自建；Cloud Enterprise 提供 RBAC + SSO(SAML/OIDC) [Cloud Plans](https://docs.letta.com/guides/cloud/plans)
- **记忆写入**：✅ 显式工具调用写入 core/archival；memory_replace/insert/rethink [Context Engineering](https://docs.letta.com/guides/agents/context-engineering)
- **记忆类型**：✅ Core / External / Archival / Conversation 四层 [Memory](https://docs.letta.com/guides/agents/memory)；事实/偏好/过程/文档；实体-关系弱
- **记忆召回**：✅ 向量 + 全文（archival）hybrid + RRF 融合 [Archival Search](https://docs.letta.com/guides/agents/archival-search)；**无独立神经 Rerank**
- **生命周期**：✅ 显式 update/delete + FIFO 层 recursive summary + sleep-time 后台整合 [Context Engineering](https://docs.letta.com/guides/agents/context-engineering)
- **跨 Agent 共享**：✅ 多 Agent 原生共享 memory blocks（可 read-only） [Multi-agent Shared Memory](https://docs.letta.com/guides/agents/multi-agent-shared-memory)
- **治理与安全**：⚠️ Enterprise 提供 RBAC + SSO + Private Deployment；SOC 2 / HIPAA 官方认证 `INSUFFICIENT_DATA`
- **可观测性**：✅ OTel + ClickHouse/Signoz/Datadog/Grafana [Server OTel](https://docs.letta.com/guides/server/otel)

**B. §4.5 RAG / 向量底座**
- **数据处理（§4.5.1）**：⚠️ 以对话为主；archival passage ≤300 tokens 简单分段；图像输入依赖底座模型 [Context Hierarchy](https://docs.letta.com/guides/agents/context-hierarchy)
- **数据存储（§4.5.2）**：⚠️ TurboPuffer(Cloud) / pgvector(自托管) / SQLite-vec(Desktop)；Memory Blocks <50k characters / <20 blocks [Context Hierarchy](https://docs.letta.com/guides/agents/context-hierarchy)
- **数据获取（§4.5.3）**：✅ RRF 融合 vector + FTS [Archival Search](https://docs.letta.com/guides/agents/archival-search)；**无独立神经 Rerank**；分数返回，阈值上层实现

### 3.4 与本场景的契合度（回答 §3 5 道业务题）

- **多 Agent 共享**：✅ **唯一**原生支持"多 Agent 共享同一份 memory blocks + read-only 权限"的框架 [Multi-agent Shared Memory](https://docs.letta.com/guides/agents/multi-agent-shared-memory)
- **四层分级**：✅ Core / External / Archival / Conversation 四层原生 [Memory](https://docs.letta.com/guides/agents/memory)
- **三级隔离**：⚠️ 框架层 user/agent 隔离；部门级需 Cloud Enterprise RBAC [Cloud Plans](https://docs.letta.com/guides/cloud/plans)
- **企业治理**：⚠️ RBAC / SSO / Private Deployment（Enterprise）；SOC 2 / HIPAA `INSUFFICIENT_DATA`
- **可观测**：✅ OTel + ClickHouse/Signoz/Datadog/Grafana 全套观测栈 [Server OTel](https://docs.letta.com/guides/server/otel)

### 3.5 差异化亮点与限制

- **独特优势**：4 款中**唯一**原生"多 Agent 共享 memory blocks + read-only 权限"；4 类记忆分层最完整；OTel + ClickHouse 观测栈最完整
- **独特短板**：记忆管理是"**显式 LLM 调用**"模式，2000 人高频场景成本显著高于 Mem0/OpenViking；**无独立神经 Rerank**；archival passage ≤300 tokens 限制文档场景

## 4. Cognee（概览）

### 4.1 产品定位
Cognee 强调 **"认知图 + 向量"融合**：把文档/对话先抽取为**实体-关系图**，再做向量与图混合检索，主打"减少 LLM 幻觉、让记忆有结构"。

### 4.2 核心设计
- **认知图 + 向量混合**：文档 → 抽取实体-关系图 → 与向量并存；`remember / recall / improve / forget` 主操作
- **默认后端**：图 = **Kuzu**（可换 Neo4j / Neptune / Memgraph）；向量 = **LanceDB**（可换 PGVector / ChromaDB / Qdrant / Redis / FalkorDB）
- **数据处理管线**：内置 Text / PDF / Unstructured / Docling 解析；**ImageLoader + AudioLoader** 多模态；AdvancedPdfLoader + OCR
- **多用户权限**：`ENABLE_BACKEND_ACCESS_CONTROL` + **Read / Write / Delete / Share** ACL，dataset 粒度
- **可观测**：OTEL Collector + 结构化日志 + audit trails（2026-06 已移除 Sentry/Langfuse）
- **检索排序**：`wide_search_top_k` + `triplet_distance_penalty` + `CHUNKS_LEXICAL`（**无独立 Cross-Encoder Rerank**）
- **许可**：Apache-2.0；官网口径 5M+ SDK runs/month，26.1k GitHub Stars

### 4.3 能力映射（§4.4 × §4.5）

**A. §4.4 Agent 记忆系统核心能力**
- **作用域与隔离**：⚠️ 自托管可控 + 多用户 ACL；企业级 ACL 平台 `INSUFFICIENT_DATA` [Multi-user Overview](https://docs.cognee.ai/core-concepts/multi-user-mode/multi-user-mode-overview)
- **记忆写入**：✅ 自动抽取实体-关系图；`remember` session vs permanent [Core Concepts Overview](https://docs.cognee.ai/core-concepts/overview)
- **记忆类型**：✅ 实体-关系图为最大特色；事实/文档亦覆盖 [Architecture](https://docs.cognee.ai/core-concepts/architecture)
- **记忆召回**：✅ 向量 + 图混合；Auto-routing、session-aware `recall`
- **生命周期**：⚠️ `forget` 支持；图去重需上层维护
- **跨 Agent 共享**：⚠️ SDK 接入；MCP + Claude Code + Cursor + LangGraph 集成；多 Agent 成熟度弱
- **治理与安全**：⚠️ 自托管 + **Read/Write/Delete/Share** 4 类 ACL，dataset 粒度 [Permissions System](https://docs.cognee.ai/core-concepts/multi-user-mode/permissions-system/overview)；SOC 2 / HIPAA `INSUFFICIENT_DATA`
- **可观测性**：✅ OTEL Collector + 结构化日志 + audit trails（2026-06 已移除 Sentry/Langfuse）

**B. §4.5 RAG / 向量底座**
- **数据处理（§4.5.1）**：✅ Text/PDF/Unstructured/Docling 解析；ImageLoader + AudioLoader；AdvancedPdfLoader + OCR [Loaders](https://docs.cognee.ai/core-concepts/further-concepts/loaders)
- **数据存储（§4.5.2）**：✅ 图 = **Kuzu**（默认）/ Neo4j / Neptune / Memgraph；向量 = **LanceDB**（默认）/ PGVector / ChromaDB / Qdrant [Graph Stores](https://docs.cognee.ai/setup-configuration/graph-stores) [Vector Stores](https://docs.cognee.ai/setup-configuration/vector-stores)
- **数据获取（§4.5.3）**：✅ hybrid vector + graph 合并；`triplet_distance_penalty` 排序；**无独立 Cross-Encoder Rerank**

### 4.4 与本场景的契合度（回答 §3 5 道业务题）

- **多 Agent 共享**：⚠️ SDK + MCP 集成（Claude Code / Cursor / LangGraph），但多 Agent 编排成熟度弱于 Mem0/Letta
- **四层分级**：⚠️ session vs permanent 二分；工作/归档层需应用层拼装
- **三级隔离**：✅ 多用户 ACL + dataset 粒度 Read/Write/Delete/Share 4 类权限 [Permissions System](https://docs.cognee.ai/core-concepts/multi-user-mode/permissions-system/overview)
- **企业治理**：⚠️ 自托管 + ACL；SOC 2 / HIPAA `INSUFFICIENT_DATA`
- **可观测**：✅ OTEL Collector + audit trails

### 4.5 差异化亮点与限制

- **独特优势**：4 款中**唯一**内置"实体-关系图 + 向量混合"；ACL 是唯一提供 4 类权限（Read/Write/Delete/Share）+ dataset 粒度的开源候选；数据处理管线最丰富（Text/PDF/Unstructured/Docling + Image/Audio Loader）
- **独特短板**：**多 Agent 成熟度弱**；图数据库运维成本高；无独立 Cross-Encoder Rerank；分层记忆抽象弱（session/permanent 二分）
