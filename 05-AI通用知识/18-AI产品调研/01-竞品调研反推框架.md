# AI Agent 竞品调研反推框架
### ——"交互层 + 技术层"双维度融合框架

> 本框架融合了交互设计视角（澄清机制、收敛判断）与技术架构视角（任务拆解、工具匹配），形成完整的 AI Agent 竞品反推方法论。

---

## 📌 文档说明

**目的**：系统反推竞品 AI Agent 的思考链路、产品设计、核心模块、架构逻辑，为自身产品需求设计、架构优化、差异化竞争提供依据。

**适用范围**：
- 企业级工具型 AI Agent（办公自动化、飞书/钉钉生态）
- 基于 OpenClaw、LangChain 等框架的 Agent
- 需求获取型 Agent（如表单创建、问卷设计）
- 工具调用型 Agent（如飞书操作、数据处理）

**前置条件**：
- 已明确调研竞品的核心场景
- 可通过实测、官方文档、产品演示，捕获 Agent 完整思考链路
- 了解调研竞品的基础技术生态

#### 【阶段2-5】信息获取与收敛

**三关检查机制**（框架创新点）：

```
┌─────────────────────────────────────────────────────────────────┐
│                        三关检查设计                               │
├─────────────────────────────────────────────────────────────────┤
│ 第1关：主表实体唯一性                                            │
│   ├─ 检查内容：核心管理对象是否唯一                              │
│   ├─ 判定标准：主表唯一性→通过，否则→澄清                       │
│   └─ 示例：知识库条目 → 唯一 → 通过                             │
├─────────────────────────────────────────────────────────────────┤
│ 第2关：写作策略确认                                              │
│   ├─ 检查内容：expert 模式是否确定                              │
│   ├─ 判定标准：模式确定→通过，否则→澄清                         │
│   └─ 示例：standard + expert → 自动通过                         │
├─────────────────────────────────────────────────────────────────┤
│ 第3关：越界检查                                                  │
│   ├─ 检查内容：需求是否在产品能力范围内                          │
│   ├─ 判定标准：能力范围内→通过，否则→拦截                       │
│   └─ 示例：AI分类/总结 → 飞书支持 → 通过                        │
└─────────────────────────────────────────────────────────────────┘
```

**场景充分性评估**：

| 评估维度 | 状态 | 缺失项 | 处理方式 |
|---------|------|--------|---------|
| 业务类型 | ✅ 明确 | - | - |
| 核心管理对象 | ✅ 明确 | - | - |
| 使用者规模 | ❌ 缺失 | 个人/团队/多部门 | 追问 |
| 核心流程 | ❌ 缺失 | 谁录入/审核/发布 | 追问 |

**问题设计模板**：

```json
{
  "clarification": "为了更好地设计XXX，我需要确认以下信息：",
  "round": 1,
  "questions": [
    {
      "标签": "使用规模",
      "问题": "这个系统的使用者规模是？",
      "类型": "单选",
      "选项": [
        {"文本": "个人使用", "推荐": false},
        {"文本": "小团队协作（1-10人）", "推荐": true},
        {"文本": "多部门协作（10人以上）", "推荐": false},
        {"文本": "自定义", "推荐": false}
      ]
    }
  ]
}
```

**设计原则**：
- **配额限制**：每轮问题 ≤3 个
- **推荐默认值**：智能推荐最常见选项
- **选项兜底**："自定义"选项避免疏漏
- **单选优先**：减少用户决策负担

**收敛判定树**：

```
用户回答问题
    │
    ▼
┌─────────────────┐
│ 收敛条件检查    │
├─────────────────┤
│ 必查项100%覆盖？│
│ 复杂度可接受？  │
│ 无越界内容？    │
└────────┬────────┘
         │
         ▼
    ┌────────┐
    │ 全部通过 │───Yes──→ 调用执行层
    └────────┘
         │
         No
         │
         ▼
    继续澄清（配额内）
```

## 四、功能模块分析

| 功能模块 | 核心作用 | 优先级 | 与自身产品差异点 |
|---------|---------|--------|----------------|
| 意图识别与澄清 | 识别办公类需求，补充缺失信息 | 高 | 竞品支持意图自动分类 |
| 三关检查机制 | 渐进式验证，减少无效交互 | 高 | 自身产品暂无此机制 |

| Runtime 执行 | 提供工具执行环境 | 高 | 竞品支持 SDK+CLI 切换 |

| 异常处理 | 重试、纠错、错误提示 | 高 | 竞品支持自动修正 |

## 八、落地建议

### 8.1 功能优化建议

1. **新增三关检查机制**：在用户输入后增加渐进式验证
2. **优化问题配额设计**：限制每轮问题数，推荐默认值
3. **新增收敛判断模块**：显式判断是否可以执行
4. **增强工具匹配算法**：提升匹配准确率
