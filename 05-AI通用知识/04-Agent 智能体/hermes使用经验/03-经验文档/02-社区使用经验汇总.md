# Hermes Agent 社区使用经验汇总（2026.05）

> 来源：官方文档、GitHub 生态、中文社区博客、技术媒体
> 整理日期：2026-05-14

## 一、核心定位

Hermes Agent 是 Nous Research 的开源自主 AI Agent，GitHub 星标 104,791+（2026.04），是 2026 年增长最快的开源 Agent。核心口号 **"The agent that grows with you"**——随你成长的 Agent。

与其他工具的区别：
- 不是聊天机器人（ChatGPT），不是 IDE 插件（Cursor/Copilot）
- 是一个**自托管的 Agent 框架**，具备持续学习能力、跨平台通信、多 Agent 协作

参考：[Hermes Atlas 初学者指南](https://hermesatlas.com/guide/)、[Analytics Vidhya 指南](https://www.analyticsvidhya.com/blog/2026/05/hermes-agent-guide/)

## 二、三层记忆系统（最核心的设计）

| 层次 | 名称 | 机制 | 存储位置 |
|------|------|------|---------|
| L1 | 会话记忆 | SQLite + FTS5 全文检索 + LLM 自动摘要压缩 | `~/.hermes/state.db` |
| L2 | 知识记忆 | Agent 主动判断哪些信息值得长期保存，写入 MEMORY.md/USER.md | `~/.hermes/memories/` |
| L3 | 技能记忆 | 完成复杂任务后自动提炼为可复用 Skill 文件 | `~/.hermes/skills/` |

实际经验：
- 记忆会"过时"，随着积累增多可能出现前后矛盾，建议定期清理
- Skill 文件是 Markdown 格式，可读、可编辑、可版本控制
- 社区 Skills 平台：agentskills.io / ClawHub

参考：[CSDN - 实际使用三个月后](https://blog.csdn.net/qq_30089667/article/details/160450098)

## 三、多 Agent 协作机制（三代演进）

| 代际 | 方式 | 版本 | 适用场景 |
|------|------|------|---------|
| 第一代 | `delegate_task()` | v0.6+ | 简单任务派发，最多 3 个并行子 Agent |
| 第二代 | **Kanban 看板** | v0.12+（推荐） | 持久化任务队列，支持崩溃恢复、依赖编排 |
| 第三代 | Agent Profile | 规划中 | YAML 配置固定角色定义 |

### delegate_task 要点

子 Agent 从**完全空白**的上下文开始，必须通过 `goal` 和 `context` 传递所有必要信息：

```
# 错误 - 子 Agent 不知道"那个错误"是什么
delegate_task(goal="Fix the error")

# 正确 - 子 Agent 拥有完整上下文
delegate_task(
    goal="Fix the TypeError in api/handlers.py",
    context="The file api/handlers.py has a TypeError on line 47..."
)
```

### Kanban 看板核心组件

- **Orchestrator**：分解目标、创建任务、路由给合适角色
- **Dispatcher**：常驻 Gateway，每 60 秒扫描看板，拉起 ready 任务
- **Worker**：独立进程执行具体任务，有独立上下文和工具集
- **Human-in-the-Loop**：`kanban_block()` 机制支持人工介入决策

看板数据持久化到 `~/.hermes/kanban.db`（SQLite），进程崩溃/重启不丢失。

参考：[GitHub 官方 delegation 文档](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/delegation.md)、[头条 - 多Agent任务编排](http://m.toutiao.com/group/7638283306533962240/)

## 四、实用技巧与最佳实践

来源：[官方 Tips & Best Practices](https://hermes-agent.nousresearch.com/docs/guides/tips/)

### 4.1 提示词技巧

- **具体化**：不要说"修复代码"，要说"修复 api/handlers.py 第 47 行的 TypeError"
- **前置上下文**：一次性提供文件路径、错误信息、预期行为，比三轮澄清更高效
- **用 AGENTS.md 消除重复指令**：项目架构、编码规范、测试框架写入后自动注入每次会话
- **让 Agent 用工具**：说"找到并修复失败的测试"而不是手把手每一步

### 4.2 CLI 高效操作

| 操作 | 快捷键/命令 |
|------|-----------|
| 多行输入 | `Alt+Enter` 或 `Ctrl+J` |
| 中断重定向 | `Ctrl+C`（一次中断，两次强制退出） |
| 恢复上次会话 | `hermes -c` |
| 按标题恢复 | `hermes -r "项目名"` |
| 粘贴剪贴板图片 | `Ctrl+V`（支持视觉分析） |
| 斜杠命令补全 | `/` + `Tab` |
| 切换详细模式 | `/verbose`（off → new → all → verbose） |

### 4.3 上下文文件体系

| 文件 | 作用 | 位置 |
|------|------|------|
| `AGENTS.md` | 项目架构、编码规范 | 项目根目录（支持 monorepo 层级发现） |
| `SOUL.md` | 自定义 Agent 人格/风格 | 项目根目录或 `~/.hermes/SOUL.md` |
| `.cursorrules` | 兼容 Cursor 规则 | 项目根目录（自动读取） |

### 4.4 模型选择建议

| 用途 | 推荐模型 |
|------|---------|
| 编程任务 | Claude Sonnet 4 / GPT-5.4 |
| 日常任务 | GLM-5.1 / MiniMax M2.7（性价比高） |
| 本地部署 | Hermes 3 8B via Ollama（工具调用准确率 ~91%） |

Fallback 配置：主模型失败自动切换备用 Provider。

### 4.5 自动化工作流

```bash
# Cron 定时任务
hermes cron add "0 8 * * *" "总结今天的 GitHub 通知"

# 技能安装
hermes skills install web-search summarize

# Python 库模式
from hermes import Agent
agent = Agent()
result = agent.run("分析这段代码的性能瓶颈")
```

参考：[CSDN - 进阶实践：自动化工作流](https://blog.csdn.net/dingjie_2930/article/details/160123350)

### 5.9 指令使用最佳实践

1. **优先使用抽象指令**：用 `/goal 完成XX任务` 代替一步步告诉它怎么做，充分发挥 Hermes 的自主规划能力
2. **长任务用看板**：超过 3 步的复杂任务，一定要用 `/kanban` 管理，避免中途崩溃丢失进度
3. **耗时任务后台跑**：爬虫、数据分析等耗时任务，用 `/background` 放到后台，不影响继续使用
4. **定时任务用自然语言**：`/cron` 支持非常灵活的自然语言描述，不需要写复杂的 cron 表达式
5. **主动沉淀记忆和技能**：每完成一个复杂任务，就用 `/remember` 和 `/skill save` 沉淀经验，下次直接复用

## 七、已知痛点与注意事项

| 问题 | 说明 |
|------|------|
| Windows 不原生支持 | 需通过 WSL2 运行 |
| 记忆会过时 | 积累过多可能产生矛盾，需定期清理 MEMORY.md |
| Config 版本迁移 | v16 → v23 有多个新增字段，建议运行 `hermes doctor --fix` |
| `api_key_env` vs `key_env` | providers 配置中 `api_key_env` 在部分代码路径不被 normalizer 处理 |
| Kanban 没有 WebUI | 目前只能通过 CLI 命令查看任务进度 |
| openai 包安装不完整 | venv 中可能缺少 `openai.types.shared`，需 `pip install --force-reinstall openai` |
