## 核心提取规则
### 一、必做事项（硬性要求）
1. 结构匹配：严格遵循"输出结构规范"中的5大模块及子模块层级，不新增任何字段、不删减任何预设子模块，完全对齐变量框架；

4. 信息完整性：核心数据（如市场规模、增长率、定价、性能指标等）必须完整提取，不得遗漏关键限定条件（如时间、地域、统计范围）。

### 二、约束条件（禁止性要求）
1. 原文忠实：严格基于MRD原文表述进行分类提取，不主观修改语义、不添加个人观点、不扩展原文未提及的信息；

3. 格式统一：同类信息遵循一致的呈现逻辑（如竞品对比统一用表格、风险点统一用"类型-描述-应对"结构），符合示例中的格式规范；
4. 层级清晰：严格按照"模块→子模块→细分项"的层级拆解，不得跨层级合并或拆分信息。

## 维度二：从功能详述推导页面清单与核心内容定义
*   **输入要素**：功能ID、功能名称、功能描述、优先级（P0/P1等）。
*   **推导规则**：
    *   **功能集合与优先级** → **页面列表（5.1.2）**：将关联性强、优先级高的功能聚合映射到一个逻辑页面。每个核心功能模块通常对应一个主页面。功能描述中的关键动词（如"录入"、"查询"、"管理"）直接映射为页面"核心功能"描述。
    *   **功能粒度与数据对象** → **页面内容区域与数据结构**：功能操作的对象决定了页面主内容区展示的信息结构（表格、卡片、表单），从而推导出"数据结构"定义。功能的增删改查需求推导出页面工具栏的操作按钮组。
*   **映射至模块要素**：
    *   `5.1.2 页面列表`表格中的所有列（页面ID、名称、核心功能、布局类型、右侧面板）。
    *   `5.2.x 页面详情`中的"核心功能"、"数据结构"。

## 维度三：从用户操作步骤推导交互模式与组件级设计
*   **输入要素**：编号的操作步骤序列，包含用户动作与系统响应。
*   **推导规则**：
    *   **操作流程与节点** → **交互模式与页面流转**：操作步骤中连续的"用户点击…进入…页"推导出"页面切换"交互模式；步骤中的"系统弹出表单"推导出"模态弹窗"交互模式。
    *   **具体动作与信息项** → **组件类型与规格**：步骤中提及的"填写"、"选择"、"上传"等动作，推导出页面需要"输入框"、"下拉选择"、"文件上传"等组件，并进一步结合用户特征推导其尺寸和间距规范。
*   **映射至模块要素**：
    *   `5.1.1 整体布局架构`中的"交互模式"。
    *   `5.2.x 页面详情`中的"页面布局架构"、"组件尺寸规范"。

# 通用适配说明

def extract_tag_content(input_str: str, tag_prefix: str, tag_suffix: str, default: str = "无") -> str:
    pattern = re.compile(
        rf"(<\s*{re.escape(tag_prefix)}\s*>[\s\S]*?<\s*{re.escape(tag_suffix)}\s*>)",
        re.IGNORECASE
    )
    match = pattern.search(input_str)
    if not match:
        logger.warning(f"未匹配到标签对：<{tag_prefix}> - <{tag_suffix}>")
        return default
    content = match.group(1).strip()
    content = re.sub(r"\n+", "\n", content)
    return content if content else default

def convert_xml_to_markdown(xml_string, level=1):
    xml_string = xml_string.strip()
    pattern = r'<([^>]+)>(.*)</\1>'
    while True:
        if not re.search(pattern, xml_string, flags=re.DOTALL):
            return xml_string
        xml_string = re.sub(pattern, lambda x: f'{"#" * level} {x.group(1)}\n{x.group(2).strip()}', xml_string, flags=re.DOTALL)
        level += 1
