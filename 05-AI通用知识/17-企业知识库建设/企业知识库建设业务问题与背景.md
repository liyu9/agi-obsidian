# 企业知识库建设：业务问题与背景（极客时间课程案例）

> 本文档整理自极客时间《成为AGI产品经理》课程，记录真实业务场景的问题、背景和解决方案。

---

## 案例一：家电消费品智能说明书

### 业务背景

**个人场景**：
- 热水器故障 → 找不到产品说明书 → 求助客服，花了十几分钟
- 音响设备问题 → 说明书被扔掉 → 求助微信公众号客服
- **现象**：产品说明书被抛弃是一种常态

**企业验证**：
- 目标企业：年出货量40万台电子消费品的硬件公司
- 产品用户：6-18岁中小学生
- 售后服务方式：扫描产品二维码，关注微信公众号进行售后咨询

### 业务问题

| 问题类型 | 具体问题 | 影响 |
|---------|---------|------|
| 客服成本高 | 需要雇佣10名全职客服人员 | 人力成本高，流动性大 |
| 问题重复 | 超过80%用户问题是产品使用的基本问题 | 客服工作重复性高 |
| 培训负担 | 新员工培训需要大量时间和资源 | 运营成本高 |
| AI效果差 | 市场上AI方案价格昂贵且效果不好 | 无法有效降本 |
| 长尾难处理 | 剩余20%长尾诉求分析耗时太长 | 难以从中提取产品改进洞察 |

### 解决方案

```
┌────────────────────────────────────────────────────────────┐
│                      三个端侧                              │
├────────────────────────────────────────────────────────────┤
│ 用户端：家电消费者扫码提问，接收AI回答                      │
│ 企业售后端：上传说明书、管理文档、查看问答记录              │
│ LLM AI应用端：生成回答、客服回答打分、用户问题打标签       │
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│                      两个功能模块                          │
├────────────────────────────────────────────────────────────┤
│ 模块1：回答产品说明书相关问题（RAG实现）                   │
│ 模块2：处理长尾诉求（转人工+AI辅助审核）                   │
└────────────────────────────────────────────────────────────┘
```

**核心技术选型理由**：
- 说明书就像客服的"外挂检索知识库"
- 客服不需要记忆说明书，只需知道怎么查
- 这与RAG赋予大模型的能力极其类似
- 本质是"检索→理解→输出"的过程

## 案例二：企业私域AI搜索

### 业务背景

**市场背景**：
- 2024年初，Perplexity AI搜索产品获得千万用户使用
- 被英伟达CEO黄仁勋推荐，得到广泛传播

**传统搜索 vs AI搜索**：

| 对比项 | 传统搜索（Google） | AI搜索（Perplexity） |
|--------|-------------------|---------------------|
| 用户输入 | 陈述性关键词 | What/Why/How问句 |
| 输入示例 | "陕西省申报绿色矿山规定" | "陕西省申报绿色矿山有什么要求" |
| 输出形式 | 若干网址链接 | 直接答案 |

**知识管理升级**：
- 传统搜索：知识获取
- AI搜索：知识调用
- 将计算机对知识的处理能力整体向前推进一步

### 业务问题

**KA客户（大型企业客户）的诉求**：
- 需要一整套解决方案，不是单一技术
- 企业内部有大量私有知识需要AI化
- 对准确性要求高，影响业务决策
- 数据源多样：内部文档、数据库、第三方系统

**企业搜索 vs 普通搜索的差异**：

| 维度 | 普通搜索 | 企业搜索 |
|------|---------|---------|
| 数据源 | 公开网页 | 内部文档、数据库 |
| 准确性要求 | 较低 | 高（影响业务决策） |
| 召回率要求 | 优先 | 必须保证 |
| 冷启动问题 | 无 | 有（新系统数据不足） |

### 解决方案架构

```
用户Query
    │
    ▼
┌─────────────────────────────────────────────┐
│  三次处理（区别于简单RAG的关键）             │
│  ① 意图识别  ② Query重写  ③ Query路由        │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│  多种数据源                                  │
│  知识库 │ 数据库 │ 搜索引擎 │ 文档库         │
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│  Agent生成（Plan-and-Solve + Re-Act + 反思） │
└─────────────────────────────────────────────┘
```

## 案例三：知识库机器人三大病症（实战问题）

### 病症一：明明有答案却回答不出来

**真实案例**：
- 用户问："在人机对话时，机器识别不到讲的语音怎么办"
- 产品说明书中有明确答案："a. 需要点击对话键，激活对话功能……"
- AI却给出笼统回答："可能多种原因导致的，比如环境噪音……"

**问题排查过程**：

```
肉眼可见有答案
       │
       ▼
检查检索结果 ──→ 发现：检索结果中没有匹配到
       │
       ▼
原因分析：
① 检索方式不合理（向量检索 vs 关键字检索）
② 分块不合理（文本块只有问题没有答案）
```

**根因分析**：

| 原因 | 具体表现 | 示例 |
|------|---------|------|
| 向量检索局限性 | 同义词距离近，但完整句子距离远 | "桃子"和"梨"向量接近，但完整问句可能不匹配 |
| 关键字检索局限性 | 要求完全匹配，比较死板 | 无法处理同义词表达 |
| 分块语义断裂 | 问题在块A，答案在块B | 检索命中块A但不包含答案 |

### 病症二：如何把图片带进回答

**业务场景**：
- 产品说明书中包含大量示意图、界面截图
- 用户问题可能需要图片辅助理解
- RAG向量化无法处理图片

**技术挑战**：
- 文本和图片无法放在同一向量库
- 需要在检索时将相关图片一并返回

### 病症三：Token消耗太快

**业务背景**：
- 大规模用户使用场景下，Token成本急剧上升
- 需要在保证效果的同时控制成本

**量化影响**：
- RAG调用成本 vs 传统方式
- 用户量级：40万台设备 × 不定次咨询

## 案例四：Perplexity类AI搜索产品

### 业务背景

**产品定位**：
- 被称为"答案引擎"，区别于传统搜索引擎
- 直接回答用户问题，而非返回链接列表

**用户行为变化**：
- 从"搜索关键词"到"提问"
- 从"自己筛选信息"到"获得直接答案"
- 对话式交互成为可能

### 业务问题

| 问题类型 | 具体表现 |
|---------|---------|
| 准确性要求高 | 答案直接呈现，错误难以容忍 |
| 实时性要求 | 需要获取最新信息 |
| 知识覆盖度 | 需要处理各种领域问题 |
| 引用溯源 | 用户需要知道答案来源 |

### 技术方案

| 模块 | 技术选型 | 业务价值 |
|------|---------|---------|
| 意图识别 | LLM Prompt | 理解用户真实需求 |
| Query改写 | 5种重写策略 | 提高检索命中率 |
| 多源路由 | 规则+LLM | 充分利用企业内部知识 |
| 生成回答 | Agent模式 | 保证答案质量 |

## 产品经理核心工作（课程总结）

### 需求发现

**方法论**：
- 从个人细微体验出发，挖掘企业级诉求
- 在了解"锤子"（技术能力）基础上找"钉子"（业务痛点）
- 从没能被上一代AI满足的需求中寻找机会

**关键转变**：
```
传统PM：等别人提出需求
AI PM：主动发现痛点
```

### 方案设计

| 环节 | PM具体工作 |
|------|-----------|
| 知识梳理 | 定义知识分类体系，确定知识边界 |
| 意图设计 | 收集用户问题，设计意图分类 |
| Query分析 | 分析Query特点，设计重写策略 |
| 数据源规划 | 定义数据源分类和检索方法 |
| 路由规则 | 定义什么问题去查哪个数据源 |
| Agent模式 | 根据场景选择合适的Agent设计模式 |
| 效果验收 | 定义验收标准，组织测试验收 |

### 产品价值公式

```
产品价值 = (新体验 - 旧体验) - 迁移成本
```

**AI产品特殊性**：
- 新旧体验对比可能非常显著（10倍提升）
- 迁移成本包括：数据迁移、学习成本、组织调整、关系建立

## AI与人工分工原则

| 问题类型 | 适合由谁回答 | 理由 |
|---------|-------------|------|
| 简单重复问题 | AI | 标准化，效率高 |
| 复杂个性化问题 | 人工 | 需要判断力和同理心 |
| 高风险决策 | 人工确认 | 责任边界明确 |
| 知识问答类 | AI（RAG） | 有明确答案来源 |
| 长尾诉求 | AI辅助+人工 | AI预处理，人工把关 |

## 实施要点总结

### 发现需求三问

1. **用户是谁？** → 明确目标用户群体
2. **痛点是什么？** → 识别真需求而非伪需求
3. **现有方案为什么不满足？** → 找到AI能解决的gap

### 方案设计三步

1. **画用户旅程** → 梳理完整交互流程
2. **找AI增强点** → 确定哪些环节用AI提升
3. **设计容错机制** → 考虑失败时的兜底方案

### 上线后运营

1. **持续收集反馈** → 用户吐槽是最好的优化方向
2. **定期评估效果** → 技术指标+业务指标双轨评估
3. **知识库更新** → 保持知识新鲜度
4. **迭代提示词** → 根据真实case优化
