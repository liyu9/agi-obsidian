# 知识库与Agent对接：技术实施问题清单

> 整理自极客时间《成为AGI产品经理》课程及企业实际落地经验，记录知识库与Agent对接过程中的真实技术问题及解决方案

## 一、知识采集与存储问题

### 1.1 文档格式问题

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 扫描件无法提取文字 | PDF是扫描图片，无法直接解析 | 使用OCR识别（paddleocr/tesseract） |
| Word公式/图表丢失 | .docx中的复杂格式转换丢失 | 使用 mammoth 库，图表单独处理 |
| HTML标签干扰 | 网页内容包含大量HTML标签 | 使用 BeautifulSoup 提取正文 |
| 编码不一致 | 不同文档编码不同（GBK/UTF-8） | 统一转换为UTF-8 |
| 表格结构丢失 | Excel/Word表格转为纯文本 | 保留表格结构，用特殊标记处理 |

### 1.2 多媒体内容处理

**图片问题**：

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 图片无法向量化 | RAG只能处理文本，图片无法入库 | Metadata存储ImageURL，检索时一并返回 |
| 图片与文字关联丢失 | 图片位置信息丢失 | 建立图片-段落关联关系 |
| 截图/流程图无法理解 | 图片内容无法被检索 | 使用多模态模型提取描述 |

**图文关联法**（极客时间课程方案）：

```python
# 文本分块时添加图片元数据
text_chunk = {
    "content": "点击对话键，激活对话功能...",
    "metadata": {
        "image_urls": ["product_manual/p10_fig3.png"]
    }
}
# 检索时返回图片URL，生成时附带展示
```

**图文转换法**（极客时间课程方案）：

```
用多模态大模型（如Google Gemini1.5）将图片内容理解后转换为文本，
存储为该文本块的元数据。
```

### 1.3 知识质量问题

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 敏感信息泄露 | 身份证号、银行卡号等 | 入库前自动脱敏（正则匹配+替换） |
| 重复内容 | 同一内容多处存在 | SimHash去重，向量相似度检测 |
| 内容冲突 | 不同文档说法矛盾 | 时间权重（取最新）、来源优先级 |
| 内容过时 | 旧知识影响回答 | 关联时间戳，过期提示 |

## 二、RAG分块（Chunking）问题

### 2.1 分块大小问题

| 问题 | 描述 | 影响 |
|------|------|------|
| 块过大 | 超过模型Context窗口 | 截断丢失信息，增加Token成本 |
| 块过小 | 语义被切断 | 答案不完整，缺少上下文 |
| 块大小不一 | 有的很长有的很短 | 检索质量不稳定 |

**推荐配置**（极客时间课程）：

```yaml
chunk_size: 512 tokens
chunk_overlap: 50 tokens  # 约10%重叠
```

### 2.2 分块边界问题（核心问题！）

**真实案例**（极客时间课程）：

> 用户问："在人机对话时，机器识别不到讲的语音怎么办"
> 知识库中有答案："a. 需要点击对话键，激活对话功能……"
> AI回答："可能多种原因导致的，比如环境噪音……"

**根因分析**：返回的文本块只有问题部分，没有答案内容

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 问题在块A答案在块B | 检索命中但无法回答 | 设置15%重叠，或强制返回相邻块 |
| 段落被切断 | 语义不完整 | 按段落切分，避免在句子中间切断 |
| 列表被切断 | 编号列表被分开 | 保持列表结构完整性 |
| 表格被切断 | 表格行被分到不同块 | 整个表格作为独立块 |

### 2.3 分块方法选择

| 方法 | 适用场景 | 问题 |
|------|---------|------|
| 固定长度 | 通用场景 | 语义可能断裂 |
| 按段落 | 结构化文档 | 段落可能过长 |
| 按句子 | 短文本 | 块太小，缺乏上下文 |
| 语义分块 | 高质量要求 | 实现复杂，效果不稳定 |
| 递归分块 | 复杂文档 | 实现复杂 |

### 2.4 分块优化策略（极客时间课程方案）

**策略一：设置冗余重合内容**

```
块1: [内容A][内容B][内容C][内容D]────────────┐
                                              │ 15%重叠
块2: [内容C][内容D][内容E][内容F]────────────┘
                                              │ 15%重叠
块3: [内容F][内容G][内容H][内容I]────────────┘
```

**代价**：增加存储

---

**策略二：强制返回相邻块**

```python
def retrieve_with_neighbors(query, top_k=5):
    chunks = vector_db.search(query, top_k=top_k*3)
    result_chunks = []
    for chunk in chunks:
        result_chunks.append(chunk)
        # 强制返回相邻块
        if chunk.prev_id:
            result_chunks.append(get_chunk(chunk.prev_id))
        if chunk.next_id:
            result_chunks.append(get_chunk(chunk.next_id))
    return deduplicate(result_chunks)[:top_k]
```

**代价**：Token成本扩大2-3倍

---

**策略三：改进分块方法**

针对不同文档类型选择不同分块策略：
- 产品说明书：按章节/步骤分块
- 政策制度：按条款分块
- FAQ：问答对作为一个整体

## 三、检索问题

### 3.1 检索方式问题

**三大检索方式对比**（极客时间课程）：

| 检索方式 | 原理 | 问题 |
|---------|------|------|
| 向量检索 | 语义相似度匹配 | 同义词可能匹配，但完整句子可能不匹配 |
| 关键字检索 | BM25精确匹配 | 无法理解语义 |
| 混合检索 | 两者结合 | 兼顾精确与语义 ✅ 推荐 |

**向量检索局限性详解**（极客时间课程）：

> 同义词在向量空间里距离很近，比如"桃子"与"梨"在很多维度相似
> 但用户的问题可能与文本块整体向量距离很远
> 因此单纯使用向量检索时，文本块不会被检索出来

### 3.2 检索问题排查流程（极客时间课程）

```
明明有答案却答不出来
       │
       ▼
检查检索结果 ──→ 发现：检索结果中没有匹配到
       │
       ▼
原因1：检索方式不合理
       │
       ├─→ 改为混合检索（向量+关键字）
       │
       ▼
原因2：分块不合理
       │
       ├─→ 设置15%重叠
       ├─→ 强制返回相邻块
       └─→ 改进分块方法

       │
       ▼
检索结果正确
       │
       ▼
检查分块内容是否覆盖答案
       │
       ├─→ 分块正确 → 优化提示词或切换模型
       └─→ 分块错误 → 优化分块策略
```

### 3.3 Query重写问题

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| 同义重写 | 同义词差异 | "入职"→"入职手续如何办理" |
| 抽象化重写 | 过多具体信息 | "张三入职手续"→"公司新员工入职流程" |
| 拆解重写 | 复合问题 | "山东陕西能源新闻"→拆为两条 |
| HyDE重写 | 开放式问题 | "什么是XX"→先生成答案再检索 |
| 多查询生成 | 语义模糊 | "产品怎么样"→5个不同角度 |

### 3.4 意图识别与路由

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 意图分类不准 | 分类错误导致路由失败 | 增加Few-Shot示例 |
| 多意图共存 | 问题涉及多个意图 | 返回多意图，主意图优先 |
| 数据源选择错误 | 应该查A却查了B | 完善路由规则 |

## 四、生成与Agent问题

### 4.1 上下文组装问题

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 上下文超长 | 检索结果太多，超出窗口 | 上下文压缩、去重、截断 |
| 噪声干扰 | 无关内容影响生成 | 相关性过滤，只取高相关块 |
| 引用丢失 | 不知道答案来源 | 返回时附带来源信息 |

### 4.2 生成质量控制

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| 幻觉回答 | 答案与检索内容不符 | 加入"仅基于以下内容回答"约束 |
| 回答不完整 | 遗漏关键信息 | 检查清单提示词 |
| 过度泛化 | 回答太笼统没有针对性 | 增加"具体说明"要求 |

### 4.3 Agent模式选择（极客时间课程）

| 场景 | 推荐模式 | 说明 |
|------|---------|------|
| 知识问答 | Plan-and-Solve + 反思 | 步骤多，需要分解 |
| 数据查询 | Re-Act | SQL可能失败需重试 |
| 文档提取 | 反思模式 | 任务简单，只需验证 |
| 简单问答 | 直接使用 | 确定性高 |

### 4.4 循环控制问题

| 问题 | 描述 | 解决方案 |
|------|------|---------|
| Re-Act死循环 | 一直检索不结束 | 设置最大循环次数（如10次） |
| 失败无兜底 | 完全失败无法处理 | 设置兜底回答/转人工 |

## 五、成本与性能问题

### 5.1 Token消耗问题

**80-20原则**（极客时间课程）：

> 20%的问题覆盖80%的用户问题

| 方法 | 说明 | 效果 |
|------|------|------|
| 问答对匹配代替RAG | 高频问题直接匹配，不走RAG | 节省80%成本 |
| 提示词压缩 | 如LLMLingua | 压缩30%，可能影响准确率 |
| 强制返回相邻块 | 返回块时带上相邻块 | Token成本扩大2-3倍 |

### 5.2 性能优化

| 问题 | 解决方案 |
|------|---------|
| 检索慢 | 优化索引（HNSW）、增加缓存 |
| 生成慢 | 使用更快的模型、流式输出 |
| 整体延迟高 | 异步处理、预热、缓存 |

## 六、知识库机器人三大病症（极客时间课程总结）

### 病症一：明明有答案却回答不出来

**排查步骤**：

1. 检查检索结果 → 修正检索方法
2. 检查分块内容 → 优化分块策略
3. 检查提示词/模型 → 优化提示词或换模型

### 病症二：如何把图片带进回答

| 方法 | 实现 | 代价 |
|------|------|------|
| 图文关联法 | Metadata存储ImageURL | 低 |
| 图文转换法 | 多模态模型转文本 | 高 |

### 病症三：Token消耗太快

| 方法 | 效果 |
|------|------|
| 问答对匹配 | 节省80%成本 |
| 提示词压缩 | 压缩30% |
