## 二、知识点分类索引

### A. 概念与术语

| 概念 | 定义 | 来源 |
|------|------|------|
| **Low Code（低代码）** | Forrester 2014年提出，通过支持拖曳操作的GUI交互界面与少量代码开发应用 | 决胜B端第08章 |
| **No Code（无代码）** | 完全不用编码即可实现应用程序开发 | 决胜B端第08章 |
| **LCAP** | Gartner 2019年提出，内涵更丰富的低代码平台，融合低代码、aPaaS | 决胜B端第08章 |
| **aPaaS** | SaaS的底层配置、定制化平台，如流程编辑器、对象编辑器 | 决胜B端第08章 |
| **PaaS** | 第三方提供开发/维护/部署环境，狭义等同于aPaaS | 决胜B端第01章 |
| **IaaS** | 第三方提供计算/存储能力，如AWS、阿里云 | 决胜B端第01章 |
| **Citizen Developer（公民开发者）** | Gartner定义：使用IT授权工具创建自用或伙伴使用应用的企业员工，业务部门角色 | 决胜B端第08章 |

### B. 平台分类

#### 按代码角色分

| 类型 | 代码角色 | 使用者 |
|------|---------|--------|
| 纯代码（Pro Code） | 关键输入 | 专业开发者 |
| 低代码（Low Code） | 中间产物（自动生成） | 专业开发者 + 业务技术人员 |
| 无代码（No Code） | 无代码 | 业务技术人员 |

#### 按适用范围分

| 类型 | 特征 | 优劣 |
|------|------|------|
| 通用型 | 纯技术底座，不绑定业务 | 适用广 / 特定场景效率低，需插件补位 |
| 专用型 | 绑定特定行业/场景 | 特定场景效率高 / 难以适应业务变化 |

#### 按输出App类型分

| App类型 | 典型场景 |
|---------|---------|
| 流程驱动型 | OA、工单系统 |
| 表单驱动型 | 调查问卷、信息登记 |
| 模型驱动型（ORM） | CRUD类业务系统 |
| BI分析型 | 报表、Dashboard |

#### 按实现模式分（决胜B端第08章）

| 模式 | 核心特点 | 目标用户 | 代表产品 |
|------|---------|---------|---------|
| **模型驱动** | 数据对象编辑器，功能强大灵活 | IT背景研发、需求分析师、项目经理 | Mendix、OutSystem、Salesforce |
| **表单驱动** | 配置表单，易理解上手 | 非IT背景业务人员 | Jira、钉钉宜搭 |
| **表格驱动** | 像Excel一样定义数据模型 | 非IT背景业务人员 | Airtable、飞书多维表格 |

### D. 核心方法论

#### 1. 三阶段发展模型

| 阶段 | 周期 | 核心目标 |
|------|------|---------|
| MVP阶段 | 3-6个月 | 快速试错、获取天使用户 |
| 成熟期 | 12-18个月 | 发展通用能力 |
| 超越期 | 长期 | 场景化超越Pro Code |

#### 2. 成熟期核心原则

1. 对任何业务需求，按最通用情形考虑
2. 充分考虑已知场景共同特征，忽略个性化特征
3. 能用已有功能实现的，决不新增功能
4. 放低姿态，培育与应用团队的关系

#### 3. AI融合的不可能三角

```
        开发效率
        /     \
   易用性 ——————— 可定制化
```

三者最多只能得其二。功能越强大→编辑器越复杂→易用性越差。

#### 4. 面向业务技术人员的体验设计

- 说人话（少用编程术语）
- 傻瓜化操作
- 渐进式引导
- 可以抄作业（提供大量模板）
- 自动化兜底

### E. 平台对比（飞书多维表格 vs 伙伴云）

| 维度 | 飞书多维表格 | 伙伴云 |
|------|------------|--------|
| 设计理念 | 简洁优先，声明式filter | 功能完备，独立筛选器对象 |
| 嵌套能力 | 两层（conjunction+children） | 任意深度（and/or递归） |
| 运算符 | is/isNot/isGreater等完整单词 | eq/ne/gt等缩写 |
| 动态时间 | TODAY()等函数 | today/yesterday/last_month等预定义变量 |
| 分页机制 | 游标分页（稳定但不能跳页） | 偏移分页（支持跳页但深度性能差） |
| 特色能力 | 视图（view_id）性能优化3-5倍 | myself变量、动态时间变量、批量检查接口 |
| 适用场景 | 中小规模、简单筛选 | 大规模、复杂企业级应用 |

### F. 大规模数据处理策略

1. **服务端筛选** — filter参数下推，计算向数据靠拢，性能提升约10倍
2. **视图优化** — 预计算+缓存，高频查询3-5倍性能提升
3. **分批与增量同步** — 时间戳/版本号/变更日志，将O(N)降至O(ΔN)
4. **合理分页大小** — 飞书单次≤500条
5. **错误重试+token自动刷新** — 飞书token有效期仅2小时
