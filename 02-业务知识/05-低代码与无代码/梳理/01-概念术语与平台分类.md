# 概念术语与平台分类

> 来源：低代码平台产品认知总览.md、PM书籍/决胜B端（第08章/第01章/第17章）

## 一、核心概念辨析

### 1.1 低代码 vs 无代码 vs 纯代码

| 维度 | 纯代码（Pro Code） | 低代码（Low Code） | 无代码（No Code） |
|------|-------------------|-------------------|-------------------|
| 代码角色 | 关键输入 | 中间产物（副产品） | 无代码参与 |
| 开发思维 | 指令式：告诉计算机如何一步步实现 | 描述式：不停描述和细化业务最终样子 | 组合式：对已有原子业务能力二次组合 |
| 框架性代码 | 手工编写 | 100%自动生成 | 不涉及 |
| 使用者 | 专业开发者 | 专业开发者 + 业务技术人员 | 业务技术人员 |

> **关键识别点**：Low Code 与 No Code 完全不是一种东西。Low Code 依然有代码，代码是自动生成的中间产物；No Code 只是对已有业务做二次组合。

### 1.2 基础设施演进路径

```
物理设备 → IaaS → PaaS → SaaS → aPaaS
```

| 概念 | 全称 | 说明 | 代表 |
|------|------|------|------|
| **IaaS** | Infrastructure as a Service | 提供计算、存储、网络等基础运算资源 | AWS、阿里云 |
| **PaaS** | Platform as a Service | 将软件研发平台作为服务提供 | — |
| **SaaS** | Software as a Service | 软件即服务，通过网络直接使用 | 钉钉、北森、销售易 |
| **aPaaS** | application Platform as a Service | 应用程序的开发和部署环境 | Salesforce PaaS |

**演进关键点：**
- SaaS 高度封装 → 定制性太弱
- 由此演进到 aPaaS → 提供迭代构建、即时提供、按需扩展、集成应用能力
- aPaaS 属于 PaaS 的子集，更聚焦应用程序定义和配置

### 1.3 LCAP（Low Code Application Platform）

由 Gartner 2019 年提出，是内涵更加丰富的低代码平台，融合了低代码、aPaaS 等概念。

> 行业现状：Gartner 每年将所有低代码供应商放在其 LCAP 魔力象限报告中进行统一打分，很少有人刻意区分低代码和无代码。

## 二、平台分类

### 2.1 按适用范围

| 类型 | 特征 | 优势 | 劣势 |
|------|------|------|------|
| **通用型** | 纯技术底座，不绑定业务 | 适用面广、想象空间大 | 特定场景效率低，需插件补位 |
| **专用型** | 绑定特定行业或场景 | 特定场景效率极高 | 难以适应业务变化 |

> **通用型的伴生特征**：有相对完善的插件机制，用插件的定制化解决具体场景的效率问题。

### 2.2 按输出 App 类型

| App类型 | 特征 | 典型场景 |
|---------|------|---------|
| 流程驱动型 | 以流程为主线，支持审批、流转 | OA、工单系统 |
| 表单驱动型 | 以数据采集为中心 | 调查问卷、信息登记 |
| 模型驱动型（ORM） | 以数据模型和关系为中心 | CRUD类业务系统 |
| BI分析型 | 以数据可视化和分析为中心 | 报表、Dashboard |

> 通用型平台不局限输出某一种类型，理论上都能支持。

### 2.3 按使用者类型

| 用户类型 | 特征 | 需求侧重 |
|---------|------|---------|
| 专业技术人员 | 掌握软件研发技能 | 底层代码掌控力、可视化辅助其他领域 |
| 业务技术人员 | 非IT部门，构建技术或分析功能 | 傻瓜化、少用编程术语、渐进式引导 |
| 无专业技能人员 | 无任何软件技能 | 极致简单、模板驱动 |

> **业务技术人员数据**（Gartner研究）：41%的员工可被称为业务技术人员；政府部门约25%，能源IT密集型行业约50%。
>
> **用户群演进规律**：低代码平台成熟度↑ → 可视化工具更丰富 → 研发生命周期覆盖更完整 → 业务技术员独立开发成为可能 → 占比↑

### 2.4 按实现模式（决胜B端第08章）

| 模式 | 核心特点 | 目标用户 | 代表产品 |
|------|---------|---------|---------|
| **模型驱动** | 通过数据对象编辑器完成底层数据建模，功能强大灵活 | IT背景研发、需求分析师、项目经理 | Mendix、OutSystem、Salesforce、销售易、纷享销客、北森 |
| **表单驱动** | 配置表单完成数据建模，易理解上手 | 非IT背景业务人员 | Jira、钉钉宜搭、Trello |
| **表格驱动** | 像Excel一样定义数据模型，类Excel+简化版VBA | 非IT背景业务人员 | Airtable、飞书多维表格 |

### 2.5 按部署方式

| 方式 | 适用 | 特点 |
|------|------|------|
| **公有云** | 中小企业 | 开箱即用 |
| **私有化部署** | 大型企业、政企客户 | 数据信息安全，应对合规要求 |

## 三、关键术语

### 3.1 角色术语

- **业务技术人员** — Gartner 定义：供内部和外部业务使用的技术或分析功能的非IT部门员工
- **公民开发者（Citizen Developer）** — 使用IT授权工具创建自用或伙伴使用应用的企业员工，属于业务部门而非IT部门
- **业务专家** — 非IT背景但精通业务的用户

### 3.2 技术术语

- **D2C** — Design to Code，UX设计稿转代码
- **ORM** — Object-Relational Mapping，对象关系映射
- **RTE** — Real-Time Engagement，实时互动
- **API网关** — API Gateway，统一管理API的入口

### 3.3 商业模式术语

- **PaaS vs 低代码** — 区别：
  - PaaS 是 SaaS 的底座，先服务于主产品（SaaS或私有化商业软件）
  - 低代码产品是独立商业化产品，售卖的是低代码平台本身
  - 例如：Salesforce 的 PaaS 仍受限于 CRM 主产品；Mendix 作为独立 LCAP 可创建各种应用

## 四、PaaS 与低代码的本质区别

| 维度 | PaaS | 低代码 |
|------|------|--------|
| 服务对象 | SaaS公司的客户/合作伙伴 | 独立的产品采购方 |
| 目标用户 | 乙方实施团队或甲方系统管理员 | 包含无技术背景的公民开发者 |
| 商业定位 | 围绕主产品的底座 | 独立商业化产品 |
| 自由度 | 受限于主产品（如Jira PaaS必须符合项目管理业务要求） | 相对自由 |

> Gartner 企业级 LCAP 魔力象限中既有 Mendix、OutSystem 这样的独立厂商，也有 Salesforce、ServiceNow 这样的 SaaS 公司。
